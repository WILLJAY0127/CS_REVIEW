# 03. 实操手册：从 0 到 1 跑通 Maven 和 Gradle

> 这是一份**边看边练**的手册，每一步都有实际命令和预期输出。
> 项目位置：`d:\myfile\CS_REVIEW\构建工具原理\demo\`

## 第一部分：Maven 实操

### 第 1 步：用 Maven 骨架生成一个项目

```bash
# 在 d:\myfile\CS_REVIEW\构建工具原理\ 下执行
cd d:\myfile\CS_REVIEW\构建工具原理

# 用 Maven archetype 快速生成
mvn archetype:generate ^
  -DgroupId=com.example ^
  -DartifactId=demo-app ^
  -Dversion=1.0.0 ^
  -DarchetypeArtifactId=maven-archetype-quickstart ^
  -DinteractiveMode=false
```

**预期输出**：
```
[INFO] BUILD SUCCESS
[INFO] Total time:  XX 秒
```

生成的目录结构：
```
demo-app/
├── pom.xml
└── src/
    ├── main/java/com/example/App.java
    └── test/java/com/example/AppTest.java
```

### 第 2 步：看生成的 pom.xml

打开 `demo-app/pom.xml`，对照着理解：

```xml
<project>
  <modelVersion>4.0.0</modelVersion>
  
  <!-- 坐标 GAV -->
  <groupId>com.example</groupId>
  <artifactId>demo-app</artifactId>
  <version>1.0.0</version>
  <packaging>jar</packaging>

  <!-- 继承 super pom（Maven 内置的，定义了默认插件） -->
  <parent>
    <groupId>org.apache.maven</groupId>
    <artifactId>maven-parent</artifactId>
    <version>38</version>
  </parent>

  <!-- JDK 版本配置（super pom 里有的话可以不用） -->
  <properties>
    <maven.compiler.source>1.8</maven.compiler.source>
    <maven.compiler.target>1.8</maven.compiler.target>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>

  <!-- 依赖 -->
  <dependencies>
    <!-- junit 是 test scope -->
    <dependency>
      <groupId>junit</groupId>
      <artifactId>junit</artifactId>
      <version>4.13.2</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>
```

### 第 3 步：跑完整构建

```bash
cd demo-app

# 清理 + 编译 + 测试 + 打包 + 安装
mvn clean install
```

**预期输出**（重点关注的行）：
```
[INFO] --- maven-clean-plugin:3.2.0:clean @ demo-app ---
[INFO] Deleting D:\...\demo-app\target

[INFO] --- maven-resources-plugin:3.3.1:resources @ demo-app ---

[INFO] --- maven-compiler-plugin:3.13.0:compile @ demo-app ---
[INFO] Compiling 1 source file with javac [options...] to target/classes

[INFO] --- maven-resources-plugin:3.3.1:testResources @ demo-app ---

[INFO] --- maven-compiler-plugin:3.13.0:testCompile @ demo-app ---
[INFO] Compiling 1 source file with javac [options...] to target/test-classes

[INFO] --- maven-surefire-plugin:3.2.5:test @ demo-app ---
[INFO] Running com.example.AppTest
[INFO] Tests run: 1, Failures: 0, Errors: 0, Skipped: 0

[INFO] --- maven-jar-plugin:3.4.1:jar @ demo-app ---
[INFO] Building jar: D:\...\demo-app\target\demo-app-1.0.0.jar

[INFO] --- maven-install-plugin:3.1.2:install @ demo-app ---
[INFO] Installing D:\...\demo-app\target\demo-app-1.0.0.jar
[INFO] To C:\Users\你的用户名\.m2\repository\com\example\demo-app\1.0.0\demo-app-1.0.0.jar

[INFO] BUILD SUCCESS
```

**对应理解**：
- `maven-clean-plugin:clean` → clean 生命周期
- `maven-compiler-plugin:compile` → 调用 javac 编译
- `maven-surefire-plugin:test` → 跑 JUnit
- `maven-jar-plugin:jar` → 打 jar 包
- `maven-install-plugin:install` → 复制到本地仓库

### 第 4 步：看编译到底调了啥

用 `-X`（debug 模式）可以看到 Maven **实际调用的 javac 命令**：

```bash
mvn clean compile -X
```

**预期输出**（找到关键行）：
```
[DEBUG] Command line options:
[DEBUG] -d D:\...\demo-app\target\classes
[DEBUG] -classpath D:\...\demo-app\target\classes
[DEBUG] -sourcepath D:\...\demo-app\src\main\java
[DEBUG] -encoding UTF-8
[DEBUG] -source 1.8
[DEBUG] -target 1.8
[DEBUG] com\example\App.java
```

**这就是 Maven 的本质：它帮你组装了 javac 命令行参数！**

### 第 5 步：跑 jar 包

```bash
# 看 jar 里面有啥
jar -tf target/demo-app-1.0.0.jar

# 运行
java -cp target/demo-app-1.0.0.jar com.example.App
```

### 第 6 步：添加一个有传递依赖的库

修改 `pom.xml`：

```xml
<dependencies>
  <dependency>
    <groupId>junit</groupId>
    <artifactId>junit</artifactId>
    <version>4.13.2</version>
    <scope>test</scope>
  </dependency>
  
  <!-- 新增：Apache Commons IO（它有很多传递依赖） -->
  <dependency>
    <groupId>commons-io</groupId>
    <artifactId>commons-io</artifactId>
    <version>2.15.1</version>
  </dependency>
</dependencies>
```

然后看依赖树：

```bash
mvn dependency:tree
```

**预期输出**：
```
[INFO] com.example:demo-app:jar:1.0.0
[INFO] +- commons-io:commons-io:jar:2.15.1:compile
[INFO] \- junit:junit:jar:4.13.2:test
[INFO]    \- org.hamcrest:hamcrest-core:jar:1.3:test
```

**看！junit 自动带进来了 hamcrest-core，这就是传递依赖！**

### 第 7 步：故意制造版本冲突

假设你加一个库，它也依赖了旧版 hamcrest：

```xml
<dependencies>
  <dependency>
    <groupId>junit</groupId>
    <artifactId>junit</artifactId>
    <version>4.13.2</version>
    <scope>test</scope>
  </dependency>
  
  <!-- 这个库可能依赖 hamcrest-core:1.2 -->
  <dependency>
    <groupId>org.hamcrest</groupId>
    <artifactId>hamcrest-all</artifactId>
    <version>1.3</version>
    <scope>test</scope>
  </dependency>
</dependencies>
```

```bash
# 详细看冲突
mvn dependency:tree -Dverbose
```

Maven 会自动选一个版本（路径最近或第一声明优先）。

### 第 8 步：手动排除传递依赖

```xml
<dependency>
  <groupId>org.hamcrest</groupId>
  <artifactId>hamcrest-all</artifactId>
  <version>1.3</version>
  <scope>test</scope>
  <exclusions>
    <!-- 排除它自带的 hamcrest-core，用 junit 带的版本 -->
    <exclusion>
      <groupId>org.hamcrest</groupId>
      <artifactId>hamcrest-core</artifactId>
    </exclusion>
  </exclusions>
</dependency>
```

## 第二部分：Gradle 实操

### 第 1 步：把 Maven 项目转成 Gradle

```bash
cd d:\myfile\CS_REVIEW\构建工具原理\demo-app

# 直接用 Maven 项目生成 Gradle 配置
# 但你机器没装 Gradle，我们先手动写 build.gradle
```

### 方式 A：手动创建 Gradle 配置

在 `demo-app/` 目录下创建两个文件：

**`settings.gradle.kts`**：
```kotlin
rootProject.name = "demo-app"
```

**`build.gradle.kts`**：
```kotlin
plugins {
    java
}

group = "com.example"
version = "1.0.0"

java {
    sourceCompatibility = JavaVersion.VERSION_1_8
    targetCompatibility = JavaVersion.VERSION_1_8
}

repositories {
    mavenCentral()
}

dependencies {
    implementation("commons-io:commons-io:2.15.1")
    testImplementation("junit:junit:4.13.2")
}
```

### 第 2 步：安装 Gradle（用 Wrapper 方式）

既然你机器没装 Gradle，我们有两种方式：

#### 方式 1：让系统帮你装一次（推荐）

```bash
# 临时下载一个 Gradle 来生成 Wrapper
# 或者直接下载完整包

# 用 Maven 装？或者手动下载
# 这里我们用最简单的：直接用 Maven 项目转 Gradle 后，手动下载 wrapper jar
```

#### 方式 2：我帮你写一个简单的 Gradle 安装脚本

```powershell
# 在 PowerShell 里执行（注意：先用 WebFetch 验证下载链接再下载）
$gradleVersion = "8.5"
$url = "https://services.gradle.org/distributions/gradle-$gradleVersion-bin.zip"
$dest = "$env:USERPROFILE\downloads\gradle-$gradleVersion-bin.zip"

# 下载（这个地址是 Gradle 官方的，应该能用）
Invoke-WebRequest -Uri $url -OutFile $dest -UseBasicParsing

# 解压到 C:\gradle
Expand-Archive -Path $dest -DestinationPath "C:\gradle" -Force

# 加环境变量（临时，当前 session 有效）
$env:Path += ";C:\gradle\gradle-$gradleVersion\bin"

# 验证
gradle -v
```

### 第 3 步：生成 Gradle Wrapper

装好 Gradle 后，在 `demo-app/` 里执行：

```bash
cd demo-app
gradle wrapper --gradle-version 8.5
```

这会生成：
```
demo-app/
├── gradlew              ← Unix 启动脚本
├── gradlew.bat          ← Windows 启动脚本
└── gradle/
    └── wrapper/
        ├── gradle-wrapper.jar
        └── gradle-wrapper.properties
```

**之后就用 `gradlew` 代替 `gradle`，不用全局安装了！**

### 第 4 步：跑 Gradle 构建

```bash
# Windows 用 gradlew.bat，Unix 用 ./gradlew
gradlew.bat clean build
```

**预期输出**（重点关注并行和增量）：
```
> Task :compileJava
> Task :processResources
> Task :classes
> Task :compileTestJava
> Task :processTestResources
> Task :testClasses
> Task :test
> Task :jar
> Task :build

BUILD SUCCESSFUL in XXs
7 actionable tasks: 7 executed
```

### 第 5 步：验证增量构建

```bash
# 第一次：完整构建
gradlew.bat clean build

# 第二次：什么都不改，直接再跑
gradlew.bat build

# 预期输出：
BUILD SUCCESSFUL in 3s
7 actionable tasks: 7 up-to-date    ← 全是 up-to-date！

# 第三次：改一个文件
# 编辑 src/main/java/com/example/App.java，加个 println

gradlew.bat build
# 预期：只有 compileJava 和依赖它的 Task 重新执行
```

### 第 6 步：对比 Maven 和 Gradle 的 jar 包

```bash
# Maven 产物
dir target\demo-app-1.0.0.jar

# Gradle 产物（路径不一样！）
dir build\libs\demo-app-1.0.0.jar

# 大小应该差不多
```

### 第 7 步：跑 Gradle 依赖树

```bash
gradlew.bat dependencies
# 或者更详细
gradlew.bat dependencies --configuration runtimeClasspath
```

## 第三部分：Maven vs Gradle 命令对照

| 你想做什么 | Maven | Gradle |
|-----------|-------|--------|
| 清理 | `mvn clean` | `gradlew clean` |
| 编译 | `mvn compile` | `gradlew compileJava` |
| 编译测试 | `mvn test-compile` | `gradlew compileTestJava` |
| 跑测试 | `mvn test` | `gradlew test` |
| 打包 | `mvn package` | `gradlew jar` |
| 安装到本地 | `mvn install` | `gradlew install`（需 maven-publish 插件） |
| 完整构建 | `mvn clean install` | `gradlew clean build` |
| 跳过测试打包 | `mvn clean package -DskipTests` | `gradlew clean jar -x test` |
| 看依赖树 | `mvn dependency:tree` | `gradlew dependencies` |
| 强制重新构建 | `mvn clean install` | `gradlew build --rerun-tasks` |
| 构建指定模块 | `mvn -pl module -am install` | `gradlew :module:build` |
| 调试查看实际命令 | `mvn compile -X` | `gradlew compileJava --info` |

## 第四部分：多模块项目实操

### Maven 多模块结构

```
demo-multi/
├── pom.xml                    ← 父 pom
├── common/
│   ├── pom.xml
│   └── src/main/java/com/example/common/Util.java
└── app/
    ├── pom.xml
    └── src/main/java/com/example/app/Main.java
```

**父 pom（demo-multi/pom.xml）**：
```xml
<project>
  <groupId>com.example</groupId>
  <artifactId>demo-multi</artifactId>
  <version>1.0.0</version>
  <packaging>pom</packaging>

  <modules>
    <module>common</module>
    <module>app</module>
  </modules>

  <properties>
    <maven.compiler.source>1.8</maven.compiler.source>
    <maven.compiler.target>1.8</maven.compiler.target>
  </properties>
</project>
```

**common/pom.xml**：
```xml
<project>
  <parent>
    <groupId>com.example</groupId>
    <artifactId>demo-multi</artifactId>
    <version>1.0.0</version>
    <relativePath>../pom.xml</relativePath>
  </parent>
  <artifactId>common</artifactId>
</project>
```

**app/pom.xml**：
```xml
<project>
  <parent>
    <groupId>com.example</groupId>
    <artifactId>demo-multi</artifactId>
    <version>1.0.0</version>
    <relativePath>../pom.xml</relativePath>
  </parent>
  <artifactId>app</artifactId>

  <dependencies>
    <!-- 依赖兄弟模块 common -->
    <dependency>
      <groupId>com.example</groupId>
      <artifactId>common</artifactId>
      <version>${project.version}</version>
    </dependency>
  </dependencies>
</project>
```

### 构建多模块

```bash
cd demo-multi

# 完整构建（先编 common，再编 app）
mvn clean install

# 只编 app 及其依赖的模块
mvn -pl app -am install
```

## 常见问题排查

### 1. 依赖下载慢？
改 `~/.m2/settings.xml`：
```xml
<settings>
  <mirrors>
    <mirror>
      <id>aliyun</id>
      <mirrorOf>*</mirrorOf>
      <url>https://maven.aliyun.com/repository/public</url>
    </mirror>
  </mirrors>
</settings>
```

### 2. 版本冲突报错？
```bash
# Maven
mvn dependency:tree -Dverbose | Select-String "conflict"

# Gradle
gradlew.bat dependencies
```

### 3. 跳过测试但不跳过 test-compile？
```bash
# Maven：只跳过测试执行，不跳过编译
mvn package -Dmaven.test.skip=false -DskipTests=true

# Maven：连测试代码编译也跳过
mvn package -Dmaven.test.skip=true
```

### 4. 临时换 JDK 版本？
```bash
# Maven 用 toolchain 配置
# 或者临时设置
mvn clean install -Dmaven.compiler.source=11 -Dmaven.compiler.target=11
```

### 5. Gradle 构建太慢？
```properties
# gradle.properties
org.gradle.parallel=true          # 并行构建子项目
org.gradle.caching=true           # 启用构建缓存
org.gradle.jvmargs=-Xmx2g         # 给 Gradle 更多内存
```
