# CS61B 知识库总览

## 8+1 总览卡

1. **课程定位**：CS61B 是伯克利的数据结构与算法课，用 Java。本质是"在工程约束下管理数据"——比 61A 多了类型系统、内存模型、复杂度下界、可维护性四件事。
2. **两条主线**：ADT（抽象数据类型，定义"能做什么"）→ 数据结构（定义"怎么实现"）；同一个 ADT 必须能给出多种实现，并按场景选择。
3. **语言载体**：Java（强类型 / 静态类型 / 引用语义 / GC），强调接口与实现分离。
4. **四个项目**：NBody（数组与仿真）→ 2048（棋盘与状态）→ Gitlet（图 + 持久化 + 工程组织）→ BYOW（世界生成 + 交互 + 架构设计）。
5. **核心思维**：先写接口契约，再选数据结构；复杂度不是事后估算，而是设计输入；正确性靠测试与不变量，不靠"看起来对"。
6. **评估维度**：ADT 选择 / 复杂度推导 / 不变量维护 / 代码组织。
7. **三道门槛**：Java 引用与静态类型、平衡树（2-3 / LLRB）、图算法的统一框架（relaxation）。
8. **本课的"反直觉"结论**：数组不是"低级"结构，ArrayList 平均性能击败多数花哨结构；哈希表不是 O(1)，是期望 O(1) 且有下界约束；递归不是慢，递归的常数开销来自调用栈而非算法本身。

**一句话**：CS61B 教的不是"背数据结构"，而是"在一组明确的约束（时间 / 空间 / 可维护性）下，做有意识的权衡"。

## 第一部分：Java 工程基础

### 1. 类型系统
- **静态类型**：编译期确定，编译器拒绝不匹配；`Object o = "hi"` 合法（向上转型），`String s = o` 非法（需显式向下转型）。
- **动态分派**：调用方法时看对象的实际类型；访问字段时看引用的声明类型——字段不具有多态性。
- **重载 vs 重写**：重载（overload）在编译期按静态类型选；重写（override）在运行期按实际类型选。
- **泛型**：`<T>` 是编译期类型检查，运行时被擦除（type erasure）；不能 `new T()`、不能 `new T[]`、不能用基本类型作类型参数。

### 2. 引用语义
- **变量存的是引用**，不是对象本身；`T a = new T(); T b = a;` 后 `a` 和 `b` 指向同一对象。
- **`==` 比引用，`.equals` 比内容**；未重写时 `equals` 默认就是 `==`。
- **不可变包装**：`Integer`、`String` 一旦创建不可改；`a = a + 1` 是新建对象，原对象不变。
- **数组协变陷阱**：`Object[] arr = new String[10]; arr[0] = 1;` 编译通过，运行时抛 `ArrayStoreException`——泛型不允许协变就是为了避免这个问题。

### 3. 接口与抽象类
- **接口**：纯契约，Java 8 后允许 `default` 方法；一个类可实现多个接口。
- **抽象类**：可含字段、构造器、具体方法；单继承。
- **选择原则**：表达"能做什么"用接口（`Comparable`、`Iterable`）；表达"是什么 + 共享代码"用抽象类。
- **ADT 边界**：对外只暴露接口类型（`List<T>`），内部具体类型（`ArrayList<T>`）可替换——这是 CS61B 的核心纪律。

### 4. Object 与集合协作的四件套
- `equals(Object o)`：自反、对称、传递、一致、对 null 返回 false。
- `hashCode()`：相等对象必须有相同 hash；不等对象尽量分散。
- `compareTo(T o)`：返回负 / 零 / 正；必须与 equals 一致，否则 TreeSet 行为异常。
- `toString()`：调试用。
- **不变量**：重写 equals 必须重写 hashCode，否则 HashMap 里同一逻辑键找不到值。

### 5. 异常与迭代器
- **受检异常**（`IOException`）：必须 throws 或 try-catch；**非受检异常**（`RuntimeException`）：不强制。
- **try-with-resources**：实现 `AutoCloseable` 的资源自动关闭，Gitlet 处理文件 IO 必须用。
- **迭代器协议**：`hasNext()` + `next()`；`next()` 在耗尽时抛 `NoSuchElementException`；`remove()` 是可选操作。
- **for-each**：类实现 `Iterable<T>` 即可用，编译器翻译成 `Iterator` 调用。

## 第二部分：复杂度与均摊

### 6. 三种记号
- **大 O**：上界（`f ≤ c·g`）。
- **大 Ω**：下界（`f ≥ c·g`）。
- **大 Θ**：紧界（同时 O 和 Ω）。
- CS61B 口语中常混用 O 和 Θ，考试会明确区分。

### 7. 均摊分析
- **问题**：ArrayList 扩容单次 `add` 是 Θ(n)，但 n 次 add 总代价是 Θ(n)，平均 Θ(1)。
- **三种方法**：
  - 聚合分析：n 次操作总代价 / n。
  - 记账法：每次便宜操作存"信用"，昂贵操作用信用支付。
  - 势能法：定义势函数 Φ，amortized cost = actual + ΔΦ。
- **关键案例**：ArrayList（几何级数扩容 1.5 或 2 倍 → 均摊 Θ(1)）、WQUPC（见并查集）、二进制计数器。

### 8. 排序下界
- **比较排序**：任何基于两两比较的排序，最坏至少 Ω(n log n)——决策树叶子数 n!，树高 log(n!) = Θ(n log n)。
- **非比较排序**：LSD / MSD 基数排序可达 Θ(n + R)（R 是字符表大小），但前提是键可枚举、定长。
- **稳定性**：相等元素排序后相对顺序不变；归并、插入、LSD 稳定；快排、堆排不稳定。
- **为什么稳定性重要**：多关键字排序（先按副键排，再用稳定排序按键排）。

## 第三部分：核心 ADT 与实现

### 9. List
| 操作 | ArrayList | LinkedList |
|---|---|---|
| get(i) | Θ(1) | Θ(n) |
| addFirst | Θ(n)（需搬移） | Θ(1) |
| addLast（均摊） | Θ(1) | Θ(1)（含尾指针） |
| add(i, x) | Θ(n) | Θ(n)（找位置）+ Θ(1) 插入 |
| 内存 | 连续、缓存友好 | 每节点多两个指针 |

**选择**：绝大多数场景 ArrayList；频繁在头部插入用 `ArrayDeque` 或 LinkedList。

### 10. 二叉搜索树 BST
- **不变量**：左子树所有键 < 节点键 < 右子树所有键。
- **操作复杂度**：取决于高度 h；平衡时 h = Θ(log n)，退化成链时 h = Θ(n)。
- **删除三种情况**：无子节点直接删；一个子节点用子节点顶替；两个子节点用前驱（左子树最大）或后继（右子树最小）替换。
- **问题**：按顺序插入会退化成链表 → 必须平衡。

### 11. 平衡树（CS61B 重点）
- **B 树 / 2-3-4 树**：节点可容纳多个键，插入时分裂向上传播；完美平衡，高度 Θ(log n)。
- **2-3 树**：B 树阶为 3 的特例；插入只有两种操作——把键塞进 2-节点变成 3-节点；3-节点满了分裂。
- **红黑树（LLRB）**：用"红边"在普通 BST 上模拟 2-3 树；红边表示"我和父节点在逻辑上是同一个 3-节点"。
  - 不变量：红边只向左；任何路径黑边数相同；节点不能同时连两条红边。
  - 三种修正：左旋、右旋、变色。
- **AVL**：每个节点记录左右子树高度差 ≤ 1；插入后从底向上旋转。
- **结论**：红黑树 / 2-3 树 / B 树本质是同一棵树的不同表示；工程实现（Java TreeMap、C++ map、Linux 调度器）几乎都用红黑或 B 树族。

### 12. 哈希表
- **核心思想**：用键的 hash 定位桶，期望 Θ(1) 查找。
- **两大问题**：
  - hash 函数质量：String 用 `h = 31·h + c[i]`（31 是奇素数，乘法可被 JIT 优化成移位减法）。
  - 冲突处理：
    - **separate chaining**：每桶一个链表 / 树；负载因子 λ = n / M，期望查找 Θ(1 + λ)。
    - **linear probing**：开放寻址，找下一个空位；要求 λ < 0.77（CS61B 阈值），否则性能急剧恶化。
- **resize**：元素数超阈值就扩容到 2 倍，全部 rehash——均摊 Θ(1)。
- **下界约束**：hash 不是魔法，若所有键 hash 相同，最坏 Θ(n)；哈希表不保证顺序。

### 13. Trie（前缀树）
- **结构**：每个节点代表一个字符前缀；查询时间 Θ(L)（L 是串长），与字典大小无关。
- **优势**：前缀查询天然支持；按字典序遍历容易。
- **劣势**：空间开销大（每字符一节点）。
- **应用**：自动补全、拼写检查、路由器最长前缀匹配。

### 14. 堆与优先队列
- **二叉堆不变量**：完全二叉树 + 父节点 ≤ 子节点（最小堆）。
- **数组表示**：父 i，子 2i+1 / 2i+2；无需指针。
- **操作**：
  - insert：加到末尾，**swim**（向上比较交换）→ Θ(log n)。
  - removeMin：取根，末尾移到根，**sink** → Θ(log n)。
  - getMin：Θ(1)。
- **不能做的事**：按任意键查找 Θ(n)；改任意键优先级需额外索引（indexed heap）。
- **堆排序**：原地、不稳定、Θ(n log n)；建堆是 Θ(n) 而非 Θ(n log n)（数学结论：sink 的总代价是等比级数）。

### 15. 并查集（Disjoint Set）
- **目的**：动态维护"连通性"，支持 `connect(p, q)` 与 `isConnected(p, q)`。
- **演进路径**（CS61B 经典）：
  1. Quick Find：id 数组存组件号；connect Θ(n)，find Θ(1)。
  2. Quick Union：id 存父指针形成树；find 沿父链到根。
  3. Weighted Quick Union（WQU）：合并时把小树挂到大树下；高度 Θ(log n)。
  4. WQU + Path Compression（WQUPC）：find 时把路径上所有节点直接挂到根；均摊近 Θ(α(n))，α 是反 Ackermann 函数，n < 宇宙原子数时 ≤ 5。
- **不能做**：不能删除边；不能回答"路径具体是什么"，只回答连通与否。

## 第四部分：排序算法

### 16. 排序对照表

| 算法 | 最好 | 平均 | 最坏 | 空间 | 稳定 | 备注 |
|---|---|---|---|---|---|---|
| 选择排序 | Θ(n²) | Θ(n²) | Θ(n²) | Θ(1) | 否 | 交换次数最少 |
| 插入排序 | Θ(n) | Θ(n²) | Θ(n²) | Θ(1) | 是 | 近乎有序时极快 |
| 希尔排序 | Θ(n log n) 取决于序列 | — | Θ(n^1.5) | Θ(1) | 否 | 插入排序的分组版 |
| 归并排序 | Θ(n log n) | Θ(n log n) | Θ(n log n) | Θ(n) | 是 | 适合外排、链表 |
| 快排 | Θ(n log n) | Θ(n log n) | Θ(n²) | Θ(log n) 栈 | 否 | 平均常数最小；随机化 pivot |
| 堆排序 | Θ(n log n) | Θ(n log n) | Θ(n log n) | Θ(1) | 否 | 原地但缓存不友好 |
| LSD 基数 | Θ(n + R) | Θ(n + R) | Θ(n + R) | Θ(n + R) | 是 | 要求定长整数 / 字符串 |

- **快排最坏情况**：pivot 总选到极值；解法是随机 shuffle 或三数取中。
- **Java 实战**：`Arrays.sort` 对对象用 TimSort（归并变种，稳定），对基本类型用双轴快排（不需要稳定性，常数小）。

## 第五部分：图算法

### 17. 图的三种表示
- **邻接矩阵**：V×V 布尔矩阵；查边 Θ(1)，空间 Θ(V²)，适合稠密图。
- **邻接表**：每顶点一个列表；空间 Θ(V + E)，查边 Θ(degree)，CS61B 默认选择。
- **Edge list**：边的集合；Kruskal 排序边时方便。

### 18. 遍历
- **DFS**：栈 / 递归；前序、后序；可用于拓扑排序、连通分量、环检测。
- **BFS**：队列；按距离分层；**无权图最短路径**。
- **复杂度统一**：Θ(V + E)（邻接表）。

### 19. 最短路径
- **Dijkstra**：所有边权非负；本质是 BFS + priority queue；每次取出当前最近节点并 relax 邻边。
  - 复杂度：binary heap Θ(E log V)；Fibonacci heap（理论）Θ(E + V log V)。
  - 失败场景：负权边 → Bellman-Ford。
- **A\***：Dijkstra + 启发函数 h(v)（到目标的估计下界，可采纳 admissible）；优先队列按 `dist + h` 取；路径最优性由 h 不高估保证。
- **relaxation 统一视角**：所有最短路径算法都在做同一件事——`if dist[v] + w(v,u) < dist[u]: dist[u] = ...`；区别只是"以什么顺序 relax"。

### 20. 最小生成树
- **切分定理**：任一切中，权值最小的跨切边必在某棵 MST 中——所有 MST 算法的理论基础。
- **Kruskal**：边按权排序，依次加入若不构成环；用并查集判环；Θ(E log E)；适合边稀疏。
- **Prim**：从一个顶点开始，每次把"连接树内与树外的最小边"加入；用 PQ；Θ(E log V)；类似 Dijkstra。
- **不适用**：边权为负不影响 MST 正确性（与最短路不同）。

### 21. 拓扑排序
- **前提**：DAG（有向无环图）。
- **两种做法**：
  - DFS 后序，再逆序。
  - Kahn 算法：每次取入度为 0 的顶点，删除其出边。
- **应用**：编译顺序、课程依赖、Gitlet 的 commit DAG。

## 四个项目方法论

### NBody（物理仿真）
- **核心**：数组存星体；每个时间步对每对星体算万有引力（O(n²)）。
- **训练点**：数组 vs 链表的性能直觉；画图分离数据与渲染；`StdDraw` 的双缓冲。
- **易错**：力必须先全部算完再更新位置，不能边算边更新（会用到一半新一半旧的状态）。

### 2048
- **核心**：棋盘用 `Board` 类；`tilt(direction)` 把每行 / 列抽取成一维列表处理。
- **训练点**：抽象出"对一维列表做一次左滑"，再用旋转适配四方向——而不是写四份代码。
- **不变量**：合并规则是"每个块每次移动至多合并一次"；必须先合并再压缩，且不能连锁。

### Gitlet（最难的一个）
- **核心数据结构**：
  - Blob：文件内容，用 SHA-1 寻址。
  - Commit：树节点，含父 commit hash、时间、message、文件树快照。
  - Branch：只是一个指向 commit hash 的指针文件。
  - HEAD：指向当前 branch。
  - Staging area：两个 map（addition / removal）。
- **本质**：Gitlet 是一个**持久化的 DAG**，所有对象通过 hash 内容寻址。
- **难点**：
  - 序列化用 Java Serializable，但反序列化要用 `ObjectInputStream` + `readObject`。
  - merge 用"最近公共祖先（LCA）"——在 commit DAG 上找分叉点，按三方合并规则处理。
  - 不能依赖全局静态变量跨命令存活；每次命令都要从磁盘恢复状态。
- **工程纪律**：先写 Repository / Commit / Blob / StagingArea 的接口契约，再实现命令；命令层只做参数解析与调用。

### BYOW（Build Your Own World）
- **核心**：随机种子世界生成（房间 + 走廊）、2D 渲染、键盘交互、存档读档。
- **训练点**：架构——引擎 / 世界 / 渲染 / 输入四层分离；seed 是世界的唯一标识，相同 seed 必须生成相同世界。
- **难点**：
  - 房间不重叠检测（矩形相交）。
  - 走廊连接保证连通（BFS 验证）。
  - 存档是序列化整个世界状态，读档要恢复到逐字节一致。
- **CS61B 借此考的是**：给一个开放需求，你能不能自己设计 ADT 并守住边界。

## 方法论卡片

### 卡片 A：ADT 选择决策树
```
需要重复元素？
├─ 是 → List
│       ├─ 主要按下标访问 / 遍历 → ArrayList
│       └─ 频繁两端增删 → ArrayDeque
└─ 否 → Set / Map
        ├─ 需要有序遍历 / 范围查询 → TreeSet/TreeMap（红黑树，Θ(log n)）
        ├─ 平均最快、不关心顺序 → HashSet/HashMap（期望 Θ(1)）
        └─ 键是字符串前缀 → Trie

需要按优先级取最小？
└─ PriorityQueue（二叉堆 Θ(log n) insert/remove）

需要动态连通性？
└─ WQUPC（均摊近 Θ(1)）
```

### 卡片 B：复杂度推导四步法
1. 明确输入规模 n 是什么（顶点数？串长？元素数？）。
2. 拆出每层循环 / 递归的代价。
3. 嵌套相乘，顺序相加。
4. 递归式用主定理或递归树：`T(n) = aT(n/b) + f(n)`。
   - f(n) 比 n^(log_b a) 小 → Θ(n^(log_b a))
   - 同级 → 乘 log n
   - 大 → 取 f(n)（正则条件下）

### 卡片 C：写递归代码的三段式（与 61A 一致，但加工程约束）
1. **Base**：最小输入直接返回。
2. **Recursive**：只处理当前节点，剩下的委托给递归。
3. **Convergence**：确认每次调用规模严格减小。
- **工程补充**：递归深度可能 Θ(n) 时（树退化），Java 会栈溢出；要么改迭代 + 显式栈，要么先用平衡结构保证高度。

### 卡片 D：图算法题的识别指纹
- "最少步数 / 无权最短" → BFS。
- "最低成本 / 带权非负" → Dijkstra；有终点且有可采纳启发 → A*。
- "连通所有点总成本最小" → MST（Kruskal 边少、Prim 点少）。
- "依赖顺序 / 编译顺序" → 拓扑排序。
- "几个人 / 几个集合 / 是否同组" → 并查集。
- "能否到达 / 是否有环 / 所有可能性" → DFS。

### 卡片 E：Gitlet 类设计模板
```
Utils（文件 / 序列化 / SHA-1 工具，静态方法）
  └── Repository（工作目录 + .gitlet 目录管理）
        ├── Commit（不可变，含 parent hash / message / timestamp / blob map）
        ├── Blob（文件内容快照，hash 寻址）
        ├── StagingArea（added map + removed map，可序列化）
        └── Branch 指针（HEAD、master、分支名 → commit hash）
命令层（init/add/commit/log/checkout/merge...）只做：
  参数解析 → 调 Repository → 打印结果
```

### 卡片 F：调试与测试纪律
- **先写不变量**：BST 的大小关系、堆的完全性、并查集的高度上界——每次修改后 assert。
- **JUnit 测试金字塔**：底层小函数大量用例；组合逻辑用少量集成用例。
- **边界用例优先**：空集合、单元素、重复元素、null、极值、容量边界（resize 前后）。
- **失败最小化**：发现 bug 先找最小复现输入，再读代码——不要在大输入上瞎猜。

## 学习路径建议

1. **前 1/3**：死磕 Java 引用 / 接口 / 泛型 + ArrayList / LinkedList；同步做 NBody，把"接口与实现分离"练成肌肉记忆。
2. **中 1/3**：复杂度 + BST → 平衡树 → 哈希 → 堆；这条线是考试核心，每个结构都能手写插入 / 删除并走查。
3. **后 1/3**：排序 + 并查集 + 图；图算法重点不在背代码，在 relaxation 框架与"识别题型"。
4. **项目节奏**：Gitlet 是分水岭，建议在学到树 / 哈希之后立即开工，不要堆到期末；BYOW 重点是架构设计，提前画类图。
5. **与算法随想录的呼应**：随想录的数组 / 链表 / 哈希表章节对应本库 List / 哈希部分；随想录偏"刷题手法"，CS61B 偏"为什么这样设计"，两者互证。
