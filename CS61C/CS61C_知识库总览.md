# CS61C 知识库总览

## 8+1 总览卡

1. **课程定位**：CS61C 是伯克利的"机器结构"课（Great Ideas in Computer Architecture），用 C 与 RISC-V。本质是"理解程序在硬件上如何真正运行，并用软硬件协同的方式榨取性能"。
2. **抽象栈的七层**（课程主线）：应用 → 算法 → 编程语言 → 操作系统 → 指令集 → 微体系结构 → 电路器件。61A/61B 站在上三层，61C 一路下探到最底层。
3. **两大 Great Idea**：**抽象分层**（每层只对上层暴露简单接口）与**通用性原则**（摩尔定律放缓后，性能靠并行而非单核心频率）。
4. **语言 / 工具载体**：C（手动内存）+ RISC-V 汇编（指令集）+ Logisim（数字电路）+ OpenMP/MPI/SIMD（并行）。
5. **核心思维**：性能不是"感觉快"，而是用 CPI / Amdahl / cache miss 率量化；正确性要一直追究到"位"这一级。
6. **评估维度**：指针与内存模型 / 调用约定走查 / 流水线冒险分析 / cache 地址划分 / 并行加速比计算。
7. **三道门槛**：C 指针与多级间接寻址、五级流水线的数据冒险与转发、cache 地址位划分（tag/index/offset）。
8. **本课的"反直觉"结论**：C 数组不存长度，数组名大多数表达式里就是首元素指针；浮点 0.1 + 0.2 ≠ 0.3（IEEE 754 二进制无法精确表示）；CPU 大部分时间在等内存——cache 命中与否对性能的影响远大于指令本身的快慢；100 核只加速其中 95% 的代码，整体最多快约 1.95 倍（Amdahl 定律，并行收益被串行部分锁死）。

**一句话**：CS61C 教的是"软件的每一行最终变成什么电信号、在哪里等、为什么慢"——从写高级语言的人变成能看穿抽象栈的人。

# 第一部分：C 语言与内存模型

## 1. 编译模型与指针本质
- **编译四阶段**：预处理（宏 / 头文件展开）→ 编译（C → 汇编）→ 汇编（→ 目标文件 .o）→ 链接（合并符号、解析地址）。
- **指针就是一个存地址的整数变量**；`*p` 表示"去 p 存的地址取值"，`&x` 表示"x 的地址"。
- **类型决定解读方式**：地址只是数字，`int*` 与 `char*` 指向同一地址时，`*p` 读出的字节宽度与解读方式不同。
- **指针运算按类型宽度跨步**：`p+1` 实际地址增加 `sizeof(*p)`，不是加 1 字节。

## 2. 数组与指针的等价与陷阱
- **核心等价**：除 `sizeof`、`&` 取址、字符串字面量初始化三种场合外，数组名表达式隐式退化为指向首元素的指针。
- 因此 `a[i]` ≡ `*(a+i)` ≡ `i[a]`（语法层面成立，后者只是不要写）。
- **数组不存长度**：函数参数里 `int a[]` 与 `int *a` 完全等价，sizeof 拿不到原数组大小——必须额外传 length 参数。
- **2D 数组 vs 指针数组**：`int a[3][4]` 是连续 12 个 int，行宽固定；`int *a[3]` 是 3 个指针，各行可不连续——传参和布局完全不同。

## 3. 内存四区
| 区域 | 存什么 | 生命周期 | 管理方 |
|---|---|---|---|
| 代码段 text | 机器指令 | 整个进程 | 只读，OS 加载 |
| 静态/全局区 | 全局变量、static 变量、字符串字面量 | 整个进程 | 编译器分配 |
| 堆 heap | malloc 出的对象 | 手动 free 前一直存活 | 程序员 |
| 栈 stack | 局部变量、参数、返回地址、栈帧 | 函数返回即回收 | 编译器自动 |

- 堆从低地址向高地址长，栈从高地址向低地址长——经典相向布局。
- **栈帧内容**：返回地址、保存的寄存器、局部变量、参数（RISC-V 中前 8 个参数走寄存器，溢出部分才上栈）。

## 4. struct、对齐与字节序
- **内存对齐**：成员按自身宽度对齐（int 对齐 4 字节），struct 末尾可能填充 padding；成员顺序影响体积——**大成员放前面通常更省**。
- `sizeof(struct)` 含尾部 padding，保证数组中每个元素对齐。
- **endianness**：多字节整数在内存中，little-endian（x86 / RISC-V 默认）低位字节放低地址；big-endian（网络字节序）相反。网络收发与文件解析必须用 `ntohl/htonl` 转换。
- **union**：所有成员共享同一起始地址，大小取最大成员；可用于类型双关（type punning），但严格别名规则下有未定义行为风险。

## 5. 手动内存管理
- `malloc(n)` 返回 n 字节未初始化块的首地址；`calloc` 额外清零；`realloc` 扩容（可能搬迁并复制）。
- **配对纪律**：每个 malloc 必须恰好对应一个 free；free 后指针成悬空指针（dangling），free 两次是 double-free。
- **内存泄漏**：丢失最后一个指向堆块的指针后，该块进程结束前无法回收。
- **valgrind**：检测非法读写、未初始化读取、泄漏的标准工具。
- **字符串**：以 `\0` 结尾的 char 数组；没有 `\0` 就不是 C 字符串，`strlen/strcpy` 会越界——C 安全漏洞第一大来源。

# 第二部分：RISC-V 与调用约定

## 6. 寄存器约定（必须背熟）
| 寄存器 | ABI 名 | 用途 / 保存责任 |
|---|---|---|
| x0 | zero | 恒为 0（硬件实现） |
| x1 | ra | 返回地址，**caller-saved**（调用者保存） |
| x5–x7, x28–x31 | t0–t6 | 临时寄存器，caller-saved |
| x10–x17 | a0–a7 | 参数 / 返回值：a0–a1 兼作返回值，caller-saved |
| x8–x9, x18–x27 | s0–s11 | 保存寄存器，**callee-saved**（被调用者负责保存恢复） |
| x2 | sp | 栈指针，向下增长，16 字节对齐 |

- **caller-saved**：函数可以随便破坏，调用方若还要用须自己先压栈。
- **callee-saved**：函数若要使用，必须在入口压栈、出口恢复——调用方可以放心地让值跨函数调用存活。
- s0 常作帧指针 fp（可选）。

## 7. 栈帧与函数调用
- 调用动作：参数放 a0–a7 → `jal ra, func`（把返回地址存 ra 并跳转）。
- 函数序言 prologue：`addi sp, sp, -N; sd ra, N-8(sp); sd s0, ...`（开栈帧、保存 ra 与用到的 s 寄存器）。
- 尾声 epilogue：恢复寄存器 → `addi sp, sp, N` → `jr ra`（即 jalr x0, 0(ra)）。
- **叶子函数**不调别的函数时可不动 ra；非叶子函数必须保存 ra——递归题走查的核心。
- 栈帧布局：参数（溢出部分）→ 保存的 ra / s 寄存器 → 局部变量。

## 8. 指令格式（六类，字段位划分以官方 Green Card 为准）
- **R 型**：寄存器-寄存器运算，如 `add x1, x2, x3`；字段 funct7/rs2/rs1/funct3/rd/opcode。
- **I 型**：立即数运算 / load，如 `addi`、`lw rd, off(rs1)`、`jalr`。
- **S 型**：store，如 `sw rs2, off(rs1)`；立即数被拆成两段（无 rd 字段）。
- **SB 型**：条件分支 `beq/bne/blt/bge`；立即数以 2 字节为单位、相对 PC 寻址。
- **U 型**：长立即数装载 `lui`、`auipc`（取高 20 位）。
- **UJ 型**：`jal`，跳转立即数也是 2 字节对齐、相对 PC。
- **伪指令**：`li`（load immediate，常展开为 lui+addi）、`mv`、`j`、`ret`、`nop`——汇编器提供，硬件没有。
- 读写内存只有 load/store 两类指令（load-store 架构），所有运算只在寄存器间进行。

## 9. 汇编走查要点
- 分支条件不满足时顺序执行下一条；PC 永远按字节计址，分支偏移 ×2。
- `lui x, 高位; addi x, x, 低位` 拼 32 位立即数时，注意 addi 做 12 位**符号扩展**，低 12 位为负时要给高位加 1。
- 所有地址最终由"某个基址寄存器 + 偏移"产生——这是后续寻址模式与寻址计算的基础。

# 第三部分：数字逻辑与 CPU

## 10. 组合逻辑与时序逻辑
- **组合逻辑**：输出仅由当前输入决定（AND/OR/NOT/MUX/ALU），无状态、无环路。
- **时序逻辑**：输出依赖状态，状态元件是**寄存器（flip-flop）**，只在时钟边沿更新；时钟同时拍动所有寄存器，这是同步设计的根基。
- **布尔代数化简**：分配律、德摩根；与或式 ↔ 或与式；真值表 → 卡诺图 → 最简门网络（了解思想）。
- **有限状态机 FSM**：状态寄存器 + 次态组合逻辑 + 输出逻辑；分 Moore（输出只看状态）/ Mealy（还看输入）。控制器本质就是一个 FSM。

## 11. 单周期数据路径
- **五阶段**（后续流水线的骨架）：
  1. **IF**：按 PC 取指令，PC = 指令存储器[PC]。
  2. **ID**：解析 opcode/funct、读寄存器文件。
  3. **EX**：ALU 计算（运算结果或访存地址或分支目标）。
  4. **MEM**：load/store 访问数据存储器。
  5. **WB**：结果写回寄存器文件。
- **关键部件**：PC 寄存器、指令存储器、寄存器文件（两读口一写口）、ALU（含 ALUSrc 多路选择）、数据存储器、控制单元（一组控制信号）。
- **控制信号**：RegWrite、MemWrite、MemtoReg、ALUSrc、Branch、PCSel……每个都是 FSM/译码逻辑根据 opcode 产生的 1 位或几位选择。
- 单周期时钟周期由最慢指令决定（关键路径），各指令被迫使用同一周期——效率低，引出流水线。

## 12. 流水线与冒险（考试核心）
- **五级流水**：IF → ID → EX → MEM → WB，相邻阶段之间插入**流水线寄存器**（IF/ID、ID/EX、EX/MEM、MEM/WB）保存中间结果。
- 理想吞吐：每个周期完成一条指令（延迟仍是 5 周期，吞吐提高 5 倍）。

### 三类冒险
1. **结构冒险**：两条指令同一周期争用同一硬件（如单端口存储器同时取指与取数）；解法：分离指令/数据存储器（哈佛结构思想）、寄存器堆"前半周期写后半周期读"。
2. **数据冒险**：后指令要用前指令尚未写回的结果。
   - **转发 forwarding（旁路 bypass）**：把 EX/MEM、MEM/WB 中的结果直接送回 ALU 输入端，不必等写回。
   - **load-use 冒险无法仅靠转发解决**（load 在 MEM 阶段才有数据，下一条 EX 就要用）→ 必须插入一个**气泡 stall（bubble）**，配合把控制信号清零。
   - 编译器 / 汇编器还可重排指令（指令调度）在 load 后塞一条无关指令。
3. **控制冒险**：分支结果在 EX（甚至更晚）才确定，其后已预取的指令可能作废。
   - 静态：分支时停顿 1–2 周期直到目标地址确定。
   - 动态：**分支预测**——预测不跳转 / 基于 BHT（分支历史表）；预测错误则冲刷 flush 已取指令。
   - 延迟分支（MIPS 时代）RISC-V 不采用。

- **冒险分析题套路**：列出两条指令的阶段时间轴 → 标出 RAW 依赖 → 判断转发能否覆盖（EX 前产生即可）→ load-use 单独 stall 一拍 → 分支误预测 flush 若干条。

# 第四部分：存储层次与 Cache

## 13. 局部性原理（一切设计的依据）
- **时间局部性**：刚访问的数据很可能很快再被访问（循环变量、栈顶）。
- **空间局部性**：访问某地址后，邻近地址很可能被访问（数组顺序遍历、指令顺序执行）。
- 层次结构（寄存器 → L1 → L2 → L3 → 内存 → SSD → 磁盘）用小而快的设备缓存大而慢设备的内容，正是利用这两条。

## 14. Cache 地址划分（必会计算）
- 物理 / 虚地址的位被切成三段：
  - **offset（块内偏移）**：位数 = log₂(块大小字节数)，决定块内定位，不参与比较。
  - **index（组索引）**：位数 = log₂(组数)，决定查哪一组。
  - **tag（标记）**：剩余高位，组内逐行比较 + **valid 位**。
- 总容量（数据部分）= 组数 × 每组行数 × 块大小；SRAM 总位数还要加上 tag、valid、dirty 位。

## 15. 三种相联方式
| 方式 | 映射规则 | 冲突缺失 | 硬件成本 |
|---|---|---|---|
| 直接映射 | 一行只去固定组（index 决定） | 高（抖动 thrashing） | 比较器最少，最快 |
| n 路组相联 | 去固定组，组内 n 行任选 | 中 | 每路一个比较器，并行比较 |
| 全相联 | 可放任意行 | 无冲突缺失 | 全部行并行比较，昂贵，只用于极小 cache（TLB） |

- **命中判断**：index 选组 → 组内同时比较所有路的 tag 且 valid=1 → 命中路用 offset 取出字。

## 16. 缺失分类（3C）与写策略
- **Compulsory（冷启动 / 强制）**：第一次访问该块，无法避免；预取可缓解。
- **Capacity（容量）**：cache 装不下工作集；增大 cache。
- **Conflict（冲突）**：相联度不够，多个块争同一组；提高相联度。
- （多核系统再加第四 C：Coherence 一致性缺失。）
- **写命中**：
  - write-through：同时写 cache 与下一级，简单但总线流量大，配 write buffer。
  - write-back：只写 cache、置 dirty 位，替换时才写回，快但复杂。
- **写缺失**：
  - write-allocate（fetch on write）：先把块载入再写，配 write-back。
  - no-write-allocate：直接写下层，配 write-through。

## 17. Cache 性能度量
- **平均访存时间 AMAT** = 命中时间 + 缺失率 × 缺失代价（miss penalty）。
- 多级 cache：L1 缺失时访问 L2，公式层层嵌套；L2 缺失率要用"全局缺失率"口径（占所有 L1 访问的比例）。
- **优化代码的直觉**：
  - 二维数组按**行优先**遍历（C 是行主序），跨行遍历会每元素 miss 一次。
  - 分块（blocking/tiling）让子矩阵块留在 cache 中复用——矩阵乘法优化竞赛的核心手法。
  - 结构体数组（AoS）vs 数组结构体（SoA）：只访问部分字段时 SoA 让每 cache 块装下更多有效数据。

# 第五部分：虚拟内存

## 18. 地址翻译
- **进程看到的是虚拟地址**；每个进程拥有独立、连续的虚拟地址空间，物理内存可被任意打散分配。
- 地址切分为 **虚拟页号 VPN + 页内偏移 offset**；offset 在翻译中不变（页大小通常 4 KiB → 低 12 位）。
- **页表**：VPN → 物理页号 PPN 的映射，每项 PTE 含 valid、dirty、使用位、权限位。
- **访问流程**：虚地址 → 查页表 → 命中得 PPN，拼 offset 得物理地址 → 访存；valid=0 触发**缺页异常 page fault**，由 OS 把磁盘上的页换入内存。

## 19. 多级页表与 TLB
- **问题**：单级页表在 64 位地址空间下体积爆炸（且大部分进程只用很小区域）。
- **多级页表**：层级查找，无效分支整层不分配——只为实际使用的区间付空间，代价是一次访存变成多次查表。
- **TLB（Translation Lookaside Buffer）**：页表项的 cache，全相联 / 高路数组相联；命中时翻译在一个周期内完成。
  - TLB 缺失 → 走页表（硬件走查或 OS 软件处理，RISC-V Sv39 支持硬件多级走查）。
- **RISC-V Sv39**：39 位虚地址、三级页表、4 KiB 页（了解结构，具体位段以官方手册为准）。

## 20. 虚拟内存的四大收益
1. **隔离与保护**：进程无法访问彼此内存；PTE 权限位防止写代码段。
2. **重定位**：物理内存任意分配，程序无感。
3. **共享**：多个进程的虚页可映射到同一物理页（共享库、`fork` 的 COW）。
4. **超售**：磁盘作 backing store，虚拟空间可比物理内存大（swap）。
- **上下文切换**：换页表基址寄存器（RISC-V 的 satp）即换地址空间；TLB 相应刷新（或用 ASID 标识避免全刷）。

# 第六部分：并行

## 21. Amdahl 定律（并行第一公式）
- 程序串行比例 s（不可并行），并行部分 1−s 使用 N 个处理器：
  - **加速比 = 1 / (s + (1−s)/N)**
- N → ∞ 时上限 = **1/s**；例：95% 可并行 → 上限 20 倍，不是无限。
- 推论：优化占比最大的部分（常见版本："让常见情况快"）；先 profile 找瓶颈，再谈并行。
- 对照：**Gustafson 定律**从"问题规模随核数扩大"的视角给出乐观结论，两者前提不同，不矛盾。

## 22. 四种并行模型
| 模型 | 抽象 | 通信方式 | 典型场景 |
|---|---|---|---|
| SIMD | 一条指令对多个数据同时运算 | 无（寄存器内） | 向量 / 多媒体 / 矩阵 |
| 共享内存（Pthreads / OpenMP） | 多线程共享同一地址空间 | 隐式（读写共享变量） | 单机多核 |
| 消息传递（MPI） | 多进程各有独立地址空间 | 显式 send/recv | 集群 / 超算 |
| MapReduce | map → shuffle → reduce | 框架托管 | 海量数据 / 分布式容错 |

- **OpenMP**：`#pragma omp parallel for` 注解式并行；fork-join 模型； reduction 子句处理求和等关联操作；陷阱是循环依赖与竞争写。
- **SIMD**：更宽的寄存器装多个 lane（如 256 位装 8 个 int）；要求数据连续、无分支、对齐；编译器自动向量化受代码形态限制，可用 intrinsics / RVV 手写。
- **MPI**：程序员显式划分数据、发送接收；通信开销决定粒度，要尽量计算/通信重叠。
- **MapReduce**：map 产出 (key, value)，shuffle 按键分组，reduce 聚合；移动计算比移动数据便宜，故障由节点重算兜底。

## 23. 一致性与并行陷阱
- **缓存一致性**：多核各有私有 cache，同一地址多份副本；MESI 协议（Modified/Exclusive/Shared/Invalid）靠总线监听/目录保证看到一致的值。
- **真假共享**：
  - 真共享：数据本身被多线程共同读写——需要同步（锁 / 原子指令 / 屏障）。
  - **false sharing（假共享）**：两个线程各写各的变量，但变量落在同一 cache 块，导致块反复失效；解法是按 cache 行（常见 64 字节）padding 对齐。
- **同步原语**：硬件提供原子指令（lr/sc 或 amoswap 等，RISC-V 原子扩展），软件据此构造锁、信号量。
- **竞态条件**：结果依赖调度顺序；加锁之外还有规约（reduction）、私有化等无锁手法。

# 第七部分：性能的量化

## 24. 核心公式
- **CPU 时间 = 指令数 × CPI × 时钟周期时间**；三项分别由算法 / 编译与 ISA / 微体系结构与电路决定。
- CPI 会被 cache 缺失、分支误预测、流水线停顿抬高：
  - **有效 CPI = 理想 CPI + 各类停顿**，如：+ 缺失率 × 缺失代价（按访存指令占比折算）。
- **MIPS / GHz 不能跨机器直接比较性能**：指令数、ISA、CPI 都不同；唯一公平的是同一程序的实际墙钟时间。
- 优化方法论：**测量 → 找热点（profiling）→ Amdahl 估算上限 → 针对性优化 → 再测量**。

## 25. 浮点 IEEE 754（位级正确性）
- 三字段：**符号 1 位 + 指数 k 位（偏移 bias = 2^(k−1)−1）+ 尾数**。
- 规格化值：值 = (−1)^s × 1.尾数 × 2^(指数−bias)；隐藏的前导 1 白送一位精度。
- 特殊编码：指数全 0（非规格化 / ±0）、指数全 1（尾数 0 → ±∞，尾数非 0 → NaN）。
- **非规格化数**实现"渐进下溢"，让最小数与 0 之间平滑衔接。
- 后果：`0.1 + 0.2 != 0.3`；浮点比较用区间 / epsilon，不用 `==`；结合律对浮点不严格成立，求和顺序影响误差（Kahan 求和缓解）。

## 典型项目类型（名称随学期变动，以当学期为准）

1. **C 编程项目（如命令行小游戏 / 字符串与数据处理）**：训练指针、struct、手动内存、valgrind 零泄漏零错误。难点：多级指针操作、字符串边界、free 配对。
2. **RISC-V 汇编项目（Venus 环境）**：用汇编写函数 / 小游戏或给 C 程序替换关键函数。难点：调用约定（哪些寄存器必须自己存）、栈帧布局、立即数装载。
3. **Logisim CPU 项目（分两阶段：单周期 → 流水线）**：搭寄存器文件、ALU、控制 FSM，再插流水线寄存器与转发/停顿逻辑。难点：控制信号真值表、load-use 检测、分支通路。
4. **性能优化竞赛（矩阵乘法 / 图像处理）**：给朴素实现，用 cache 分块、SIMD、OpenMP 多线程逐步提速并排名。难点：先测再优化、分块尺寸调参、避免 false sharing。
5. **MapReduce / 并行项目（部分学期）**：用单机多进程模拟 MapReduce 或 OpenMP/MPI 处理大数据集。

## 方法论卡片

### 卡片 A：C 指针 / 段错误排查流程
1. 崩溃地址是多少？接近 0（空指针解引用）还是大地址（野指针 / 栈越界）？
2. 这个指针从哪来：malloc 返回？函数参数？数组退化？
3. 指向的内存还活着吗（已 free / 函数已返回的栈帧）？
4. 跨步对吗：指针类型宽度、二维数组的行步进。
5. 上 valgrind：Invalid read/write 看越界，definitely lost 看泄漏。

### 卡片 B：RISC-V 调用约定走查清单
1. 参数依次进 a0–a7，多余参数压栈。
2. 调前想清楚：哪些 t/a 寄存器的值我后面还要？要就先存栈（caller-saved）。
3. 函数里要用 s 寄存器？入口存、出口恢复（callee-saved）。
4. 非叶子函数先在 prologue 保存 ra。
5. 返回值放 a0（双字返回才用 a1）。

### 卡片 C：流水线冒险判定三步
1. 列出相邻指令的阶段重叠时间轴。
2. 对每个 RAW 依赖：产生结果的阶段 vs 消费结果的阶段——EX 及之前已有值就能转发；唯独 load → 紧邻使用 必须 stall 一拍 + 转发。
3. 控制冒险：分支在第几级决定？误预测冲刷该级之后预取的所有指令。

### 卡片 D：Cache 地址划分题标准动作
1. 确定块大小 B → offset = log₂B。
2. 确定组数 = 总数据容量 / (块大小 × 相联度) → index = log₂组数。
3. tag = 地址总位数 − index − offset。
4. 给定地址：先按块大小取整理解块号，块号对组数取模得 index，整除组数得 tag。
5. 命中题：换一组数据重算 index，再逐路比 tag + valid。

### 卡片 E：访存层次性能公式嵌套
```
AMAT_L1 = HitTime_L1 + MR_L1 × MissPenalty_L1
MissPenalty_L1 = HitTime_L2 + MR_L2(全局) × MissPenalty_L2
MissPenalty_L2 ≈ 主存访问时间（再往下可含 TLB、缺页代价）
TLB 翻译代价按"TLB缺失率 × 页表遍历代价"并入命中时间
```

### 卡片 F：并行优化决策
```
先 profile，找到占比 p 的热点（Amdahl 决定天花板）
│
├─ 数据连续、算术密集、无分支 → SIMD 向量化
├─ 单机多核、可按迭代独立切分 → OpenMP parallel for
│       ├─ 求和/计数 → reduction
│       └─ 各写各的 → 注意按 cache 行 padding 防 false sharing
├─ 多机 / 独立地址空间 → MPI，粗粒度切分，通信与计算重叠
└─ TB / PB 级、需要容错 → MapReduce 数据并行
任何共享写 → 原子或锁；先问能否改算法消除共享
```

### 卡片 G：性能分析题公式链
```
CPU 时间 = IC × CPI × T_cycle
有效 CPI = 基础 CPI
          + 访存指令占比 × cache缺失率 × 缺失代价(周期)
          + 分支频率 × 误预测率 × 冲刷周期
加速比 = 旧时间 / 新时间；并行部分受 Amdahl 1/s 封顶
```

## 学习路径建议

1. **第一段（C）**：死磕指针与内存四区，所有作业用 valgrind 跑到零报错；能在纸上画出每个变量在哪个区、指针指向哪。
2. **第二段（RISC-V）**：背熟寄存器保存责任，能手写带递归函数的完整汇编（prologue/epilogue），这是衔接软件与硬件的接口层。
3. **第三段（逻辑 + 单周期）**：在 Logisim 里理解"一切计算都是组合逻辑 + 时钟驱动的状态更新"；先把单周期数据路径走通，再谈流水线。
4. **第四段（流水线 / Cache / VM）**：考试重心。流水线靠画时间轴，cache 靠地址位切分的机械训练，VM 重点理解"翻译 + 异常 + OS 介入"的三方协作。
5. **第五段（并行）**：公式（Amdahl、AMAT）必须秒算；动手部分抓住"分块 + SIMD + OpenMP"三连，性能竞赛项目是最直接的演练场。
6. **总原则**：61C 的每个概念都追问两个问题——"它对上一层隐藏了什么细节？""它在什么情况下变慢？" 抽象分层与性能量化两条线索就能全部串起来。

## 三门课的整体关系（61A / 61B / 61C）

- **61A**：如何用抽象组合程序（函数 / 数据 / 元语言）——关注"表达力"。
- **61B**：在工程约束下组织数据与算法（ADT / 复杂度 / 权衡）——关注"结构与代价"。
- **61C**：程序如何落到机器并榨取性能（指令 / 流水线 / cache / 并行）——关注"物理现实"。
- 串联示例：同一句 `a[i] = a[i] + 1`——61A 看到名字绑定与求值，61B 看到 Θ(1) 随机访问的抽象假设，61C 看到这个假设在 cache miss 时可能是几百个周期；三层认知合在一起才是完整的计算机素养。
