## 一、核心主线：三种二进制有符号整数编码，重点：符号幅值 Sign and Magnitude（PPT内容）
内存/寄存器只有bit串，bit本身无含义；**ISA编码规则决定bit如何翻译成数字，ALU硬件电路完全跟着编码规则走。**

### 1. 符号幅值 Sign and Magnitude（PPT幻灯片的重点）
规则：最高1bit = 符号位（0=正数，1=负数）；剩下低位是绝对值（幅值）。
例子（32bit）：
- `0x00000000` → +0
- `0x80000000` → −0
- `0x00000005` → +5
- `0x80000005` → −5

#### ✅【重点：符号幅值的硬件缺点，PPT列出3条】
1. **算术运算电路（ALU）非常复杂**
> 需要根据两个操作数的符号是否相同，走两套完全不同的运算逻辑：
> - 两个数**同号**：幅值部分相加，符号位保持不变。
> - 两个数**异号**：不能直接相加。必须**比较幅值大小，大数减小数，再把结果符号设置成大数的符号**。

👉 硬件上，ALU不能只用一套加法器。必须同时具备：加法器、减法器、幅值比较器、多路选择器MUX，硬件门电路数量多，延时更大。
> 补码：**只需要一套加法器，加减统一用加法实现，不需要比较幅值、不需要分支判断**。硬件极简。

2. **存在两个独立的0：+0 和 −0**
两套不同bit编码，语义都代表数字0。
带来硬件麻烦：
- 硬件比较电路需要特殊处理，保证`+0 == -0`判定为true；
- 取反、减法运算，会意外产生`−0`，ISA必须定义一堆边界规则处理这个特殊值；
- 码点浪费：32bit符号幅值范围 $-(2^{31}-1) \sim +(2^{31}-1)$，**无法表示 $-2^{31}$**，少了一个可用数字。

3. **bit串自增（二进制里程表 odometer）顺序，和数值大小顺序断裂**
把bit串当成无符号数字逐bit+1，bit值变大，但代表的整数不一定变大。
4bit例子：
`0111`（+7），bit+1 → `1000`（-0）
bit串数值增加了，但数字从+7变成0，没有递增。
再举例：`1001`(-1)，bit+1 → `1010`(-2)
bit串变大，**代表的数字反而变小**。

👉 很多基础硬件逻辑（增量器、比较逻辑）依赖bit顺序与数字顺序一致；符号幅值破坏这个性质，进一步增加硬件复杂度。

#### ✅ 符号幅值的唯一优势
单独操作符号、绝对值很方便。取绝对值只需要清掉最高位；翻转正负只需要翻转最高位。
所以**仅DSP数字信号处理器使用**；通用CPU因为加减运算量巨大，无法接受复杂ALU，放弃符号幅值。

### 2. 反码 One's Complement（历史过渡方案）
负数 = 正数所有bit全部按位取反。
同样存在双0（+0、-0）；电路复杂度比符号幅值略低，但依然没有解决双0问题，通用CPU同样淘汰。

### 3. 补码 Two's Complement（现代通用CPU全部选用）
负数 = 正数按位取反 + 1。
优点：
1. 只用一套加法器，加法、减法统一为加法运算；**不需要判断符号、不需要比较幅值，没有分支硬件逻辑**，ALU最简单。
2. 只有唯一的0，码点没有浪费，可以多表示一个负数（`INT_MIN`）。
3. bit串的滚动顺序和整数数值顺序对齐，里程表自增逻辑连续。
> 这就是为什么现代通用CPU全部选择补码。

> 一句话硬件层面总结：**符号幅值不是不能用，是通用CPU做加减运算时硬件代价太高，所以被补码淘汰**。

## 二、硬件ISA多样性 → C语言设计的起源（硬件带来的衍生）
C诞生在70年代，市面上机器ISA不统一：有补码、反码、符号幅值三种硬件。
C的核心设计哲学：**语言层尽量不绑定固定硬件ISA，让编译器适配底层硬件，最小化移植成本**。
1. `unsigned`无符号整数：所有ISA定义统一，就是纯二进制幅值。溢出规则C标准固定：模 $2^w$回卷，不是UB。
2. `signed int`有符号整数：C标准允许硬件是补码 / 反码 / 符号幅值，不强制。
    > 这就是**C有符号溢出UB的历史源头**：不同ISA，溢出后的硬件行为完全不同。
    > - 符号幅值机器：INT_MAX + 1 得到 `-0`
    > - 补码机器：INT_MAX +1 得到 INT_MIN
    > 标准无法统一溢出行为，直接定义：**有符号整数溢出属于未定义行为UB**。

> ⚠️ 区分：C不绑定编码这件事，**根源是早年硬件有符号整数存在多种ISA（符号幅值是其中一种），且硬件电路行为差异巨大**。

### C语言模型：极薄抽象层，直接挂靠ISA
C没有虚拟机，源码编译为原生机器码，直接交给CPU执行。
cast强制转换：**不修改内存bit，只是切换编译器对同一串bit的解释规则**。
OS只管理虚拟内存、进程调度；OS**完全不关心内存bit代表什么数字**。

## 三、Java(JVM)模型（扩展对比）
JVM是OS之上的用户态虚拟机，定义独立虚拟ISA。
Java规范**强制int永远32bit补码，和底层硬件无关**。
假想一台符号幅值硬件：JVM要在软件层做bit编码翻译（JVM补码 ↔ 硬件符号幅值），上层Java代码看不到底层ISA差异。
JVM做类似OS的隔离工作：OS隔离物理硬件与进程；JVM隔离宿主CPU ISA与Java代码。但JVM没有内核特权，不是操作系统。

Python默认int是任意精度大数，脱离固定宽度硬件bit模型；只有ctypes调用C时，才会使用固定宽度bit。

## 四、C语言UB（衍生内容：硬件历史带来的特性，现代新增编译器优化）
> 历史成因：多ISA硬件差异，无法统一溢出行为 → 定义UB。
> 现代保留UB：就算现在全部CPU都是补码，UB依然保留，用来支持编译器静态范围分析优化。

### C的契约：合格C程序不会触发UB
双向契约：
1. 标准承诺：程序所有路径都不触发UB，代码行为严格遵守C标准。
2. 程序员义务：代码不能存在任何可以触发UB的执行路径。

编译器优化逻辑：假设UB路径永远不会发生，可以直接删除对应的代码分支。
```c
int func(int a) {
    if (a + 1 < a) {
        return 1;
    }
    return 0;
}
```
开启O2优化，编译器判定`a+1 < a`不可能成立，直接删掉if分支。
> 如果你想要固定bit环绕行为：优先`uintXX_t`无符号类型；或者GCC扩展`-fwrapv`（非标准）。
> 溢出检测工程写法：提前值域判断，永远不执行溢出运算，避免UB。

### 三类行为区分
1. UB未定义行为：触发后标准无任何保证（signed溢出、野指针解引用）
2. 实现定义行为：平台文档写明行为，属于合格程序（int位宽、char有无符号）
3. 未指定行为：有限多种合法结果，程序合法。

## 五、主线链路复盘（从硬件编码出发）
```
硬件设计目标：做ALU加减电路
    ↓
方案A：符号幅值 → ALU电路复杂，双0，bit顺序断裂，仅DSP适用
方案B：反码 → 电路简化一点，但仍有双0
方案C：补码 → ALU最简，单0，bit顺序连续 → 现代通用CPU全部选用
    ↓
70年代多种ISA硬件并存
    ↓
C语言设计：不绑定单一有符号编码，signed溢出行为无法统一 → UB
    ↓
现代：CPU全是补码，但UB保留，用于编译器范围推导优化
```

## 核心要点清单（按你的优先级排序）
1. **符号幅值最大短板：ALU算术电路复杂**。加减要判断符号、比较幅值，需要加法器、减法器、比较器、多路选择器，硬件门更多，延迟更高。
2. 符号幅值附带另外两个缺陷：存在+0/-0两个0；bit串递增顺序不等于数值递增顺序。
3. 符号幅值唯一优势：单独操作符号、绝对值很方便，只在DSP使用；通用CPU优先选择补码简化ALU硬件。
4. 早年硬件ISA不统一（补码/反码/符号幅值），是C不绑定有符号编码、signed溢出定为UB的**历史根源**。
5. C紧贴硬件ISA，抽象层极薄；JVM在OS之上额外虚拟ISA，屏蔽硬件编码差异。
6. UB双向契约：合格C程序不能触发UB；编译器基于这个假设做激进优化，会删除不可能执行的UB路径。
