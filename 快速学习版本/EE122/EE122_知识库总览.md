# EE122 知识库总览（Introduction to Communication Networks）

## 8+1 总览卡

1. **课程定位**：EE122 是伯克利的通信网络导论。本质是"在一个不可靠、异构、跨管理域的信道上，如何分层地提供从比特传输到应用语义的逐级服务"。
2. **一条主线**：分层（layering）——每层对下层只做一组假设、向上层只提供一种服务，复杂性被封在层间接口之后。
3. **两个端到端的难点**：**可靠性**（丢包/乱序/损坏/重复下如何交付正确字节流）与**资源竞争**（无数流共享瓶颈链路时如何不崩溃、还公平）。
4. **协议栈五层视角**：应用层（HTTP/DNS）→ 传输层（UDP/TCP）→ 网络层（IP/路由）→ 链路层（以太网/Wi-Fi/交换）→ 物理层（信号，课程点到为止）。
5. **三个"没有"**：网络没有全局状态（每个路由器只知局部）、没有全局时钟（RTT 估计是猜的）、没有对主机的信任（端到端原则与拥塞控制靠自觉）。
6. **核心思维**：每个机制都对应一种"失效模式"——CRC 对损坏、序号对乱序/重复、ACK/超时对丢失、TTL 对环路、滑动窗口对流速、拥塞窗口对网络过载。
7. **三道门槛**：TCP 可靠传输机制全套（序号/ACK/超时/重传/滑动窗口）、拥塞控制的 AIMD 动力学、路由两大算法（LS 与 DV）的对比与收敛分析。
8. **本课的"反直觉"结论**：网络层 IP 只承诺"尽力而为"，可靠性是端主机自己在 TCP 里做的（端到端原则）；增加缓冲不总让网络更快，深缓冲导致 bufferbloat（延迟暴涨）；两条等代价路径上做随机分流，用每包分流会因乱序拖垮 TCP，用每流分流才有效；以太网"先听后说"仍会碰撞，碰撞不是 bug 而是协议的正常工作方式；BGP 不选最短路径，而按商业策略（路由策略压过技术最优）。

**一句话**：EE122 教的是"每一层都假设下层会出什么错、用什么机制把它藏起来，以及这些藏起来的代价最终在哪里爆发"。

# 第一部分：分层与体系结构

## 1. 为什么要分层
- **问题**：网络要处理硬件异构、介质不可靠、跨厂商互联、规模到数十亿主机——一锅炖的设计无法演化。
- **分层的收益**：每层只依赖下层的服务接口，内部可独立替换（以太网换光纤、IPv4 演进 IPv6，上层不重写）；故障可按层定位。
- **分层的代价**：层间信息隐藏导致重复（链路层与 TCP 都做校验）、握手冗余、跨层优化困难。
- **封装 encapsulation**：数据自上而下，每层加自己的首部（段 segment → 包 packet → 帧 frame）；接收端逐层剥首部。路由器只解到网络层，交换机只解到链路层——设备类型由"处理到哪一层"决定。

## 2. 端到端原则（课程设计哲学核心）
- **论点**：只有通信端点掌握完整应用语义；把可靠性、安全、顺序等功能放在网络内部，往往不完整或冗余。
- **推论**：IP 保持极简（尽力而为、无连接、无状态），可靠性由端主机 TCP 实现；网络中间设备不维护连接状态。
- **收益**：网络简单可扩展（互联网能长大的根本原因）、创新在端侧发生。
- **现代张力**：NAT、防火墙、CDN、负载均衡都在中间破坏了端到端透明性——工程现实对纯原则的折中。

## 3. 协议数据单位与地址
| 层 | 数据单位 | 地址 | 典型设备 |
|---|---|---|---|
| 应用 | 报文 message | 域名 / URL | 主机进程 |
| 传输 | 段 segment（TCP）/数据报（UDP） | 端口号 | 端主机 OS |
| 网络 | 包 packet / IP 数据报 | IP 地址 | 路由器 |
| 链路 | 帧 frame | MAC 地址 | 交换机 / AP |
| 物理 | 比特 / 符号 | — | 集线器 / 线缆 |

# 第二部分：应用层

## 4. HTTP 与 Web
- **请求-响应模式**：客户端发 request（方法、URL、首部、体），服务器回 status line + 首部 + 体。
- **无状态**：服务器不保存前次请求信息；会话靠 Cookie 承载在端侧。
- **连接演化**：HTTP/1.0 每请求一 TCP 连接（握手开销大）→ HTTP/1.1 keep-alive 复用连接 + pipeline 有队头阻塞 → HTTP/2 单连接多路复用（二进制分帧）→ HTTP/3 跑在 QUIC（UDP 之上，解决 TCP 级队头阻塞与握手延迟）。
- **缓存与 CDN**：Cache-Control/Expires 控制新鲜度；CDN 把内容推到边缘，本质是用"覆盖网络 + 缓存"降低 RTT 与骨干压力。

## 5. DNS（分布式系统的经典案例）
- **目标**：域名 → IP；主机名到邮件服务器等记录的解析。
- **层次结构**：根 `.` → 顶级域 `.com/.cn` → 权威域；客户端指向**递归解析器**（resolver），由它逐级迭代查询（recursive vs iterative 要分清）。
- **缓存**：每条记录带 TTL，解析器与主机都缓存——DNS 变更有传播延迟，根源就是 TTL。
- **记录类型**：A（IPv4）、AAAA（IPv6）、NS（委派给哪个名字服务器）、CNAME（别名）、MX（邮件）。
- **工程教训**：分层委派 + 缓存是超大规模分布式目录的范本；UDP 查询（快、无状态），大响应/区域传送用 TCP（现代也支持 DoT/DoH 加密）。

## 6. Socket 接口（应用与传输层的边界）
- TCP socket：`socket → bind(服务端) → listen → accept`；客户端 `connect`；连接是四元组（源 IP、源端口、目的 IP、目的端口）。
- UDP socket：无连接，`sendto/recvfrom`，一次调用对应一个数据报，**保留消息边界**（与 TCP 字节流的关键区别）。
- 端口：16 位，服务端知名端口 <1024 需特权；五元组（加协议号）唯一标识一条连接。

# 第三部分：传输层（课程重头戏之一）

## 7. UDP：最小化传输
- 无连接、无握手、无拥塞控制、不保证可靠/顺序；首部仅 8 字节。
- 适合：查询-响应（DNS）、实时音视频（迟到的包不如不要）、自定义协议载体（QUIC）。
- UDP 也有校验和（可选/现代默认开），但只丢弃不恢复。

## 8. 可靠传输的演进（必须能推导，不只是记结论）
### 8.1 基本构件
- **序号 seq**：给字节/分组编号 → 解决乱序与重复。
- **ACK**：接收方报告收到的进度。
- **超时重传 timer**：发送后等 ACK，超时认为丢失并重发。
- **校验和**：检测损坏，损坏即丢弃（交由超时机制恢复）。

### 8.2 停止-等待 stop-and-wait
- 发一个等一个 ACK；信道利用率 = 发送时间 /（发送 + RTT + 处理），RTT 远大于发送时间时吞吐极低。
- 必须区分"数据丢失"与"ACK 丢失"：ACK 丢失导致发送方重传 → 接收方会收到重复 → 用序号去重；协议号 rdt1.0→rdt3.0 的演进就是逐步加入差错、丢包、乱序的处理。

### 8.3 流水线与滑动窗口
- **允许已发未确认的段数 = 窗口大小 N**，把 RTT 填满，吞吐 ≈ N·MSS/RTT。
- **GBN（Go-Back-N）**：接收方只按序收，累计 ACK；任一段丢失，其后全部重传——实现简单但浪费带宽。
- **SR（Selective Repeat）**：接收方缓存乱序段，ACK 各自独立，只重传真正丢失的——效率高但接收方要缓冲、窗口与序号空间设计须防新旧混淆。
- **累计 ACK**：ACK n 表示 n 之前全部收到；TCP 主用累计 ACK，SACK 选项报告乱序块以逼近 SR 的效率。

### 8.4 TCP 的具体机制
- **字节流序号**：序号按字节计（SYN/FIN 各占一个逻辑序号）；ACK 字段 = 期望收到的下一个字节。
- **快速重传**：收到 3 个重复 ACK（dupACK）立即重传，不必等超时。
- **RTT 估计（Jacobson 公式思想）**：平滑估计 RTT 与偏差，Timeout = EstimatedRTT + 4·DevRTT——超时必须动态适应，设短了误重传、设长了恢复慢。
- **连接管理**：三次握手（SYN / SYN-ACK / ACK，交换初始序号 ISN）与四次挥手（FIN / ACK / FIN / ACK，双方各关一个方向）；TIME_WAIT 持续 2MSL，理由：让旧连接的迷途包消亡 + 可靠地确认对方收到最后的 ACK。
- **流量控制 flow control**：接收方通过 rwnd（接收窗口）告诉发送方自己的缓冲余量——防的是"发送方淹没接收方"，与网络拥塞无关。
- **状态机**：LISTEN / SYN-SENT / SYN-RCVD / ESTABLISHED / FIN-WAIT / CLOSE-WAIT / CLOSING / TIME-WAIT；SYN flood 攻击针对半连接队列。

## 9. 拥塞控制（课程重头戏之二）
### 9.1 拥塞是什么
- 太多发端向网络灌数据，瓶颈路由器队列变长 → 延迟增大；队列满 → 丢包；严重时吞吐量坍塌（拥塞崩溃，1986 年互联网真实发生过）。
- **丢包不是"链路出错"，在现代有线网里绝大多数丢包是队列溢出的拥塞信号**。
- 关键区分：**流量控制**（端到端缓冲匹配）vs **拥塞控制**（发送方与网络容量匹配）。

### 9.2 TCP 拥塞控制四件套
- **拥塞窗口 cwnd**：发送方自限，实际窗口 = min(cwnd, rwnd)。
- **慢启动 slow start**：连接起步 cwnd=1 MSS，每收一个 ACK 约 +1 MSS → 每个 RTT 翻倍（指数增长），快速探到可用容量；遇到 ssthresh 转拥塞避免。
- **拥塞避免**：每个 RTT cwnd 约 +1 MSS（加性增，线性爬坡）。
- **丢包反应**：超时（严重信号）→ ssthresh = cwnd/2，cwnd 归 1 重新慢启动；3 dupACK（轻度信号）→ 减半后进入快速恢复，不回 1。
- 整体形状：指数起步 → 线性爬升 → 遇丢包腰斩，循环往复，形成经典锯齿。

### 9.3 AIMD 与公平性
- **加性增、乘性减**：多条 AIMD 流在同一瓶颈上收敛到"公平"的均分点（效率-公平图上轨迹收敛于 (1/2, 1/2) 一带）——这是 TCP 被全球部署的理论合法性来源。
- 对比：MIMD 不公平；MIAD 不稳定；只有 AIMD 同时达到效率与公平。
- **TCP 友好性**：UDP 流不做拥塞控制会"搭便车"抢走 TCP 流的带宽——互联网没有强制执法，靠协议自觉。

### 9.4 现代议题
- **RED（随机早期检测）**：队列将满时按概率随机丢包/标记，把信号提前分散给不同流，避免全局同步（所有 TCP 同时腰斩再同时爬升的振荡）。
- **ECN**：不丢包，路由器在 IP 首部打标记由接收方回告发端减速。
- **bufferbloat**：运营商/家用路由器缓冲过大 → 不丢包但 RTT 膨胀到数百毫秒；解法：AQM（CoDel/PIE）+ 小缓冲。
- **BBR**：不再把丢包当拥塞信号，转而主动测量带宽与最小 RTT 决定发送速率（在浅缓冲、无线、长肥网络上表现不同，公平性有争议）。

# 第四部分：网络层

## 10. IP 与转发
- **IP 提供的服务**：无连接、不可靠、尽力而为；每个包独立选路；网络不维护连接状态。
- **IPv4 首部要点**：源/目的地址、TTL（每跳减 1，防路由环路永生）、协议号（交给 TCP 还是 UDP）、首部校验和（只保护首部）、分片字段。
- **分片与重组**：包大于链路 MTU 时可由路由器分片（DF/MF/offset），接收端重组；现代实践靠 PMTUD/MSS clamp 尽量避免分片。
- **ICMP**：网络层的"错误信使"（目的不可达、超时、echo ping）；traceroute 利用 TTL 递增 + ICMP 超时报文还原路径。

## 11. 编址、子网与最长前缀匹配
- **分类编址（历史）**：A/B/C 类固定边界 → 浪费严重 → **CIDR**：`a.b.c.d/n` 表示前 n 位是网络前缀。
- **子网划分**：组织内部再切前缀；主机位全 0 为网络号、全 1 为广播。
- **转发本质**：路由器拿目的地址查转发表，做**最长前缀匹配 LPM**——多条前缀都匹配时选最长（最具体）的一条；数据结构常用 trie。
- **DHCP**：新主机四步（DISCOVER/OFFER/REQUEST/ACK）动态获得 IP、网关、DNS——网络层的"即插即用"。
- **NAT**：家用/企业边缘设备把私有地址（10/8、172.16/12、192.168/16）映射成一个公网 IP + 不同端口；缓解地址枯竭，但破坏端到端直连，需 UPnP/STUN/TURN 打洞。
- **ARP**：同子网内 IP → MAC 解析，广播请求单播应答，结果缓存；跨子网时先 ARP 网关 MAC——ARP 是链路/网络层边界的胶合层。

## 12. 路由：两大自治域内算法（必考对比）

### 12.1 链路状态 Link State（OSPF 家族）
- **做法**：每个路由器测出到各邻居的代价，把 LSA **泛洪**给全网；每台路由器因此得到完整网络图，各自跑 **Dijkstra**。
- 消息复杂度 O(N·E) 量级的泛洪；计算复杂度 O(E log V)。
- 优点：收敛快、每台都有全局视图便于流量工程、坏消息传播快。
- 缺点：泛洪与计算开销随规模增长 → 用**区域分层**（OSPF areas）限制范围。

### 12.2 距离向量 Distance Vector（RIP 家族）
- **做法**：每台路由器只维护"到各目的地的距离向量"，周期性与**直接邻居**交换；本地用 **Bellman-Ford** 更新：`Dx(y) = min_z(c(x,z) + Dz(y))`。
- 优点：消息小、本地计算、配置简单。
- 致命弱点：**计数到无穷**——好消息传得快，坏消息传得慢（链路断了，错误的廉价路由在邻居间反复迭代，距离逐步涨向无穷大）。
- 缓解：定义无穷为小值（如 16 跳，限制网络规模）、**水平拆分 split horizon**（不把从某邻居学来的路由再发回给它）、poison reverse。
- **对比结论**：LS 像每个人都拿到全地图自己算；DV 像只听邻居的二手路标。规模小用 DV（简单），规模大用 LS（收敛快），超大网用层次化 + 域间路由。

### 12.3 域间路由 BGP
- Internet 由数万个 **AS（自治系统）**组成，AS 内跑 IGP（OSPF/IS-IS/RIP），AS 间跑 **BGP**。
- **路径向量**：BGP 通告的不只是代价，而是完整 AS 路径（AS-PATH）——天然防环。
- **策略优先于最优**：BGP 决策先看商业关系（客户 > 对等 > 上游提供商的偏好），再看路径长度等技术属性；"最短"未必被选。
- 收敛慢、可能短暂不一致；BGP 是互联网脆弱性的集中点（路由劫持、前缀误宣告事故）。

## 13. IPv6
- 128 位地址、首部精简（去掉分片字段、取消首部校验和）、原生支持扩展首部；地址数量级 2¹²⁸。
- 不强制 NAT，恢复端到端直连；过渡技术：双栈、隧道（6in4）、翻译（NAT64）。

# 第五部分：链路层与局域网

## 14. 成帧与差错检测
- **成帧**：标志位/长度字段界定帧边界，比特填充防止载荷中出现标志序列。
- **检错码**：
  - 奇偶校验/互联网校验和（反码求和）：弱，只检少量错。
  - **CRC（循环冗余校验）**：把比特串当多项式，用生成多项式做模 2 除；能检所有奇数位错、所有 ≤r 位的突发错；硬件实现为移位寄存器，便宜可靠，用于以太网/Wi-Fi。
- 检错 ≠ 纠错：链路层检出错就丢（靠端到端重传）；FEC 前向纠错（海明码/LDPC）在无线与物理层直接纠部分错。

## 15. MAC 协议（共享介质如何分配）
- **信道分配问题**：一条广播信道多个站要发，怎么协调？
- **静态划分**：FDMA/TDMA/CDMA——无冲突但僵化，突发流量浪费。
- **随机访问**：
  - **纯 ALOHA**：想发就发，冲突后随机等一会重发；最大吞吐仅约 18%。
  - **分槽 ALOHA**：只能在时隙起点发，吞吐提到约 37%。
  - **CSMA（先听后说）**：先载波侦听，空闲才发，减少但无法消除冲突（传播延迟内可能同时开头发）。
  - **CSMA/CD（以太网，冲突检测）**：边发边听，冲突立即中止并执行二进制指数退避；要求"发送时长 ≥ 2τ"（最远两站的往返传播时间），短帧要用最小帧长 64 字节保证冲突窗口内能检测到。
  - **CSMA/CA（Wi-Fi，冲突避免）**：无线无法边发边听（自己的信号盖过远端），改用 RTS/CTS 预留 + 随机竞争窗口 + ACK 确认；还有**隐藏终端**（A、C 互相听不见但都能打到 B）与**暴露终端**问题，RTS/CTS 缓解但不彻底。
- 现代交换式以太网：每端口一个独立冲突域，CSMA/CD 实际已退场，全双工无冲突。

## 16. 交换机与局域网
- **自学习交换机**：收到帧时记录"源 MAC 来自哪个端口"（转发表）；查表命中则定向转发，未命中则洪泛到其他端口——即插即用，无需配置。
- **环路问题**：冗余链路导致洪泛帧无限循环、转发表振荡 → **STP 生成树**：交换机跑分布式算法选出根桥，逻辑阻塞部分端口形成无环树；代价是被阻塞链路闲置（现代用 TRILL/SPB 等最短路径多路径替代）。
- **VLAN**：在同一物理设施上逻辑划分子网，隔离广播域。

# 第六部分：排队、QoS 与跨层主题

## 17. 排队论入门（量化拥塞的语言）
- **Little 定律**：L = λ·W——系统中平均任务数 = 到达率 × 平均逗留时间。知道任意两个求第三个，不依赖具体分布。
- **M/M/1 结论**：利用率 ρ = λ/μ（μ 服务率）时，平均延迟 W = 1/(μ−λ)；ρ → 1 时延迟趋于无穷——**延迟在高负载下是非线性爆炸，不是线性变差**。
- 工程推论：链路不能按"长期平均利用率 90%"规划；突发 + 排队意味着要留明显余量（常见经验：链路过 70% 就该扩容）。

## 18. QoS 与队列管理
- **为什么难**：互联网核心按包平等、无连接状态；为每个流预留资源违背端到端极简原则，IntServ/RSVP 未成功。
- 实际机制：
  - 队列调度：FIFO → 优先级队列 PQ（低优先级可能饥饿）→ 公平队列 FQ/WFQ（按流轮询/加权，给每流保底份额）。
  - 流量整形：令牌桶（允许突发但约束平均速率）。
  - 区分服务 DiffServ：在包首部打少数几类标记，核心网按类别给不同调度/丢弃待遇。
- 拥塞控制（端侧）+ AQM/调度（网络侧）是一对配合关系。

## 19. 多媒体与无线补充
- 实时流更关心延迟与抖动而非完全可靠；FEC、自适应抖动缓冲、自适应码率（ABR：按实测带宽切分辨率档位）。
- 无线特点：误码率高（靠 FEC/重传）、信号衰减与干扰、移动导致切换 handoff；802.11 的关联、AP、CSMA/CA 与隐藏终端是链路层重点。

## 典型实验 / 项目类型（随学期变动）

1. **Socket 编程**：TCP/UDP 实现客户端-服务器或简易协议；难点：处理短读短写（一次 read 不保证拿到整个消息，必须自己定长头/分隔符成帧）、粘包与消息边界。
2. **可靠传输实验（如 Pydatack / 教学用不可靠信道）**：在给定丢包/乱序/损坏的 UDP 信道上实现序号、ACK、超时、滑动窗口、流控——把第 8 节亲手写一遍。
3. **IP 转发 / 路由器实验（如 mininet 仿真）**：解析 IP 包、实现最长前缀匹配转发表、ARP、TTL 减 1 与 ICMP；难点：转发表数据结构与边界包处理。
4. **路由协议仿真**：实现 DV 的 Bellman-Ford 更新与 split horizon / poison reverse，观察计数到无穷与收敛过程。
5. **排队/拥塞仿真**：改变 offered load 画吞吐-延迟曲线，复现 AIMD 锯齿、bufferbloat、RED 与 tail-drop 的差异。

## 方法论卡片

### 卡片 A：按"失效模式"反推机制
```
观察到的问题            对应机制
比特损坏                校验和 / CRC（检错），FEC（纠错）
包丢失                  ACK + 超时重传
包重复                  序号去重
包乱序                  序号 + 缓存重排
发送方淹没接收方         接收窗口 rwnd（流量控制）
发送方淹没网络           拥塞窗口 cwnd（拥塞控制）
路由环路                TTL / 水平分割 / 生成树
规模爆炸（地址/路由表）  CIDR/子网、层次路由、BGP 聚合
身份与会话              四元组、Cookie、TLS
```
学任何协议先问：它在对抗哪一种失效？没有对应失效的机制一定是历史包袱。

### 卡片 B：TCP 排障思路
1. 现象是"连不上"还是"连上了慢/断流"？前者查握手（SYN 丢包、防火墙、RST、半连接队列）。
2. 慢：先测 RTT 与丢包率；抓包看 cwnd 是否被丢包反复腰斩、是否卡在慢启动、rwnd 是否为 0（接收窗口受限）。
3. 重传：区分超时重传（间隔 ~200ms+ 翻倍）与快速重传（3 dupACK）；前者是严重拥塞或真丢包。
4. 高延迟低丢包：怀疑 bufferbloat（排队延迟），看 RTT 是否随负载上涨。
5. 大量 TIME_WAIT：高频短连接，考虑长连接 / 连接池 / 调参。

### 卡片 C：LS vs DV 答题对照
| 维度 | LS | DV |
|---|---|---|
| 谁知道拓扑 | 每台都有全网图 | 只有邻居视角 |
| 算法 | Dijkstra | Bellman-Ford 迭代 |
| 交换内容 | 自己的链路状态（给全网泛洪） | 自己的完整距离向量（只给邻居） |
| 收敛 | 快 | 慢，计数到无穷 |
| 报文开销 | 泛洪 O(N·E) 级别 | 周期小报文 |
| 典型协议 | OSPF（域内） | RIP（域内） |
| 防环/防坏消息 | 全局图天然避免 | split horizon / poison reverse |
| 域间 | — | BGP 用路径向量（DV 思想 + 带路径防环 + 策略） |

### 卡片 D：滑动窗口吞吐与速率计算
```
理想流水线吞吐 ≈ 窗口大小 / RTT
  窗口 = min(cwnd, rwnd)，单位字节
  例：rwnd=64KB, RTT=50ms → 约 64KB/0.05s ≈ 10.24 Mbps（这就是早年长肥网络窗口太小的瓶颈）
利用率 = 窗口 / (带宽 × RTT)；要打满管道必须 窗口 ≥ 带宽时延积 BDP
停止-等待利用率 ≈ (MSS/B) / (MSS/B + RTT)
```
**带宽时延积 BDP = 链路带宽 × RTT**：管道中"在途数据"总量；窗口小于 BDP 就填不满链路——长肥网络（卫星、跨洋）的核心设计约束。

### 卡片 E：抓包/分层定位问题的顺序
1. 物理/链路：接口 up 吗？ARP 解析得到网关 MAC 吗？
2. 网络：本机 IP/路由表对吗？`ping` 网关、ping 外网、traceroute 在哪一跳断？DNS 能解析吗？
3. 传输：TCP 三次握手完成吗？有无 RST/重传/零窗口？
4. 应用：TLS 握手过吗？HTTP 状态码与响应体？
分层的价值：每一层只需对"下一层能否提供服务"做二分定位。

### 卡片 F：设计一个协议时的清单
- 消息边界怎么定（长度字段 / 定长 / 分隔符）？
- 丢包怎么办（超时多久？RTT 怎么估？幂等吗？）？
- 乱序/重复怎么办（序号空间多大？绕回会混淆吗）？
- 谁先说话（握手）？怎么确认对方还活着（keepalive/心跳）？怎么关（半关闭/TIME_WAIT 等价物）？
- 发多快（有无拥塞控制，会不会伤害共享网络）？
- 安全：消息能伪造/篡改/重放吗（认证、完整性、nonce/时间戳）？

## 学习路径建议

1. **先吃透分层与端到端原则**：这两个思想是后面所有"为什么不在网络里做 X"的答案来源。
2. **传输层推导优先于记忆**：从 rdt 停等一路自己推到滑动窗口，再看 TCP 的每一项机制（dupACK、SACK、RTO 公式）就都只是工程补丁。
3. **拥塞控制画图学**：cwnd-时间的锯齿图、效率-公平相图、队列长度-延迟曲线各画三遍；AIMD 的公平性证明要能手写。
4. **网络层做对比表**：LS vs DV vs BGP 三者的信息、算法、收敛、规模、策略维度一张表收口。
5. **链路层抓主线**：共享介质 → 随机访问 → 冲突处理的演进（ALOHA→CSMA→CD/CA）；交换式网络让 CD 退场是"技术随基础设施变化而隐身"的好例子。
6. **动手验证**：Wireshark 抓一次完整 HTTP/TCP/DNS/ARP 流量，把课本字段在真实包里逐个找到，理论立刻落地。
