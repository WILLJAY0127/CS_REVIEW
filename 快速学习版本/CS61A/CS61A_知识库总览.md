# CS61A 知识库总览

## 8+1 总览卡

1. **课程定位**：CS61A 是伯克利版 SICP，用 Python 重写。本质是"用抽象控制复杂度"，不是 Python 语法课，不是数据结构课。
2. **三条主线**：函数抽象（怎么封装计算）→ 数据抽象（怎么封装状态）→ 元语言抽象（怎么描述语言本身）。
3. **语言载体**：Python（主线）+ Scheme（解释器项目）+ SQL（声明式对照）+ 正则。
4. **四个项目**：Hog（函数与控制流）→ Cats（高阶函数与字符串）→ Ants（面向对象与数据抽象）→ Scheme Interpreter（元抽象）。
5. **核心思维**：不是"写代码能跑"，而是"能否用更小的抽象单元组合出更复杂的系统"。
6. **评估维度**：环境模型走查 / 递归分解 / 数据抽象边界 / 解释器求值循环。
7. **三道门槛**：高阶函数、环境模型、解释器递归求值——三处不过关，后续全塌。
8. **本课的"反直觉"结论**：变量不存值，存的是名字到值的绑定；对象不是面向对象的重点，"消息传递"才是；解释器不是黑盒，它本身就是一个递归函数。

**一句话**：CS61A 教的不是写代码，而是"抽象的纪律"——能否在每一步把不必要的复杂度关进笼子。

**如何使用本文**：下面的每个概念、每个项目、以及知识图谱，都带一句加粗的 **【关进笼子】**——它就是"抽象的纪律"落在该知识点上的具体形态（**把哪种复杂度，关进什么笼子**）。读任何一条时，先找这句话，再回看正文，主线就不会散。

## 核心概念 12 项

### 1. 表达式与语句
- **【关进笼子】**：把"一个操作到底产不产生值、有没有副作用"的复杂度，关进**表达式 / 语句**这个二分笼子。
- **定义**：表达式求值产生值；语句执行改变状态但不返回值。
- **动机**（为什么要区分这两者）：赋值 `=` 是**语句**，而语句**不产生值**，所以它不能出现在任何"需要一个值"的位置——这正是 `a = (b = 1)` 会直接报 `SyntaxError` 的原因（C 语言里赋值是表达式，那样写合法；Python 故意不让）。那 `a = b = 1` 为什么合法？因为它是**链式赋值**这条语句级语法，等价于"先 `b = 1`，再 `a = b`"，并不是"把 `(b = 1)` 当成一个值来用"。
- **易错**：
  - `==` 比**值**、`is` 比**同一性**：`[1, 2] == [1, 2]` 是 `True`，而 `[1, 2] is [1, 2]` 是 `False`（两个不同的列表对象）。
  - `and` / `or` **返回的是操作数本身**（不是 `True`/`False`），并且**会短路**（左边一旦定局，右边根本不求值）：`0 and f()` 返回 `0`、且 `f()` 不会被执行；`2 or 3` 返回 `2`。

### 2. 环境模型
- **【关进笼子】**：把"这个名字到底指向哪个值、作用域从哪来"的复杂度，关进**帧 + 父指针链**的笼子——一个名字的含义由它所在的帧唯一确定。
- **定义**：每个名字都存在于某个"帧"中，帧通过父指针串成链。
- **走查 6 步**（见方法论卡片 A）。
- **易错**：
  - **默认参数只在函数定义时求值一次**：`def f(acc=[])` 里的列表只创建一次，之后每次调用都共用它——这是"可变默认参数"陷阱（详见概念 7）。
  - **闭包捕获的是变量、不是当时的值**：见概念 4 的例子。

### 3. 高阶函数
- **【关进笼子】**：把"流程里哪一处会变"这层复杂度，关进**函数参数的边界**——通用流程与具体差异就此分离。
- **定义**：函数作为参数 / 返回值。
- **动机**：把"通用流程"和"具体差异"分离——`sum_using` 接受一个 term 函数就是典型。
- **桥接**：高阶函数是闭包的前置，也是装饰器的底层。

### 4. 闭包与 nonlocal
- **【关进笼子】**：把"函数定义时的环境该放在哪、能活多久"的复杂度，关进**闭包**——环境随函数一起走，且只能通过 `nonlocal` 被定向修改。
- **定义**：内层函数捕获外层帧的变量，外层帧因此不能被回收。
- **nonlocal 的作用**：让内层函数能"写"外层变量，否则只能读。
- **类比**：闭包像"带抽屉的便携工具箱"，抽屉里装的是定义时的环境。
- **易错**：**捕获的是变量，不是值**——`fs = [lambda: i for i in range(3)]` 之后，`fs[0]()` 得到的是 `2`（循环结束时 `i` 的终值），不是 `0`；想要"定格"每次的值，得再套一层默认参数：`lambda i=i: i`。

### 5. 递归
- **【关进笼子】**：把"重复且规模递减的过程"关进**自相似分解**的笼子——你不写循环，只回答"怎么把问题缩小一点"。
- **三段式**：base case（最小可解）→ recursive case（向 base 收敛）→ combination（合并子结果）。
- **线性递归**：阶乘、length。
- **树递归**：fib、counting change。
- **尾递归**：把累计结果作为参数传下去，递归调用是最后一步——Scheme 能优化成循环，Python 不能。
- **易错**：**忘记 base case 或没有向 base 收敛** → 触发 `RecursionError: maximum recursion depth exceeded`（Python 默认递归深度约 1000 层）。症状是"栈被撑爆"，而不是"算出错误答案"（后者是逻辑写错，不是这一条）。

### 6. 树与链表（数据抽象）
- **【关进笼子】**：把"数据内部到底怎么表示"关进**构造器 + 选择器**这道屏障之后，使用者只看接口、不碰表示。
- **核心**：用"构造器 + 选择器"定义抽象边界，使用者不关心内部表示。
- **链表**：`link(first, rest)` + `first(link)` / `rest(link)`。
- **树**：`tree(label, branches)` + `label(tree)` / `branches(tree)`。
- **桥接**：树的递归处理与函数递归同构（每个节点是一个 sub-tree）。

### 7. 可变性与对象
- **【关进笼子】**：把"这是不是同一个东西、改动会不会波及别处"的复杂度，关进**可变 / 不可变 + `is` 同一性**的笼子。
- **核心**：可变对象的同一性用 `is` 判断；`+=` 对可变对象是原地操作，对不可变对象是新建。
- **类比**：列表是"可擦写的白板"，元组是"封存的相册"。
- **易错**：**可变对象当默认参数** → `def f(x=[])` 里的 `[]` 只创建一次，`f()` 和 `f()` 改的是同一个列表。正确写法：`def f(x=None)`，在函数体内 `if x is None: x = []`。

### 8. 面向对象
- **【关进笼子】**：把"状态 + 操作状态的行为"打包关进**对象**这个笼子——外界只能发消息（属性查找 / MRO），碰不到内部状态。
- **属性查找流程**：实例字典 → 类字典 → 父类链（MRO）→ `AttributeError`。
- **继承**：子类复用父类行为，`super()` 是"调用 MRO 中的下一个类"而不是"父类"。
- **多继承 MRO**：C3 线性化，菱形继承时顺序决定行为。
- **设计动机**：把"状态 + 操作该状态的行为"封装成单元，方便复用。

### 9. 迭代器与生成器
- **【关进笼子】**：把"算到哪一步了"这个进度状态，关进**生成器的暂停点**——于是"惰性求值"与"无穷流"才成为可能。
- **迭代器协议**：`__next__` 返回下一个值，耗尽时抛 `StopIteration`。
- **生成器**：`yield` 让函数变成"可暂停的状态机"，每次 `next` 从上次 yield 处恢复。
- **惰性**：无穷流 `integers_from(n)` 用生成器实现，需要时才算下一个。
- **易错**：
  - **迭代器只能遍历一次**：`it = iter([1, 2])`；`list(it)` 得 `[1, 2]`，再 `list(it)` 得 `[]`。要反复遍历请用**可迭代对象**（如列表本身），不要用迭代器。
  - **生成器提前结束时收尾**：生成器被 `close()` 或 GC 掉时，`yield` 之后的清理代码不一定执行——涉及资源清理时要写进 `try / finally`。

### 10. Scheme 与解释器
- **【关进笼子】**：把"语言如何求值"这条规则本身关进**eval / apply 互递归**的笼子——语言不再是黑魔法，而是可被写出来的循环。
- **核心循环**：`eval` 接受表达式 + 环境，返回值；`apply` 接受过程 + 实参，返回结果。两者互递归。
- **特殊形式**：`if` / `define` / `lambda` / `cond` 不能用普通函数实现，要在 `eval` 里特判。
- **尾递归**：解释器需要做尾调用优化，否则递归深时栈溢出。
- **动机**：证明"语言不是黑魔法"——任何语言都能用几十行 Python 写出来。

### 11. 正则与 BNF
- **【关进笼子】**：把"字符串的结构"关进**产生式规则**的笼子；但正则这个笼子关不住嵌套，必须换成 BNF——笼子能力不足时，就换一个更大的笼子。
- **正则**：描述字符串模式，但表达力有限（无法匹配嵌套结构）。
- **BNF**：用产生式规则描述嵌套语法（如 Scheme 列表的递归定义）。
- **桥接**：解释器的 `read` 步骤用 BNF 解析字符串成 AST。

### 12. SQL 与声明式
- **【关进笼子】**：把"怎么取（执行计划）"关进**优化器**的笼子——用户只描述"要什么"，完全不问"怎么取"。
- **核心**：描述"要什么"而不是"怎么取"。
- **三组操作**：`SELECT/FROM/WHERE`（投影 + 筛选）、`JOIN`（笛卡尔积 + 筛选）、`GROUP BY/HAVING`（分组 + 聚合）。
- **对照**：SQL 的 `JOIN` 类似 Python 的嵌套循环，但执行计划由优化器决定。

## 4 个项目（关进笼子 + 目标 + 难点提示）

### Hog（骰子游戏）
- **【关进笼子】**：把"何时该 reroll、何时该 hold"的决策复杂度，关进**策略函数**的笼子。**通关判据**：能在不改主流程的前提下替换任意策略。
- **目标函数**：`dice`、`take_turn`、`play`、`always_roll` 策略。
- **考察**：函数组合、控制流、策略函数作为参数。
- **难点提示**：注意"何时该 reroll、何时该 hold"的决策不是写死，而是通过策略函数注入——这是高阶函数的实战。

### Cats（打字练习自动纠错）
- **【关进笼子】**：把"搜索空间爆炸"关进**剪枝 + 记忆化**的笼子。**通关判据**：编辑距离能在可接受时间内算完，而不是爆栈。
- **目标函数**：`autocorrect`、`distance`、`shifty_shifts`、`meowstake_matches`。
- **考察**：字符串处理、高阶函数、性能优化（剪枝 + 缓存）。
- **难点提示**：编辑距离的递归会爆栈，必须引入记忆化或限制窗口。

### Ants（塔防游戏，旧版为 Hog 之外的项目）
- **【关进笼子】**：把"成千上万只蚂蚁各自的行为差异"关进**继承 + `action` 多态分发**的笼子。**通关判据**：新增一种蚂蚁时，无需改动已有代码。
- **目标类**：`Ant`、`ThrowerAnt`、`HarvesterAnt`、`QueenAnt` 及其子类。
- **考察**：继承、多态、数据抽象、状态机。
- **难点提示**：`action` 方法的多态分发是核心；`QueenAnt` 死亡时游戏结束的"全局信号"如何通过对象关系传递。

### Scheme Interpreter
- **【关进笼子】**：把"语言的语法与求值规则"关进**eval/apply + tail 包装**的笼子。**通关判据**：能正确跑递归，且不撑爆 Python 栈。
- **目标函数**：`eval`、`apply`、`eval_all`、`make_frame`。
- **考察**：递归下降解析、环境帧链、尾调用优化。
- **难点提示**：`tail` 包装是关键——它把"返回表达式"变成"继续求值"，避免 Python 栈增长。

## 方法论卡片

### 卡片 A：环境模型走查 6 步
1. 画出全局帧。
2. 函数定义时，在全局帧新建一个绑定，函数对象带上 `parent=全局帧`。
3. 函数调用时，新建一个帧，`parent = 函数对象的 parent`，把形参绑定到实参。
4. 在新帧中求值函数体。
5. 若函数体内有嵌套函数定义，重复 2-4，新函数的 parent 是当前帧。
6. 函数返回时，帧不立即销毁——若被内层函数捕获，就活到内层函数死亡为止。

### 卡片 B：递归三段式
1. **Base**：最小可解的输入是什么？返回什么？
2. **Recursive**：假设子问题已解决，怎么用子结果拼出当前答案？
3. **Convergence**：每次递归调用是否更接近 base？

### 卡片 C：面向对象属性查找流程
```
1. 查实例字典 → 命中则返回
2. 查类字典 → 命中则返回
3. 按 MRO 顺序查父类字典 → 命中则返回
4. 若是数据描述符（property），优先级高于实例字典
5. 否则 AttributeError
```

### 卡片 D：解释器求值循环
```
eval(expr, env):
    if self_evaluating(expr):  # 数字、字符串
        return expr
    if variable(expr):          # 名字
        return env.lookup(name)
    if special_form(expr):     # if / define / lambda
        return eval_special(expr, env)
    if call(expr):             # (op arg1 arg2)
        proc = eval(op, env)
        args = [eval(a, env) for a in rest]
        return apply(proc, args)  # apply 内部继续调用 eval
```
互递归终止于 self_evaluating；启动于顶层表达式。

### 卡片 E：抽象的纪律
每次写代码前自问：
- 这个函数的输入 / 输出契约是什么？调用者需要知道内部表示吗？
- 如果内部表示变了，调用者需要改吗？（不需要 = 抽象边界清晰）
- 这段代码里有没有"不必要的复杂度"泄漏出去？（如让调用者关心我的循环变量）

## 学习路径建议

1. **第一遍**：以"环境模型走查"为锚——每个语法都问"这会在帧里发生什么"。
2. **第二遍**：以"抽象边界"为锚——每个数据结构都问"构造器 + 选择器"是什么。
3. **第三遍**：以"解释器"为锚——每个语法都问"`eval` 怎么处理它"。
4. **三个项目分阶段做**：Hog 通关后做 Cats，Cats 通关后做 Ants，最后才碰 Scheme Interpreter。解释器项目不过关，整个 CS61A 算没学完。
