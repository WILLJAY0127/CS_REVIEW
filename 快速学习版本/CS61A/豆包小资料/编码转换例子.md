# 最终完整版C代码
新增：`b_sub2 = b - 150;`，无符号减法，**数学上100-150=-50**，但`b_sub2`是`unsigned int`。
> 重点：`addi`硬件只做bit运算，发生模回绕；同一个bit串，用`slti`(补码)和`sltiu`(无符号)对比，结果完全相反。

```c
#include <stdio.h>

int main(void)
{
    int           a  = -20;
    unsigned int  b  = 100;

    // 原有加减
    int           a_add = a + 5;
    unsigned int  b_sub = b - 30;

    // =====新增：无符号减法，结果数学上是负数=====
    unsigned int  b_sub2 = b - 150;

    printf("a = %d\n", a);
    printf("b = %u\n", b);
    printf("a +5 = %d\n", a_add);
    printf("b -30 = %u\n", b_sub);
    printf("b -150 = %u\n", b_sub2);

    if (a_add < 0)
    {
        printf("a_add <0：int，补码解读\n");
    }
    if (b_sub < 0)
    {
        printf("b_sub <0：unsigned，永远不会执行\n");
    }
    if (b_sub2 < 0)
    {
        printf("b_sub2 <0：unsigned，永远不会执行\n");
    }

    // 【重点实验】同一个bit串，强行用int的视角去看
    // 把b_sub2里面的bit拿出来，当成int（补码）来判断
    if ( (int)b_sub2 < 0 )
    {
        printf("(int)b_sub2 <0：同一串bit，切换成补码解读，条件成立！\n");
    }

    return 0;
}
```

## 从上到下逐行变化（32bit）
1. `int a = -20;`
十进制`-20`，int补码编码：`0xFFFFFFEC`，存入a独立内存。
bit：`11111111 11111111 11111111 11101100`

2. `unsigned int b = 100;`
十进制`100`，无符号编码：`0x00000064`，存入b独立内存。
bit：`00000000 00000000 00000000 01100100`

3. `int a_add = a + 5;`
读取a的bit，`addi`硬件二进制加法：`0xFFFFFFEC + 0x5 = 0xFFFFFFF1`
存入`a_add`。int补码翻译：`-20+5 = -15`，bit `0xFFFFFFF1`

4. `unsigned int b_sub = b - 30;`
读取b的bit，`addi t4,t4,-30`硬件bit运算。
`0x00000064 - 0x1E = 0x00000046`，无符号翻译`100-30=70`

5. `unsigned int b_sub2 = b - 150;` ✅新增核心行
读取b的bit `0x00000064`，硬件做二进制减法：`100 - 150`
硬件ALU：$0\text{x}00000064 + (-150\text{的32bit补码}) = 0\text{xFFFFFFCE}$
bit串：`11111111 11111111 11111111 11001110`
存入`b_sub2`（unsigned变量内存）
- 按**无符号解读**：`0xFFFFFFCE = 4294967246`
- 按**补码(int)解读**：同一串bit = `-50`

6. 打印语句
- `printf("a = %d\n",a)`：bit `0xFFFFFFEC`，`%d`补码 → `-20`
- `printf("b = %u\n",b)`：bit `0x00000064`，`%u`无符号 → `100`
- `printf("a +5 = %d\n", a_add)`：bit`0xFFFFFFF1`补码 → `-15`
- `printf("b -30 = %u\n", b_sub)`：bit`0x00000046`无符号 → `70`
- `printf("b -150 = %u\n", b_sub2)`：bit`0xFFFFFFCE`无符号 → `4294967246`

7. `if (a_add < 0)`
读取`a_add`bit，int类型 → 生成`slti`补码比较。`-15<0`成立，打印。

8. `if (b_sub < 0)`
unsigned类型 → `sltiu`无符号比较。永远false，跳过。

9. `if (b_sub2 < 0)`
unsigned类型 → `sltiu`。`4294967246 <0` 假，跳过。

10. `if ( (int)b_sub2 < 0 )` ✅关键对比
读取`b_sub2`内存里的bit `0xFFFFFFCE`（bit**完全没变**）
强制转换`(int)`告诉编译器：**这串bit改用补码规则解读**，生成`slti`指令。
补码解读：`0xFFFFFFCE = -50 <0` → 条件成立，打印！

11. `return 0;` 结束

    beq  t1, x0, L4

# 最终完整总结
1. **加减运算（add/addi）硬件指令只有一套！**
不管变量是`int`还是`unsigned int`，加减都生成`add/addi`。CPU ALU只做32位模$2^{32}$二进制bit运算，**硬件本身不区分补码/无符号**。

2. **差别出现在【比较指令】**
- `slti`：把寄存器内bit当做**补码**解释（对应C `int`）
- `sltiu`：把寄存器内bit当做**无符号数**解释（对应C `unsigned int`）
> 同一串bit，换这两条指令，比较结果可以完全相反。`b_sub2`这个例子就是最好证明。

3. **强制类型转换 `(int)b_sub2`**
✅ **不会修改内存里的bit！**
只是告诉编译器：**后续操作这串bit的时候，改用补码规则（选slti）**。内存、寄存器里面0/1完全不变。

4. **printf打印**
`%d` / `%u`是printf内部两套翻译规则，把传入寄存器的bit翻译成十进制字符串。

5. C语言类型的生命周期：**只在编译期有效**
编译完成，机器码里没有“这个变量是int / unsigned”标记。类型信息全部转化为：
- 赋值阶段：十进制数字编码成bit
- 比较阶段：选择`slti` / `sltiu`
加减运算不变，永远是add。

> 核心一句话：**运算（加减）看bit；比较、判断正负、打印，才看解读规则。bit本身不带正负。**

如果你想，我们可以单独把`0xFFFFFFCE`这串bit，单独拿出来再细拆slti和sltiu的判定逻辑。
