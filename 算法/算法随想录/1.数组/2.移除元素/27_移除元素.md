# 27. 移除元素

## 📌 题目链接

[力扣题目链接](https://leetcode.cn/problems/remove-element/) | [代码随想录讲解](https://programmercarl.com/algo/array/0027-remove-element.html)

## 📋 题目描述

给你一个数组 `nums` 和一个值 `val`，你需要**原地**移除所有数值等于 `val` 的元素，并返回移除后数组的新长度。

不要使用额外的数组空间，你必须仅使用 `O(1)` 额外空间并**原地**修改输入数组。

元素的顺序可以改变。你不需要考虑数组中超出新长度后面的元素。

### 示例

```python
# 示例 1
输入: nums = [3,2,2,3], val = 3
输出: 2, nums = [2,2]
解释: 函数应该返回新的长度 2, 并且原数组 nums 的前两个元素都是 2

# 示例 2
输入: nums = [0,1,2,2,3,0,4,2], val = 2
输出: 5, nums = [0,1,3,0,4]
解释: 函数应该返回新的长度 5
```

### 提示

- `0 <= nums.length <= 100`
- `0 <= nums[i] <= 50`
- `0 <= val <= 100`

---

## 🧠 核心思维转换

### 普通人的直觉 vs 算法最优解

| 视角 | 关注点 | 实现方式 |
|------|--------|----------|
| **直觉视角** | 寻找要**删除**的元素 | 找到 val → 消除它 |
| **优化视角** | 收集要**保留**的元素 | 收集非 val → 覆盖到前方 |

> ⚠️ 这是这道题最大的思维门槛，不是代码难，是**视角转换**。

---

## 🎯 模型一：暴力解法（重力堆叠模型）

### 想象画面

数组像竖直堆叠的方块：
- 从上往下逐个检查
- 如果当前方块要被移除，直接抽走
- 上方所有方块整体往下坠落一格填补空位
- 指针不前进，留在当前位置，重新检查新落下来的方块

### 代码实现

```python
def remove_element(nums, val):
    i = 0
    n = len(nums)
    
    while i < n:
        if nums[i] == val:
            # 找到坏人，后面所有人往前挤填坑
            for j in range(i + 1, n):
                nums[j - 1] = nums[j]
            n -= 1  # 有效长度减少
        else:
            i += 1  # 不是坏人，继续检查下一个
    
    return n
```

### 问题分析

```
nums = [2, 3, 3, 3], val = 3

第一次遇到 3 → 后面两个 3 前移，数组变成 [2, 3, 3]
第二次又遇到 3 → 最后一个 3 前移，数组变成 [2, 3]
第三次还遇到 3 → 继续前移...
```

**问题**：同一个元素会被多次移动，时间复杂度 O(n²)。

### 痛点

1. 只要出现一个坏人，后面一整段全部集体平移
2. 如果连续多个坏人，会发生重复搬运同一个好人
3. 现实思维很容易想到这个，但效率低

## 🎯 模型二：快慢指针（两道传送带模型）⭐

### 想象画面

抛弃「抽方块、下落」的思路，换画面：

```
fast 快指针：一道传送带，从头走到尾，负责检阅每一个元素
            ↓
slow 慢指针：一块有效区域缓冲区，标记缓冲区末尾

规则：
- fast 一路向前不回头
- 检阅到「不需要删除」的元素 → 复制送入缓冲区，slow 向后挪一格
- 检阅到「要删除的 val」 → 直接忽略，slow 不动
```

### 执行过程示例

```
nums = [0, 1, 2, 2, 3, 0, 4, 2], val = 2

步骤  fast  检阅元素  动作        数组状态          slow 位置
 1     0     0 ✅     送入缓冲区    [0,1,2,2,3,0,4,2]   1
 2     1     1 ✅     送入缓冲区    [0,1,2,2,3,0,4,2]   2
 3     2     2 ❌     丢弃         [0,1,2,2,3,0,4,2]   2
 4     3     2 ❌     丢弃         [0,1,2,2,3,0,4,2]   2
 5     4     3 ✅     送入缓冲区    [0,1,3,2,3,0,4,2]   3
 6     5     0 ✅     送入缓冲区    [0,1,3,0,3,0,4,2]   4
 7     6     4 ✅     送入缓冲区    [0,1,3,0,4,0,4,2]   5
 8     7     2 ❌     丢弃         [0,1,3,0,4,0,4,2]   5

结果：返回 slow=5，数组前5个元素 = [0,1,3,0,4]
```

### 代码实现

```python
def remove_element(nums, val):
    slow = 0  # slow 标记有效区域的末尾
    
    for fast in range(len(nums)):
        if nums[fast] != val:
            # 遇到好人，登记进有效区
            nums[slow] = nums[fast]
            slow += 1
    
    return slow
```

### 与暴力解法的本质区别

| 对比维度 | 暴力解法 | 快慢指针 |
|---------|---------|---------|
| 触发移动的时机 | 找到坏人后，被动移动后方所有人 | 找到好人后，主动搬到前方 |
| 移动范围 | 每次坏人触发，后方全部平移 | 只搬运好人，每次最多1次赋值 |
| 重复移动 | 同一元素可能被多次搬运 | 每个好人只搬运1次 |
| 时间复杂度 | O(n²) | O(n) |
| 视角 | 盯着坏人 | 盯着好人 |

### 形象比喻

**暴力方案**：发现垃圾 → 所有人往前挤填坑
**快慢指针**：只挑选好人，依次排队站到前排，坏人原地无视

## 🔄 关于 `nums[slow] = nums[fast]` 的困惑

### 问题

初学者常会觉得这段代码别扭：

```python
if nums[fast] != val:
    nums[slow] = nums[fast]
    slow += 1
```

**困惑**：当 `slow == fast` 时，`nums[slow] = nums[fast]` 变成了 `nums[x] = nums[x]`，这不是多余的自赋值吗？

### 两种理解方式

#### 方式一：「搬运元素」的物理视角

```
slow == fast 时：
元素已经在目标位置，没必要搬运自己
```

→ 这种视角下确实会觉得别扭，会想加个判断

#### 方式二：「构建有效区间」的容器视角 ⭐

```
slow 划定一片区域 [0, slow)
这片区域持续保存所有已经筛选出来的好人

nums[slow] = nums[fast] 的含义：
把当前这个好人登记进有效区的下一个位置

当 slow == fast：
登记位置刚好就是元素本身所在位置
登记动作执行了，但数据不变
```

### 两种写法对比

#### 方案 A：标准模板（推荐）

```python
def remove_element(nums, val):
    slow = 0
    for fast in range(len(nums)):
        if nums[fast] != val:
            nums[slow] = nums[fast]  # 接受少量无危害自赋值
            slow += 1
    return slow
```

- 优点：代码短，分支少，模板通用性强
- 缺点：有少量无害自赋值

#### 方案 B：逻辑严谨版

```python
def remove_element(nums, val):
    slow = 0
    for fast in range(len(nums)):
        if nums[fast] != val:
            if slow != fast:  # 只有真的需要搬运时才赋值
                nums[slow] = nums[fast]
            slow += 1
    return slow
```

- 优点：逻辑更严谨，无多余动作
- 缺点：多一层判断，代码略长

> 💡 两种写法时间复杂度都是 O(n)，性能差距微乎其微。**考场推荐方案 A**。

### 用填表类比

> 表格空位（slow 位置）正好在这个人（fast 位置）面前，依旧执行「登记」这个流程，只是人不用移动。

## 🎯 模型三：左右对撞双指针

### 想象画面

左右两个哨兵：
- 左哨兵：从左边开始，寻找待删除的值
- 右哨兵：从末尾开始，拿一个元素覆盖左边待删除位置

### 代码实现

```python
def remove_element(nums, val):
    left, right = 0, len(nums) - 1
    
    while left <= right:
        # 左哨兵找 val
        while left <= right and nums[left] != val:
            left += 1
        # 右哨兵找非 val
        while left <= right and nums[right] == val:
            right -= 1
        
        if left < right:
            # 用右哨兵的元素覆盖左哨兵位置
            nums[left] = nums[right]
            left += 1
            right -= 1
    
    return left
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 减少拷贝次数 | **打乱了原数组顺序** |
| 时间复杂度 O(n) | 逻辑稍复杂 |

> ⚠️ 注意：题目允许打乱顺序，所以这种方法也可行。

---

## 📊 三种解法对比

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 暴力双层循环 | O(n²) | O(1) | 直观但低效 |
| 快慢指针 | O(n) | O(1) | **推荐**，不打乱顺序 |
| 左右对撞 | O(n) | O(1) | 效率高，但打乱顺序 |

## 📝 通用套路总结

很多数组原地类题目都存在**视角转换**：

| 直觉视角（删除） | 优化视角（收集） |
|-----------------|-----------------|
| 寻找要删除的元素 | 收集要保留的元素 |
| 处理空缺 | 向前重组 |
| 容易写出 O(n²) | 双指针 O(n) |

### 适用题型

| 题目 | 核心思路 |
|------|---------|
| 移除元素 | 收集非 val 的元素 |
| 移动零 | 收集非零元素 |
| 合并有序数组 | 收集有效元素 |
| 删除有序数组重复项 | 收集不重复元素 |
| 颜色分类 | 收集各类元素 |

## 🔌 接口抽象

### 通用元素过滤接口

```python
def filter_elements(arr, should_keep):
    """
    通用元素过滤接口（快慢指针实现）
    
    参数:
        arr: 待过滤的数组
        should_keep: 判断函数，返回 True 表示保留该元素
    
    返回:
        过滤后的有效长度
    """
    slow = 0
    for fast in range(len(arr)):
        if should_keep(arr[fast]):
            arr[slow] = arr[fast]
            slow += 1
    return slow
```

### 使用示例

```python
# 移除元素
nums = [3, 2, 2, 3]
length = filter_elements(nums, lambda x: x != 3)
print(nums[:length])  # [2, 2]

# 移动零
nums = [0, 1, 0, 3, 12]
length = filter_elements(nums, lambda x: x != 0)
print(nums[:length])  # [1, 3, 12]
```

### 策略模式体现

| 接口层 | 策略层 | 结果 |
|--------|--------|------|
| `filter_elements(arr, lambda x: x != 3)` | `x != 3` | 移除值为3的元素 |
| `filter_elements(arr, lambda x: x != 0)` | `x != 0` | 移除所有零 |
| `filter_elements(arr, lambda x: x % 2 == 0)` | `x % 2 == 0` | 只保留偶数 |

## ⚠️ 常见错误

| 错误 | 原因 | 解决方法 |
|------|------|----------|
| 忘记返回 slow | 直接返回了 len(nums) | 返回 slow 而非 len(nums) |
| 快慢指针方向搞反 | slow 和 fast 的角色混淆 | slow 是边界标记，fast 是扫描指针 |
| 处理连续 val 时出错 | 用暴力解法时忘了 i 不递增 | 暴力解法遇到 val 时 i 保持不变 |

## 📝 总结

### 三层理解

| 层次 | 内容 | 目标 |
|------|------|------|
| **L1 实现层** | 暴力、快慢指针、对撞三种写法 | 能正确写出代码 |
| **L2 思维层** | 视角转换：从「删除」到「收集」 | 理解核心思想 |
| **L3 应用层** | 通用接口 + 策略模式 | 应用到各类题目 |

### 核心要点

1. **视角转换**：从「删除 val」转变为「收集非 val」
2. **快慢指针模板**：`for fast in range(len(nums))` + `if nums[fast] != val`
3. **接口抽象**：`filter_elements(arr, should_keep)` 可以复用
4. **同类题型**：移除元素、移动零、合并有序数组等

> 💡 **关键心得**：算法的本质不是代码技巧，而是**换一个视角看问题**。当你从「盯着坏人」变成「盯着好人」，世界就简单了！
