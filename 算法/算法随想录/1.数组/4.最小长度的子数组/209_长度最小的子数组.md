# LeetCode 209 - 长度最小的子数组

## 📌 题目链接

[力扣题目链接](https://leetcode.cn/problems/minimum-size-subarray-sum/) | [代码随想录讲解](https://programmercarl.com/algo/array/0209-minimum-size-subarray-sum.html)

## 📋 题目描述

给定一个正整数数组 `nums` 和一个正整数 `target`，找出满足其和 ≥ `target` 的长度最小的连续子数组。如果不存在符合条件的子数组，返回 0。

### 示例

```python
# 示例 1
输入: target = 7, nums = [2,3,1,2,4,3]
输出: 2
解释: 子数组 [4,3] 的长度为 2，是满足条件的最短子数组

# 示例 2
输入: target = 4, nums = [1,4,4]
输出: 1

# 示例 3
输入: target = 11, nums = [1,1,1,1,1,1]
输出: 0
解释: 总和为 6 < 11，不存在符合条件的子数组
```

### 提示

- `1 <= target <= 10^9`
- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^4`

---

## 核心前提（重中之重）

**数组全部元素为正整数**，这是滑动窗口解法能生效的关键。

### 性质

- 右边界向右扩展 → 区间总和变大
- 左边界向右收缩 → 区间总和变小
- 如果存在负数，滑动窗口思路直接失效

### 目标

找连续子数组，总和 ≥ target，求最小长度；没有则返回 0

---

## 思路 1：暴力解法（理解用，大数据超时 O(n²)）

固定起点 `start`，`end` 不断往右累加，一旦和满足条件记录长度并 break。

数组上限 10^5，双层循环一定会超时，只能用来理解题意。

### 代码实现

```python
from typing import List

def minSubArrayLen(target: int, nums: List[int]) -> int:
    n = len(nums)
    min_len = float("inf")
    for start in range(n):
        total = 0
        for end in range(start, n):
            total += nums[end]
            if total >= target:
                min_len = min(min_len, end - start + 1)
                break
    return min_len if min_len != float("inf") else 0
```

- **时间复杂度**：O(n²)
- **空间复杂度**：O(1)

---

## 思路 2：滑动窗口（同向双指针，最优 O(n)）

### 核心变量

| 变量 | 含义 |
|------|------|
| `start` | 窗口左边界 |
| `end` | 窗口右边界（for 循环持续向右走，只前进不回退） |
| `total` | 当前窗口 [start, end] 的累加和 |
| `min_len` | 保存满足条件区间的最小长度 |

### 执行逻辑

1. `end` 不断向右，把 `nums[end]` 加入窗口总和
2. 当 `total ≥ target`：
   - 当前窗口合法，尝试压缩左边界寻找更短区间
   - 更新最小长度
   - 左边界右移：`total -= nums[start]; start += 1`
3. **必须用 `while`，收缩后继续判断是否依旧满足条件，不能用 `if`！**

### 标准代码

```python
from typing import List

def minSubArrayLen(target: int, nums: List[int]) -> int:
    start = 0
    total = 0
    min_len = float("inf")
    n = len(nums)
    
    for end in range(n):
        total += nums[end]
        
        # 满足条件，持续收缩左边界
        while total >= target:
            window_len = end - start + 1
            min_len = min(min_len, window_len)
            total -= nums[start]
            start += 1
    
    return min_len if min_len != float("inf") else 0
```

- **时间复杂度**：O(n)（每个元素最多被访问两次，进窗口一次、出窗口一次）
- **空间复杂度**：O(1)

## 样例推演

`target=7，nums=[2,3,1,2,4,3]`

| 步骤 | end | total 变化 | total ≥ 7? | 窗口操作 | min_len |
|------|-----|-----------|------------|---------|---------|
| 1 | 0 | 0→2 | ❌ | 继续扩展 | ∞ |
| 2 | 1 | 2→5 | ❌ | 继续扩展 | ∞ |
| 3 | 2 | 5→6 | ❌ | 继续扩展 | ∞ |
| 4 | 3 | 6→8 | ✅ | len=4, total-=2→6, start=1 | 4 |
| 5 | 4 | 6→10 | ✅ | len=4(不变), total-=3→7, start=2 | 4 |
| 5' | 4 | 7 | ✅ | len=3, total-=1→6, start=3 | 3 |
| 6 | 5 | 6→9 | ✅ | len=3(不变), total-=2→7, start=4 | 3 |
| 6' | 5 | 7 | ✅ | len=2, total-=4→3, start=5 | **2** |

**最终返回 2** ✅

## 思路 3：前缀和 + 二分（O(n log n)，备选方案）

因为全正数，前缀和数组单调递增。对每个起点，二分查找最小右端点使区间和 ≥ target。

性能次于滑动窗口，适合拓展思路。

### 代码框架

```python
from typing import List
import bisect

def minSubArrayLen(target: int, nums: List[int]) -> int:
    n = len(nums)
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + nums[i]
    
    min_len = float("inf")
    for i in range(n):
        # 二分查找使 prefix[j] - prefix[i] >= target 的最小 j
        j = bisect.bisect_left(prefix, prefix[i] + target)
        if j <= n:
            min_len = min(min_len, j - i)
    
    return min_len if min_len != float("inf") else 0
```

## 高频疑问解答

### 1. 嵌套循环为什么不是 O(n²)？

`start` 和 `end` 只会单向前进，每个元素最多被左右指针各访问一次，总操作次数 ≤ 2n，复杂度为 O(n)。

### 2. 和 LC27 快慢指针有什么区别？

| 对比项 | LC27 移除元素 | LC209 长度最小的子数组 |
|--------|--------------|----------------------|
| 窗口操作 | 只扩张窗口，不需要回缩 | 条件满足后持续收缩左边界 |
| 循环结构 | 单层 `if` | 必须用 `while` 循环收缩 |
| 本质 | 收集"好元素"到前面 | 寻找满足条件的最短连续区间 |

### 3. 什么时候不能用这套滑动窗口？

**数组包含负数、0 时不能使用。**

一旦有负数，左边界右移总和可能变大，无法保证收缩窗口不会丢失最优解。

---

## 容易踩坑点

| 坑点 | 说明 | 正确做法 |
|------|------|---------|
| 初始化错误 | 最小长度初始化为 0 会导致结果永远为 0 | 初始化为 `float("inf")` 或 `INT32_MAX` |
| 收缩逻辑 | 写成 `if` 而不是 `while`，漏掉继续压缩的机会 | 必须用 `while` 持续收缩 |
| 忽略前置条件 | 忽略数组元素全为正数的前提，错误套用模板 | 先确认数组是否全为正数 |
| 返回值处理 | 忘记判断是否找到解，直接返回 min_len | 检查 `min_len != float("inf")` |

## 三种思路对比总结

| 思路 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|-----------|-----------|---------|
| 暴力解法 | O(n²) | O(1) | 仅用于理解题意 |
| 滑动窗口 | O(n) | O(1) | 最优解，推荐使用 |
| 前缀和 + 二分 | O(n log n) | O(n) | 备选方案，需额外空间 |

## 核心模板记忆

```python
# 滑动窗口模板（同向双指针）
def sliding_window(nums, target):
    left = 0
    total = 0
    result = float("inf")
    
    for right in range(len(nums)):
        # 1. 扩展窗口
        total += nums[right]
        
        # 2. 收缩窗口（核心！用 while 而非 if）
        while total >= target:
            # 3. 更新答案
            result = min(result, right - left + 1)
            # 4. 收缩左边界
            total -= nums[left]
            left += 1
    
    # 5. 处理无解情况
    return result if result != float("inf") else 0
```

**关键口诀**：右扩左收，条件满足时持续收缩，用 `while` 不用 `if`。

## 🧠 深度理解：滑动窗口的本质（重要！）

> **本节记录了对滑动窗口算法的深层思考，建议在掌握基本写法后再阅读。**

### 一、形象类比：捕虫网模型 🕸️

想象一根**可伸缩的捕虫网**：

| 场景 | 对应 LC209 |
|------|-----------|
| `right` | 网的右端，一直往右走，不断把虫子（数字）兜进网里 |
| `left` | 网的左端；当网内总和达标，尝试收缩左边，看能不能把网缩得更小 |
| 目标 | 抓住满足条件的**最小网宽度** |

```
        🕸️ 捕虫网 🕸️
    ┌─────────────────┐
    │  2 │ 3 │ 1 │ 2 │ 4 │ 3 │  ← 数字（虫子）
    └───┴───┴───┴───┴───┘
     ↑                   ↑
    left               right
    
    右边界向右扩张 → 网变大 → 虫子变多（总和变大）
    左边界向右收缩 → 网变小 → 虫子变少（总和变小）
```

### 二、核心疑问：凭什么能全覆盖？

**关键前提**：数组所有元素 > 0（题目硬性条件）

#### 推论 1：固定 right，left 右移只会更优

当窗口 `[left, right]` 满足条件时：
- 任何 `left' > left` 的区间 `[left', right]`
- 区间长度更短，总和**更小**（因为拿走了正数）
- 👉 所以一旦满足条件，立刻尝试右移 `left`，寻找同一下标 `right` 下更优（更短）的解

#### 推论 2：right 不需要回退

- 暴力：`i` 变了，`j` 重新从 `i` 出发
- 滑动窗口：`left` 和 `right` 只会单向往前走，绝不回头

**为什么可以不回头？**
- 假设对于起点 `i0`，最优右端点是 `r0`
- 当起点变成 `i1 = i0 + 1`
- 新的最优右端点 `r1` 一定 ≥ `r0`，不可能比 `r0` 更小

**直观理解**：
```
i=0，找到满足条件最小右端到 j=3
当 i=1，你不可能在 j<3 的位置凑出目标和
（因为少了一个正数 nums[0]，总和只会变小）
👉 因此 right 不需要重置，保证 O(n)
```

### 三、本质：单调性剪枝 💡

**算法本质**：暴力枚举的优化，依靠单调性消除指针回退

```
单调性质（充要条件）：
  窗口右边界向右扩展 → 指标单调不减
  窗口左边界向右收缩 → 指标单调不增

只要满足这个单调性，就可以用滑动窗口！
```

### 四、为什么负数会失效？

**反例**：`nums = [2, -1, 2], target = 3`

有负数时：
- 左边界右移（丢掉左侧数字），总和**不一定变小**，有可能变大
- 单调性消失，"右边界不用回退"这条推论直接失效

```
有负数时的混乱场景：
  [-1, 4], target=4
  left 右移，总和增减不再具备稳定单向趋势
  → 推论 1 和 2 全部崩塌
  → 算法失效
```

### 五、抽象适用条件（重要！）

**滑动窗口模板适用的严格条件**：

```
设窗口 [l, r]：
  区间向右扩大（r+1）：总和单调不减
  区间左边界收缩（l+1）：总和单调不增

👉 只要满足这个单调性，求最短满足条件连续子区间
   都可以用这套滑动窗口模板！
```

**不局限于"数字相加"**：
- 可以自定义指标，只要指标具备单调特性
- 例如：子数组的最大值、最小值、平均值等

**两个容易忽略的限制**：
1. 必须是**连续子数组**，不连续子集不能用
2. 模板目标是**求最短区间**，如果问题变成求最长，逻辑要反过来

### 六、两种滑动窗口区分 ⚠️

| 类型 | 代表题目 | 底层逻辑 |
|------|---------|---------|
| **同向滑动窗口** | LC209 | 依靠单调性，指针不回退 |
| **另一类窗口** | LC3 无重复最长子串 | 底层单调性逻辑不同，不能套用 |
| **相向双指针** | LC977 有序数组的平方 | 独立模型，不要混淆 |

### 七、极简内化总结 📝（四层递进结论）

> **第一层：算法本质 → 比暴力强在哪？**
> 滑动窗口不是全新魔法，是暴力枚举的优化版。
> - ✅ 正确：利用单调性砍掉「指针回退」和「重复扫描」，O(n²) → O(n)
> - ❌ 脑补误区：以为滑动窗口和暴力是两套完全不同的算法，没有同源关系

> **第二层：成立基石 → 凭什么能不回退？**
> 扩大窗口 → 指标单调不减；收紧左边界 → 指标单调不增
> - ✅ 正确：正数数组（全 > 0）天然满足这条性质，是算法生效的充要条件
> - ❌ 脑补误区：只要是「连续子数组题」就能用，不管里面有没有负数

> **第三层：失效红线 → 哪些题直接不能套？**
> 数组一旦包含 0 或负数，单调性立刻崩塌，推论全部失效
> - ✅ 正确：遇到负数立即换思路（前缀和 + 二分 / 分治 / 其他）
> - ❌ 脑补误区：先硬写出来「跑一下再说」，往往有测试用例过不了还不知道根因在哪

> **第四层：名字的真相 → "滑动窗口"到底是什么？**
> 这四个字只是工具形态的描述（像一根可伸缩的网）
> - ✅ 正确：底层是「单调性剪枝」，**先有单调性质，后有窗口工具**
> - ❌ 脑补误区：先有"滑动窗口"四字套路，看到连续子数组就往上面硬套

### 八、常见思维误区：`if` vs `while` 的隐藏认知漏洞

> **本节记录了初学者极易陷入的一个隐性 bug：理论正确，但执行模型残缺。**

#### 现象：为什么你觉得"和代码对不上"？

很多同学（包括曾经的你）在理解滑动窗口时，会在脑子里**脑补一条额外规则**：

> "找到合法窗口后，左指针只移动一格，然后继续推进 right。"

这条规则在教材、推导中**从来不存在**，但它会在你模拟执行时造成困惑。

#### 两层认知的分离（关键！）

| 层级 | 内容 | 典型状态 |
|------|------|---------|
| **顶层理论** | 单调性 ⇒ right 永不回退 | ✅ 容易掌握 |
| **下层执行** | 固定 right 时，必须用 `while` 持续收缩直到不合法 | ❌ 容易脑补为 `if` 只收缩一次 |

#### 具体漏洞对比

```
❌ 脑补版本（if 单次收缩）：
   right 前进 → 窗口合法 → left 移一次 → 停止收缩 → 继续 right

✅ 标准版本（while 持续收缩）：
   right 前进 → 窗口合法 → 进入 while 循环 → 每移一次记录答案
   → 直到窗口不再合法 → 跳出 while → 继续 right
```

#### 用反例看漏洞：`nums = [1,2,3,4,5]，target = 11`

- `right` 走到下标 4，窗口 `[0,4]` sum=12 ≥ 11
- **只收缩一次**：`left` 移到 1，窗口 `[1,4]` sum=11 ≥ 11 → 记录长度 4
- 但 `left` 移到 2 时 sum=9 < 11，长度 3 才是更优解 → **被漏掉了！**

#### 为什么当时没被发现？

这是典型的**"隐性认知 bug"**——文字上你写对了理论（单调性、指针不回退），但脑子里默默加了一条简化执行规则（左移一次就停）。

> **类比**：有人读懂"红灯停绿灯行"，但心里默默加了"绿灯只能走 3 步"。大规则没错，但自创的小规则会出问题。

#### 永久区分口诀

```
【单调性】解决：right 要不要回头（算法能不能优化到 O(n)）
【while 持续收缩】解决：针对当前 right，如何找到最短窗口
```

### 九、视角分水岭：锚左思维 vs 锚右思维

> **学滑动窗口跨不过去的坎：从"数组为主"切换到"窗口工具为主"。**

#### 两种思维模式对比

| 维度 | 锚左思维（暴力原始思路） | 锚右思维（标准滑动窗口） |
|------|------------------------|------------------------|
| **主体** | 数组本身 | 窗口（工具） |
| **视角** | 站在数组上，逐个挑选起点 | 手握伸缩窗口，数据依次流过 |
| **关注点** | 每个起点能延伸出什么区间 | 窗口内状态是否满足条件 |
| **思维方式** | 静态切割数组片段 | 动态操作流式数据 |

#### 直观感受

**锚左思维**：
> "我要遍历数组上每个起点 i，从 i 往后找满足条件的终点 j。"
> → 脑子里是一段一段独立的区间
> → 找到一个解，记录后起点右移，重新找新区间

**锚右思维**：
> "我手里有个捕虫网（窗口），数据从左到右流过。网内总和不够就往右扩张，够了就往左收缩。"
> → 窗口连续不断，元素只是短暂经过
> → 自然诞生：流入 → 检查 → 反复挤压

#### 为什么锚左思维很难自发想到收缩？

因为锚左思维把数组切成独立片段，找到一个解后天然想"切下一段重新来"。而窗口思维是**流式处理**——同一个元素可以持续留在窗口、也可以随时被剔除，状态连续变化。

> **训练建议**：刻意用"窗口工具为主"的语言描述算法，而不是"切割数组片段"的语言。

### 十、单调性的真正角色：窗口单向运动的通行证

> **单调性不只是"用来找最小"，而是整套扩张+挤压模型安全运行的前提。**

#### 单调性到底做了什么？

很多人误以为单调性的作用是"帮助找最短长度"。实际上它的作用更基础：

```
如果没有单调性：
  窗口收缩一次 → 你无法判断继续收缩还会不会满足条件
  窗口扩张一次 → 你无法判断需要不需要回退
  → 只能推倒重来，回到暴力 O(n²)
```

正数数组赋予的**强保证**：
```
窗口向右扩张 → 总和只会变大（不会变小）
窗口向左收缩 → 总和只会变小（不会变大）
```

这个保证让我们可以：
1. **一次性持续收缩**：从合法窗口一路缩到不合法，中间所有可能性一次性扫完
2. **右指针永不回退**：因为少了正数只会让总和变小，不可能在更左边的位置凑出目标

#### 单调性的三种用途（统一视角）

| 题型 | 扩张条件 | 收缩条件 | 单调性的作用 |
|------|---------|---------|------------|
| **LC209 最短满足条件** | 不够就右扩 | 够了就左收 | 保证右指针不回退 + 可以持续收缩到极限 |
| **LC3 最长无重复子串** | 不满足就右扩 | 满足就左收 | 同上（虽然指标不同，但都是"单调不减/不增"） |
| **LC1004 水果成篮** | 不够种类就右扩 | 超过种类就左收 | 同上 |

#### 抽象适用条件（最终版）

```
设窗口 [l, r]，指标 f(l, r)：
  r 右移一格 → f(l, r+1) 单调不减
  l 右移一格 → f(l+1, r) 单调不增

👉 满足这个单调性的连续区间问题，都可以用同向滑动窗口！
👉 不局限于"求和"，任何具备单调特性的指标都行（最大值、最小值、不同元素数等）
```

#### 两个重要限制

1. 必须是**连续子数组**，不连续子集不能用
2. 如果目标是**求最长**，逻辑反过来：条件不满足时扩张，条件满足时收缩

### 十一、三句话看透单调性（三层结论分层）⭐

> **本节是本节文档所有单调性讨论的收口总结，用三层递进回答：「单调性到底有多重要？」**

#### 第一层：没有单调性，**整套算法根本写不出来**

正数数组提供的单调性 = 两条无法替代的保证：

```
单调性质：
  右扩 → 总和只增不减
  左收 → 总和只减不增

┌─────────────────────────────────────────────┐
│ 保证 1：right 永不回头                       │
│   起点左移后，最优右端点只会不变或更靠右        │
│   → right 不需要重置                           │
├─────────────────────────────────────────────┤
│ 保证 2：while 可以持续收缩到极限              │
│   合法窗口 → 一路收紧到不合法                  │
│   → 中间所有长度一次性扫完，不用怀疑"会不会漏"  │
└─────────────────────────────────────────────┘
```

少了任何一条保证，都要退化成暴力 O(n²)。这两条保证就是这道题的**地基**。

- ✅ 正确理解：单调性是「算法存在」的前提，不是「算法优化」的附加品
- ❌ 脑补误区：以为「双指针结构」本身是核心，结构只是单调性的外在形态；结构没变、单调性没了，立刻出错

#### 第二层：单调性 = 暴力剪枝的工具 ⚡

```
暴力枚举：
  起点 i 每次前进一格 → j 都要从 i 重新出发
  = 每次都推倒重来，大量重复累加
  → O(n²)

滑动窗口（有单调性剪枝）：
  i 前进一格 → j 不用回头，最多在原地继续前进
  = 之前的工作成果全部保留，只砍掉「i 前进导致肯定不可能的前缀」
  → 总扫描量 n + n ≤ 2n = O(n)
```

你之前的感悟：「本质还是暴力，只是因为 left+1 后 right 不用回头了，不用循环了而已」——**这就是单调性剪枝最通俗、最精准的文字版**。

- ✅ 正确理解：`滑动窗口 = 暴力 + 单调性剪枝`（不是独立魔法，是暴力的高级进化形态）
- ❌ 脑补误区：「滑动窗口」四个字是一种凭空发明的新算法，和暴力没关系

#### 第三层：单调性 = 识别「这题能不能用滑动窗口」的指纹 🔍

以后拿到一道**连续子数组题**，不要先想「双指针怎么写」，先问自己三句话：

```
1. 我定义一个窗口指标 f(l,r)，指标是什么？（和 / 最大值 / 不同元素数 / 种类数 …）
2. r 右移一格，f 是不是单调不减？（或者至少不会反向摆动）
3. l 右移一格，f 是不是单调不增？

✅ 三个问题都答是 → 同向滑动窗口直接套用
❌ 任何一个不确定 → 先别写窗口，想其他思路
```

这就是你之后独立判断新题的依据，而不是凭「这题像 LC209」去套。

### 十三、一页速查表（复习专用） 📌

> 临考 / 复习时只需要看这一节，5 分钟覆盖所有关键点。

#### 🎯 适用前提（缺一不可）

| # | 前提 | 原因 |
|---|------|------|
| 1 | **数组元素全部是正整数**（不包含 0 和负数） | 保证单调性成立 |
| 2 | 求**连续子数组** | 不连续子集不能用 |
| 3 | 指标满足单调性（和、最大值、种类数的单调） | 否则 right 需要回退 |

#### 🧮 复杂度 + 保证

| 项目 | 数值 | 说明 |
|------|------|------|
| 时间 | **O(n)** | 每个元素最多进窗口一次 + 出窗口一次，总操作 ≤ 2n |
| 空间 | **O(1)** | 只开 4 个变量（start、end、total、min_len） |
| 完整覆盖性 | ✅ 枚举每个 right + 收紧到极限 | 所有合法区间都被考察过，不漏解 |

#### 📝 模板（3 句就能写出来）

```python
left = 0, total = 0, min_len = ∞

for right in range(n):             # ① 右扩
    total += nums[right]
    while total >= target:         # ② while 持续收缩（绝对不能是 if）
        min_len = min(min_len, right-left+1)  # ③ 记录答案
        total -= nums[left]; left += 1

return min_len if min_len != ∞ else 0   # ④ 处理无解
```

口诀：**右扩 → while 左收 → 无解判断**。

#### ❌ 三大脑补坑（考场必判）

| 坑点 | 后果 | 正确写法 |
|------|------|---------|
| ❌ 收缩写成 `if` 不是 `while` | 会漏一次收缩就合法的更优解（如 nums=[1,2,3,4,5] target=11 时长度 3 漏） | `while total >= target` |
| ❌ 有负数 / 0 硬套 | 单调性崩塌，right 不回退会丢正确区间 | 先判数组是否全正；不是就换前缀和二分 |
| ❌ `min_len = 0` 初始化 / 最后忘记判断 `min_len != ∞` | 结果永远为 0 或在无解时返回 ∞ 被判错 | 初始 `float("inf")`，最后三元判断 |

#### 🔍 识别指纹（看到就想到滑动窗口）

题目描述出现以下**任一组合**，直接触发滑动窗口思路：

```
① 连续子数组 + 和 / 种类 / 最值等指标
     + 指标有单调性质（正数和、窗口扩大只会更"复杂"等）
        → LC209 / LC3 / LC904

② 求"最短满足条件"或"最长满足条件"的长度
     + 扩大和收缩窗口时，合法性是单向变化的
        → 最短：合法就收缩；最长：不合法就扩张
```

这就是你以后独立判断新题的「套路检测器」。
