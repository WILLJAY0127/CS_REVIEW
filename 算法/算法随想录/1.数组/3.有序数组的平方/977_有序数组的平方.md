# 977. 有序数组的平方

## 📌 题目链接

[力扣题目链接](https://leetcode.cn/problems/squares-of-a-sorted-array/) | [代码随想录讲解](https://programmercarl.com/algo/array/0977-squares-of-a-sorted-array.html)

## 📋 题目描述

给你一个按 **非递减顺序** 排序的整数数组 `nums`，返回 **每个数字的平方** 组成的新数组，要求也按 **非递减顺序** 排序。

### 示例

```python
# 示例 1
输入: nums = [-4,-1,0,3,10]
输出: [0,1,9,16,100]
解释: 平方后，数组变为 [16,1,0,9,100]，排序后，数组变为 [0,1,9,16,100]

# 示例 2
输入: nums = [-7,-3,2,3,11]
输出: [4,9,9,49,121]
```

### 提示

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- `nums` 已按 **非递减顺序** 排序

## 🧠 核心思维转换

### 从暴力到最优的思维链条

#### 第一步：观察暴力方案存在什么浪费

```
nums = [-4,-1,0,3,10]
平方后：[16, 1, 0, 9, 100]

暴力做法：丢给排序算法 O(n log n)
但原始数组是有序的！暴力解法完全没有利用有序这个信息。
```

#### 第二步：分析有序数组平方后的分布规律

```
原数组升序：负数 ... 0 ... 正数

负数部分：越往左，数值越小，绝对值越大 → 平方越大
正数部分：越往右，数值越大 → 平方越大

结论：
- 平方之后，最小的值出现在中间
- 最大值只会出现在最左端 或者 最右端
```

#### 第三步：矛盾来了

```
题目要求输出：从小到大（升序）
但是我们能稳定拿到的数：从大到小

怎么解决？
新建一个结果数组，倒着存放。
```

#### 第四步：完整方案

```
left 左指针，right 右指针，k 指向结果数组末尾。
比较两端平方，更大的放进 res[k]，对应指针收缩，k -= 1。
```

## 🏆 擂台比武模型（直观想象版）

> **LC27 快慢指针、LC209 滑动窗口**，你能想象成「传送带、窗口」；
> 本题相向双指针，很难直观联想到传送带——**让我们换成「擂台比武」模型**！

### 核心条件回顾

```
原数组：非递减有序

性质：
  平方后的最大值 → 一定在左右两端
  平方后的最小值 → 藏在中间
  
  左端元素：[-4, -1, 0, 3, 10]
  绝对值：  4,  1,  0, 3, 10
  ← 左端比武选手              右端比武选手 →
```

### 擂台比武模型 🏆

```
想象一场比武大会：

    擂台                          领奖台
  ┌───────┐                    ┌─────────┐
  | 选手A |                    | 空位 k  |
  |(左端) |                    | ← 放最大 |
  └───┬───┘                    └─────────┘
      │ 比武!                    ↑
  ┌───┴───┐                    ┌─────────┐
  | 选手B |                    | 空位k-1 |
  |(右端) |                    | ← 放次大 |
  └───────┘                    └─────────┘

比赛规则：
1. 左右选手站在剩余区间两头
2. 比较谁的绝对值更大 → 胜者获得当前领奖台最后空位
3. 胜者所在一侧的指针向内收缩
4. 领奖台指针向左挪一格，继续比武
```

### 完整比武流程（nums = [-4,-1,0,3,10]）

```
回合  左端选手  右端选手  胜者     领奖台位置  结果数组
 1    | -4 |²=16  | 10 |²=100  🏆右端    k=4      [_,_,_,_,100]
 2    | -4 |²=16  |  3 |²=9    🏆左端    k=3      [_,_,_,100,16]
 3    | -1 |²=1   |  3 |²=9    🏆右端    k=2      [_,_,100,16,9]
 4    | -1 |²=1   |  0 |²=0    🏆左端    k=1      [_,100,16,9,1]
 5    |  0 |²=0   |  0 |²=0    🏆左端    k=0      [100,16,9,1,0]

最终结果：[0, 1, 9, 16, 100] ✅
```

### 代码实现对照

```python
def sortedSquares(nums):
    n = len(nums)
    result = [0] * n        # 领奖台
    k = n - 1               # 领奖台指针（指向最后空位）
    left, right = 0, n - 1  # 左右选手位置

    while left <= right:
        left_sq = nums[left] ** 2   # 左端选手实力
        right_sq = nums[right] ** 2  # 右端选手实力

        if left_sq < right_sq:      # 右端选手获胜
            result[k] = right_sq
            right -= 1              # 右端选手退场，下一位补上
        else:                       # 左端选手获胜（或平局）
            result[k] = left_sq
            left += 1               # 左端选手退场，下一位补上

        k -= 1                      # 领奖台空位前移

    return result  # 自然就是升序数组
```

## � 模型二：擂台比武法（双指针，推荐！）

### 核心思路

数组有序 → 平方后的**最大值一定在两端** → 可以从大到小收集 → 倒序填入结果数组

### 代码实现（带擂台注释版）

```python
def sortedSquares(nums):
    """擂台比武法：左右选手比武，胜者上领奖台"""
    n = len(nums)
    podium = [0] * n            # 🏆 领奖台（结果数组）
    k = n - 1                   # 领奖台指针，指向最后空位
    
    left, right = 0, n - 1      # 🥊 左右选手位置
    
    while left <= right:
        left_power = nums[left] ** 2    # 左端选手战斗力
        right_power = nums[right] ** 2  # 右端选手战斗力
        
        if left_power < right_power:    # 右端选手获胜 🏆
            podium[k] = right_power
            right -= 1                  # 右端选手退场
        else:                           # 左端选手获胜 🏆（或平局）
            podium[k] = left_power
            left += 1                  # 左端选手退场
        
        k -= 1                          # 领奖台空位前移
    
    return podium                      # 领奖台从左到右就是升序
```

### 代码对照速查表

| 擂台术语 | 代码变量 | 含义 |
|---------|---------|------|
| 擂台 | `left, right` | 左右选手位置指针 |
| 选手实力 | `left_power`, `right_power` | 平方值 |
| 领奖台 | `podium` | 结果数组 |
| 领奖台空位 | `k` | 结果数组当前填充位置 |
| 比武规则 | `if left_power < right_power` | 比较谁的平方更大 |
| 胜者领奖 | `podium[k] = winner` | 胜者上领奖台 |
| 选手退场 | `left += 1` 或 `right -= 1` | 指针收缩 |

### 执行过程（可视化）

```
nums = [-4, -1, 0, 3, 10]
       L              R
       ↓              ↓
选手:  [-4]  [0]  [3]  [10]
实力:   16   0    9    100
       ↓              ↓
       比武! 16 vs 100 → 🏆 右端胜!

回合1: 右端100上领奖台    podium = [_, _, _, _, 100]
                         left=0, right=3, k=3
                         
选手:  [-4]  [0]  [3]
实力:   16   0    9
       ↓         ↓
       比武! 16 vs 9 → 🏆 左端胜!

回合2: 左端16上领奖台     podium = [_, _, _, 100, 16]
                         left=1, right=3, k=2

...继续比武...

最终: podium = [100, 16, 9, 1, 0]
      反转? 不用! 自然升序返回即可 ✅
```

### 时间复杂度

- O(n)

## 🔑 双指针方案的硬性前提

### 成立条件（缺一不可）

1. **原始数组是升序有序的整数数组**
2. **平方之后，最大值一定出现在数组两端**

### 边界情况验证

```
# 情况一：有负数、有0、有正数
[-7,-3,2,3,11] → 平方后最大值在右端 ✅

# 情况二：全部负数
[-6,-5,-2] → 平方后最大值在左端 ✅

# 情况三：全部正数
[1,3,5] → 平方后最大值在右端 ✅

# 情况四：只有一个元素
[5] → 直接返回 [25] ✅
```

### ⚠️ 不适用场景

- **无序数组**：无法保证最大值在两端，双指针策略直接失效
- 如果数组无序，只能用暴力：平方 + 排序

## 🔄 为什么感觉脱节、像取巧？

### 三层原因分析

#### 原因一：普通人的思考习惯

```
总想从小到大构造答案
本能想：先找最小的，依次往数组头部填
但这道题很难快速找到最小值（最小值在中间）
```

#### 原因二：最优解法反直觉

```
最优解法：先从大到小收集，反向填充结果数组
思维方向反转，这就是最大的门槛
```

#### 原因三：思维链条更长

```
LC27 移除元素（同向快慢指针）：
筛选元素 → 两块重叠缓冲区 → fast 搜寻、slow 写入
思路顺着人的直觉走，门槛低

LC977 有序数组的平方（相向双指针）：
有序数组平方分布特性 → 极值在两端 → 只能优先获取最大值 → 必须反向构建结果数组
链条更长，任何一环没想到，思路就卡住
```

## 🔌 接口抽象

### 通用有序数组绝对值最大值接口

```python
def merge_sorted_abs(arr):
    """
    通用接口：有序数组的绝对值最大值排序
    
    参数:
        arr: 升序有序的整数数组
    
    返回:
        每个元素的平方组成的升序有序数组
    """
    n = len(arr)
    result = [0] * n
    k = n - 1
    left, right = 0, n - 1
    
    while left <= right:
        left_sq = arr[left] * arr[left]
        right_sq = arr[right] * arr[right]
        
        if left_sq < right_sq:
            result[k] = right_sq
            right -= 1
        else:
            result[k] = left_sq
            left += 1
        
        k -= 1
    
    return result
```

### 使用示例

```python
# 基本用法
nums = [-4,-1,0,3,10]
result = merge_sorted_abs(nums)
print(result)  # [0, 1, 9, 16, 100]

# 其他场景：平方、绝对值等
nums = [-7,-3,2,3,11]
result = merge_sorted_abs(nums)
print(result)  # [4, 9, 9, 49, 121]
```

## ⚠️ 常见错误（擂台事故）

| 错误 | 擂台术语 | 原因 | 解决方法 |
|------|---------|------|----------|
| 忘记创建结果数组 | 没搭建领奖台 | 直接在原数组上操作 | 必须创建 podium 数组 |
| 循环条件写成 `<` | 漏掉最后一场比赛 | 漏检最后一个选手 | 用 `left <= right` |
| 忘记处理 `left == right` | 平局选手漏赛 | 最后一个元素未处理 | 循环条件必须包含等号 |
| 结果数组顺序错误 | 领奖台方向反了 | 忘记倒序填充 | 从后往前填 k-- |

## 📝 总结

### 三层擂台理解

| 层次 | 内容 | 擂台术语 | 目标 |
|------|------|---------|------|
| **L1 实现层** | 暴力、双指针两种写法 | 学会比武规则 | 能正确写出代码 |
| **L2 思维层** | 极值在两端、反向填充 | 理解擂台布局 | 理解核心思想 |
| **L3 应用层** | 接口抽象 + 场景识别 | 识别何时开赛 | 判断何时适用 |

### 擂台比武核心要点

1. **适用前提**：数组有序 + 平方后极值在两端（选手必须分两端站位）
2. **核心矛盾**：能从大到小获取 → 但需要从小到大输出（领奖台要倒着搭）
3. **与其他双指针区别**：
   - LC27 快慢指针 = 传送带捡货（通用）
   - LC977 擂台比武 = 两头对打、胜者领奖（特化）
4. **思维门槛**：需要连续推理多个环节，链条较长

### 擂台口诀

```
有序数组平方后，极值藏两端
两端来比武，胜者上领奖
领奖台倒搭，结果自然升
```
