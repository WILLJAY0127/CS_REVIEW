# LeetCode 160 / 面试题 02.07 - 链表相交

## 📌 题目链接

[力扣 LC160 链接](https://leetcode.cn/problems/intersection-of-two-linked-lists/) | [代码随想录讲解](https://programmercarl.com/algo/linked-list/interview-02-07-linked-list-intersection.html)

## 📋 题目描述

给你两个单链表的头节点 `headA` 和 `headB`，请你找出并返回两个单链表相交的起始节点。如果两个链表不存在相交节点，返回 `null`。

### 题意核心前提（重中之重！）

| 前提 | 说明 | 不满足会怎样 |
|------|------|-------------|
| 相交 = **节点地址完全相同** | 不是 node.val 相等！ | val 相等但地址不同不算相交 |
| 形状是「Y」，不是「X」 | 相交之后所有节点**全部共用** | 不可能相交后又分开 |
| 链表无环 | 保证遍历会终止 | 有环会无限循环 |
| 不能修改链表结构 | 不能把两条链尾相连造环 | 会破坏原始链表 |

### 示例

```
# 示例 1（存在交点）
链表 A：  a1 → a2 ─┐
                    ├→ c1 → c2 → c3 → null
链表 B：  b1 → b2 → b3 ─┘

交点：c1（A 和 B 从 c1 开始节点地址完全一致）
```

```
# 示例 2（无交点）
链表 A：  1 → 2 → 3 → null
链表 B：  4 → 5 → null

返回：null
```

---

## 🧠 统一认知：所有解法的终极目标 = **对齐公共起点 c1**

```
链表 A：[ A 独立段 a ] + [ 公共段 c1→c2→c3 ]
链表 B：[ B 独立段 b ] + [ 公共段 c1→c2→c3 ]

问题本质：如何让两个指针同时踩到 c1？
         └─ 只要同时进入公共段，后续每一步位置永远相同
```

> 🔑 **核心公式**：两种解法都是「对齐 c1」，只是实现方式不同。
>
> - **长度对齐法**：主动计算差距，一次性抹平前置长度差（显性）
> - **往返双指针**：不计算差值，通过交换链表自动补齐前置差距（隐性）

---

## 思路 1：长度对齐法（推荐！符合直觉，首选掌握）

### 实现思路（三步走）

```
Step 1：分别算出 A、B 的长度 lenA、lenB
Step 2：如果 lenB > lenA，B 的指针先行 (lenB - lenA) 步
        → 反过来 A 先行同样的道理
        → 目标：两者距离 c1 的剩余步数完全一样
Step 3：同步前进，直到地址相等
```

### 代码实现（Python）

```python
from typing import Optional

class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None

class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> Optional[ListNode]:
        # Step 1：计算两个链表的长度
        lenA, lenB = 0, 0
        cur = headA
        while cur:
            lenA += 1
            cur = cur.next
        cur = headB
        while cur:
            lenB += 1
            cur = cur.next

        # Step 2：抹平长度差，长链表先行 gap 步
        pA, pB = headA, headB
        if lenB > lenA:
            gap = lenB - lenA
            for _ in range(gap):
                pB = pB.next
        else:
            gap = lenA - lenB
            for _ in range(gap):
                pA = pA.next

        # Step 3：同步前进，找同一个对象
        while pA and pB:
            if pA is pB:   # ⚠️ 比较地址，不能用 val！
                return pA
            pA = pA.next
            pB = pB.next

        return None
```

### 逐步骤模拟（存在交点场景）

```
A: a1→a2→c1→c2→c3 (lenA=5)
B: b1→b2→b3→c1→c2→c3 (lenB=6)
gap = lenB - lenA = 1

Step 2：pB 先行 1 步
  pA: a1
  pB: b2（已经消耗了多出的前置节点）

Step 3：同步前进
  第 1 步  pA=a1   pB=b2   ≠
  第 2 步  pA=a2   pB=b3   ≠
  第 3 步  pA=c1   pB=c1   ✅ 地址相同 → 返回 c1
```

### 直观理解

```
原来长度不一致：
A  [____][________]
B  [_______][________]
     ↑ a     ↑ c     长度不同 → 不同步进入 c 段

抹平差之后：
      pA  [____][________]
      pB     [_______][________]
            后面剩余长度完全一样 → 必然同时踩到 c1
```

## 思路 2：浪漫双指针 / 往返双指针（巧解，面试加分）

### 核心逻辑

指针 `pA` 走链表 A，走完就跳到 `headB` 继续走；
指针 `pB` 走链表 B，走完就跳到 `headA` 继续走；
两者速度一致，循环条件 `while pA != pB`。

### 数学上为什么必然相遇？

```
A 独立段长 a，B 独立段长 b，公共段长 c。

pA 总路程：a + c + b
pB 总路程：b + c + a
            ↓
      两段路程完全相等！
```

**两种结果**：

| 情况 | 结果 |
|------|------|
| 存在交点 | 同时踩到 c1 |
| 不相交 | 同时走到 null（此时也满足 pA == pB） |

### 代码实现（极简）

```python
from typing import Optional

class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None

class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> Optional[ListNode]:
        pA = headA
        pB = headB

        while pA != pB:
            # pA 走到末尾就切到 B，否则前进一步
            pA = pA.next if pA else headB
            # pB 走到末尾就切到 A，否则前进一步
            pB = pB.next if pB else headA

        return pA
```

### 场景 1：存在交点（完整行走路线）

```
A: a1→a2→c1→c2→c3 (a=2, b=3, c=3)
B: b1→b2→b3→c1→c2→c3

pA 路线：a1 → a2 → c1 → c2 → c3 → null → b1 → b2 → b3 → c1
        └───── A 全长 5 ─────┘    └──── B 独立段 3 ───┘
总路程 = 5 + 3 = 8  =  a + c + b = 2+3+3 = 8

pB 路线：b1 → b2 → b3 → c1 → c2 → c3 → null → a1 → a2 → c1
        └────── B 全长 6 ──────┘   └── A 独立段 2 ─┘
总路程 = 6 + 2 = 8  =  b + c + a = 3+3+2 = 8

→ 两者第 8 步同时踩到 c1，循环结束返回 c1。
```

### 场景 2：无交点（同时走到 null）

```
A: 1→2 (lenA=2)
B: 3   (lenB=1)
公共段长度 c=0

pA：1 → 2 → null → 3 → null
     └─ 2 步 ─┘  └─ 1步 ─┘  总计 4 步

pB：3 → null → 1 → 2 → null
     └─1步─┘  └──2 步──┘  总计 4 步

→ 同时走到 null，pA == pB，返回 null
```

### 为什么你会觉得双指针"怪异"？

| 维度 | 长度对齐法 | 往返双指针 |
|------|-----------|-----------|
| 对齐 c1 方式 | **显性**：先算差 → 砍掉前缀 → 人眼能直接看到对齐了 | **隐性**：交换链表继续走 → 数学上等价，但肉眼难直接看出 |
| 因果关系 | 动作 → 目标 直接挂钩 | 动作和目标隔了一层数学变换 |
| 考场复现 | 忘代码也能从「对齐 c1」推导出来 | 必须记住「切换链表」这步技巧 |

> 💡 **学习建议**：优先牢牢掌握「长度对齐法」，它和你的直觉模型完全同频。往返双指针当作巧解看懂即可。
> 面试时写出任一种都满分，优先写直觉最强、写不错的那版。

## 思路 3：哈希集合（暴力思路，仅理解用，面试别写）

### 思路

- 遍历链表 A，把每个节点 `add` 进 `set`
- 再遍历链表 B，第一个在集合内找到的节点就是交点

### 代码

```python
def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> Optional[ListNode]:
    seen = set()
    cur = headA
    while cur:
        seen.add(cur)
        cur = cur.next
    cur = headB
    while cur:
        if cur in seen:
            return cur
        cur = cur.next
    return None
```

### 缺点

额外空间 O(n)，不如前两个 O(1) 方案优雅。

## 📊 三种方案对比

| 方案 | 时间 | 空间 | 推荐度 | 特点 |
|------|------|------|--------|------|
| **长度对齐法** | O(n) | O(1) | ⭐⭐⭐⭐⭐ | 符合直觉，好复现，考试首选 |
| 往返双指针 | O(n) | O(1) | ⭐⭐⭐⭐ | 代码极短，面试加分巧解 |
| 哈希集合 | O(n) | O(n) | ⭐⭐ | 暴力好理解，额外空间不推荐 |

## ⚠️ 高频易错坑

| 坑 | 反例 | 正确做法 |
|----|------|---------|
| **❌ 用 val 比较是否相交** | A=[1,2,3] B=[1,2,3] 但地址不同，不算相交 | 用 `pA is pB`（对象身份），不要用 `==` 比较 val |
| **❌ 把链表尾接起来造环** | 题目明确说不能修改原结构 | 老老实实双指针 |
| **❌ 循环条件写成 `while pA.next != pB.next`** | 会跳过 c1 本身，导致漏 | 必须 `while pA != pB`，相等立刻返回 |
| **❌ 空链表不处理** | A=null、B=null 直接返回 null | 代码天然支持 null 比较安全 |

## 🧪 思考题

1. 如果两条链表其中一条**有环**，浪漫双指针方案还能用吗？
   - 答案：不能，会在环里无限死循环 → 先分别判断环 + 找环入口再判断是否相交

2. 为什么不需要 dummy？
   - dummy 解决「头结点可能被删 / 前驱不好找」问题；本题只遍历不修改，直接用原始头节点没问题

## 📝 核心口诀

```
链表相交不看值，地址相同才算遇。
                   
长度对齐先算差，长链先行消差距。
同步前进地址比，同遇即刻返回去。

浪漫双指针更酷：
你走我也走，到头换路走；
相遇即交点，同时 null 也作休。
```
