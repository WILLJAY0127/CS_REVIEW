## 思路 1：暴力解法（哈希集合 Set）✅ 能过、简单、保底

### 核心思路

环的特征 = **一定会第二次踩到同一个节点对象**。
第一次重复相遇的那个节点，就是环的入口。

### 代码（Python）

```python
from typing import Optional

class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None

class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        visited = set()
        cur = head
        while cur:
            if cur in visited:      # 第二次遇见 = 环入口
                return cur
            visited.add(cur)        # 第一次见，记录
            cur = cur.next
        return None                 # 走完了也没重复 = 无环
```

### 完整模拟（有环例子）

```
链：3 → 2 → 0 → -4
         ↑________↓

cur=3   visited={3}         add
cur=2   visited={3,2}       add
cur=0   visited={3,2,0}     add
cur=-4  visited={3,2,0,-4}  add
cur=2   2 in visited ✅   → return 2（环入口）
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 🧠 人脑零推导，面试紧张也写不错 | ❌ 额外空间 O(n) |
| 不需要考虑速度差、数学公式 | 达不到「进阶 O(1) 空间」考点 |
| 链表类查找暴力通用模板（和 LC160 暴力同构） | |

> 💡 **面试策略**：如果一时推不出快慢指针公式，先写 Set 版过面试，再说「我还可以优化空间到 O(1)，用快慢指针」。
> 写完有分、再秀进阶，比卡壳强太多。

## 思路 2：快慢指针（O(1) 空间，最优考点）

### 分两步执行

```
Step 1：判环 + 找相遇点
        slow 走 1 步，fast 走 2 步
        相遇 → 有环；fast 空 → 无环

Step 2：找环入口
        新指针 p = head
        p 和 slow 同步 1 步/次
        相遇位置 = 环入口
```

### ⚠️ 最重要的易错点

> ❌ **相遇点 ≠ 入环点！**
>
> 绝大多数人第一次学都会在这里翻车。快慢只是用来证明「有环」，给定位入口提供数学条件。

---

### 核心数学推导（决定第二步怎么写）⭐

#### 符号约定

```
   x                y
head → ── → 入环点 → ── → 快慢相遇点
                ↑              │
                └──── z ───────┘
                     (绕一圈回入环点)

x：head → 入环点 的步数
y：入环点 → 相遇点 的步数
z：相遇点 → 入环点（继续向前绕一圈）的步数
环长 = y + z
```

#### 先讲为什么是 2 倍关系

slow 一次走 1 格，fast 一次走 2 格，**相同时间内 fast 路程永远是 slow 的 2 倍**——这是后面所有等式成立的根基。

#### 完整推导（每一步等式性质都讲清楚）

```
slow 走过的总路程：x + y              （slow 进去环里刚走了 y 就被追上）
fast 走过的总路程：x + y + n*(y+z)    （n 是 fast 比 slow 多绕的整圈数，最少 n=1，可能 n=2、3...）
```

**第一步：列路程等式（2 倍关系）**

$$
2(x+y) = x + y + n(y+z)
$$

左边展开：$2x + 2y = x + y + n(y+z)$

**第二步：等式两边同时减掉 $(x+y)$（等式性质：左右减同一项仍相等）**

左边减 $(x+y)$：$2(x+y) - (x+y) = x+y$
右边减 $(x+y)$：$\big[x+y + n(y+z)\big] - (x+y) = n(y+z)$

得到：

$$
\boldsymbol{x + y = n(y+z)} \tag{中间式}
$$

**第三步：继续推到最终通用公式（把左边 y 移走）**

我们真正关心的是 x（头到入口），所以把 y 移到右边：

$$
x = n(y+z) - y
$$

对右边**拆一项出来**（核心技巧，把 $n(y+z)$ 拆成 $(n-1)(y+z) + 1(y+z)$）：

$$
\begin{align}
x
&= (n-1)(y+z) + (y+z) - y \\
&= (n-1)(y+z) + y + z - y \\
&= \boldsymbol{(n-1)(y+z) + z}
\end{align}
$$

#### ✅ 最终通用公式（所有情况都覆盖）

$$
\boldsymbol{x = (n-1) \cdot (环总长) + z}
$$

#### 公式翻译成代码直觉（分两种场景理解）

| 场景 | 公式简化 | 人话解释 |
|------|---------|---------|
| **n = 1（fast 只多绕 1 圈就追上，99% 面试题情况）** | **x = z** | head 到入口的距离  ==  相遇点继续向前回到入口的距离 |
| **n > 1（fast 多绕了好几圈才被慢指针跟上）** | $x = (n-1)圈 + z$ | 从相遇点出发的指针会先绕 $(n-1)$ 整圈（还在原地！），**最终还是再走 z 步到入口**，和从 head 走 x 步到入口**仍然同速同时到达** |

> 🔑 **为什么 n>1 时算法还能用？（很多教程没讲透）**
>
> 因为 $(n-1)(y+z)$ 是整圈数，一个指针在环里绕整数圈后位置完全没变！所以不管 fast 多绕了几圈，
> 只要从相遇点继续往前走 z 步的那个位置，**永远 = 从 head 走 x 步到的位置**。
>
> 所以代码实现上**完全不用管 n 的具体数值**，一套「head 指针 + 相遇点指针同速走」通吃所有有环场景。

#### 结论怎么落地成代码？

从 **head** 拿个指针 `p`（要走 x 步到入环），
从 **相遇点** 拿 slow 自己（要走 z 步，先走若干整圈不影响位置），
因为 $x = (n-1)(y+z) + z$，两者一步一步同步走 → **必然在入环点相撞**。

### 完整代码（Python）

```python
from typing import Optional

class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None

class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = head
        fast = head

        # =============== Step 1：找相遇点（判环） ===============
        while fast and fast.next:
            slow = slow.next            # 1 步
            fast = fast.next.next       # 2 步

            if slow is fast:            # 相遇 = 有环
                # ============= Step 2：对齐找入口 ==============
                p = head                # p 从头（要走 x 步）
                while p is not slow:    # slow 从相遇点（要走 z 步）
                    p = p.next
                    slow = slow.next
                return p                # x == z，必在入口相遇

        # fast / fast.next 为空 → 无环
        return None
```

### 完整模拟（题解官方示例）

**链表：`3 → 2 → 0 → -4 → (回 2)`，入环点 = 2**

```
Step 1：找相遇点
  起点  slow=3  fast=3
  1轮   slow=2  fast=0
  2轮   slow=0  fast=2
  3轮   slow=-4 fast=-4   ✅ 相遇在 -4

  此时对照图示：
    x = 1（head=3 → 入环点2）
    y = 2（入环点2 → 相遇点-4，步数：2→0→-4 = 2 步）
    z = 1（相遇点-4 → 入环点2，步数：-4→2 = 1 步）
    ❓ 这里 x=1，z=1，满足 x = z ✔️（n=1 结论成立）

Step 2：p=head(3)，slow=相遇点(-4)，同步前进
  1轮  p=2  slow=2   ✅ p == slow → return 2
```

**结果正确，入口就是节点 2。**

### 🧠 深度：为什么会想到这套解法？——算法设计的完整思考链路

这一节回答你最想问的：**不是"公式是什么"，是"人类是怎么想出这道题要这么解的"。**

#### 一、根源：单链表两大天生死限制，逼出这套数学解法

链表本身的结构约束，导致我们不能用最直观的朴素方案解决问题：

| 限制 | 说明 | 如果能突破会怎么做？ |
|------|------|-------------------|
| **单向不可逆** | 只有 `node.next` 往后走，**没有 prev 不能回溯** | 如果是双向链表：在相遇点标记，绕一圈计数/对比，轻轻松松找入口 |
| **环尺寸未知** | 入口在哪、环周长多少、x/y/z 的值**完全不可提前测量** | 如果允许先遍历算环长：一个指针先走 L 步、两指针同步找入口也行，但要多扫好几轮 |

> 正因为这两条限制，我们不能靠「遍历一次记录绝对位置」，只能依靠**指针步数差做相对运动推导**。

#### 二、先拆解我们要解决的两个子问题

```
问题 LC142 =  阶段 1 判环（有没有）
           + 阶段 2 已知有环，精准定位入口（难点！）
```

**阶段 1 判环：朴素方案 vs 最优方案**

- 朴素：用哈希集合存走过的节点，第二个重复出现就是有环 → 逻辑简单，空间 O(n) 不达标
- 最优：快慢指针（slow 1 步 + fast 2 步）→ 有环必相遇，空间 O(1) ✅

**阶段 2 定位入口：快慢指针相遇 ≠ 入口，三条路可选**

```
入口是 C，slow 和 fast 在 D 撞上 → D 不是 C，直接返回 D 就错
此时面临三条路：

① 粗暴哈希：从 head 开始遍历存 Set，第一个命中 = 入口
   ✅ 逻辑无脑简单
   ❌ 额外空间 O(n)，不是面试官要的最优解

② 先算环周长：从相遇点跑一圈计数得到环长 L
            → 一个指针从头先走 L 步，再和另一个从头指针同步走
            → 第一次相遇 = 入口
   ✅ 可行，逻辑上也不复杂
   ❌ 多扫一轮算环长，代码啰嗦，边界容易写错

③ ✅ 数学公式推导法（本题标准最优解）
   利用 fast 路程 = 2 × slow 路程，列方程化简得到：
   x = (n-1)环长 + z（通常 n=1 化简为 x=z）
   只需要：head 指针 + 相遇点 slow 指针，同速一起走，撞头 = 入口
   ✅ 空间 O(1)
   ✅ 不扫额外轮次，直接复用第一步相遇点结果
   ✅ 代码极简（就一个 while 同步走），逻辑自洽
```

#### 三、这套解法的 4 个核心设计目的（为什么选③而不是①②）

| 设计目标 | 具体做到了什么 |
|---------|--------------|
| **1. O(1) 常数级空间（面试官最看重）** | 只用 slow / fast / p 三个指针变量，不借助 Set / 数组 / 栈任何额外容器 |
| **2. 复用第一次遍历结果，扫描次数最少** | 第一步快慢遍历已经得到相遇点，不要浪费这条信息，直接基于它继续走，整体链表访问次数最少 |
| **3. 绕开环周长计算（规避易错代码）** | 不需要写「从相遇点循环一圈计数」的那轮循环，少写一段就少一段可能写错的边界 |
| **4. 统一极简代码范式** | 全流程只有指针移动 + `is` 比较，没有数值计算、没有计数器，逻辑高度自洽，手写代码出 bug 率极低 |

#### 四、用人话还原算法作者的完整思考过程

```
① 问题：如何在单链表（不能改结构、不能加标记）中检测环并找入口，且空间要 O(1)？
② 先解决判环：fast/slow 速度差，1 步 / 2 步，有环一定会在环内相遇。
③ 发现卡点：相遇点不等于入口啊！知道有环但不知道在哪进。
④ 那就把距离量化出来：列路程等式 fast 路程 = 2 × slow 路程。
⑤ 引入三段变量 x（头→入口）、y（入口→相遇）、z（相遇→入口）。
⑥ 代数化简：
     2(x+y) = x+y+n(y+z)
     → x+y = n(y+z)
     → x = (n-1)(y+z) + z
⑦ 发现神奇结论：head 到入口的距离 x，
   正好等于「相遇点绕 (n-1) 整圈 + 再走 z 步」。
   整圈数不影响位置，所以实际上就是走 z 步！
⑧ 落地成代码：一个从 head（走 x 步），一个从相遇点（绕整圈若干 + 走 z 步），
   同速一步一步走，第一次相撞就正好在入口点。
```

#### 五、一句话高度总结

> **因为单链表单向不可回溯、无法直接测量环的长度，并且我们要求不用额外存储空间，所以只能通过快慢指针的路程倍数关系做数学推导，最终设计出「先快慢判环相遇 → 再双同速指针碰头找入口」的经典方案。**

>
> - 链表查找类暴力 = **牺牲 Set 空间换无脑逻辑**

## 🧭 和 LC141 的关系

写 LC141（只判有没有环）可以直接写 Step 1 的循环：

```python
def hasCycle(self, head: Optional[ListNode]) -> bool:
    slow = head
    fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False
```
