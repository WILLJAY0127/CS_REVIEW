# LeetCode 19 - 删除链表的倒数第 N 个结点

## 📌 题目链接

[力扣题目链接](https://leetcode.cn/problems/remove-nth-node-from-end-of-list/) | [代码随想录讲解](https://programmercarl.com/algo/linked-list/0019-remove-nth-node-from-end-of-list.html)

## 📋 题目描述

给你一个链表，删除链表的倒数第 `n` 个结点，并且返回链表的头结点。

### 示例

```python
# 示例 1
输入: head = [1,2,3,4,5], n = 2
输出: [1,2,3,5]
解释: 删除倒数第 2 个节点 4

# 示例 2
输入: head = [1], n = 1
输出: []
解释: 链表只有一个节点，直接删除它

# 示例 3
输入: head = [1,2], n = 1
输出: [1]
解释: 删除倒数第 1 个节点 2，剩节点 1
```

### 提示

- 链表中结点的数目为 `sz`
- `1 <= sz <= 30`
- `0 <= Node.val <= 100`
- `1 <= n <= sz`
- **进阶**：你能尝试使用一趟扫描实现吗？

---

## 🎯 核心难点（三重挑战）

| 难点 | 说明 | 解决方案 |
|------|------|---------|
| **单向不能倒推** | 单链表只能向后遍历，无法从尾部往前找 | 快慢指针（双指针） |
| **一趟遍历** | 进阶要求不能先算长度再走 | 人为制造固定间隔 n |
| **可能删头节点** | 待删节点可能是第一个节点，前面没有前驱 | Dummy 虚拟头结点（必加！） |

> **先建立直觉**：这道题本质 = 「找倒数第 n+1 个节点（前驱）」+「删除它的后继」。
> 真正困难的是**定位前驱**，删除本身就是一行代码。

---

## 思路 1：先算长度，再删除（两趟遍历，理解用）

### 步骤

1. **第一趟**：遍历链表，算出总长度 `len`
2. **第二趟**：从头出发走 `len - n` 步，正好停在**前驱节点**，然后删后继

### 代码实现

```python
from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)   # 必须 dummy！删头节点用
        length = 0
        cur = head

        # 第一趟：计算长度
        while cur:
            length += 1
            cur = cur.next

        # 第二趟：走到前驱节点（共走 length - n 步）
        cur = dummy
        for _ in range(length - n):
            cur = cur.next

        # 删后继
        cur.next = cur.next.next

        return dummy.next
```

- **时间复杂度**：O(n)（但遍历了两遍）
- **空间复杂度**：O(1)

> 缺点：扫了两遍链表。进阶要求一趟，所以用快慢指针。

## 思路 2：快慢双指针（一趟扫描最优解，必掌握！）

### 核心思路

> **人为制造一个固定间隔 n+1，让 fast 先冲 n+1 步；之后两者匀速一起跑。fast 越过终点 None 的那一刻，slow 正好停在待删除节点的前驱。**
>
> 👉 先冲 n+1（不是 n）的核心原因：我们永远需要【前驱】才能删后继，fast 多走 1 步 = slow 最终少走 1 格，正好落在前驱。

### 核心变量

| 变量 | 含义 | 初始值 |
|------|------|--------|
| `dummy` | 虚拟头结点，焊死「永远有合法前驱」 | `ListNode(0, head)` |
| `fast` | 快指针，先冲 **n+1** 步（多走 1 格留前驱位） | `dummy` |
| `slow` | 慢指针，最终停在待删节点的前驱位置 | `dummy` |

> **为什么必须从 dummy 出发，不能从 head 出发？**
> 见后文「深度反例：起点从 head 出发不用 dummy 的后果」，极端 case（删头、删唯一节点）直接崩。

---

### 三步走（固定流程，死记这一套）

```
第一步：fast 先走 n+1 步，拉开固定间距（多走 1 步是留给前驱位）
第二步：fast、slow 同步同速前进，直到 fast == None 越过终点
        （两者每轮都走 1 步，间隔永远保持 n+1）
第三步：slow 的下一个就是倒数第 n 个节点
        直接 slow.next = slow.next.next 删除！
```

---

### 完整 Python 代码（可直接提交，标准版 ⭐）

```python
from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        # 造虚拟头，永远保证有前驱（删头节点不需要单独分支）
        dummy = ListNode(0, head)

        slow = dummy
        fast = dummy

        # ──────── 第一步：fast 先走 n+1 步（预留前驱位） ────────
        for _ in range(n + 1):
            fast = fast.next

        # ──────── 第二步：一起走到 fast 越过终点 None ────────
        while fast:
            fast = fast.next
            slow = slow.next

        # ──────── 第三步：slow 是前驱，删后继 ────────
        slow.next = slow.next.next

        return dummy.next    # 永远返回 dummy.next，不是 head！
```

- **时间复杂度**：O(n)（一趟扫描，满足进阶要求）
- **空间复杂度**：O(1)

```

  第 1 次：fast=1
```

## ⚠️ 高频易错点（4 个死亡陷阱，以标准版 n+1 步 + while fast 为基准）

| 陷阱 | 错误写法 | 正确写法（标准版） | 后果 |
|------|---------|-------------------|------|
| **起点错误** | `fast=head; slow=head` | `fast=dummy; slow=dummy` | 删头/删唯一节点时访问 None.next 崩溃 💥，或找不到前驱删不掉 |
| **走步数错误** | `fast 走 n 步`（少走 1 步） | `fast 走 n+1 步` | slow 最终落在**待删节点本身**而不是前驱，单链表没前驱就删不掉 ❌ |
| **循环条件错** | `while fast.next`（提前停） | `while fast`（冲到 None 才停） | 少走一轮，slow 停在前驱的前驱，删除节点错位 ❌ |
| **返回值错** | `return head` | `return dummy.next` | 删掉头节点时，head 已经是被删掉的野指针，返回直接错 ❌ |

> 💡 说明：市面上另一种等价合法写法是「fast 先走 n 步 + while fast.next」，本质和标准版完全一样，只是"间隔测量基准不同"。**只选一套死记，绝不能把 A 的走步数和 B 的循环条件混搭！**
>
> | 两种正确组合（都能跑） | fast 先走 | 同步条件 |
> |---|---|---|
> | 推荐标准版（本文） | **n+1 步** | `while fast` |
> | 另一种合法版 | **n 步** | `while fast.next` |

## 🧠 深度理解：快慢指针把「倒数问题」转成「正数定位」⭐

### 一、本质：单向链表的短板 + 等价转换

单链表只能**从头到尾单向遍历**，没办法从尾巴倒着走。
所以「倒数第 n 个」这种问题对单链表来说是天然不友好的。

**底层数学拆解：**

```
设链表总长度 = L（不含 None）
倒数第 n 个  =  正数第 (L - n + 1) 个

暴力两趟扫描 =  第一遍遍历算出 L
                第二遍从头走 (L - n) 步到前驱（正数第 L-n 位）

快慢指针一趟扫描 =  用两个指针的「固定距离差」代替「先算长度」
                   不靠 L 这个数，靠位置差直接锁目标
```

你说的完全正确：**快慢指针 = 把「倒数定位」等价转换为「正数位置锁定」，只扫一趟完成。**

---

### 二、标准模型（推荐掌握这一套，不要再混搭）：快慢双指针 + 虚拟头结点

#### 为什么必须有 dummy？（反复强调：不是锦上添花）

单独删除**原头节点**时（比如 `[1], n=1`、`[1,2], n=2`），要修改的就是 head 本身。如果没有 dummy 统一逻辑，你必须写 `if` 分支单独处理，极端场景极易写崩（比如访问 None.next）。

dummy 就是把「我永远有前驱」这个前提焊死。

#### 指针规则（固定间距 **n+1**）

| 规则 | 说明 |
|------|------|
| 起点 | **fast、slow 全部从 dummy 出发** |
| 第一步 | fast 先走 **n+1** 步，和 slow 拉开固定间距 |
| 第二步 | fast 和 slow 同速一步一步往后走，**直到 fast == None** |
| 第三步 | slow 此时正好停在「待删除节点的前驱」，执行 `slow.next = slow.next.next` |
| 返回值 | `return dummy.next`（永远别返回 head！） |

> **为什么是 n+1，不能是 n？**
> 
> 因为：我们最终的目标不是定位【待删除节点本身】，而是定位【待删除节点的前驱】。
> 
> 单链表删节点必须通过前驱才能改 `next` 指针，永远找不到前驱就删不掉。
> fast 多走 1 步，slow 最终就会**少前进一格**，正好落在前驱位置。
> 
> - fast 走 n 步 → slow 最终落在【待删节点本身】→ ❌ 找不到前驱，删不掉
> - fast 走 n+1 步 → slow 最终落在【待删节点前驱】→ ✅ 能执行删除

### 三、标准代码（先走 n+1 步 + while fast，组合 B 标准版）

```python
from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        # 虚拟头节点：焊死「永远有合法前驱」这个前提
        dummy = ListNode(0, head)
        slow = dummy
        fast = dummy

        # ── 第一步：fast 先走 n+1 步，拉开固定间距 ──
        for _ in range(n + 1):
            fast = fast.next

        # ── 第二步：同速走到 fast 撞线（None） ──
        while fast:
            fast = fast.next
            slow = slow.next

        # ── 第三步：slow 是前驱，删后继 ──
        slow.next = slow.next.next

        return dummy.next
```

#### 正确手动模拟：head = [1,2,3,4,5], n = 2 ✅（已逐行验证）

```
目标：删除倒数第 2 个 = 节点 4

初始：dummy → 1 → 2 → 3 → 4 → 5 → None
      slow=dummy, fast=dummy

═══════════════════════════════════════════════
第一步 fast 先走 n+1 = 3 步：
  第 1 次：fast = 1
  第 2 次：fast = 2
  第 3 次：fast = 3
  当前：fast=3, slow=dummy（间距 = 3 格）

═══════════════════════════════════════════════
第二步同步走 while fast：
  轮 1：fast 非空（3）→ fast=4, slow=1
  轮 2：fast 非空（4）→ fast=5, slow=2
  轮 3：fast 非空（5）→ fast=None, slow=3
  轮 4：fast 是空 → 退出

  slow=3 ✅ 正好是节点 4 的前驱节点！

═══════════════════════════════════════════════
第三步删除：
  slow.next = slow.next.next
  → 3.next = 4.next = 5   →   3 直接连 5

最终：dummy → 1 → 2 → 3 → 5 → None  ✅ 正确
```

#### 两个极端边界验证

- **Case [1], n=1**：fast 走 2 步到 None → 同步 while fast（立即退出）→ slow=dummy，`dummy.next=None` ✅
- **Case [1,2], n=2**：fast 走 3 步到 None → 同步 while fast（立即退出）→ slow=dummy，`dummy.next=2` ✅

两种极端场景（删唯一节点、删头节点）一套逻辑全覆盖，**不需要任何 if 分支**。

### 四、两种正确组合（防止交叉混搭出 bug）

> 💡 先记住：**市面上快慢指针有两套合法写法，区别只是"快多少步"和"走到哪停"，只要搭配对结果都正确。但选一套死记，绝不能交叉混用！**

| 组合 | fast 先走 | 同步循环条件 | slow 最终停在哪 | 对应文档版本 |
|------|----------|-------------|---------------|-------------|
| **B（推荐标准版 ⭐）** | **n+1 步** | `while fast` → 冲到 None 停 | ✅ 前驱（正好能删） | 本文标准代码 / 代码随想录 |
| A（另一种合法版） | **n 步** | `while fast.next` → 冲到最后一个节点停 | ✅ 前驱（正好能删） | 老版讲解 |

**错误混搭（直接出 bug）**：

| 错误组合 | 现象 |
|---------|------|
| ❌ 先走 n 步 + `while fast` | slow 多走一格，直接落在**待删节点本身**，删不掉 |
| ❌ 先走 n+1 步 + `while fast.next` | fast 还没到 None 就停，slow 少走一格，删除节点错位 |

> **记忆建议**：选组合 B 作为标准就好。**先冲 n+1 步 → 一起冲到 None**，直觉更好——"fast 过线那一瞬间 slow 的下一个就是目标"。

### 五、具象类比：🏃 跑步赛道模型（超好懂！）

```
赛道：起跑线（前一格 dummy）→ 1→2→3→4→5→撞线 None
队伍：所有节点站在赛道上排成一队，只能向前走，不能回头

两个人：slow（慢跑者）、fast（快跑者）
裁判命令：删除「距离终点线（None）倒数第 n 个人」

规则四步走：
① 两个人都站在起跑线前一格 dummy（不是第一个节点，是节点外的起点）
② fast 先冲出去，提前跑出 n+1 个人的身位（留 slow 多慢一格，正好定位前驱）
③ 之后两人同速向前，直到 fast 冲过终点线（撞到 None）才停下
④ 此时 slow 的下一个人，正好就是距离终点倒数第 n 个人！
   → 直接把这个人移出队伍（slow.next = slow.next.next）
```

用示例 1 套一下：

```
n=2，fast 先冲 3 个身位（n+1）
同速往前走，fast 冲过 None 时：
  slow 正好站在 3 号位
  slow 下一个 = 4 = 倒数第 2 个
  移出 4 → 正确 ✅
```

### 六、浓缩核心要点（5 句话）

```
① 单链表只能单向遍历，快慢指针用「固定距离差」把「倒数定位」转成「正数定位」，
   省掉第一遍遍历算长度。

② dummy 必须加：删除头节点、删唯一节点时，没有 dummy 就找不到前驱，
   会出现访问 None.next 崩溃，dummy 焊死「永远有合法前驱」这个前提。

③ fast 先走 n+1 步（不是 n）：多走 1 步保证 slow 最终落在前驱，
   这是单链表"只能通过前驱删后继"的结构决定的。

④ while fast：同步同速走到 fast 越过终点 None，
   此时 slow 的下一个就是待删节点。

⑤ 全程一趟扫描 O(L)，空间 O(1)，满足进阶要求。
```

### 七、反例再强调：起点从 head 出发（不用 dummy）的后果

「一般性场景能跑，但极端场景一定翻车」是不用 dummy 的最大陷阱：

```
✅ 一般情况 head=[1,2,3,4,5], n=2：
    从 head 出发，fast=1, slow=1
    fast 走 n+1=3 步到 4
    同步走到 fast=None，slow=3 → 也能正好删 4

❌ 反例 1：head=[1], n=1（删唯一节点）
    fast=1 走 2 步 = None，同步 while fast 退出
    slow=1，删除 slow.next（但 slow 本身就是要删的！）
    → 或者更直接：走 n+1 步时 fast=1 走第 2 步就访问 None.next 💥 崩溃

❌ 反例 2：head=[1,2], n=2（删头节点）
    fast=1 走 3 步 → 1→2→None→？走第 3 步访问 None.next 💥 崩溃
```

**结论**：dummy 不是"写着更漂亮"，是**能保证所有边界 case 都不崩的刚需**。

| **LC203 移除元素** | 删除多个指定值节点 | cur 单指针（站前驱，检查 cur.next） | ✅ 必须推荐 | 头节点可能被删除，缺前驱 |
| **LC206 反转链表** | 翻转所有节点指向 | pre+cur 双指针（pre 当虚拟前驱） | ❌ 不需要 | `pre=None` 天然就是最开头的"虚拟前驱" |
| **LC19 删倒数第 N 个** | 删除单个节点（可能是头）| fast+slow 快慢双指针（制造固定间隔） | ✅ 必须推荐 | 极端场景（删头、删唯一节点）无 dummy 直接报错 |

### 共性总结

```
只要你做的是「通过前驱删后继」这类操作 → 永远优先 dummy 统一逻辑
```

### dummy 是实体好还是逻辑好？

| 场景 | 替代"虚拟前驱"的方式 |
|------|-------------------|
| LC203 删除 | 只能用实体 dummy 节点（要保证永远有前驱删后继） |
| LC206 反转 | `pre=None` 就是逻辑前驱（只改 cur.next=pre，不用前驱"去删"） |
| LC19 倒数删除 | 只能用实体 dummy（删头节点时必须有前驱） |

> **判断口诀**：你的操作是不是「前驱.后继 = 前驱.后继.后继」这种跳跃删除？
> 如果是 → 必须有实体 dummy，否则极端场景找不到前驱。

## 📝 模板记忆（标准版 ⭐：先走 n+1 步 + while fast）

```python
def removeNthFromEnd(head, n):
    dummy = ListNode(0, head)       # ① 永远造 dummy，焊死前驱合法性
    slow = dummy
    fast = dummy

    for _ in range(n + 1):          # ② fast 先冲 n+1 步（多走1步预留前驱位）
        fast = fast.next

    while fast:                     # ③ 同步走到 fast 越过终点 None 才停
        fast = fast.next
        slow = slow.next

    slow.next = slow.next.next      # ④ slow 是前驱，删后继
    return dummy.next               # ⑤ 永远返 dummy.next，不是 head
```

**口诀**：**Dummy 起步、快冲 n+1 步、冲到 None 同速停、慢是前驱、删后继、返 dummy.next。**

> 💡 另一种等价速记（组合 A）：`Dummy 起步、快冲 n 步、fast.next 空就停、慢是前驱、删后继、返 dummy.next。`
>
> 两套都对，**选一套死记，不要混搭走步数和循环条件**。
