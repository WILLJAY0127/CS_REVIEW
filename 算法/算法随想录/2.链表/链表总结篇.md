## 一、链表理论基础速记（1 分钟过一遍）

### 1. 三种链表类型

| 类型 | 结构 | 特点 |
|------|------|------|
| **单链表** | 只有 `next` 指针，单向 | 面试 99% 考的是这个 |
| **双链表** | 既有 `next` 也有 `prev`，双向可走 | 某些特定问题极大简化（如 LRU） |
| **循环链表** | 尾节点 next 指回头节点，成环 | 约瑟夫环、环形问题 |

### 2. 内存存储方式

- **数组**：连续内存地址存储，可以用下标 O(1) 随机访问，但插删需要搬移元素 O(n)
- **链表**：节点**在内存中分散存放**，通过指针串联在一起，插删只需断链 O(1)，但查找必须从头遍历 O(n)

> 🧠 **选择口诀**：查多改少 → 数组；改多查少 → 链表。

### 3. 单链表节点结构（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val      # 节点值域
        self.next = next    # 指针域：指向下一个节点对象（不是值！）
```

**⚡ 最重要的认知：**
链表的「相等」比较分两种：
- `nodeA.val == nodeB.val` ：值相等（不算同一个节点！）
- `nodeA is nodeB` ：**地址 / 对象身份相等**（这才是同一个节点，判相交、判环入口、判相遇永远用这个）

## 二、虚拟头结点 Dummy：什么时候必须用？

链表操作的**第一大通用规律**。

### 1. 为什么要 dummy？

单链表操作当前节点，**必须找到它的前驱**才能做 `前驱.next = 新节点 / 前驱.next.next` 这种跨接。
但头节点**没有前驱**，每次遇到"可能操作头节点"的情况都要写 if 分支，极端场景还会访问 None.next 崩溃。

**dummy = 给头节点也伪造一个前驱出来，焊死「任何节点都有合法前驱」这个前提。**

```
原链表：head → 1 → 2 → 3 → None
加 dummy：dummy → head → 1 → 2 → 3 → None
          (dummy 永远存在，所以 1 也有前驱 dummy)
```

### 2. 一张表判断"用不用 dummy"

| 场景 | 操作本质 | 要不要 dummy？ | 对应题目 |
|------|---------|---------------|---------|
| 删除指定节点（可能删头） | 前驱.next = 后继 | ✅ **必须推荐** | LC 203、LC 19 |
| 通过前驱删后继 | 前驱.next = 前驱.next.next | ✅ **必须推荐** | LC 203、LC 19 |
| 反转链表 | 纯断链+调转方向 | ❌ 不需要 | LC 206 里 `pre=None` 就是天然虚拟前驱 |
| 遍历查找（不修改结构） | 纯遍历找相等 | ❌ 不需要 | LC 160 相交链、LC 141 判环 |
| 环形链表定位入口 | 纯指针移动，不修改结构 | ❌ 不需要 | LC 142 |

> 🔑 **判断口诀**：你写的代码里有没有出现「前驱.next = ...」这种跳跃？
> 如果有 → 基本都要 dummy；否则不需要。

### 3. dummy 模板代码（3 行通用）

```python
dummy = ListNode(0, head)  # 第 1 行：焊死前驱
# ... 在 dummy 之后的链上做任何操作 ...
return dummy.next          # 第 2 行：永远返回 dummy.next，不是 head！
```

**易错**：如果删除的就是 head 本身，`return head` 会返回一个已经被删掉的野指针，永远错。

### 题型 1：移除链表元素（LC 203）🎯

**🔍 场景**：删除链表中所有 `node.val == target` 的节点

**✅ 核心模板**：dummy + cur 站前驱，检查 cur.next

```python
def removeElements(head, val):
    dummy = ListNode(0, head)
    cur = dummy
    while cur.next:                  # 注意：检查 cur.next 不是检查 cur
        if cur.next.val == val:
            cur.next = cur.next.next  # 前驱跨过待删节点
        else:
            cur = cur.next
    return dummy.next
```

**⚠️ 易错**：删除后不要 `cur = cur.next`！删除后 `cur.next` 已经是新的下一个，要再检查一遍。

详细文档：[203_移除链表元素.md](./1.移除链表元素/203_移除链表元素.md)

---

### 题型 2：反转链表（LC 206）🔄

**🔍 场景**：把整个链表调转方向 `1→2→3→None` 变成 `3→2→1→None`

#### 版 A：迭代法（首选掌握，逻辑最直观）

```python
def reverseList(head):
    pre = None     # 工作台 A：已翻转段的尾指针（天然虚拟前驱，不需要 dummy 节点）
    cur = head     # 抓手：当前正在处理的节点
    while cur:
        tmp = cur.next   # 工作台 B：先保存还没处理的部分（防止断链）
        cur.next = pre   # 翻转当前节点的箭头
        pre = cur        # 更新工作台 A 的尾
        cur = tmp        # 抓手移到下一个要处理的
    return pre
```

**固定顺序口诀**：**先保后继 → 调转箭头 → pre 前移 → cur 前移**。顺序错一个就崩。
（类比：双工作台 + 三抓手搬家模型）

详细文档：[206_反转链表.md](./3.反转链表/206_反转链表.md)

### 题型 3：删除链表的倒数第 N 个节点（LC 19）⏳

**🔍 场景**：单链表单向不可逆，倒数第 N 个前驱无法直接靠倒推定位

**✅ 标准模板（推荐掌握这一套：先走 n+1 步 + while fast）**

```python
def removeNthFromEnd(head, n):
    dummy = ListNode(0, head)
    slow = dummy
    fast = dummy

    for _ in range(n + 1):            # ① fast 先冲 n+1 步（多走1格留前驱位）
        fast = fast.next

    while fast:                       # ② 同步走到 fast 越过终点 None
        fast = fast.next
        slow = slow.next

    slow.next = slow.next.next        # ③ slow 是前驱，删后继
    return dummy.next
```

**🧠 设计思路**：快慢指针固定间距 → 把「倒数定位」等价转换为「正数位置锁定」，一趟扫描 O(1) 空间。

**口诀**：**Dummy 起步、快冲 n+1 步、冲到 None 同速停、慢是前驱、删后继、返 dummy.next。**

详细文档：[19_删除链表的倒数第N个节点.md](./6.删除链表的倒数第N个节点/19_删除链表的倒数第N个节点.md)

### 题型 4：链表相交（LC 160 / 面试 02.07）🤝

**🔍 场景**：两条链尾合并（Y 型），找公共起点 c1；相交 = 地址相同不是 val 相同

#### 方案 A：长度对齐法（直觉首选，忘代码也能推）

```python
def getIntersectionNode(headA, headB):
    # Step1 算 lenA / lenB
    lenA = lenB = 0
    cur = headA
    while cur: lenA += 1; cur = cur.next
    cur = headB
    while cur: lenB += 1; cur = cur.next

    # Step2 长链表先吃掉差值
    pA, pB = headA, headB
    if lenB > lenA:
        for _ in range(lenB - lenA): pB = pB.next
    else:
        for _ in range(lenA - lenB): pA = pA.next

    # Step3 同步前进，比较地址
    while pA and pB:
        if pA is pB: return pA
        pA = pA.next
        pB = pB.next
    return None
```

#### 方案 B：A+B 拼接循环 / 往返双指针（代码极短，面试加分巧解）

```python
def getIntersectionNode(headA, headB):
    p, q = headA, headB
    while p != q:
        p = p.next if p else headB
        q = q.next if q else headA
    return p  # 有交点返回 c1，无交点返回 None
```

**🧠 数学支撑**：p 总路程 `a+c+b`，q 总路程 `b+c+a`，永远相等。有交点同时踩 c1；没交点同时到 None。

详细文档：[160_链表相交.md](./7.链表相交/160_链表相交.md)

### 题型 5：环形链表 I（LC 141）⭕

**🔍 场景**：只判断有没有环，返回 True / False

```python
def hasCycle(head):
    slow = fast = head
    while fast and fast.next:       # 无环 fast 先到 None 退出
        slow = slow.next            # 慢走 1
        fast = fast.next.next       # 快走 2
        if slow is fast: return True  # 环内必然相遇
    return False
```

> 原理：速度差 + 环 = 快的每轮距离慢的拉近 1 格，有环一定被追上。

### 题型 6：环形链表 II（LC 142）🔮

**🔍 场景**：判环 + 精准找环的入口节点（两阶段）

```python
def detectCycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next

        if slow is fast:                    # 相遇 = 有环
            # x = (n-1)环长 + z  →  同速走必在入口撞
            p = head
            while p is not slow:
                p = p.next
                slow = slow.next
            return p
    return None
```

**🧠 三步数学根基**（必须会讲，面试会问）：
1. `2(x+y) = x+y+n(y+z)`（fast 路程 = 2 × slow 路程）
2. 化简 → `x = (n-1)(y+z) + z`
3. 通常 n=1 → `x = z`，一个头指针 + 一个相遇点指针，同速走，撞头 = 入口。

详细文档：[142_环形链表II.md](./8.环形链表II/142_环形链表II.md)

## 四、双指针模型一张表：所有链表难题的设计模式

把链表双指针题拉通看，**本质全都是「设计指针移动规则，让它们同时踩到目标节点」**：

| 题目 | 目标节点 | 指针方案 | 数学支撑 |
|------|---------|---------|---------|
| LC 206 反转 | 每一个节点的前驱 | `pre` 虚拟前驱 + `cur` 抓手 + `tmp` 保后继 | 指针步骤不变量 |
| LC 19 删倒数 N | 倒数第 N 个前驱 | `fast` 先冲 n+1 步拉开间距 + `slow` 同速走 | 固定距离差 n+1 |
| LC 160 相交 | 公共起点 c1 | 长度对齐 / 交换链表继续走 | a+c+b = b+c+a |
| LC 142 环形 | 环入口点 | 快慢 1/2 判环 → 头 + 相遇点同速对撞 | x = (n-1)L + z |

> 🔑 **链表难题万能思考路径**：
>
> ① 目标节点是谁？（要删的？前驱？入口？交点？）
>
> ② 怎么通过「指针移动规则」设计，让**指针同时踩到目标节点**？
>
> ③ 如果长度不一致 → 想办法**抹平长度差**（手动对齐 / 交换链表 / 固定间距）。

## 五、高频易错死亡陷阱（TOP 8）

| 陷阱 | 常见错误 | 正确姿势 |
|------|---------|---------|
| 🔴 **比较用 == 不是 is** | `if pA == pB` 只比较了 val，地址不一样也会相等 | 链表节点判断永远用 `is`（对象身份比较） |
| 🔴 **删除/断链顺序反了** | 反转时写反了 `pre=cur; cur=tmp` 这两步，或者先丢了 `tmp=cur.next` | 严格按口诀：先保后继 → 调转 → 移 pre → 移 cur |
| 🔴 **需要 dummy 没加** | LC19/LC203 删头节点时直接访问 None.next 崩 | 只要写前驱删后继，第一反应先写 dummy |
| 🔴 **返回 head 不是 dummy.next** | 删除的正好是头节点，head 是已被删掉的野指针 | 永远 `return dummy.next` |
| 🔴 **LC19 快慢搭配混搭错** | 先走 n 步 + while fast → slow 多走一格删错 | 两套合法组合二选一记死：<br>① n+1 步 + while fast<br>② n 步 + while fast.next |
| 🔴 **相遇点当入口返回** | LC142 Step1 相遇就 return slow | 相遇点 ≠ 入口，必须 Step2 再同速对撞一次 |
| 🔴 **while fast.next.next** 没判两次空 | `while fast: fast = fast.next.next` → NPE | 标准写法 `while fast and fast.next:` |
| 🔴 **卡壳死磕最优解** | 面试紧张忘了快慢公式，还死耗 | 先写 HashSet 暴力版过了，再说"我还可以优化空间到 O(1)"→ 先拿分再秀 |

## 七、📊 跨章节容器总图：数组 vs 哈希表 vs 链表（回答：查找题为什么从来不用链表？）

> 👈 这就是你刷完哈希章 + 链表章后的直觉发问：
> 「好像查找、配对、判重题永远用数组或哈希表，为什么题目从来不让我『把数据先装进链表再查询』？链表题全是操作链表结构本身？」
> **一句话先给核心结论**：✅ 你的直觉 100% 正确。

### 🎯 核心定性

- **链表几乎不会作为「查找容器」使用**：永远不会「先把一批数据塞进链表，然后靠链表做查询/去重/计数/配对」
- **链表算法题 99% 都是「操作链表结构本身」**：反转、删节点、判环、找相交、合并有序链、断链重接……
- **查找场景的优先级永远是**：**数组哈希（值域小）> 哈希表 dict/set（值域大）**，链表从根本上就没进过这场比赛

### 一、为什么链表不能做查找容器？底层性能硬伤（3 张 O 对比一眼看懂）

| 数据结构 | 查某值 / 取第 k 个元素 | 为什么能做到？ | 对应本章/哈希章题目选型 |
|---------|-------------------|-------------|---------------------|
| **数组** | **O(1) 随机访问** | `arr[5]` = 基地址 + 5×单格字节数，CPU 一次寻址命中，不管数组 1 个元素还是 1000 万个 | ✅ 小范围值域做哈希：<br>[242 有效的字母异位词](../3.哈希表/1.有效的字母异位词/242_有效的字母异位词.md)、[383 赎金信](../3.哈希表/6.赎金信/383_赎金信.md)（26字母→[0]*26）<br>✅ 前缀和、二分查找、双指针、滑动窗口 |
| **哈希表 Dict / Set** | **平均 O(1) 查找** | 通过哈希函数把 key 直接定位到桶下标；极少冲突下常数次访问 | ✅ 存在判重/去重：[349 数组交集](../3.哈希表/2.两个数组的交集/349_两个数组的交集.md)、[202 快乐数](../3.哈希表/3.快乐数/202_快乐数.md)<br>✅ 键值映射/反向查：[1 两数之和](../3.哈希表/4.俩数之和/1_两数之和.md)（值→下标）<br>✅ 频次累加：[454 四数相加 II](../3.哈希表/5.四数相加II/454_四数相加II.md)（和→次数）|
| **单向链表** | **必须 O(n) 线性遍历** | 节点在内存中**分散存储**，没有基地址+偏移的寻址方式，找任何节点都必须从 head 一步步 .next 爬 | ❌ **链表不承担查找工作**。如果硬用链表存 454 的 25 万 A+B 的和，每次匹配要扫一遍链表 25 万步 → 总复杂度变成 n²×n = O(n³) ≈ 12.5 亿次，比 O(n⁴) 好一点但还是 TLE 爆炸，等于没优化 |

> 🔴 **补充：哪怕有序链表也没用！**
> 很多人会想："我把链表排好序能不能二分查找？"——**不能**。二分查找的核心是 `mid = (l+r)/2` 后**O(1) 直接跳转到中间节点**，链表没有随机访问，要到中间节点必须从头走 n/2 步——直接退化回线性遍历，二分的 O(log n) 优势全丢。

### 二、链表**真正**的两大使用场景（99% 的链表题都在这两块）

#### 场景 1：纯结构修改（最常见，本文件「三、六大经典题型」全覆盖）

> 核心优势：链表**插入/删除只需要改前后 2 个指针 O(1)**，不用像数组那样把后面的元素整个搬移 O(n)。
> 本质考的是「怎么断链 + 怎么重接」，完全不涉及查找效率。

你前面做过的 5 道链表题**全部在这一类**：
1. 反转链表（题型 2）：调转每个节点的 next 方向指针
2. 移除链表元素（题型 1）：跨过待删节点改前驱.next
3. 删除倒数第 N 个节点（题型 3）：找到前驱后改前驱.next.next
4. 两两交换节点（进阶题型）：每对节点互换前驱后继关系
5. 合并两个有序链表（归并排序基础）：两个链按大小拆节点重组成一个新链
6. 链表排序：利用链表 O(1) 插删做归并/快排

---

#### 场景 2：链表只是「被遍历的数据源」，配合哈希/快慢指针解题（这是链表+哈希唯一合法组合）

这是你可能会看到"链表和哈希一起出现"的少数题目，但**要分清主次**：
- **哈希表才是承担查找、判重、映射工作的工具**（核心职责）
- 链表只是负责**按链式关系一个个吐出节点让你处理的数据源**（结构载体）
- **绝对不会反过来：用链表做查找工具去查哈希产生的数据**

| 典型题目 | 具体怎么分工？ | 本仓库对应文档 |
|---------|--------------|------------|
| **环形链表判环 & 找入口** | 方案 A（纯链表操作）：快慢 1/2 指针同速追，看会不会撞（纯指针操作，无哈希）<br>方案 B（哈希保底版）：把**遍历过的节点地址**一个个塞进 `set`，遇到已存在的 = 环入口<br>👉 **set 干判重查找活，链表只负责顺着 .next 往外吐节点** | [142_环形链表II.md](./5.环形链表II/142_环形链表II.md) |
| **找两链表相交节点** | 方案 A/B（纯链表）：长度对齐法 / A+B 往返双指针（纯指针）<br>方案 C（哈希保底版）：先把链表 A 所有节点塞进 set，遍历链表 B 每遇到一个查 set 命中就是交点<br>👉 **set 干查找活，链表是两个待遍历数据源** | [160_链表相交.md](./4.链表相交/160_链表相交.md) |
| **复制带随机指针的链表**（扩展经典题）| 难点：每个节点除了 next 还有 random 指针，clone 后你得快速找到「原链表这个节点的 random 指向的原节点 → 对应的新克隆节点是谁」<br>👉 解决：`dict {旧节点对象: 新克隆节点对象}` 干映射查找活；链表只是两轮遍历建链的数据源 | 本仓库未收录，面试高频 |

### 三、三大基础容器分工总表（数组 / 哈希表 / 链表 一张图画清边界）

> 刷完数组基础 + 链表章 + 哈希章 6 题之后，这张表直接刻进脑子，从此不再纠结"这题到底用什么结构存"

| 维度 | 🟦 数组 Array | 🟥 哈希表 Dict / Set | 🟩 链表 Linked List |
|------|------------|-------------------|------------------|
| **查询/随机访问** | ✅ **头号擅长** O(1) | ✅ **平均 O(1)**，仅次于数组 | ❌ **O(n) 全面落后**，永远不承担查询职责 |
| **插入/删除（中间位置）** | ❌ 后面所有元素要整体搬移 O(n) | ✅ 平均 O(1)（dict/set 内部增删键很快）| ✅ **头号擅长** O(1)，只需改前后 2 根指针，不用搬移任何节点 |
| **空间内存特点** | 需要整块连续内存分配（值域大就爆）| 稀疏存储，只存实际出现过的键（454 只存 25 万条 vs 数组要 10 亿格）| 节点分散在内存任意位置，靠指针串联，无连续内存要求 |
| **最典型的算法题应用** | ① 小范围值域做哈希（26 字母）<br>② 前缀和数组、差分数组<br>③ 二分查找、双指针、滑动窗口 | ① 存在判断、去重：交集、快乐数、环入口<br>② 值→下标：两数之和<br>③ 值→出现次数：454 四数相加II<br>④ 旧→新映射：克隆随机链表 | ① 结构修改：反转、删除、合并、交换节点<br>② 链式数据源：配合快慢指针 / 配合哈希判环找相交 |
| **选型触发信号** | 整数小范围连续 / 必须用下标访问 / 前缀和 / 二分 / 双指针 / 滑窗 | 判存在 / 去重 / 频次统计 / 反向查下标 / 值域巨大稀疏 / 任意 key→value 映射 | **题目直接给了你 ListNode 结构**，让你改指针、断链、拼链、判环、找相交 → 不用想，肯定是链表算法 |

### 四、🔚 终极记忆口诀（一句话永不混淆）

> **查数据，用数组或哈希；改结构，才轮到链表。**

展开一下就是：
- 碰到「找元素 / 算次数 / 判重复 / 配对求和 / 反向映射下标」—— 第一反应永远是数组哈希（26 字母等小范围）或者 dict/set（大范围稀疏），**这辈子链表在查找场景连备选名单都进不去**
- 只有当题目**明明白白给了 `class ListNode` 定义**、让你处理 head 指针、删除节点、反转、断链重接、快慢指针追及、判环找交点—— 这时候才拿出本总结前面的「六大题型模板 / 双指针一张表 / dummy 规则」去套。

> 你的刷题直觉完全正确：
> 「链表题 = 操作链表结构本身；查找题 = 数组 or 哈希表做工具」
> 这是由它们底层内存分布和访问方式决定的**客观物理限制**，不是偏好问题。
