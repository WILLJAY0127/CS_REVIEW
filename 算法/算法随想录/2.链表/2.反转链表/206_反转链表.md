# LeetCode 206 - 反转链表

## 📌 题目链接

[力扣题目链接](https://leetcode.cn/problems/reverse-linked-list/) | [代码随想录讲解](https://programmercarl.com/algo/linked-list/0206-reverse-linked-list.html)

## 📋 题目描述

给你单链表的头节点 `head`，请你反转链表，并返回反转后的链表。

### 示例

```python
# 示例 1
输入: 1 -> 2 -> 3 -> 4 -> 5 -> NULL
输出: 5 -> 4 -> 3 -> 2 -> 1 -> NULL

# 示例 2
输入: 1 -> 2 -> NULL
输出: 2 -> 1 -> NULL

# 示例 3
输入: NULL
输出: NULL
```

### 提示

- 链表中节点的数目范围是 `[0, 5000]`
- `-5000 <= Node.val <= 5000`
- **进阶**：链表可以选用迭代或递归方式完成反转，你能否用两种方法解决这道题？

---

## 🎯 核心难点

| 难点 | 说明 |
|------|------|
| 单向遍历 | 单链表只能向后遍历，无法找到前驱 |
| 指针调转 | 需要把 `cur → cur.next` 改成 `cur → pre` |
| 防止断链 | 修改 `cur.next` 前必须先保存后继节点，否则后面的链表会丢失 |

直观理解：

```
原链表：  1  →  2  →  3  →  4  →  5  →  NULL
              ↓    ↓    ↓    ↓
反转后：  1  ←  2  ←  3  ←  4  ←  5  ←  NULL
```

**不需要重新建新链表！** 只修改每个节点 `next` 指针的指向即可，原地反转 O(1) 空间。

---

## 思路 1：迭代法（双指针，刷题最常用，优先掌握！）

### 核心变量

| 变量 | 含义 | 初始值 |
|------|------|--------|
| `pre` | 前一个节点（反转后 cur 应该指向它） | `None` |
| `cur` | 当前正在处理的节点 | `head` |
| `temp` | 临时保存 `cur.next`（防止改指针后断链） | 每次循环内定义 |

> **为什么 pre 初始为 None？** 因为原链表第一个节点（1）反转后变成尾节点，尾节点的 `next` 本来就应该指向 `None`。`pre=None` 天然充当了最开头的"逻辑前驱"。

### 形象类比：双工作台流水线模型 ⚙️

> **用工厂流水线的思路吃透 pre / cur / tmp 三个指针的身份，再也不会混。**
>
> 你自己提出的「双工作台 + 抓手」模型，是目前讲反转链表最形象、最不容易脑补错的版本。下面分两种抽象力度分别描述。

#### 模型一：三抓手具象版（最容易上手的初想）

##### 场景设定

```
┌──────────────────────┐           ┌──────────────────────┐
│  🛠️ 右侧原始待加工台   │           │  🛠️ 左侧反转成品台     │
│                       │           │                      │
│  1 → 2 → 3 → 4 → 5   │           │  （空）               │
│  ↑                    │           │  ↑                    │
│  cur                  │           │  pre                  │
│  (移动主抓手)         │           │  (成品台末端固定抓手) │
└──────────────────────┘           └──────────────────────┘
                                          ↑
                                      初始 pre = None
                                      （左边还没零件，抓手悬空）

第三只抓手 tmp = 保险抓手（防止右侧流水线断开，每次操作先锁好下一个物料）
```

三个抓手的身份一句话记死：

| 抓手 | 工作台 | 身份 | 初始状态 |
|------|--------|------|---------|
| **pre** | 左侧成品台 | 永远抓住「左侧已拼好链条的最后一个零件」（即成品台末端） | `None`（左边空） |
| **cur** | 两侧之间移动 | 「当前正在被处理的那一个零件」的主抓手 | 抓住右边第一个零件 1 |
| **tmp** | 右侧原始台 | **保险抓手**，每次处理前先牢牢抓住 cur 后面的零件，防止右侧整条流水线断料 | 循环开始时才伸出去 |

##### 完整流水线操作过程

原始右台：`1→2→3→4→5`，左台空：`pre=None`

```
━━━━━━ 第 1 次操作（加工零件 1）━━━━━━
① tmp 伸出去，抓住 cur（零件 1）后面的 2   → 把右侧剩余物料锁住
② cur 把零件 1 的卡扣反向扣向左侧 pre（空）→ 零件 1 落户左台
③ pre 抓手移动到零件 1                  → 左台末端标记更新为 1
④ cur 移交控制权，去抓 tmp 锁住的零件 2
  左台现在：1，右台剩余：2→3→4→5

━━━━━━ 第 2 次操作（加工零件 2）━━━━━━
① tmp 抓住 3                            → 锁住右台剩余 3→4→5
② 零件 2 卡扣反向扣住左台末端 pre（1）    → 2→1 落户
③ pre 挪到 2，cur 去抓 3
  左台现在：2→1，右台剩余：3→4→5

━━━━━━ 第 3 次操作（加工零件 3）━━━━━━
① tmp 抓 4  ② 3 扣住 2 → 3→2→1  ③ pre=3, cur=4

━━━━━━ 第 4 次操作（加工零件 4）━━━━━━
① tmp 抓 5  ② 4 扣住 3 → 4→3→2→1  ③ pre=4, cur=5

━━━━━━ 第 5 次操作（加工零件 5）━━━━━━
① tmp 抓 5 后面的空位 None（B 台要空了）
② 5 扣住 4 → 左台完整链条 5→4→3→2→1
③ pre=5, cur=tmp=None  →  🔚 机械手空手，循环停机
```

##### 四行代码翻译成流水线语言

```python
tmp = cur.next   # ① 保险抓手 tmp 先锁住下一个物料，防止右侧流水线断料
cur.next = pre   # ② 当前零件反向卡扣到左侧成品台的末端 pre
pre = cur        # ③ 左侧成品台末端抓手更新为刚装好的新零件
cur = tmp        # ④ 主抓手去 tmp 保险抓手那里，取下一个待加工零件
```

> **口诀**：**先保右台，再扣左台，左台更新，主手下一个。**

#### 模型二：双工作台 + 单机械手（更抽象，回答你的追问）

> **用户追问：能不能把 pre 和 tmp 直接抽成两个工作台，只有 cur 一个抓手？**
>
> 答案：**抽象层面完全成立**。两个工作台的"标记点"就是 pre 和 tmp，真正移动搬运的只有 cur 这个机械手。代码里三个变量不能少，是因为 tmp 承担"工作台 B 起点指针"的功能，不是语义上第三个角色。

##### 抽象映射表

| 抽象概念 | 代码变量 | 语义 |
|---------|---------|------|
| **工作台 A（成品台）** | `pre` | 放已反转好的链条，"标记点 pre" 永远指向 A 台链条的末尾节点 |
| **工作台 B（未加工台）** | `tmp` | 放剩下没处理的原始链条，"标记点 tmp" 永远指向 B 台链条的开头节点 |
| **唯一机械手** | `cur` | 每次从 B 台起点抓一个零件，装到 A 台链条末尾 |

```
┌──────────────────────┐           ┌──────────────────────┐
│  工作台 B（未加工）   │           │  工作台 A（成品）     │
│ tmp = 起点指针       │           │ pre = 末尾指针       │
│                      │           │                      │
│  2→3→4→5             │──cur──▶  │  1（刚装好）          │
└──────────────────────┘           └──────────────────────┘
           cur = 唯一搬运机械手
```

##### 双工作台复述完整流程（5 轮一致）

```
初始：B 台放整链 1→2→3→4→5，A 台空 pre=None

Step1（cur 从 B 抓 1）：
  tmp = 2 锁定 B 台剩余起点
  1 反向挂钩挂到 A 台末尾 pre（空）
  A 台：1，pre 更新为 1
  cur 走到 B 台起点 tmp = 2

Step2（cur 从 B 抓 2）：
  tmp = 3 锁定 B 台剩余
  2 挂钩挂到 A 台末尾 pre（1）
  A 台：2→1，pre 更新为 2
  cur=3

... 后续完全一样 ...

Step5（cur 抓 5，tmp=None 说明 B 台空）
  5 挂到 pre（4）  →  A 台完整 5→4→3→2→1
  pre=5, cur=None →  加工完毕，返回 A 台的头 pre
```

##### 🔥 为什么代码里绝对不能删掉 tmp？

这是你问的最有价值的一个边界问题，根因如下：

```python
cur.next = pre          # 这行执行之后 → cur 和后面的 B 台链表直接断开！
```

断开的瞬间，如果没有 tmp 在断开**之前**先把 `cur.next` 记下来：
- 工作台 B 的起点指针直接消失
- 所有未处理的零件 2、3、4、5 全部失联
- 下一轮循环 cur 根本不知道该去哪里抓下一个零件

> **一句话点破**：`pre` 是 A 台的"锚"，`tmp` 是 B 台的"锚"。**两个锚点都不能少，少一个整块工作台就消失了。**
> 代码层面 tmp 不能删，但语义上可以把它理解为「B 工作台的起点指针」。

##### 贴合双工作台的代码注释版（默写专用）

```python
def reverseList(head):
    # 工作台 A：已反转区域，标记 pre（A 台末尾指针）
    pre = None
    # 唯一机械手 cur，初始直接抓 B 台第一个零件（原始整链全在 B）
    cur = head

    while cur:
        # tmp = 工作台 B 的新起点指针，先锁牢剩余未加工部分！
        # （必须写在 cur.next=pre 之前，不然断开就找不到 B 台了）
        tmp = cur.next

        # 当前加工零件反向挂载到工作台 A 的末尾
        cur.next = pre

        # 工作台 A 的末尾指针更新为刚入台的新零件
        pre = cur

        # 机械手走到 B 台的新起点 tmp，抓取下一个待加工零件
        cur = tmp

    # A 台全部零件加工完毕，返回 A 台标记指针 pre（它就是反转后的头）
    return pre
```

### 循环不变式（固定四步走）

```
每一轮循环做 4 件事，顺序不能乱：

① temp = cur.next      ← 先把后继存起来！改指针就找不到了
② cur.next = pre       ← 调转方向：cur 不再指向后继，转而指向前驱 pre
③ pre = cur            ← pre 向前走一步，指向当前节点
④ cur = temp           ← cur 向前走一步，指向刚才保存的后继
```

**顺序口诀**：**存后 → 调向 → pre 走 → cur 走**

### 标准代码

```python
from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        pre = None          # 前一个节点，初始 = None
        cur = head          # 当前节点，初始 = 头

        while cur:
            temp = cur.next    # ① 先保存后继（关键！防止断链）
            cur.next = pre     # ② 反转：cur 指向前驱
            pre = cur          # ③ pre 前进到 cur
            cur = temp         # ④ cur 前进到刚才保存的后继

        return pre          # 循环结束 cur=None，pre 正好是新头！
```

- **时间复杂度**：O(n)（每个节点遍历一次）
- **空间复杂度**：O(1)（原地反转，只用了几个指针变量）

## 思路 2：递归法（理解即可，面试常问）

### 两种递归思路

| 递归方向 | 思路 | 难度 |
|---------|------|------|
| 从前向后翻转 | 和双指针法**逻辑完全一样**，只是把循环改成递归 | ⭐⭐ 易理解 |
| 从后向前翻转 | 先递归到尾部，再逐层返回时调转指针 | ⭐⭐⭐⭐ 略抽象 |

### 递归写法一：从前向后翻转（对应双指针）

本质就是把双指针的循环条件 + 更新步骤写成递归调用。

```python
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        # 和双指针法初始状态完全对应：
        #   双指针：pre=None, cur=head
        #   递归：调用 reverse(None, head)
        def reverse(pre: Optional[ListNode], cur: Optional[ListNode]) -> Optional[ListNode]:
            # 循环终止条件：while cur: → 改成 if cur is None: return pre
            if cur is None:
                return pre

            temp = cur.next           # ① 保存后继
            cur.next = pre            # ② 调转方向
            # ③ pre=cur  ④ cur=temp  →  直接作为下一层递归的参数
            return reverse(cur, temp)

        return reverse(None, head)
```

### 递归写法二：从后向前翻转（经典版本）

**思路**：
1. 一直递归到链表最后一个节点（它就是反转后的头节点 `new_head`）
2. 返回时逐层调转指针：`head.next.next = head; head.next = None`

```python
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        # 递归终止条件：空节点 或 只有一个节点，直接返回
        if not head or not head.next:
            return head

        # 第一步：先递归到尾部，拿到新头 new_head
        new_head = self.reverseList(head.next)

        # 第二步：返回过程中调转指针
        # 设当前节点 head，其后继是 head.next
        # 反转：head.next.next 指向 head 自己
        head.next.next = head
        # head 自身的 next 设为 None（防止循环引用）
        head.next = None

        # 新头一路向上传递，不改变
        return new_head
```

#### 递归过程图解：1 → 2 → 3 → NULL

```
第 1 层：head=1 → 还没反转，调用 reverseList(2)
第 2 层：head=2 → 还没反转，调用 reverseList(3)
第 3 层：head=3 → head.next is None → 返回 3（new_head=3）

━━━━━ 返回过程开始反转 ━━━━━
回到第 2 层（head=2, new_head=3）：
  head.next       = 3
  head.next.next  = head → 3.next = 2
  head.next = None        → 2.next = None
  局部：3 -> 2 -> None     返回 new_head=3

回到第 1 层（head=1, new_head=3）：
  head.next       = 2
  head.next.next  = head → 2.next = 1
  head.next = None        → 1.next = None
  全局：3 -> 2 -> 1 -> None  返回 new_head=3 ✅
```

- **时间复杂度**：O(n)（每个节点访问一次）
- **空间复杂度**：O(n)（递归调用栈深度为 n）

> **对比**：面试优先写迭代法（双指针），空间更优 O(1)。递归法主要用来考察你对递归的理解。

## 核心对比：LC203 移除链表元素 VS LC206 反转链表

> 这是两道链表入门题，但算法模型底层差别非常大，很容易混淆。

### 先建立两条结论

| 题目 | 核心诉求 | 最优工具 |
|------|---------|---------|
| **203 删除节点** | 安全修改后继指针；难点是头节点可能被删除 | Dummy 虚拟头结点 |
| **206 反转链表** | 逐个颠倒所有节点指针方向 | pre + cur 双指针 |

### 一、203 移除链表元素回顾

```
痛点：单向链表不能直接删当前节点，必须借助前驱执行：
  pre → target → next
  pre.next = next    完成删除

但如果要删的是头节点，前面没有前驱！
→ 用 Dummy 凭空造一个永久前驱，统一逻辑。
```

核心循环视角：**cur 是"前驱守护者"**，目光永远看向 `cur.next`（待检查节点）：

```python
# 203 核心循环
while cur.next:
    if cur.next.val == val:
        cur.next = cur.next.next   # 跳过后继（删后继）
    else:
        cur = cur.next             # 安全才前进
```

> 特点：**只修改别人的指针，不会改变 cur 自己和前面节点的关系。**

---

### 二、206 反转链表逻辑

```
任务：把 1→2→3→4→5 改成 5→4→3→2→1
本质：每一个节点的 next 箭头调转方向
  原始：cur → cur.next
  反转：cur ← pre
```

天然需要两个角色：
- `pre`：前一个节点（反转后 cur 应该指向它）
- `cur`：当前正在处理的节点

核心循环视角：**我站在当前节点，把自己转头看向身后的 pre**：

```python
# 206 核心循环
while cur:
    temp = cur.next      # ① 存后继
    cur.next = pre       # ② cur 转头看 pre
    pre = cur            # ③ pre 走到 cur
    cur = temp           # ④ cur 走到后继
```

> 特点：**直接修改 cur 自己的 next 指针，整条链表方向持续翻转，所有节点指针全部改动。**

### 三、为什么 206 不需要 Dummy？

| 题目 | Dummy 的作用 | 有没有天然替代品 |
|------|-------------|-----------------|
| **203 删除** | 头节点可能被删除，需要一个"永远安全的前驱" | 没有，必须造 Dummy |
| **206 反转** | pre=None 天然充当"最开头的虚拟前驱" | ✅ `pre=None` 就是！ |

> **Dummy 是实体节点**，反转完了你还要处理它，徒增工作量。反转链表 `pre=None` 就够了，行业里没人加 Dummy。

---

### 四、最关键视角差异（重中之重）

| 对比维度 | 203 删除链表 | 206 反转链表 |
|---------|-------------|-------------|
| **我的站位** | 站在前驱，观察身后的人 | 站在当前节点，转头看身后 |
| **修改对象** | 只改 `cur.next`（别人的指针），不动自己 | 改 `cur.next`（自己的指针） |
| **移动规则** | 只有确认身后安全，cur 才往前走 | pre 和 cur 同步每轮都前进 |
| **是否需要 dummy** | ✅ 推荐用 | ❌ 不需要 |
| **核心痛点** | 头节点可能被删除，缺前驱 | 防止反转时链表断裂，要先 temp 存后继 |

### 五、汇总表

| 题目 | 核心目标 | 指针模型 | 是否需要 dummy | 核心痛点 |
|------|---------|---------|--------------|---------|
| **203 移除链表元素** | 删除指定节点 | cur 作为前驱，操作 cur.next | ✅ 推荐 | 头节点可能被删除，缺少前驱 |
| **206 反转链表** | 翻转所有节点指向 | pre + cur 双指针，原地反转 | ❌ 不需要 | 防止链表断裂，必须临时保存后继 |

### 六、边界区分口诀

```
只要需求是【删除节点】→ 优先思考能不能用 Dummy 统一逻辑
只要需求是【原地翻转节点指针】→ 优先思考 pre + cur 双指针模型
```

### 延伸思考题（检验理解）

> **能不能强行给反转链表加 Dummy？**
>
> 答案：可以写，但完全多余。Dummy 是实体节点，反转结束你还要额外处理它和真实头节点的关系，代码反而更复杂。行业里没人这么写。

## ⚠️ 高频易错点

| 坑点 | 说明 | 正确做法 |
|------|------|---------|
| 没保存 `cur.next` 就改指针 | 直接 `cur.next = pre`，后继链表直接失联！ | 永远第一步：`temp = cur.next` |
| 返回 `cur` 而不是 `pre` | 循环结束时 `cur=None`，`pre` 才是新头节点 | 固定返回 `pre` |
| pre / cur 移动顺序搞反 | 先移 pre 再移 cur，顺序不能乱 | 记住：存后 → 调向 → pre走 → cur走 |
| `temp` 存错时机 | 调转方向之后才存 temp，存的就是 pre 了 | 调转方向**之前**必须存 |
| 递归中忘记 `head.next = None` | 会导致链表中出现循环引用 | 一定加：`head.next.next = head; head.next = None` |
| 反转链表强行加 Dummy | 代码复杂化，多此一举 | 直接 `pre=None` 起步 |

## 🧠 深度理解：指针不变量（核心 4 步的数学本质）

### 什么是"不变量"？

每轮循环开始和结束时，都保持一条不变的性质。反转链表的不变量是：

```
循环开始前：
  pre 已经指向反转完毕的那一段链表的头
  cur 指向还没处理的下一个节点

每轮循环处理完 cur 后：
  pre 成为了包含 cur 的新反转段的头
  cur 前进到下一个未处理节点
```

### 为什么 4 步顺序绝对不能变？

```
假设你乱序：先 cur.next=pre（第②步），再 temp=cur.next（第①步）
→ 此时 cur.next 已经是 pre 了，temp 存到的是 pre 不是原后继
→ 整条链表直接丢失！
```

**为什么要先 temp 存？** 因为一旦你写 `cur.next = pre`，`cur.next` 原来的值就被覆盖了。**单向链表没有回头路**，不提前保存就真的找不到后面的节点了。

### 类比大全对照：双工作台 / 搬家 / 三抓手 三套模型统一表

> 三套类比说的是同一套四步代码，只是视角不同。按需选最顺手的理解就行。

| 步骤 | 代码 | 🏭 双工作台（最强） | 📦 换房子搬家 | 🤖 三抓手 |
|------|------|------------------|-------------|---------|
| ① | `temp = cur.next` | tmp 锚点锁定工作台 B 的剩余起点（防止 B 台失联） | 先把新家地址写在**小纸条**上收好 | 保险抓手 tmp 先抓住 cur 后面的零件 |
| ② | `cur.next = pre` | 当前零件反向卡扣到工作台 A 末尾 pre | 把**旧家**的换方向（指向身后的旧家 / 新家前身） | cur 抓手转头，把零件反向扣向 pre 抓手的节点 |
| ③ | `pre = cur` | 工作台 A 末尾标记更新为刚装好的新零件 | 现在"我"搬到这家住（新家） | pre 抓手跟进，移到刚处理完的 cur 节点 |
| ④ | `cur = temp` | 机械手 cur 走到 B 台起点，抓下一个待加工 | 按照小纸条去找**下一家**处理 | cur 抓手移交，去 tmp 抓新的一个零件 |

三套模型的核心对应关系一览：

| 代码变量 | 🏭 双工作台 | 📦 搬家 | 🤖 三抓手 |
|---------|-----------|--------|---------|
| `pre` | 工作台 A 末尾指针（A 锚） | "我"现在所处的位置 | 成品台末端固定抓手 |
| `cur` | 唯一搬运机械手 | "我"（处理者） | 移动主抓手 |
| `tmp` | 工作台 B 起点指针（B 锚） | 小纸条上的地址 | 保险抓手 / 防止断链 |
| `cur.next = pre` | 零件挂到 A 台末尾 | 旧家方向调转 | 卡扣反向 |

> **推荐学习顺序**：先用「🏭 双工作台」搞懂谁是谁（工作台 + 一个抓手的抽象最贴合指针语义），再用「📦 搬家」当一句话口诀速记，最后「🤖 三抓手」作为细节补充防止混淆。

### 类比：换房子搬家

| 反转链表步骤 | 搬家类比 |
|-------------|---------|
| ① `temp = cur.next` | 先把新家地址写在小纸条上存好 |
| ② `cur.next = pre` | 把旧家的门锁方向换了（指向旧家） |
| ③ `pre = cur` | 搬到新家，现在"我"在新家住 |
| ④ `cur = temp` | 按照小纸条去找下一家处理 |

> 如果你不写小纸条（①），改完门锁（②）之后就找不到新家在哪了！

## 📊 三种解法对比总结

| 解法 | 时间复杂度 | 空间复杂度 | 推荐度 | 适用场景 |
|------|-----------|-----------|--------|---------|
| **迭代双指针** | O(n) | O(1) | ⭐⭐⭐⭐⭐ | 面试/刷题首选，原地反转 |
| 递归（前→后） | O(n) | O(n) | ⭐⭐⭐ | 理解用，和双指针一一对应 |
| 递归（后→前） | O(n) | O(n) | ⭐⭐⭐ | 面试考察递归思维 |

## 📝 模板记忆（迭代法）

```python
def reverseList(head):
    pre = None
    cur = head
    while cur:
        temp = cur.next       # ① 存后继（防断链！）
        cur.next = pre        # ② 调转方向
        pre = cur             # ③ pre 走
        cur = temp            # ④ cur 走
    return pre                # 返回新头
```

**关键口诀**：**存 → 调 → 双走**（先存后继、再调方向、pre/cur 同步前进）。
