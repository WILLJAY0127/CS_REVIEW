# LeetCode 19 - 删除链表的倒数第 N 个结点

## 📌 题目链接

[力扣题目链接](https://leetcode.cn/problems/remove-nth-node-from-end-of-list/) | [代码随想录讲解](https://programmercarl.com/algo/linked-list/0019-remove-nth-node-from-end-of-list.html)

## 📋 题目描述

给你一个链表，删除链表的倒数第 `n` 个结点，并且返回链表的头结点。

### 示例

```python
# 示例 1
输入: head = [1,2,3,4,5], n = 2
输出: [1,2,3,5]
解释: 删除倒数第 2 个节点 4

# 示例 2
输入: head = [1], n = 1
输出: []
解释: 链表只有一个节点，直接删除它

# 示例 3
输入: head = [1,2], n = 1
输出: [1]
解释: 删除倒数第 1 个节点 2，剩节点 1
```

### 提示

- 链表中结点的数目为 `sz`
- `1 <= sz <= 30`
- `0 <= Node.val <= 100`
- `1 <= n <= sz`
- **进阶**：你能尝试使用一趟扫描实现吗？

---

## 🎯 核心难点（三重挑战）

| 难点 | 说明 | 解决方案 |
|------|------|---------|
| **单向不能倒推** | 单链表只能向后遍历，无法从尾部往前找 | 快慢指针（双指针） |
| **一趟遍历** | 进阶要求不能先算长度再走 | 人为制造固定间隔 n |
| **可能删头节点** | 待删节点可能是第一个节点，前面没有前驱 | Dummy 虚拟头结点（必加！） |

> **先建立直觉**：这道题本质 = 「找倒数第 n+1 个节点（前驱）」+「删除它的后继」。
> 真正困难的是**定位前驱**，删除本身就是一行代码。

---

## 思路 1：先算长度，再删除（两趟遍历，理解用）

### 步骤

1. **第一趟**：遍历链表，算出总长度 `len`
2. **第二趟**：从头出发走 `len - n` 步，正好停在**前驱节点**，然后删后继

### 代码实现

```python
from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)   # 必须 dummy！删头节点用
        length = 0
        cur = head

        # 第一趟：计算长度
        while cur:
            length += 1
            cur = cur.next

        # 第二趟：走到前驱节点（共走 length - n 步）
        cur = dummy
        for _ in range(length - n):
            cur = cur.next

        # 删后继
        cur.next = cur.next.next

        return dummy.next
```

- **时间复杂度**：O(n)（但遍历了两遍）
- **空间复杂度**：O(1)

> 缺点：扫了两遍链表。进阶要求一趟，所以用快慢指针。

## 思路 2：快慢双指针（一趟扫描最优解，必掌握！）

### 核心思路

> **人为制造一个固定间隔 n，让 fast 先冲 n 步；之后两者匀速一起跑。fast 撞到终点 None 的那一刻，slow 正好停在待删除节点的前驱。**

### 核心变量

| 变量 | 含义 | 初始值 |
|------|------|--------|
| `dummy` | 虚拟头结点，保证永远有合法前驱 | `ListNode(0, head)` |
| `fast` | 快指针，先冲 n 步，用来定位终点 | `dummy` |
| `slow` | 慢指针，最终会停在待删节点的前驱位置 | `dummy` |

> **为什么 fast/slow 必须从 dummy 出发，不能从 head 出发？**
> 见后文「深度反例：起点不在 dummy 会发生什么？」

---

### 三步走（固定流程）

```
第一步：fast 先走 n 步，制造固定间隔
第二步：fast、slow 同步前进，直到 fast == None
        （两者每轮都走 1 步，间隔永远保持 n）
第三步：此时 slow 的下一个就是倒数第 n 个节点
        直接 slow.next = slow.next.next 删除！
```

---

### 完整 Python 代码（可直接提交）

```python
from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        # 造虚拟头，永远保证有前驱
        dummy = ListNode(0)
        dummy.next = head

        slow = dummy
        fast = dummy

        # ──────── 第一步：fast 先走 n 步 ────────
        for _ in range(n):
            fast = fast.next

        # ──────── 第二步：一起走直到 fast 到底 None ────────
        while fast:          # 注意：while fast，不是 while fast.next！
            fast = fast.next
            slow = slow.next

        # ──────── 第三步：slow 是前驱，删后继 ────────
        slow.next = slow.next.next

        return dummy.next    # 注意：返回 dummy.next，不是 head！
```

- **时间复杂度**：O(n)（一趟扫描）
- **空间复杂度**：O(1)

```
  第 2 次：fast = 2
  当前：fast=2, slow=dummy（两者距离=2）

  slow.next.next = 5
```

### 边界样例 1：head=[1], n=1（删唯一节点，极端情况）

```
初始：dummy → 1 → None
fast=dummy, slow=dummy

第一步：fast 走 1 步 → fast=1
第二步（同步 while fast）：
  fast = 1.next = None
  slow = dummy.next = 1
  循环退出（fast==None）

slow 现在 = dummy
slow.next = dummy.next = 1
slow.next = slow.next.next → dummy.next = None

结果：返回空链表 ✅
```

> **你看！** 如果没有 dummy，这里 head 就是唯一节点，它根本没有前驱，根本没法通过"前驱删后继"完成删除。dummy 直接拯救了这种极端场景。

```
  轮 1：fast=None, slow=1 → 退出
```

## ⚠️ 高频易错点（4 个死亡陷阱）

| 陷阱 | 错误写法 | 正确写法 | 后果 |
|------|---------|---------|------|
| **起点错误** | `fast=head; slow=head` | `fast=dummy; slow=dummy` | 见下文「反例」，slow 直接停在待删节点本身，拿不到前驱 |
| **走步数错误** | `fast 走 n+1 步` | `fast 走 n 步`（配合下文 while fast） | 多走一步，slow 多前移一格，可能删错 |
| **循环条件错** | `while fast.next` | `while fast` | 少走一轮，slow 停在前驱的前驱，删错节点 |
| **返回值错** | `return head` | `return dummy.next` | 删掉头节点时，返回的 head 已经是失效的野指针 |

> 走步数的另一种等价写法：代码随想录版本让 `fast` 先走 **n+1** 步，再 `while fast != None` 同步走。本质完全一样，只是间隔定义不同，不要搞混。**选一种记住，不要来回切换。**

### 两种正确的快慢指针组合（不能混搭！）

| 组合 | fast 先走 | 同步循环条件 | 最终 slow 位置 |
|------|----------|-------------|---------------|
| **A（用户版直观）** | **n 步** | `while fast.next`（fast 不是最后一个节点就走） | 正好在前驱 ✅ |
| **B（代码随想录版）** | **n+1 步** | `while fast`（fast 不是 None 就走） | 正好在前驱 ✅ |

> **选一个记住，不要把组合 A 的走步数和组合 B 的循环条件混在一起！**

#### 组合 A 代码（先走 n 步 + while fast.next）

```python
class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        slow = dummy
        fast = dummy

        # fast 先走 n 步
        for _ in range(n):
            fast = fast.next

        # 同步走，直到 fast 是最后一个节点（fast.next == None）
        while fast.next:
            fast = fast.next
            slow = slow.next

        slow.next = slow.next.next
        return dummy.next
```

#### 组合 B 代码（先走 n+1 步 + while fast）

```python
class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        slow = dummy
        fast = dummy

        # fast 先走 n+1 步（多走 1 步确保 slow 最终到前驱）
        for _ in range(n + 1):
            fast = fast.next

        # 同步走到 fast == None
        while fast:
            fast = fast.next
            slow = slow.next

        slow.next = slow.next.next
        return dummy.next
```

> 两种写法本质完全一样，只是"间隔的计算基准"一个从 dummy 内部量、一个从节点位置量。**选一个顺眼的记住就行。**

```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> **结论**：不用 dummy 在一般情况能跑，**但极端情况（删唯一节点、删头节点）必然翻车**。dummy 不是"锦上添花"，是**必须**。

### 最简比喻：跑道模型（好记！）

```
跑道：起点 dummy → 1 → 2 → 3 → 4 → 5 → 终点 None
两个人：slow，fast 都站在起点 dummy

规则：
① fast 先冲出去 n 个身位，提前跑
② 之后两人匀速一起跑
③ fast 撞线（到达 None / 或者 fast 跑不动看场景）立刻停下
④ 此时 slow 的下一步，就是倒数第 n 个节点

→ slow 本人就是前驱，慢 1 步正好！
```

### 延伸思考题（检验理解）

> **Q：如果我想让 slow 直接定位到【待删除节点本身】而不是前驱，fast 应该先走几步 + 什么循环条件？**
>
> 提示：此时 slow 少走 1 格即可。从前驱少前移 1 格等价于 fast 多走 1 格。
> 组合 A 改成：fast 先走 **n-1** 步 + while fast.next → slow 会正好停在待删节点本身
> 或者 fast 先走 **n** 步 + while fast → slow 也会停在待删节点本身（就是之前的"陷阱组合"）
>
> ⚠️ 但注意：就算你能定位到待删节点本身，**单链表还是删不掉它**，因为你找不到前驱！所以这种定位实际上没用，最后还得走回"找前驱"的路子。这就是为什么标准写法永远定位在前驱。

|------|---------|---------|-----------|---------|
| **LC203 移除元素** | 删除多个指定值节点 | cur 单指针（站前驱，检查 cur.next） | ✅ 必须推荐 | 头节点可能被删除，缺前驱 |
| **LC206 反转链表** | 翻转所有节点指向 | pre+cur 双指针（pre 当虚拟前驱） | ❌ 不需要 | `pre=None` 天然就是最开头的"虚拟前驱" |
| **LC19 删倒数第 N 个** | 删除单个节点（可能是头）| fast+slow 快慢双指针（制造固定间隔） | ✅ 必须推荐 | 极端场景（删头、删唯一节点）无 dummy 直接报错 |

### 共性总结

```
只要你做的是「通过前驱删后继」这类操作 → 永远优先 dummy 统一逻辑
```

### dummy 是实体好还是逻辑好？

| 场景 | 替代"虚拟前驱"的方式 |
|------|-------------------|
| LC203 删除 | 只能用实体 dummy 节点（要保证永远有前驱删后继） |
| LC206 反转 | `pre=None` 就是逻辑前驱（只改 cur.next=pre，不用前驱"去删"） |
| LC19 倒数删除 | 只能用实体 dummy（删头节点时必须有前驱） |

> **判断口诀**：你的操作是不是「前驱.后继 = 前驱.后继.后继」这种跳跃删除？
> 如果是 → 必须有实体 dummy，否则极端场景找不到前驱。

## 📝 模板记忆（快慢指针组合 A）

```python
def removeNthFromEnd(head, n):
    dummy = ListNode(0, head)       # ① 永远造 dummy
    slow = dummy
    fast = dummy

    for _ in range(n):              # ② fast 先冲 n 步（造固定间隔）
        fast = fast.next

    while fast.next:                # ③ 同步走到 fast 是尾节点
        fast = fast.next
        slow = slow.next

    slow.next = slow.next.next      # ④ slow 是前驱，删后继
    return dummy.next               # ⑤ 返回 dummy.next
```

**口诀**：**Dummy 起步、快冲 n 步、共走到尾（fast.next 空就停）、慢是前驱、删后继、返 dummy.next。**
