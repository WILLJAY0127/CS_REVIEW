# LeetCode 203 - 移除链表元素

## 📌 题目链接

[力扣题目链接](https://leetcode.cn/problems/remove-linked-list-elements/) | [代码随想录讲解](https://programmercarl.com/algo/linked-list/0203-remove-linked-list-elements.htm)

## 📋 题目描述

给你一个链表的头节点 `head` 和一个整数 `val`，请你删除链表中所有满足 `Node.val == val` 的节点，并返回新的头节点。

### 示例

```python
# 示例 1
输入: head = [1,2,6,3,4,5,6], val = 6
输出: [1,2,3,4,5]

# 示例 2
输入: head = [], val = 1
输出: []

# 示例 3
输入: head = [7,7,7,7], val = 7
输出: []
```

### 提示

- 链表中节点的数目在范围 `[0, 10^4]` 内
- `1 <= Node.val <= 50`
- `0 <= val <= 50`

---

## 🧠 前置知识：单链表结构

```
单链表节点结构：
┌──────┬──────┐
│ val  │ next │
└──────┴──────┘
  值     下一个节点的地址

特点：
  每个节点只知道「自己」+「下一个节点地址」
  👉 节点无法找到它的前驱（前面是谁指向它）！
```

---

## 思路 1：无 dummy 头结点（两步走）

### 核心矛盾

> **单链表没有办法直接删除当前节点！**

假设：`A → B → C`，想删除 `B`
- 必须修改 `A.next = C`
- 但 `B` 不知道 `A` 在哪里（单向链表无前驱信息）
- **解决办法**：让 `cur` 站在「前驱」位置，操作 `cur.next`

### 代码实现

```python
from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def removeElements(head: Optional[ListNode], val: int) -> Optional[ListNode]:
    # 第一段：清理头部所有等于 val 的节点
    while head and head.val == val:
        head = head.next
    
    # 第二段：处理链表中间、尾部
    cur = head
    while cur and cur.next:
        if cur.next.val == val:
            cur.next = cur.next.next
        else:
            cur = cur.next
    
    return head
```

### 为什么要分两段？

**第二段循环的致命限制**：只能删除 `cur` 的**下一个节点**，永远删不掉 `cur` 自身！

**极端案例演示**：`head = [7,7,7,7], val = 7`

```
（去掉第一段清理，直接跑第二段会发生什么）

初始：cur → 第一个7

第1轮：cur.next.val == 7 → cur.next = cur.next.next
       链表：7 → 7 → 7  ⚠️ cur 依旧卡在第一个7！

第2轮：cur.next.val == 7 → cur.next = cur.next.next
       链表：7 → 7  ⚠️ cur 还是原地不动！

第3轮：cur.next.val == 7 → cur.next = cur.next.next
       链表：7 → None

第4轮：cur.next == None → 退出循环！

❗ 结果：链表头部依旧保留 7！删除不掉！
```

**第一段的作用**：专门清理头部，保证 `head` 指向安全节点。

### 完整流程示例

`[6,1,2,6,3], val = 6`

```
原始链表：6 → 1 → 2 → 6 → 3

第一段循环：
  head → 6 (匹配) → head = head.next
  head → 1 (不匹配) → 停止

第二段循环：cur → 1
  cur.next = 2 (保留) → cur → 2
  cur.next = 6 (删除) → cur.next = cur.next.next
  cur.next = 3 (保留) → cur → 3

最终：1 → 2 → 3 ✅
```

## 思路 2：带 dummy 虚拟头结点（推荐！）

### 核心思想

**凭空造一个假节点放在最前面**，所有真实节点都变成 `cur.next`，统一用一套逻辑。

```
dummy（假节点）→ 6 → 1 → 2 → 6 → 3
  ↑
  cur 永远站在 dummy 上（永远安全，绝对不会被删除）
```

### 代码实现

```python
def removeElements(head: Optional[ListNode], val: int) -> Optional[ListNode]:
    dummy = ListNode(val=0, next=head)
    cur = dummy
    
    while cur and cur.next:
        if cur.next.val == val:
            cur.next = cur.next.next
        else:
            cur = cur.next
    
    return dummy.next
```

### dummy 的魔法

| 对比项 | 无 dummy 版本 | 有 dummy 版本 |
|--------|--------------|--------------|
| 头部处理 | 需要单独 while 清理 | 不需要，统一逻辑 |
| 循环结构 | 两段 while | 一段 while |
| 代码复杂度 | 较高 | 简洁 |
| 边界情况 | 需要特殊判断 | 无特殊情况 |

## 思路 3：pre + cur 双指针版本（了解即可）

### 代码实现

```python
def removeElements(head: Optional[ListNode], val: int) -> Optional[ListNode]:
    pre = None
    cur = head
    
    while cur:
        if cur.val == val:
            if pre is None:
                # 头结点特殊处理
                head = cur.next
            else:
                pre.next = cur.next
        else:
            pre = cur
        cur = cur.next
    
    return head
```

### 特点

- 需要维护两个指针 `pre` 和 `cur`
- 依然要判断头结点特殊情况
- 代码更繁琐，**不推荐**

## 🧠 深度思考：为什么链表删除当前节点这么难？

### 单链表的根本限制

```
A → B → C

想删除 B：
  必须修改 A.next = C
  但 B 不知道 A 的地址！
  B 只存了自己的值和 C 的地址
```

### 三种策略对比

| 策略 | 可行性 | 适用场景 |
|------|--------|---------|
| 直接删除 cur | ❌ 行不通 | 找不到前驱 |
| 复制后继的值再删后继 | ⚠️ 取巧 | LeetCode 237，但无法删尾节点 |
| 让 cur 站在前驱位置 | ✅ 通用 | 主流写法 |

### 双向链表的优势（对比）

```
双向链表节点结构：
┌──────┬──────┬──────┐
│ prev │ val  │ next │
└──────┴──────┴──────┘

双向链表每个节点同时存 prev 和 next
👉 可以直接删除当前节点！
```

---

## ⚠️ 容易踩坑点

| 坑点 | 说明 | 正确做法 |
|------|------|---------|
| 忘记清理头部 | 头结点等于 val 时死循环 | 用 dummy 或单独 while 清理 |
| `cur` 移动逻辑 | 删除后 `cur` 不能移动 | 删除操作后 `cur` 保持不动 |
| 返回值 | 直接返回 `head` | dummy 版本返回 `dummy.next` |
| 空链表 | head 为 None 时的处理 | 循环条件 `while cur and cur.next` |

---

## 📊 三种解法对比

| 解法 | 时间复杂度 | 空间复杂度 | 推荐度 |
|------|-----------|-----------|--------|
| 无 dummy（两段） | O(n) | O(1) | ⭐⭐ |
| **有 dummy** | **O(n)** | **O(1)** | ⭐⭐⭐⭐⭐ |
| pre + cur 双指针 | O(n) | O(1) | ⭐⭐ |

---

## 📝 核心总结

> **单链表不能直接删除当前节点，因为找不到前驱。**
> 
> **最简单的策略**：让 `cur` 充当前驱，检查、删除后继节点。
> 
> **dummy 的魔法**：保证永远存在合法前驱，消除所有特殊情况。
> 
> **这不是习惯问题，是单链表结构逼出来的最优写法！**
