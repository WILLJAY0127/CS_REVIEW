# LeetCode 344 - 反转字符串

> 📌 **题面一句话**：给你一个字符数组 `s`（Python 里是 `list[str]`，每个元素是单个字符字符串），**原地**反转它，**不要返回任何值**，直接修改输入数组，空间复杂度必须严格 `O(1)`。
> 注意：不能用内置 `s.reverse()` 方法答题（面试会让你手写底层逻辑）。

---

## 🎯 一句话核心思路：首尾双指针原地交换

> 这是字符串/数组反转的**标准模版题**，也是**相向双指针**的最纯粹形态。

```
原始数组：  0    1    2    3    4
值：       h    e    l    l    o
           ↑                   ↑
         left=0            right=4

第一轮交换：o ←→ h → [o,e,l,l,h]
  left++(=1), right--(=3)

第二轮交换：l ←→ e → [o,l,l,e,h]
  left++(=2), right--(=2)  → left < right 不成立，退出
```

**固定步骤不变量：**
1. 左指针 `left` 永远站在**当前待反转区间的最左端**
2. 右指针 `right` 永远站在**当前待反转区间的最右端**
3. 只要 `left < right`（两个指针还没相遇/交叉）：
   - 交换两个位置的值
   - `left += 1` 右移一步，`right -= 1` 左移一步
4. 两个指针撞到一起 → 整个数组已经对称交换完毕

> 💡 细节：为什么用 `left < right` 而不是 `left <= right`？
> 奇数长度（如 5 个元素）最后会剩一个**正中间的元素**，它自己和自己交换没有任何意义；用 `<` 正好在中间位置停下来，省掉一次无意义自交换；偶数长度刚好在交叉那一刻停，同样完美。

## 💻 Python 代码两个版本（都是原地，都 O(1) 空间）

### 版本 A：Python 惯用写法（元组解包一行交换，日常首选）

```python
def reverseString(s: list[str]) -> None:
    """
    Do not return anything, modify s in-place instead.
    """
    left = 0
    right = len(s) - 1
    while left < right:
        # Python 特有的一行交换，不用临时变量
        s[left], s[right] = s[right], s[left]
        left += 1
        right -= 1
```

### 版本 B：面试通用手写交换（临时变量版，不依赖 Python 语法糖）

面试如果要求"**用 C/Java/Python 通用逻辑写，别用 Python 元组解包这种语言特性**"，就写这个版本，所有语言都通用：

```python
def reverseString(s: list[str]) -> None:
    left = 0
    right = len(s) - 1
    while left < right:
        # 三步走：先存左 → 左位置接右的值 → 右位置接存下来的左
        temp = s[left]
        s[left] = s[right]
        s[right] = temp
        left += 1
        right -= 1
```

> 🔑 **交换三步走口诀**（任何语言手写都不会错）：
> ① 把左值先拿在手里 `temp = 左`
> ② 左位置空出来了 → 右值搬过去 `左 = 右`
> ③ 右位置现在空了 → 手里存的旧左值放过去 `右 = temp`

两个版本的**时间、空间复杂度完全一样**，只是语法糖差异。

## ▶️ 执行演示（跑一遍验证）

### Case 1：奇数长度 `"hello"` 5 个字符

```python
s1 = ["h", "e", "l", "l", "o"]
reverseString(s1)
print(s1)  # ['o', 'l', 'l', 'e', 'h']  ✅
```

### Case 2：偶数长度 `"HannaH"` 6 个字符（类回文）

```python
s2 = ["H", "a", "n", "n", "a", "h"]
reverseString(s2)
print(s2)  # ['h', 'a', 'n', 'n', 'a', 'H']  ✅
```

> 注意 Case 2 的大小写：`H`（大写）和 `h`（小写）是两个不同字符，交换后首尾大小写互换了，结果是正确的。不要拿"看起来还是回文"当成验证标准，要**逐位看值对不对**。

## 📊 复杂度分析

| 维度 | 复杂度 | 解释 |
|------|-------|-----|
| **时间复杂度** | **O(n)** | n 是字符总数。一共要交换 `⌊n/2⌋` 次（一半），每次交换 O(1)。虽然是 n/2 次但大 O 表示法常数忽略，还是线性 O(n) |
| **额外空间复杂度** | **O(1)** | 只用了 `left`、`right` 两个变量（版本 B 多一个 `temp`，依然是常数个）。**没有开辟任何长度随输入变大的额外空间**，严格满足题目 O(1) 原地要求 |

## 🔗 横向对比：「反转字符数组 344」 vs 「反转单链表 206」（为什么做法天差地别？）

这是你之前问过"为什么查找/反转题从来不用链表"的又一个生动例子——**同样是"反转"二字，内存结构不同导致解法本质完全不一样**：

| 维度 | 🟦 344 反转字符数组（列表） | 🟩 206 反转单向链表 |
|------|--------------------------|------------------|
| **底层内存** | 连续内存块，每个格子位置固定 | 节点分散在内存各处，靠 `next` 指针串联 |
| **能不能随机访问？** | ✅ O(1) 直接 `s[0]`、`s[len(s)-1]` 拿到首尾、中间任何下标 | ❌ **完全不行**。想拿到尾节点必须从 head 从头 .next 爬一遍 O(n) |
| **反转的本质是什么？** | **交换位置上的「值」**：首尾两个位置存的值对调一下就行，指针/位置本身一个不动 | **改每个节点的 next 方向指针**：不是移动节点内存，是 1→2→3 改成 1←2←3，指针方向全反过来 |
| **算法工具** | 🔧 **首尾相向双指针**：left、right 一把梭 | 🔧 **迭代三抓手 pre/cur/tmp 或递归**：（pre=已反转尾, cur=当前抓手, tmp=保存未处理段防止断链）|
| **代码量** | ~8 行极简 | 迭代版也要 10 行左右 + 递归版还要理解栈调用 |
| 对应文档跳转 | **本题 👈** | [206_反转链表.md（双工作台+三抓手搬家模型详解）](../../../2.链表/2.反转链表/206_反转链表.md) |

> 🧩 **一句话终极区分**：
> **数组（连续内存+随机访问）= 交换值**，所以左右对调指针就完事；
> **链表（分散+无随机访问）= 改指针方向**，所以只能迭代/递归翻转每个节点的 next。

## ⚠️ 面试常见防坑 & 死亡陷阱

| 陷阱 | 会怎么挂？ | 正确姿势 |
|------|----------|---------|
| ❌ 返回了东西 / 写成 `return s[::-1]` | `s[::-1]` 是**新建了一份反转后的数组**，空间 O(n) 直接违反题目 O(1) 要求；函数签名写着返回 None | 必须原地改原 `s` 列表，函数最后啥也别 return |
| ❌ 用了内置 `s.reverse()` | 题目就是考你手写双指针，调 built-in 等于白写面试 0 分 | 老老实实双指针 while left < right |
| ❌ 循环条件写成 `left <= right` | 奇数长度最后中间那个元素自己和自己交换（毫无意义），虽然不会错但不专业 | 严格用 `<`，在相遇那一刻停 |
| ❌ 交换顺序写错（`temp = s[left]` 放后面）| `s[left] = s[right]` 先执行后左值就没了，再写 `temp = s[left]` 拿的就是右值 → 左右两个位置都变成右值，原左值丢了 | 严格三步走口诀：**先存左 → 左放右值 → 右放旧左值** |

## 🧱 固化模板 & 最后口诀

```
反转字符数组固定 4 步流水账：
  ① left = 0, right = len(s) - 1
  ② while left < right:
  ③   交换 s[left] 和 s[right]（不管用元组解包还是三步走 temp）
  ④   left += 1; right -= 1
  ⑤ 函数结束啥也别 return
```

**🔚 一句话口诀刻进大脑**：
> 字符串数组反转：**左右指针两头夹，没碰头就对调，碰到头就收工。**
