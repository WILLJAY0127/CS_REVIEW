## 📋 题目描述

给定两个字符串 `s` 和 `t`，判断 `t` 是否是 `s` 的字母异位词。

**字母异位词定义**：两个字符串中，字母的 **种类** 和 **每个字母出现的次数** 完全一致，只是**排列顺序**不同。

### 核心限制（决定用什么哈希）

> ⭐ 字符串仅包含小写英文字母 `a~z`（共 26 个，范围有限）

### 示例

| s | t | 结果 | 说明 |
|---|---|------|------|
| `"anagram"` | `"nagaram"` | `true` | a:3、n:1、g:1、r:1、m:1，计数全相等 |
| `"rat"` | `"car"` | `false` | 字符种类不同：r/a/t vs c/a/r |
| `"aab"` | `"abb"` | `false` | 数量不同：a=2/b=1 vs a=1/b=2 |
| `""` | `""` | `true` | 空串算有效 |

## 🔑 先给你一个统一思想：空间换时间

| 解题方案 | 本质 | 多次重复查找怎么处理？ |
|---------|------|----------------------|
| 最原始暴力（双重 for + 删除） | 不额外开空间，边查边删 | 每次临时扫描 t（O(n²)） |
| 排序暴力 | 少开空间，靠排序消除顺序差异 | 排序后 O(n log n) 直接比较 |
| **哈希数组（最优）** | 开 26 长度数组，**提前一次性统计数量** | 之后 O(1) 读取，不用重复遍历 |
| 通用字典哈希 | 开字典，key 是字符 value 是次数 | 字符范围无限时通用 |

> 💡 **和前序题目横连：**
>
> - 链表相交 / 环形链表：暴力用 Set 记走过的节点 = **把信息先存下来，避免重复扫**
> - 滑动窗口 LC209：单调性剪枝，避免暴力重复枚举子数组
>
> **这道题也是一模一样的优化思路：不要等用到的时候再查，先一次性统计存好，之后直接拿。**

## 思路 1：最原始暴力（两层 for 循环 + 手写删字符）❌ 不用，仅理解用

### 需求 + 思路拆解

> **要达到什么效果？**
> s 里每一个字符，在 t 里都能找到**对应一个**，并且用过的字符要**删掉不允许再被匹配多次**（一一抵消）。
>
> **怎么做？**
> 把字符串 t 转成列表（Python 字符串不可变，没法删单个字符）。
> 外层 for 遍历 s 的每个字符 c → 内层 for 扫一遍 t 列表找匹配 → 找到就从 t 里 `del` 这个位置，跳出内层；找不到直接 return False。
> 全部跑完如果 t 列表正好被删空，说明匹配成功。

### Python 暴力两层循环代码（**手写版，最直观**）

```python
def isAnagram(s: str, t: str) -> bool:
    if len(s) != len(t):
        return False
    t_list = list(t)
    
    for c in s:                      # 外层：遍历 s 的每个字符，n 次
        found = False
        for i in range(len(t_list)): # 内层：逐个扫 t_list，最坏 n 次
            if t_list[i] == c:
                del t_list[i]        # 找到就删掉这一个（用完了，不能再被匹配）
                found = True
                break
        if not found:                # s 里有一个字符在 t 里找不到，直接 false
            return False
    return len(t_list) == 0
```

### 完整手动模拟两个典型例子

#### 例 1：true 场景（s = "anagram" , t = "nagaram"）

```
t_list 初始：['n','a','g','a','r','a','m']

s 第 1 个字符 = 'a'
   内层扫 i=0 'n'≠a  →  i=1 'a'==a  → del t_list[1]
   t_list 变成 ['n','g','a','r','a','m']

s 第 2 个字符 = 'n'
   内层扫 i=0 'n'==n → del t_list[0]
   t_list 变成 ['g','a','r','a','m']

... 依次类推，7 个字符全部找到并删除

最终 t_list = [] 空，len=0 → return True ✅
```

#### 例 2：false 场景（s = "rat" , t = "car"）

```
t_list 初始：['c','a','r']

s 第 1 个字符 = 'r'
   内层扫 i=0 'c'≠r  →  i=1 'a'≠r  →  i=2 'r'==r → del
   t_list 变成 ['c','a']

s 第 2 个字符 = 'a'
   内层扫 i=0 'c'≠a  →  i=1 'a'==a → del
   t_list 变成 ['c']

s 第 3 个字符 = 't'
   内层扫 i=0 'c'≠t → 内层结束，found 仍然 False
   → return False ✅（t 里根本没有 t）
```

### 复杂度分析（为什么是 O(n²)，而且实际更差）

```
假设 s / t 长度都是 n：

外层 for：固定执行 n 次
内层 for：最坏情况匹配不到，或者要扫到最后一个才找到 → 每次 ~ n 次
→ 比较次数：n × n = O(n²)

❗ 再加一个隐藏开销：
   del t_list[i] 删除的是中间位置时，Python 列表底层会把后面所有元素整体向前移动一位，
   这个搬移本身也是 O(n)。
→ 实际效率：比较 O(n²) + 搬移 O(n²) ≈ 更慢的平方级，完全不值得。
```

### 为什么不推荐暴力法

| 维度 | 评价 |
|------|------|
| 时间复杂度 | **O(n²)** 平方级，字符串稍长（1w 字符）就肉眼可见的慢 |
| 代码复杂度 | 要手写两层循环 + found 标志 + 长度空判断，容易边界写错（空 t_list 时 range(len(t_list)) 要当心） |
| 易错点 | `del` 会立即缩短数组长度，继续用原来的 i 下标会错位；删除最后一个元素、第一个元素逻辑微妙差异 |

> **最优直接用数组计数法**，一趟 O(n) 统计 + 抵消 + 检查，代码更短、更快、零边界坑。

## 思路 2：排序暴力（简单短平快）⭐ 实在想不到哈希的兜底

### 核心思路

异位词 = 字符种类数量相同，只是顺序不同。排序之后顺序被「强制统一」，如果完全相等，就是异位词。

```
s = sorted("anagram")  → ['a','a','a','g','m','n','r']
t = sorted("nagaram")  → ['a','a','a','g','m','n','r']
s == t → true
```

### 代码

```python
def isAnagram(s: str, t: str) -> bool:
    if len(s) != len(t):  # 长度不等直接 false（剪枝，非常推荐）
        return False
    return sorted(s) == sorted(t)
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 两行搞定，面试脑子短路也能写 | 时间 **O(n log n)**，排序耗时 |
| 不依赖 26 字母限制，Unicode 也能跑 | 没法 O(n)，达不到最优 |

## 思路 3：数组哈希（最优！本题考点 ⭐⭐⭐⭐⭐）

### 前置知识：**数组本身就是最简单的哈希表**

```
  key（字符） ──映射──▶  value（出现次数）

  'a'  →  ord('a')-ord('a') = 0   → record[0]
  'b'  →  ord('b')-ord('a') = 1   → record[1]
  ...
  'z'  →  ord('z')-ord('a') = 25  → record[25]

  字符 ↔ 下标：一一对应，冲突为零。
```

> 🔑 **纠正一个常见误区**：下标 0~25 的顺序不是为了排序！
>
> 我们根本不在乎 a 在前还是 z 在前，**只是需要每个字符有唯一固定的格子位置**。
> 即便 a→25、z→0 倒序映射，算法仍然完全正确。哈希关心的是「唯一性」，不是「有序性」。

### 执行流程（三步走）

1. 开数组 `record = [0] * 26`
2. 遍历 s，对应位置 **+1**（统计 s 的字符数）
3. 遍历 t，对应位置 **-1**（用 t 的字符数抵消 s）
4. 最后检查：**record 全 0 → true，有非 0 → false**

### 代码

```python
def isAnagram(s: str, t: str) -> bool:
    if len(s) != len(t):      # 长度不等直接 false（剪枝）
        return False

    record = [0] * 26

    # 统计 s：字符计数 +1
    for c in s:
        record[ord(c) - ord('a')] += 1

    # 抵消 t：字符计数 -1
    for c in t:
        record[ord(c) - ord('a')] -= 1

    # 检查是否全部归零
    for num in record:
        if num != 0:
            return False
    return True
```

### 完整模拟示例（s="aab", t="abb" → 预期 false）

```
初始 record = [0]*26
s = aab     t = abb

Step1 统计 s：
  c='a'  record[0] +=1 → [1,0,...]
  c='a'  record[0] +=1 → [2,0,...]
  c='b'  record[1] +=1 → [2,1,...]

Step2 抵消 t：
  c='a'  record[0] -=1 → [1,1,...]
  c='b'  record[1] -=1 → [1,0,...]
  c='b'  record[1] -=1 → [1,-1,...]

Step3 检查：
  record[0] = 1 ≠ 0 → return false ✅（a 多了一次，b 少了一次）
```

### 复杂度

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | **O(n)** | s 一遍 + t 一遍 + 26 检查 = 2n+26 ≈ n |
| 空间 | **O(1)** | 数组固定长度 26，与输入规模无关 |

## 思路 4：通用字典哈希（字符范围无限时使用）

### 适用场景

题目升级：包含大小写、数字、中文、Unicode。
→ 26 字母假设失效，不能用定长数组，改用字典。

### 代码

```python
from collections import defaultdict

def isAnagram(s: str, t: str) -> bool:
    if len(s) != len(t):
        return False

    count = defaultdict(int)
    for c in s:
        count[c] += 1
    for c in t:
        count[c] -= 1
    for v in count.values():
        if v != 0:
            return False
    return True
```

或者用 `Counter`（代码更短，本质一样）：

```python
from collections import Counter

def isAnagram(s: str, t: str) -> bool:
    return Counter(s) == Counter(t)
```

> 💡 纯知识点：`defaultdict` 和 `Counter` 内部仍然是哈希表（字典）。
> 当字符范围被限制到 26 时，数组比字典轻量得多：不用计算 hash、不用解决 hash 冲突、内存占用也更小。

## 📊 四种方案总对比

| 方案 | 时间 | 空间 | 字符限制 | 推荐度 | 定位 |
|------|------|------|---------|--------|------|
| 双层循环 + 删除 | O(n²) | O(n) | 不限 | ⭐ | 理解暴力，不写 |
| 排序后比较 | O(n log n) | O(log n)~O(n) | 不限 | ⭐⭐⭐ | 兜底短代码 |
| **数组哈希** | **O(n)** | **O(1)** | 26 小写字母 | ⭐⭐⭐⭐⭐ | **本题最优** |
| 字典哈希 / Counter | O(n) | O(n) | 不限 | ⭐⭐⭐⭐ | 字符无限通用 |

---

## ⚠️ 高频坑点

| 坑 | 说明 | 正确姿势 |
|----|------|---------|
| 漏判断长度 | `len(s)≠len(t)` 还傻乎乎统计，白忙活 | 开头 `if len(s)!=len(t): return False` |
| `ord(c)-ord('a')` 公式写错 | 写成 `ord(c)` 或 `-97` 硬编码都不够直观 | 统一写 `ord(c) - ord('a')` |
| 认为 a→0 / z→25 顺序有关 | 哈希要的是唯一映射，和排序无关 | 只要每个字符固定格子就行 |
| 把数组哈希推广到 unicode | unicode 有 15 万字符，不能开数组 | 切换到字典哈希 |

## 🎯 考点集中总结（复习最后 30 秒过一遍）

1. **定长字符集优先数组替代哈希表**：题面限定只有 26 个小写英文字母，就别上字典/set，开长度 26 的定长数组 —— 无需算 hash、没有冲突、**空间压到 O(1)**，比字典轻量得多。
2. **先判长度是经典剪枝小技巧**：`len(s) != len(t)` 直接 return False，不做后面任何统计，一行代码提前卡死一大半不可能情况（面试里加这一行印象分 +1）。
3. **本质：统计每个字符出现次数是否完全相等**。字母异位词的定义翻译到代码，就是"每个字符计数一模一样"；暴力 / 排序 / 数组哈希 / 字典哈希 四种方法只是实现这个比较的路径不同。

> 💡 一句话压轴：**哈希类题永远先想「值域大不大」—— 值域小可枚举（26/256/1k）→ 定长数组最轻；值域大或未知（数字/任意字符）→ 字典 / Set 通用解。**
