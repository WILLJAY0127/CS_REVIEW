## 📋 题目描述

编写一个算法来判断一个数 `n` 是不是快乐数。

### **快乐数的定义规则**

对一个正整数，反复做下面两步操作：
1. **把当前数的每一位取出来**，分别做**平方**，然后**全部相加**，得到一个新数
2. 用这个新数作为下一轮的输入，**重复步骤 1**

终止有两种结果：

| 终止条件 | 判断 |
|---------|------|
| 最终结果**收敛到 1** | ✅ **是快乐数，返回 true** |
| 在过程中**某个数字重复出现**（陷入无限循环） | ❌ **不是快乐数，返回 false** |

> 🌱 底层保证（题目隐含）：不可能出现「数越来越大无限发散」的情况。
> 因为最大的三位数 999 下一轮才变成 `9²+9²+9²=243`，更大的四位数五位数每一轮都会快速坍缩到 3 位数，然后在 243 以内的小范围里要么走向 1、要么循环。所以只需要考虑「收敛到 1」和「循环」两种分支。

### 典型示例

#### 例 1：n = 19 → true（是快乐数）

```
19
  1² + 9² = 1 + 81 = 82
  8² + 2² = 64 + 4 = 68
  6² + 8² = 36 + 64 = 100
  1² + 0² + 0² = 1
→ 收敛到 1，返回 true ✅
```

#### 例 2：n = 2 → false（无限循环，不是快乐数）

```
2
  2² = 4
  4² = 16
  1² + 6² = 1 + 36 = 37
  9 + 49 = 58
  25 + 64 = 89
  64 + 81 = 145
  1 + 16 + 25 = 42
  16 + 4 = 20
  4 + 0 = 4 ← ⚠️ 数字 4 在上面第 2 轮已经出现过了！
→ 循环 = 非快乐数，返回 false ❌
```

## 🔑 核心本质：一句话解这道题

> **快乐数 = 判断「各位平方和」序列会不会出现重复数字。**
>
> 一旦**某次计算结果之前出现过** ⟺ 进入死循环 ⟺ 永远到不了 1 ⟺ 非快乐数。

这就是为什么本题是**标准哈希 Set 题**（和 LC 349「两个数组的交集」归为同一类：只关心"出现过没有"）。

---

## 🛠 工具函数：计算 n 的各位平方和

两种解法都需要反复算「各位平方和」，先抽成独立函数：

```python
def get_sum(n):
    """求 n 的各位数字平方和"""
    total = 0
    while n:
        digit = n % 10      # 取出个位
        total += digit ** 2 # 个位平方累加
        n = n // 10         # 扔掉个位，继续处理更高位
    return total
```

**小例子手动跑一遍**：`get_sum(19)`
```
n=19: digit=9, total=81, n=1
n=1:  digit=1, total=81+1=82, n=0
→ return 82 ✅
```

## 思路 1：哈希集合判重（最直观，首选 ⭐⭐⭐⭐⭐）

### 核心思路

把每一轮计算出的中间值，全部丢进一个 `set`。
每算出一个新的数，先查 set：

| 查询结果 | 说明 | 处理 |
|---------|------|------|
| `n == 1` | 收敛到快乐数 | **return True** |
| `n in seen` 为 True | 这个数算过了，已进入循环 | **return False** |
| `n not in seen` | 第一次见 | 加入 set，继续下一轮 |

### 完整 Python 代码（可直接提交）

```python
def get_sum(n):
    total = 0
    while n:
        digit = n % 10
        total += digit ** 2
        n = n // 10
    return total

class Solution:
    def isHappy(self, n: int) -> bool:
        seen = set()          # 哈希集合：存所有出现过的中间值
        while n != 1:
            if n in seen:     # ⚠️ 这一行 = 核心：出现过 = 循环 = 非快乐数
                return False
            seen.add(n)       # 记录本轮数字，避免后面再遇到时误以为是新的
            n = get_sum(n)    # 算下一轮的平方和
        return True           # 跳出 while 说明 n==1
```

### 完整模拟两个典型例子

#### 模拟 1：n = 19（快乐数）

```
seen = {}
n=19 → 19 != 1; 19 not in seen → seen.add(19); n=get_sum(19)=82
n=82 → 82 != 1; 82 not in seen → seen.add(82); n=68
n=68 → 68 != 1; 68 not in seen → seen.add(68); n=100
n=100 →100 != 1;100 not in seen →seen.add(100);n=get_sum(100)=1
n=1 → 退出 while! → return True ✅
```

#### 模拟 2：n = 2（非快乐数）

```
seen = {}
n=2 → not 1; add {2}; n=4
n=4 → not 1; add {2,4}; n=16
n=16→ not 1; add {2,4,16}; n=37
n=37→ not 1; add ...; n=58
n=58→ not 1; add ...; n=89
n=89→ not 1; add ...; n=145
n=145→not 1; add ...; n=42
n=42→ not 1; add ...; n=20
n=20→ not 1; add ...; n=4
n=4 → ❗ 4 在 seen 里！ → return False ✅（正确判断已循环）
```

### 复杂度分析

- 时间：**O(log n)**。每一轮 `get_sum` 处理位数 O(log n)，但由于数字快速坍缩，整体轮数基本是常数级，近似 O(log n)
- 空间：**O(log n)**。集合要存的中间值数量不会太多（坍缩到 243 以内最多循环有限几个数）

## 思路 2：快慢指针（链表判环思路，O(1) 空间进阶 ⭐⭐⭐⭐）

### 🔗 本质 = 把 LC142「环形链表」套过来！

把「每算一次平方和」当成链表 `next` 指针：
```
n → get_sum(n) → get_sum(get_sum(n)) → ...
就等于：node → node.next → node.next.next → ...
```
所以：
- 出现循环（非快乐数）= **链表有环**
- 收敛到 1（快乐数）= **链表无环，fast 先到尾节点 1**

这正好就是 **LC 141 环形链表 I 的判环模型**！直接套快慢指针：

| 指针 | 速度 |
|------|------|
| `slow` | 每次算 1 次平方和（走 1 格） |
| `fast` | 每次连续算 2 次平方和（走 2 格） |

| 退出条件 | 结果 |
|---------|------|
| `fast == 1` | 收敛了 → ✅ 快乐数 |
| `slow == fast`（相遇） | 有环 → ❌ 非快乐数 |

### Python 代码（O(1) 空间，不用集合）

```python
def get_sum(n):
    total = 0
    while n:
        d = n % 10
        total += d * d
        n = n // 10
    return total

class Solution:
    def isHappy(self, n: int) -> bool:
        slow = n
        fast = get_sum(n)          # 开局 fast 先一步，保证不同起点

        # 有两个跳出条件：fast==1（快乐） 或 slow==fast（有环）
        while fast != 1 and slow != fast:
            slow = get_sum(slow)            # slow 走 1 步
            fast = get_sum(get_sum(fast))   # fast 走 2 步

        return fast == 1   # 只要 fast 能到 1 就是 True，否则 (slow==fast) 就是 False
```

### 模拟示例：n = 2（非快乐数，快慢一定相遇）

```
初始：slow=2, fast=get_sum(2)=4

第 1 轮：
  slow = get_sum(2)  = 4
  fast = get_sum(get_sum(4)) = get_sum(16) = 37
  (4 != 1 且 4 != 37 → 继续)

第 2 轮：
  slow = get_sum(4)  = 16
  fast = get_sum(get_sum(37)) = get_sum(58) = 89
  (16 != 1 且 16≠89 → 继续)

... 继续若干轮 ...
最终：slow 和 fast 会在环里某个位置相撞 → slow == fast → 跳出 while → fast !=1 → return False ✅
```

### 复杂度分析

- 时间：O(log n)（和 Set 法同量级，但每轮少了 set 查找和插入的常数开销）
- 空间：**O(1)**！只有两个指针变量，不用开任何辅助容器 —— 这就是快慢指针版相对 Set 版的进阶优势

## 📊 两种解法总对比

| 解法 | 时间 | 空间 | 直观性 | 面试定位 |
|------|------|------|--------|---------|
| **Set 哈希判重** | O(log n) | O(log n) | ⭐⭐⭐⭐⭐ 最直白，讲一遍谁都能懂 | **首选**，面试紧张时最稳不会错 |
| 快慢指针（判环） | O(log n) | **O(1)** | ⭐⭐⭐⭐ 需要先转化成「链表」 | 进阶加分项，面试官追问"能不能 O1 空间"时写 |
