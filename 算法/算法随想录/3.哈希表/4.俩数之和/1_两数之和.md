## 📋 题目描述

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值 `target`** 的那 **两个** 整数，并返回它们的**下标**（数组下标，不是元素值本身！）。

### 题目隐含三大前提（决定用什么解法）

| 前提 | 说明 | 没满足会怎样 |
|------|------|-------------|
| **每种输入有且只有一个答案** | **只会有恰好 1 个下标二元组**满足 nums[i]+nums[j]==target（不会有 2 对、3 对多个不同解同时成立）| 不用考虑多解怎么排序、怎么选、要不要去重，找到立刻 return 就行 |
| **不能重复使用同一个元素** | `nums[i]` 和 `nums[j]` 必须 **i ≠ j**，哪怕数值相等也必须是两个不同位置（比如 `[3,3], target=6` → `[0,1]` 才对，`[0,0]` 错）| 两数用同一个会踩坑 |
| **返回下标顺序随意** | `[0,1]` 和 `[1,0]` 都判对 | 不用再做最后翻转 |

### 经典示例

| 例 | nums | target | 正确答案 | 说明 |
|----|------|--------|---------|------|
| 1 | `[2,7,11,15]` | 9 | `[0,1]` | nums[0]+nums[1]=2+7=9 |
| 2 | `[3,2,4]` | 6 | `[1,2]` | nums[1]+nums[2]=2+4=6（**注意不是 [0,0]**，不能重复用第一个 3！）|
| 3 | `[3,3]` | 6 | `[0,1]` | 同一个数字出现两次在不同位置，返回两个下标 **0 和 1** |

## 思路 0：纯暴力双重循环（最差，仅对比用）❌

先扫一眼作为基准。两个 for 嵌套，枚举所有 i<j 配对：

```python
def twoSum(nums, target):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []
```

- 时间 **O(n²)**：n=1w 就要比较 1 亿次，秒不过
- 空间 O(1)
- 问题：完全不符合「哈希空间换时间」的优化目标

## 思路 1：两趟遍历哈希（你的直觉版 ✅，完全正确）

### 第一步：先想清楚哈希表要存什么

| 存什么？ | 键 key | 值 value | 为什么？ |
|---------|--------|---------|---------|
| **元素 ↔ 下标** 映射 | 数组里的数值 `nums[i]` | 这个数所在的**下标 `i`** | 题目最后要返回**下标**，不是返回值本身。如果只存"有没有这个数"就拿不到下标了，所以必须用 **Dict 不是 Set** |

> 🎯 选型铁则命中：[LC349 铁则 2](../2.两个数组的交集/349_两个数组的交集.md#L372-L374) —— 需要存「键值对应关系（值→下标映射）」 → 用 **Dict / HashMap**

---

### 思路 1 具体流程（2-pass）

```
Pass 1：先遍历数组一遍，把「每个数字 → 它的下标」全存进 num_map 字典
         （就是你说的「先都放 dict」）

Pass 2：再遍历一遍数组，对每个 nums[i]：
           我希望找到的互补数 = diff = target - nums[i]
           查 num_map 里有没有 diff
           有 → 返回 [i, num_map[diff]]
```

### ⚠️ ❗ 2-pass 版本最容易踩的致命坑：不能同一个元素自己加自己

**如果 2-pass 写成这样会出 bug：**

```python
# ❌ 错误版：没加「下标不能相同」判断
def twoSum(nums, target):
    num_map = {}
    for i, v in enumerate(nums):
        num_map[v] = i          # Pass1：全存
    for i, v in enumerate(nums):
        diff = target - v
        if diff in num_map:     # ⚠️ diff 很可能就是 v 本身！
            return [i, num_map[diff]]
    return []
```

**反例翻车：nums=[3,2,4], target=6**
```
Pass1存完：num_map = {3:0, 2:1, 4:2}

Pass2 i=0, v=3: diff=6-3=3 → 3 in num_map ✅ → return [0, 0] ❌ 错！
（i=0 和 num_map[3]=0 是同一个下标！重复用了同一个 3，违反「不能重复用同一元素」规则）
```

### ✅ 正确的 2-pass 写法（加一行判断）

```python
def twoSum(nums, target):
    num_map = {}
    # ────────── Pass 1：一次性把所有 值→下标 存字典 ──────────
    for i, v in enumerate(nums):
        num_map[v] = i              # 相同值会被后出现的下标覆盖，没关系（题目恰好只有一个解）

    # ────────── Pass 2：再扫一遍，查互补 diff  ──────────
    for i, v in enumerate(nums):
        diff = target - v
        if diff in num_map and num_map[diff] != i:   # ✅ 关键：不能是同一个下标！
            return [i, num_map[diff]]
    return []
```

**上面翻车险情再走一遍正确版：**
```
i=0, v=3, diff=3:
  diff in num_map → True，但 num_map[diff]==0 == i==0 → ❌ 条件不成立，不返回
i=1, v=2, diff=4:
  diff in num_map → True，num_map[4]=2 ≠ 1 → ✅ 成立，return [1,2]
```

### 复杂度

- 时间：O(n)（Pass1 一次 n + Pass2 一次 n）
- 空间：O(n)（字典存 n 个键值对）

> ✅ **再次强调：你的直觉版完全正确，只要补上「num_map[diff] != i」这一行判断就没任何问题，OJ 100% 过。**

## 思路 2：一遍遍历边存边查（优化版 ⭐⭐⭐⭐⭐）

### 🔑 优化契机：能不能把两趟合成一趟？

从 2-pass 往下想一个问题：

> 当我们站在第 i 位处理 `nums[i]` 的时候，需要的互补数 `diff = target - nums[i]`，
> 这个 diff 的下标一定在 `0..i-1` 或 `i+1..n-1` 两种情况。
>
> **能不能我只让 "diff 在左边" 的情况被发现？ 右边那部分等轮到它自己的时候再发现？**

答案是可以！**每一对合法答案 (j, i) 都能被约定：j 在左、i 在右。**
当我们走到右脚 i 的时候，左脚 j 必然已经在前面遍历过了 → 已经被存进字典！
而 i 右边那些将来可能和 i 配对的数 → 等它们自己变成"右脚"的时候，i 作为"左脚"已经在字典里了。

这就是**边存边查**的根基：**用"左脚先入字典，右脚来查"保证任何一对只会被发现一次，而且 i 永远>j → 自然不可能同一个下标 → 连 `!=i` 判断都省了！**

```
核心不变量：站在位置 i → dict 里恰好装着 nums[0]~nums[i-1] 的 值→下标映射
                 ↓
           diff 命中 = 左脚在里面 = 配对一定是合法 (j,i) j<i
           diff 没命中 = 左脚没出现 / 没有合法左脚 → 那把当前 i 当左脚存起来，等以后的右脚
```

### 固定三步流程（每次循环）

```
① 先查：diff = target - nums[i] 在不在当前 dict 里？
         在  → 直接 return [dict[diff], 当前 i] （结束）
② 不在  → 把 nums[i] → i 存进 dict（让当前元素成为"未来右脚的左脚候选"）
③ 进入下一轮 i+1
```

### Python 完整标准代码（可直接提交，面试写这个）

```python
def twoSum(nums, target):
    num_map = {}                  # key: 值,  value: 这个值的下标
    for i, v in enumerate(nums):
        diff = target - v
        if diff in num_map:       # ① 先查：有没有左脚已经在里面
            return [num_map[diff], i]  # ✅ 自然 j < i，同一个元素 bug 永不出现
        num_map[v] = i            # ② 查不到，把自己当左脚存入，等将来的右脚
    return []
```

> 🔥 **为什么比 2-pass 更好？**
>
> 1. **少一轮完整遍历**（2n → n，常数级提速但实际很明显）
> 2. **去掉了 `num_map[diff] != i` 的判断**，代码更短、完全不会踩 2-pass 的自杀 bug
> 3. **最好情况非常快**：如果答案恰好在前两位，第一轮就 return，字典只装了 1 个数

---

### 🧱 1-pass 思路逐轮模拟：nums=[2,7,11,15], target=9 + 错误用例 [3,2,4] 对比

#### 例 1：nums=[2,7,11,15], target=9 → 答案 [0,1]

```
初始 num_map = {}

i=0, v=2:
  diff = 9-2 = 7，7 in {} ? ❌
  num_map[2] = 0 → num_map = {2: 0}

i=1, v=7:
  diff = 9-7 = 2，2 in {2:0} ✅
  → return [num_map[2], 1] = [0, 1] ✅ 正确！
（只遍历了 2 个元素就退出，dict 里甚至还没存 7、11、15）
```

#### 例 2：**最容易踩 2-pass 自杀 bug 的例子** nums=[3,2,4], target=6 → 答案 [1,2]

```
初始 num_map = {}

i=0, v=3:
  diff = 6-3 = 3，3 in {} ? ❌
  num_map[3] = 0 → {3:0}   (第一个 3 当左脚先存)

i=1, v=2:
  diff = 6-2 = 4，4 in {3:0} ? ❌
  num_map[2] = 1 → {3:0, 2:1}

i=2, v=4:
  diff = 6-4 = 2，2 in {3:0, 2:1} ✅
  → return [num_map[2]=1, 2] = [1, 2] ✅（正确！没有出现 i=0 和 自己配对的自杀 bug）
```

> 🔑 **为什么 1-pass 自动避免自杀 bug？**
>
> 因为当前 i 自己的值 v 我们是「先查、再存」！存 v 的动作在**查完之后**才发生。
> 轮到 i 这一回合，dict 里**绝对还没有 v 自己**，所以 diff==v 时不可能命中（想命中必须等后面另一个位置存着相同 v 的时候）。
> 对比 2-pass：提前把 v 已经存在 dict 里了，必须手动 `!= i` 排除自己。

---

### ➕ 例 3：nums=[3,3], target=6 → 答案 [0,1]

```
i=0 v=3: diff=3 → 不在{} → 存 {3:0}
i=1 v=3: diff=3 → 在 {3:0} ✅ → return [0, 1] ✅
```

完美处理相同数值在两个位置的情况。

## 📊 三种解法对比表 + 选型

| 解法 | 时间 | 空间 | 自杀 bug（自己+自己）| 遍历趟数 | 推荐度 | 定位 |
|------|------|------|-------------------|---------|--------|------|
| 暴力双重 for | O(n²) | O(1) | 自然不会（j>i 保证）| 1 趟但 n² 次 | ⭐ | 仅对比，不用 |
| **2-pass 哈希（你的直觉版）** | O(n) | O(n) | ⚠️ **容易中招，必须加 `num_map[diff] != i`** | 2 趟 | ⭐⭐⭐⭐ | 正确解，完全能写，只是 1-pass 更优 |
| **1-pass 哈希边存边查 ⭐** | **O(n)** | **O(n)** | ✅ **天然不会出现**（先查后存，dict 没自己）| **1 趟** | ⭐⭐⭐⭐⭐ | **面试/刷题标准写法，首选** |

## 📝 一句话复习版（20 秒记住）

> **两数之和 = 铁则 2，用 Dict 存值→下标。**
>
> 第一直觉 2-pass 没问题，**只要加 `diff下标 != 当前i` 防自己加自己。**
>
> 优化成 1-pass 的精髓：**左脚先存 dict，右脚来查**（先查 diff、查不到再存自己）→ 自然 j<i 不同人、自杀 bug 自动免疫、只扫一遍。
