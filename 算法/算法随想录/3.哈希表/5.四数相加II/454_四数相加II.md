# LeetCode 454 - 四数相加 II

> 📌 **题面一句话**：给你四个整数数组 `nums1、nums2、nums3、nums4`，数组长度都是 `n`，请你统计有多少个四元组 `(i, j, k, l)` 满足：
> - `nums1[i] + nums2[j] + nums3[k] + nums4[l] == 0`
> - 四个下标各自从 0 到 n-1 **完全独立**、互不干扰（同一数组内可以重复选下标、不需要去重四元组），**只要求返回总方案数**。

---

## 🎯 一句话核心本质：**等式移项对半拆，哈希降维把四数平方变两数平方**

原式（四个数组各取一个，四层循环爆炸）：
```
nums1[i] + nums2[j] + nums3[k] + nums4[l] = 0
```

移项变形（把4个数组**劈成左右两半**）：
```
(nums1[i] + nums2[j])  =  -(nums3[k] + nums4[l])
```

**含义**：
- 左半部分：把 A+B 所有可能的两两之和**全部算出来**，用哈希字典记录"每个和出现过多少次"
  - key = a+b 的值
  - value = **这个和一共由多少种 (i,j) 组合产生**（不是下标！是次数！）
- 右半部分：遍历 C+D 所有两两之和，对每个和算 `need = -(c+d)`
  - `need` 去字典里查，如果查得到 → 说明有 `record[need]` 组 A+B 的组合正好和当前 C+D 抵消成 0
  - 总方案数 **`count += record[need]`**（累加次数，不是加 1！）

---

## 💥 复杂度量化对比（为什么必须哈希）

| 做法 | 时间复杂度 | n=500 时操作次数 | 能不能跑 |
|------|-----------|-----------------|---------|
| 纯暴力四层嵌套 `a b c d` | `O(n⁴)` | 500⁴ = **625 亿** | ❌ 直接爆炸 |
| 三层 + set 存 D 值 | `O(n³)` | 500³ = **1.25 亿** | ❌ 还是爆炸 |
| **本题哈希：两部分各双层** | `O(n² + n²) = O(n²)` | 25 万 + 25 万 = **50 万** | ✅ 0.1 秒内跑完 |
| 空间复杂度 | `O(n²)`（字典最多存 n² 个不同和） | 25 万条键值对 | ✅ 内存无压力 |

> ✅ **哈希的本质**：用 `O(n²)` 空间（存 A+B 的和→次数映射），换来了从 `O(n⁴)` 到 `O(n²)` 的时间飞跃。典型的「空间换时间 + 分组降维」。

## 🔢 手推例子（对照原题示例 1）

```
A(nums1) = [1, 2]
B(nums2) = [-2, -1]
C(nums3) = [-1, 2]
D(nums4) = [0, 2]
输出: 2
```

### 第一步：A+B 所有 2×2=4 组求和，装进字典，**value 存次数**

```
i=0,j=0: A[0]+B[0] = 1 + (-2) = -1  → record[-1] = 1
i=0,j=1: A[0]+B[1] = 1 + (-1) =  0  → record[0]  = 1
i=1,j=0: A[1]+B[0] = 2 + (-2) =  0  → record[0]  = 2  ← 同一和0出现了两次！累加次数
i=1,j=1: A[1]+B[1] = 2 + (-1) =  1  → record[1]  = 1
```

最终 record = `{-1: 1, 0: 2, 1: 1}`

### 第二步：C+D 所有 2×2=4 组求和，算相反数 `need = -(c+d)` 查 record，查到就累加次数

```
k=0,l=0: C[0]+D[0] = -1+0 = -1 → need =  1
        record 里 1:1  → count += 1   (count=1)

k=0,l=1: C[0]+D[1] = -1+2 =  1 → need = -1
        record 里 -1:1 → count += 1   (count=2)

k=1,l=0: C[1]+D[0] =  2+0 =  2 → need = -2
        record 里没有 → 不加

k=1,l=1: C[1]+D[1] =  2+2 =  4 → need = -4
        record 里没有 → 不加
```

最终 `count = 2`，正好对应题目输出 ✅。

### 🔑 这里最容易错的两个点

1. **value 存「次数」，不存下标**：A=B=0 的两数组全 0，A+B 的和 0 会出现 n² 次，查到就加 n²，不是加 1
2. **累加次数，不是 `count += 1`**：如果写成 `if need in record: count+=1`，同一个 need 对应多组 A+B 的情况会被你漏掉，答案一定小很多

## 💻 Python 完整可提交代码（两个版本，都能直接 AC）

### 版本 A：`defaultdict(int)` 写法（语义最清晰，面试推荐）

```python
from collections import defaultdict

class Solution:
    def fourSumCount(self, nums1: list[int], nums2: list[int],
                     nums3: list[int], nums4: list[int]) -> int:
        record = defaultdict(int)
        # 左半：A+B 所有两两之和 → 次数统计
        for a in nums1:
            for b in nums2:
                s = a + b
                record[s] += 1

        count = 0
        # 右半：C+D 所有两两之和 → 查相反数，累加对应次数
        for c in nums3:
            for d in nums4:
                need = -(c + d)
                if need in record:
                    count += record[need]
        return count
```

### 版本 B：普通字典 + `get(key, 0)` 简写（更短，不需要 `if need in record`）

```python
class Solution:
    def fourSumCount(self, nums1: list[int], nums2: list[int],
                     nums3: list[int], nums4: list[int]) -> int:
        record = {}
        for a in nums1:
            for b in nums2:
                s = a + b
                record[s] = record.get(s, 0) + 1  # 没有就默认 0，再加 1

        res = 0
        for c in nums3:
            for d_val in nums4:
                need = -(c + d_val)
                res += record.get(need, 0)  # 查不到就是加 0，直接省掉 if 判断
        return res
```

> 两个版本时间、空间复杂度完全一样，版本 B 少了 2 行 `if`，代码更紧凑。

## 🔗 与「两数之和签到模型」横向类比（哈希思想一脉相承）

两数之和 LC 1 和 四数相加 II LC 454 是哈希「降维 + 历史库匹配」思路的**亲姊妹**：

| 维度 | LC 1 两数之和（单数组，返回下标对） | LC 454 四数相加 II（四独立数组，返回计数）|
|------|----------------------------------|----------------------------------------|
| **核心等式** | `a + b = target` → `b = target - a` | `(A+B) + (C+D) = 0` → `A+B = -(C+D)` |
| **哈希 dict 的 value** | 下标索引（因为要返回下标对）| 组合**次数**（因为只统计方案数）|
| **"历史库"是什么** | 左侧已遍历过的单个数（签到本，前辈）| A+B 所有可能组合的**总和**（相当于把前辈批量先全签完到）|
| **会不会有"自己配自己"自杀 bug？** | ❗ 单数组有风险：2-pass 先全存要加 `!=i`；1-pass 先查后存用时间隔离免疫 | ✅ **完全不会**！四数组各自独立：C+D 查的永远是别的数组 A+B 存进去的，不可能出现同一个位置下标自匹配 |
| **为什么不需要签到模型的先查后存？** | 单数组依赖遍历时序防自杀 | 天然跨数组隔离：把 A+B 先"批量全部签到"，然后 C+D 再"批量全部找人"，完全安全 |

> **一句话统一视角**：哈希在这里的角色永远是「**提前把一部分结果做存档**」，然后当前遍历到的另一半去「**查存档做匹配**」——只是 LC 1 把存档和查询**交错在同一趟**（单趟省时间还顺便防自杀），LC 454 把存档和查询**拆成前后两大块**（跨数组天然安全，不用交错）。

## 🆚 关键 FAQ：为什么 454 用哈希计数，LC 18 四数之和（单数组）不行？

很多人会把两道"四数"题搞混，这是最关键的区分：

| 维度 | LC 454 四数相加 II | LC 18 四数之和 |
|------|-------------------|---------------|
| **输入形式** | **四个互相独立的数组**，四元组从四数组各挑 1 个 | **同一个数组**里挑 4 个不同下标 |
| **输出要求** | **只返回方案数（整数）**，不要求返回具体四元组 | **返回所有不重复的四元组列表** `List[List[int]]` |
| **是否要去重** | ❌ 不需要去重（不同 (i,j,k,l) 就算两个方案）| ✅ 必须严格去重（值一样的四元组只能保留 1 个）|
| **哈希好不好用** | ✅ **哈希是标准答案**，value 直接累加次数最自然 | ❌ **哈希会很难处理去重**：你需要存四元组集合判重、还要剪枝、容易遗漏边界。标准答案是**排序 + 双指针** |

**记忆口诀**：
- 「几个独立数组 / 只数个数」 → **哈希分组计数**（LC 454、LC 1 变种）
- 「单数组挑几个 / 要返回具体去重元组」 → **排序 + 双指针**（LC 15 三数之和、LC 18 四数之和）

## 🧱 固化思考模板（以后 N 数组拆分求和直接套用）

```
拿到题目，先审题 3 问：
  ├─ Q1: 是否是多个独立数组 / 多个独立维度求和等于某个常数？
  ├─ Q2: 输出是否只需要「组合总数」、不需要返回具体元组、不需要去重？
  ├─ Q3: 纯暴力嵌套循环复杂度 ≥ n³，会不会爆？
  └─ 三问全 YES → 启用「对半拆 + 哈希计数」模型

模型固定 4 步：
  Step 1 等式移项，对半拆分：
         a+b+c+d = 0  →  (a+b) = -(c+d)
         核心：把 k 个数组分成前后两组，前一组的总和 = 后一组总和的相反数
  Step 2 前半部分：双层（或多层）循环，所有两两之和算出来，
         用 dict 统计次数：{和: 出现多少种组合}
  Step 3 后半部分：双层（或多层）循环，所有两两之和算出来，
         算 need = -当前和（或 target - 当前和，依题面等式变形）
         去 dict 查 need，查到就累加对应次数到答案
  Step 4 返回累加的答案
```

### 极简 1 句通用公理

> **多个独立数组求和配 0 / 配 target、只统计方案数不需要去重 → 对半拆，前半哈希计数后半查，复杂度直接开平方降维。**
