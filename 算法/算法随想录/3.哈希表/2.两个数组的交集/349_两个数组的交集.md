# LeetCode 349 - 两个数组的交集

## 📌 题目链接

[力扣 LC349 链接](https://leetcode.cn/problems/intersection-of-two-arrays/) | [代码随想录讲解](https://programmercarl.com/algo/hash-table/0349-intersection-of-two-arrays.html)

## 📋 题目描述

给定两个数组 `nums1` 和 `nums2`，返回**它们的交集**。

输出结果要求：

| 要求 | 说明 | 反例 |
|------|------|------|
| 元素必须「同时出现」在两个数组里 | 两个数组里都有才有效 | |
| **输出去重** | 结果里同一个数字只能出现**一次** | nums1=[2,2], nums2=[2,2] → 输出只能 `[2]`，不能是 `[2,2]` |
| 顺序不限 | 结果数组里元素顺序无所谓 | `[4,9]` 和 `[9,4]` 都算对 |

### 示例

| nums1 | nums2 | 输出 | 说明 |
|-------|-------|------|------|
| `[1,2,2,1]` | `[2,2]` | `[2]` | 2 都出现，但只返回一次 |
| `[4,9,5]` | `[9,4,9,8,4]` | `[9,4]` 或 `[4,9]` | 4、9 都出现过；5、8 只一边有 |
| `[1,2,3]` | `[4,5,6]` | `[]` | 没有交集 |
| `[]` | `[1,2]` | `[]` | 一边空数组 |

## 🔑 与上一题 LC242 的统一认知

| 维度 | LC242 字母异位词 | **LC349 两个数组交集** |
|------|----------------|----------------------|
| **核心问法** | 每个字符出现次数一致吗？ | 元素有没有同时出现过？ |
| 关心计数？ | ✅ 关心每种字母多少次 | ❌ 只关心「有没有」，不关心几次 |
| 暴力 | 双重 for + 删除字符 | 双重 for + 额外去重 |
| 优化思路 | **哈希先存一边 → 再扫另一边抵消** | **哈希先存一边 → 再扫另一边看命中** |
| 值域小的时候 | 长度 26 数组 | 长度 N 数组（比如题目限 1000 就用 1001） |
| 值域任意 | defaultdict / Counter | set / dict 做标记 |

> 🔥 **统一规律**：所有「A 集合与 B 集合交叉 / 统计 / 比较」类问题，统一流程：
>
> ```
> 1. 先把 A 的信息一次遍历存到哈希（记录特征）
> 2. 再遍历 B，去哈希里查命中 / 抵消
> 3. 得到结果
>
> 对比暴力：n*m 次扫描；优化后：n+m 次，空间换时间
> ```

## 思路 1：最原始暴力（双重循环 + 手动去重）❌ 仅理解

### 核心思路

- 每个 `nums1` 元素，去 `nums2` 里从头到尾看有没有
- 找到了就算交集，但要注意不能重复加进结果

### 代码

```python
def intersection(nums1, nums2):
    res = []
    for n1 in nums1:
        # 去 nums2 线性搜索
        for n2 in nums2:
            if n1 == n2:
                # 命中 + 结果里还没加过（手动去重）
                if n1 not in res:
                    res.append(n1)
                break
    return res
```

### 复杂度

- 时间 **O(n*m)**：每个 n1 都要扫一遍 nums2，`n1 not in res` 又是线性搜索
- 空间 O(1)：除结果外不开额外容器
- 慢到过不了大数据用例

## 思路 2：哈希集合（代码最短，首选刷题 ⭐⭐⭐⭐）

### 核心思路

用 `set` 解决两件事：

1. `set(nums1)` 自动去重，避免后续重复判断
2. `if num in setA` 哈希查找 O(1)，直接取代暴力线性搜索
3. **命中后立刻从集合删去** → 自然不会重复加到结果里

### 代码

```python
def intersection(nums1, nums2):
    set1 = set(nums1)       # 第一步：A 存哈希，自动去重
    res = []
    for num in nums2:
        if num in set1:     # 第二步：扫 B，哈希 O(1) 查命中
            res.append(num)
            set1.remove(num)  # ⚠️ 关键：从哈希里删掉，防止被 nums2 下一个相同数字再命中
    return res
```

### 完整模拟示例

```
nums1 = [1,2,2,1]  nums2 = [2,2]

Step 1 set1 = {1, 2}        # 自动去重

Step 2 遍历 nums2：
  num = 2
    2 in {1,2} ✅ → res=[2]
    set1.remove(2) → set1 = {1}   # 关键：下次再遇 2 不会命中

  num = 2
    2 in {1} ❌ → 跳过

最终 res = [2] ✅
```

> 🔑 **`set1.remove(num)` 是去重的关键**。
>
> 如果不删：nums2=[2,2] 两次命中，结果变成 [2,2]，违反题目「输出唯一」要求。
> 也可以用第二个 set 存结果（自动去重），但思路上不如「用完删除」直观。

### 复杂度

- 时间 O(n + m)
- 空间 O(n)：set1 存储 nums1 去重后元素

## 思路 3：数组哈希（值域有限时使用 ⭐⭐⭐⭐）

> 和 LC242 `record[26]` 数组哈希完全同源！只是从 26 字母变成题目给的数字范围。

### 适用前提

题目明确限制数值范围（比如 0 ≤ nums[i] ≤ 1000），可以用数组下标当 key。

### 代码

```python
def intersection(nums1, nums2):
    # 假设数值范围 0~1000，开 1001 长度数组
    record = [0] * 1001

    # Step 1：标记 nums1 出现过的数字（=1 代表出现过）
    for n in nums1:
        record[n] = 1

    res = []
    # Step 2：扫 nums2，命中 1 的数字就是交集
    for n in nums2:
        if record[n] == 1:
            res.append(n)
            record[n] = 0   # ⚠️ 标记成 0，防止再次命中导致输出重复
    return res
```

### 和 set 方案对比

| 维度 | 数组哈希 | 集合哈希 |
|------|---------|---------|
| 时间 | 同样 O(n+m) | 同样 O(n+m) |
| 空间 | 固定 1001 个，不管 nums1 多小 | 取决于 nums1 去重后大小 |
| 限制 | 值域必须有限且范围小 | 任意数字（含负数、大数） |
| 哈希冲突？ | 数组下标一对一，完全无冲突 | set 内部有 hash 冲突（Python set 处理掉了，不用管） |

> 💡 经验法则：题目如果没给范围，默认写 **set 版本**，最安全。
> 很多力扣题解喜欢开 1001 数组是因为知道力扣后台数据范围，但面试时最好先问面试官「数值范围是多少」再选择。

## 思路 4：双指针排序（不开哈希，时间换空间）⭐⭐⭐

### 核心思路

既然要找两边都出现的数字 → 先把两边排好序 → 两个指针同步向前对撞比较：

- `nums1[i] < nums2[j]`：nums1 这边太小，i++
- `nums1[i] > nums2[j]`：nums2 这边太小，j++
- **相等**：命中交集，加结果；然后**各自跳过所有重复值**，避免重复输出

### 代码

```python
def intersection(nums1, nums2):
    nums1.sort()
    nums2.sort()

    i = j = 0
    res = []
    n1, n2 = len(nums1), len(nums2)

    while i < n1 and j < n2:
        a, b = nums1[i], nums2[j]
        if a < b:
            i += 1
        elif a > b:
            j += 1
        else:
            # 命中交集
            res.append(a)
            # 跳过 nums1 中全部和 a 相同的值
            while i < n1 and nums1[i] == a:
                i += 1
            # 跳过 nums2 中全部和 a 相同的值
            while j < n2 and nums2[j] == a:
                j += 1
    return res
```

### 完整模拟

```
nums1 = [4,9,5] 排序后 → [4,5,9]
nums2 = [9,4,9,8,4] 排序后 → [4,4,8,9,9]

i=0(4), j=0(4)：相等！res=[4]
  i 跳过 4 → i=1(5)
  j 跳过 4 → j=2(8)

i=1(5), j=2(8)：5<8 → i=2(9)

i=2(9), j=2(8)：9>8 → j=3(9)

i=2(9), j=3(9)：相等！res=[4,9]
  i 跳过 9 → i=3（结束）
  j 跳过 9 → j=5（结束）

循环退出，res=[4,9] ✅
```

### 复杂度 & 取舍

- 时间 **O(n log n + m log m)**：排序是主要开销，双指针部分线性
- 空间：如果允许修改原数组就是 **O(1)**（除结果外不开容器）
- 适合：**内存紧张**、**排序结果本身后续还要用**的场景

## ⚠️ 高频坑点

| 坑 | 后果 | 修复 |
|----|------|------|
| ❌ 找到相同就 append，不去重 | `[1,2,2,1] & [2,2]` 输出 `[2,2]` 被判错 | 找到后 set.remove / 数组清 0 / 结果用 set |
| ❌ 数组哈希直接开 `[0]*10000` 不确认范围 | 负数、大数立刻越界 RE | 没给范围就用 set，先问面试官 |
| ❌ 双指针相等只 i++, j++ 不跳重复 | 连续重复命中多次，结果重复 | 相等后 while 跳到下一个不同的值 |
