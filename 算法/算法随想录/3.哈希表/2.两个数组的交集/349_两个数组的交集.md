## 📋 题目描述

给定两个数组 `nums1` 和 `nums2`，返回**它们的交集**。

输出结果要求：

| 要求 | 说明 | 反例 |
|------|------|------|
| 元素必须「同时出现」在两个数组里 | 两个数组里都有才有效 | |
| **输出去重** | 结果里同一个数字只能出现**一次** | nums1=[2,2], nums2=[2,2] → 输出只能 `[2]`，不能是 `[2,2]` |
| 顺序不限 | 结果数组里元素顺序无所谓 | `[4,9]` 和 `[9,4]` 都算对 |

### 示例

| nums1 | nums2 | 输出 | 说明 |
|-------|-------|------|------|
| `[1,2,2,1]` | `[2,2]` | `[2]` | 2 都出现，但只返回一次 |
| `[4,9,5]` | `[9,4,9,8,4]` | `[9,4]` 或 `[4,9]` | 4、9 都出现过；5、8 只一边有 |
| `[1,2,3]` | `[4,5,6]` | `[]` | 没有交集 |
| `[]` | `[1,2]` | `[]` | 一边空数组 |

## 🌏 跨语言统一认知：HashSet 三家等价（Python / C++ / Java）

> 🔑 做哈希题第一件事：不管用什么语言，**unordered_set / set / HashSet 指的是同一件东西**，行为 100% 等价。

| 语言 | 容器名 | 本题作用（3 点完全一致） |
|------|--------|------------------------|
| **Python** | `set()` | ① 自动去重（元素唯一）<br>② 底层哈希表，`in` 查询 / `add` 插入 O(1)<br>③ 无序（契合题目"不考虑输出顺序"） |
| **C++** | `std::unordered_set<int>` | 同上三件套：自动去重 / 哈希 O(1) / 无序 |
| **Java** | `HashSet<Integer>` | 同上三件套：`.contains()` O(1) / `.add()` / 无序 |

> 💡 对照关系速记：`Python set ≡ C++ unordered_set ≡ Java HashSet`
>
> （注意：C++ 的 `std::set` / Java 的 `TreeSet` 是**有序红黑树**，不是哈希表，O(log n)，不要搞混！）

### 本题核心需求翻译

给两个数组 `nums1`、`nums2` → **公共元素**，且**输出结果天然去重**（同一个元素在两边出现多次也只输出一次）。

## 🔑 与上一题 LC242 的统一认知

| 维度 | LC242 字母异位词 | **LC349 两个数组交集** |
|------|----------------|----------------------|
| **核心问法** | 每个字符出现次数一致吗？ | 元素有没有同时出现过？ |
| 关心计数？ | ✅ 关心每种字母多少次 | ❌ 只关心「有没有」，不关心几次 |
| 暴力 | 双重 for + 删除字符 | 双重 for + 额外去重 |
| 优化思路 | **哈希先存一边 → 再扫另一边抵消** | **哈希先存一边 → 再扫另一边看命中** |
| 值域小的时候 | 长度 26 数组 | 长度 N 数组（比如题目限 1000 就用 1001） |
| 值域任意 | defaultdict / Counter | set / dict 做标记 |

> 🔥 **统一规律**：所有「A 集合与 B 集合交叉 / 统计 / 比较」类问题，统一流程：
>
> ```
> 1. 先把 A 的信息一次遍历存到哈希（记录特征）
> 2. 再遍历 B，去哈希里查命中 / 抵消
> 3. 得到结果
>
> 对比暴力：n*m 次扫描；优化后：n+m 次，空间换时间
> ```

## 思路 1：最原始暴力（双重循环 + 手动去重）❌ 仅理解

### 核心思路

- 每个 `nums1` 元素，去 `nums2` 里从头到尾看有没有
- 找到了就算交集，但要注意不能重复加进结果

### 代码

```python
def intersection(nums1, nums2):
    res = []
    for n1 in nums1:
        # 去 nums2 线性搜索
        for n2 in nums2:
            if n1 == n2:
                # 命中 + 结果里还没加过（手动去重）
                if n1 not in res:
                    res.append(n1)
                break
    return res
```

### 复杂度

- 时间 **O(n*m)**：每个 n1 都要扫一遍 nums2，`n1 not in res` 又是线性搜索
- 空间 O(1)：除结果外不开额外容器
- 慢到过不了大数据用例

## 思路 2：哈希集合（代码最短，首选刷题 ⭐⭐⭐⭐⭐）

### 核心思路

用 `set` 解决两件事：
1. `set(nums1)` 自动去重，后续天然不用再判重
2. `if x in setA` 哈希查找 O(1)，直接取代暴力里 O(m) 的线性搜索
3. 用某种"去重手段"保证同一个公共元素不会被重复加入结果（有 3 种常见写法，见下文）

---

### 🌟 三种 Set 写法（宝藏典藏：面试随便选一个写）

#### 写法 A：一行极简「& 运算符」（Python 特有的面试最省事）

Python 集合内置了**交集运算符 `&`**，直接一行求公共部分，面试官一眼就懂。

```python
def intersection(nums1, nums2):
    return list(set(nums1) & set(nums2))
```

> 优缺点：最短、最 Pythonic，秒写完；**但面试时通常希望你写"遍历+查哈希"的过程版**（否则体现不出哈希 O(1) 查找这个考点），所以一般作为"代码开头说一下我还会这种一行写法，然后写正式版"用。

---

#### 写法 B：结果集合 res_set 版（✅ **首选！和 C++/Java 代码完全对应**）

这是教材级标准写法，和 C++ `unordered_set` / Java `HashSet` 的解题代码一一对应，任何语言都能 1:1 翻译。

```python
def intersection(nums1, nums2):
    s = set(nums1)          # 第一步：A 进哈希集合（自动去重）
    res_set = set()         # 结果也用集合，自动保证唯一
    for x in nums2:
        if x in s:          # 第二步：扫 B，哈希 O(1) 查是否存在
            res_set.add(x)  # 命中就加结果集（重复 add 不影响，set 自动去重）
    return list(res_set)
```

**完整手动模拟：**
```
nums1=[1,2,2,1]  nums2=[2,2]

s = {1, 2}                # nums1 进集合，自动去重
res_set = {}

扫 nums2：
  x=2  →  2 in {1,2} ✅ → res_set.add(2) → res_set={2}
  x=2  →  2 in {1,2} ✅ → res_set.add(2) → 还是 {2}（set 自动忽略重复！）
list(res_set) = [2] ✅
```

> 🔑 为什么推荐这个版本？
>
> - 结果去重**不需要额外逻辑**，完全交给 set 本身机制（不会忘写 set.remove 导致错）
> - 和 Java `HashSet<Integer> resSet` 写法一一对应，跨语言学习零成本切换
> - 也不会把原 set1 改掉，调试更直观

---

#### 写法 C：命中后「用完即删」型（本文档最早版本）

```python
def intersection(nums1, nums2):
    set1 = set(nums1)
    res = []
    for num in nums2:
        if num in set1:
            res.append(num)
            set1.remove(num)  # ⚠️ 从哈希里删掉，下次再遇到同名直接跳过
    return res
```

> 逻辑上正确，且**最后一个相同数字也只加一次**。但缺点是修改了原 set1 内容、以及 `remove` 不存在的元素会抛异常（本题流程保证只有存在才 remove，所以安全）。

---

### 三种写法选型一张表

| 写法 | 去重机制 | 代码长度 | 跨语言对应度 | 面试推荐度 | 用在哪 |
|------|---------|---------|-------------|-----------|--------|
| A 一行 `&` 运算符 | 内置运算符 | ⭐ 1 行 | ⚠️ 只有 Python 有 | ⭐⭐⭐ | 展示 Pythonic 熟练度，口语补充 |
| **B res_set 结果集** | res_set 自动去重 | 短 | ✅ 完全对齐 C++/Java 教材版 | ⭐⭐⭐⭐⭐ | **面试笔试首选，稳** |
| C 用完即删 remove | 命中后从 set1 删除 | 中 | ⭐⭐ | ⭐⭐⭐⭐ | 理解用，也能写但容易记错 |

### 复杂度（三种写法完全一样）

- 时间 **O(n + m)**：s 建集合 n + 扫 nums2 m
- 空间 **O(n)**：集合存 nums1 全部不同元素（写法 A 多一个 set2，但量级相同）

## 思路 3：数组哈希（值域有限时使用 ⭐⭐⭐⭐）

> 和 LC242 `record[26]` 数组哈希完全同源！只是从 26 字母变成题目给的数字范围。

### 适用前提

题目明确限制数值范围（比如 0 ≤ nums[i] ≤ 1000），可以用数组下标当 key。

### 代码

```python
def intersection(nums1, nums2):
    # 假设数值范围 0~1000，开 1001 长度数组
    record = [0] * 1001

    # Step 1：标记 nums1 出现过的数字（=1 代表出现过）
    for n in nums1:
        record[n] = 1

    res = []
    # Step 2：扫 nums2，命中 1 的数字就是交集
    for n in nums2:
        if record[n] == 1:
            res.append(n)
            record[n] = 0   # ⚠️ 标记成 0，防止再次命中导致输出重复
    return res
```

### 和 set 方案对比

| 维度 | 数组哈希 | 集合哈希 |
|------|---------|---------|
| 时间 | 同样 O(n+m) | 同样 O(n+m) |
| 空间 | 固定 1001 个，不管 nums1 多小 | 取决于 nums1 去重后大小 |
| 限制 | 值域必须有限且范围小 | 任意数字（含负数、大数） |
| 哈希冲突？ | 数组下标一对一，完全无冲突 | set 内部有 hash 冲突（Python set 处理掉了，不用管） |

> 💡 经验法则：题目如果没给范围，默认写 **set 版本**，最安全。
> 很多力扣题解喜欢开 1001 数组是因为知道力扣后台数据范围，但面试时最好先问面试官「数值范围是多少」再选择。

## 思路 4：双指针排序（不开哈希，时间换空间）⭐⭐⭐

### 核心思路

既然要找两边都出现的数字 → 先把两边排好序 → 两个指针同步向前对撞比较：

- `nums1[i] < nums2[j]`：nums1 这边太小，i++
- `nums1[i] > nums2[j]`：nums2 这边太小，j++
- **相等**：命中交集，加结果；然后**各自跳过所有重复值**，避免重复输出

### 代码

```python
def intersection(nums1, nums2):
    nums1.sort()
    nums2.sort()

    i = j = 0
    res = []
    n1, n2 = len(nums1), len(nums2)

    while i < n1 and j < n2:
        a, b = nums1[i], nums2[j]
        if a < b:
            i += 1
        elif a > b:
            j += 1
        else:
            # 命中交集
            res.append(a)
            # 跳过 nums1 中全部和 a 相同的值
            while i < n1 and nums1[i] == a:
                i += 1
            # 跳过 nums2 中全部和 a 相同的值
            while j < n2 and nums2[j] == a:
                j += 1
    return res
```

### 完整模拟

```
nums1 = [4,9,5] 排序后 → [4,5,9]
nums2 = [9,4,9,8,4] 排序后 → [4,4,8,9,9]

i=0(4), j=0(4)：相等！res=[4]
  i 跳过 4 → i=1(5)
  j 跳过 4 → j=2(8)

i=1(5), j=2(8)：5<8 → i=2(9)

i=2(9), j=2(8)：9>8 → j=3(9)

i=2(9), j=3(9)：相等！res=[4,9]
  i 跳过 9 → i=3（结束）
  j 跳过 9 → j=5（结束）

循环退出，res=[4,9] ✅
```

### 复杂度 & 取舍

- 时间 **O(n log n + m log m)**：排序是主要开销，双指针部分线性
- 空间：如果允许修改原数组就是 **O(1)**（除结果外不开容器）
- 适合：**内存紧张**、**排序结果本身后续还要用**的场景

## � 暴力 vs 哈希：空间换时间的本质（你刚才问到的核心）

> **一句话**：暴力法是「几乎不占用额外辅助空间，纯靠时间硬堆」；哈希解法是「用额外存储空间换时间复杂度大幅下降」。这就是算法里最经典的 **⏰ 时间 ↔ 💾 空间 互兑**。

### 1. 两种方案的空间开销逐行拆解

| 方案 | 开了什么容器？ | 和输入规模 n 的关系？ | **额外空间复杂度**（题目要求必须返回的 res 不计入） | 时间 |
|------|--------------|---------------------|------------------------------------------------|------|
| **① 纯暴力双层循环** | 只用到了 `res=[]`（题目要求必须输出）+ 循环变量 `a, b` | 完全没有和 n 成正比的临时容器 | **O(1)** 常数级 | O(n·m) ≈ O(n²) ❌ 最慢 |
| **② Set 哈希解法（写法 B）** | 两个集合 `s = set(nums1)` + `res_set = set()` | s 要容纳 nums1 全部不重复元素，大小随 n 变大而变大 | **O(n)** 线性级 | **O(n + m)** ≈ O(n) ✅ 最快 |

> ❓ **细节澄清**：为什么 `res` / 结果数组不算空间？
> 算法里说的"额外空间复杂度"指的是**算法为了加速自己额外开的辅助容器**。
> 题目要求必须返回的结果列表，是"输出义务"不是"辅助容器"，统计时不计入。
> 所以纯暴力 = 零辅助空间，只有哈希解法才自己多开了 s 和 res_set 两个辅助集合。

### 2. 一句话对比：为什么不用哈希要慢那么多？

| 维度 | 暴力双层 for | 哈希 Set |
|------|-------------|---------|
| 查找 "x 在不在 nums1 里" | 每次从头到尾扫一遍 nums1 = O(n) | 直接哈希表一步到位 = O(1) |
| 本质 | 靠"一个个碰运气比对" | 靠"提前把信息存哈希，之后直接取" |

所以当 n=1w 时：暴力要比较 1 亿次（10⁸，肉眼可见的慢），哈希只需要 2w 次操作（秒完成）。

### 3. 哈希题三大方案的「时空选型体系」（建立你的知识树）

这是哈希类题通用的三层金字塔（从「时空双优」到「纯牺牲一边」）：

```
         🔝 数组哈希（如 242 字母 [0]*26）
        空间 O(1)  时间 O(n)   （时空双优！前提：数值范围有限连续）
              │
    ──────────┼──────────
    │                     │
   ⬇                    ⬇
Set/Dict 哈希（如 349 本题）      排序 + 双指针（折中）
空间 O(n)  时间 O(n)           空间 O(1)   时间 O(n log n)
（空间换时间，适用数值散乱）    （时间换空间，内存紧张场景）
              │
             ⬇
    暴力双层循环（纯理论）
    空间 O(1)  时间 O(n²)
    （纯牺牲时间省空间，仅理解用）
```

**对应 349 本题 4 种方案定位完整表：**

| 方案 | 额外空间 | 时间 | 定位 | 什么时候用？ |
|------|---------|------|------|-------------|
| 数组哈希 | O(MAX) 固定 | O(n+m) | 🟢 最左上（双优） | 题目明确给范围 0~1000 这种 |
| Set 哈希（推荐写法 B） | O(n) | O(n+m) | 🟡 中间（用空间换时间） | **本题默认选择**（数值无限制） |
| 排序 + 双指针 | O(1) | O(n log n) | 🟠 折中 | 面试官追问「能不能不开哈希？」 |
| 纯暴力双层循环 | O(1) | O(n²) | 🔴 最差 | 仅作为"哈希优越性"的对比教材 |

## 🎯 哈希选型三条铁则（记死！所有哈希题通用）

直接用你最后发的规则，哈希类题目一上来 3 秒内判断用什么容器：

| 铁则序号 | 条件 | 选型 | 原因 | 例题 |
|---------|------|------|------|------|
| **铁则 1 ✅** | 数值范围**很小、连续、可控**（如 26 个字母、0~1000） | **数组当哈希** | 空间 O(1) 固定 + 取数 O(1) 无冲突，时空双优天花板 | LC 242 异位词<br>本题限范围版 |
| **铁则 2 ✅** | 数值**跨度极大、散乱、不知道范围**（比如本题任意整数、含负数） | **哈希 Set / 哈希 Dict** | 集合不需要预知范围，自动伸缩；代价是空间 O(n) | **LC 349 本题（默认）**<br>LC 1/ LC 160 等 |
| **铁则 3 ✅** | 除了"有没有"之外，**还要存键值对应关系**（出现频次、映射关系） | **Dict / HashMap** | Set 只能存存在性；Dict 可以存 `key → count / key → value` | LC 242（不限字符版）<br>LC 383 赎金信<br>LC 49 异位词分组 |

> **落到本题的结论**：题目只要求"判断元素是否同时存在过"，不需要计数 + 数值范围没给限 → 命中**铁则 2**，因此最优选择是**哈希 Set**（就是思路 2 写法 B）。

## ☕ 附：Java 标准版代码（对照复习用）

Java `HashSet<Integer>` 和 Python `set(int)` 行为完全等价，流程和「思路 2 写法 B res_set 版」1:1 对应：

```java
import java.util.HashSet;
import java.util.ArrayList;
import java.util.List;

class Solution {
    public int[] intersection(int[] nums1, int[] nums2) {
        HashSet<Integer> set1 = new HashSet<>();
        HashSet<Integer> resSet = new HashSet<>();

        // Step 1：nums1 进哈希集合（对应 Python: s = set(nums1)）
        for (int x : nums1) {
            set1.add(x);
        }

        // Step 2：扫 nums2，查存在就加结果集（对应 Python: if x in s: res_set.add(x)）
        for (int x : nums2) {
            if (set1.contains(x)) {   // 对应 Python: x in set1  哈希 O(1)
                resSet.add(x);
            }
        }

        // Step 3：Set → int[] 数组（对应 Python: list(res_set)）
        int[] arr = new int[resSet.size()];
        int idx = 0;
        for (int num : resSet) {
            arr[idx++] = num;
        }
        return arr;
    }
}
```

> 对照速记：
> - `set1.add(x)` ≡ `set1.add(x)`
> - `set1.contains(x)` ≡ `x in set1`
> - `resSet.add(x)` ≡ `res_set.add(x)`（set 自动去重）
> - Set 转数组稍微麻烦一点（Java 强类型），Python `list(res_set)` 直接搞定

| ❌ 找到相同就 append，不去重 | `[1,2,2,1] & [2,2]` 输出 `[2,2]` 被判错 | 找到后 set.remove / 数组清 0 / 结果用 set |
| ❌ 数组哈希直接开 `[0]*10000` 不确认范围 | 负数、大数立刻越界 RE | 没给范围就用 set，先问面试官 |
| ❌ 双指针相等只 i++, j++ 不跳重复 | 连续重复命中多次，结果重复 | 相等后 while 跳到下一个不同的值 |
