# 977. 有序数组的平方

## 📌 题目链接

[力扣题目链接](https://leetcode.cn/problems/squares-of-a-sorted-array/) | [代码随想录讲解](https://programmercarl.com/algo/array/0977-squares-of-a-sorted-array.html)

## 📋 题目描述

给你一个按 **非递减顺序** 排序的整数数组 `nums`，返回 **每个数字的平方** 组成的新数组，要求也按 **非递减顺序** 排序。

### 示例

```python
# 示例 1
输入: nums = [-4,-1,0,3,10]
输出: [0,1,9,16,100]
解释: 平方后，数组变为 [16,1,0,9,100]，排序后，数组变为 [0,1,9,16,100]

# 示例 2
输入: nums = [-7,-3,2,3,11]
输出: [4,9,9,49,121]
```

### 提示

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- `nums` 已按 **非递减顺序** 排序

---

## 🧠 核心思维转换

### 从暴力到最优的思维链条

#### 第一步：观察暴力方案存在什么浪费

```
nums = [-4,-1,0,3,10]
平方后：[16, 1, 0, 9, 100]

暴力做法：丢给排序算法 O(n log n)
但原始数组是有序的！暴力解法完全没有利用有序这个信息。
```

#### 第二步：分析有序数组平方后的分布规律

```
原数组升序：负数 ... 0 ... 正数

负数部分：越往左，数值越小，绝对值越大 → 平方越大
正数部分：越往右，数值越大 → 平方越大

结论：
- 平方之后，最小的值出现在中间
- 最大值只会出现在最左端 或者 最右端
```

#### 第三步：矛盾来了

```
题目要求输出：从小到大（升序）
但是我们能稳定拿到的数：从大到小

怎么解决？
新建一个结果数组，倒着存放。
```

#### 第四步：完整方案

```
left 左指针，right 右指针，k 指向结果数组末尾。
比较两端平方，更大的放进 res[k]，对应指针收缩，k -= 1。
```

## 🎯 模型一：暴力排序（最直观）

### 代码实现

```python
def sortedSquares(nums):
    """暴力解法：每个数平方后排序"""
    # 方法一：直接平方后排序
    return sorted(x * x for x in nums)

```

### 时间复杂度

- O(n + nlog n) = O(nlog n)

## 🎯 模型二：双指针法（推荐！）

### 核心思路

数组有序，平方后的**最大值一定在两端**（最左或最右），不可能在中间。

### 执行过程示例

```
nums = [-4,-1,0,3,10]

步骤  left  right  比较        动作                    result
 1     0      4     16 < 100  取右端100，k左移       [_,_,_,_,100]
 2     0      3     16 > 9    取左端16，i右移        [_,_,_,100,16]
 3     1      3     1 < 9     取右端9，j左移         [_,_,100,16,9]
 4     1      2     1 > 0    取左端1，i右移         [_,100,16,9,1]
 5     2      2     0 == 0   取左端0，i右移         [100,16,9,1,0]

最终结果：[0, 1, 9, 16, 100] （反转后）
```

### 代码实现

```python
def sortedSquares(nums):
    """双指针法：从两端取最大值，倒序填充"""
    n = len(nums)
    result = [0] * n  # 提前创建结果数组
    k = n - 1  # k 指向结果数组末尾
    
    left, right = 0, n - 1  # 左右指针
    
    while left <= right:
        left_square = nums[left] * nums[left]
        right_square = nums[right] * nums[right]
        
        if left_square < right_square:
            # 右端平方更大，放入结果数组末尾
            result[k] = right_square
            right -= 1
        else:
            # 左端平方更大或相等，放入结果数组末尾
            result[k] = left_square
            left += 1
        
        k -= 1  # 结果数组指针左移
    
    return result
```

### 时间复杂度

- O(n)

## 🔑 双指针方案的硬性前提

### 成立条件（缺一不可）

1. **原始数组是升序有序的整数数组**
2. **平方之后，最大值一定出现在数组两端**

### 边界情况验证

```
# 情况一：有负数、有0、有正数
[-7,-3,2,3,11] → 平方后最大值在右端 ✅

# 情况二：全部负数
[-6,-5,-2] → 平方后最大值在左端 ✅

# 情况三：全部正数
[1,3,5] → 平方后最大值在右端 ✅

# 情况四：只有一个元素
[5] → 直接返回 [25] ✅
```

### ⚠️ 不适用场景

- **无序数组**：无法保证最大值在两端，双指针策略直接失效
- 如果数组无序，只能用暴力：平方 + 排序

## 🔄 为什么感觉脱节、像取巧？

### 三层原因分析

#### 原因一：普通人的思考习惯

```
总想从小到大构造答案
本能想：先找最小的，依次往数组头部填
但这道题很难快速找到最小值（最小值在中间）
```

#### 原因二：最优解法反直觉

```
最优解法：先从大到小收集，反向填充结果数组
思维方向反转，这就是最大的门槛
```

#### 原因三：思维链条更长

```
LC27 移除元素（同向快慢指针）：
筛选元素 → 两块重叠缓冲区 → fast 搜寻、slow 写入
思路顺着人的直觉走，门槛低

LC977 有序数组的平方（相向双指针）：
有序数组平方分布特性 → 极值在两端 → 只能优先获取最大值 → 必须反向构建结果数组
链条更长，任何一环没想到，思路就卡住
```

### 💡 刷题策略建议

```
考场之上，如果一时想不出双指针思路：
1. 优先写暴力平方 + sort，先拿到正确答案
2. 暴力写完后，强迫自己思考：题干给的「有序条件」我有没有用上？
3. 这个自问，就是打通从暴力走向最优解的桥梁
```

## 🔌 接口抽象

### 通用有序数组绝对值最大值接口

```python
def merge_sorted_abs(arr):
    """
    通用接口：有序数组的绝对值最大值排序
    
    参数:
        arr: 升序有序的整数数组
    
    返回:
        每个元素的平方组成的升序有序数组
    """
    n = len(arr)
    result = [0] * n
    k = n - 1
    left, right = 0, n - 1
    
    while left <= right:
        left_sq = arr[left] * arr[left]
        right_sq = arr[right] * arr[right]
        
        if left_sq < right_sq:
            result[k] = right_sq
            right -= 1
        else:
            result[k] = left_sq
            left += 1
        
        k -= 1
    
    return result
```

### 使用示例

```python
# 基本用法
nums = [-4,-1,0,3,10]
result = merge_sorted_abs(nums)
print(result)  # [0, 1, 9, 16, 100]

# 其他场景：平方、绝对值等
nums = [-7,-3,2,3,11]
result = merge_sorted_abs(nums)
print(result)  # [4, 9, 9, 49, 121]
```

## ⚠️ 常见错误

| 错误 | 原因 | 解决方法 |
|------|------|----------|
| 忘记创建结果数组 | 直接在原数组上操作 | 必须创建新数组 |
| 循环条件写成 `<` | 漏检最后一个元素 | 用 `left <= right` |
| 忘记处理 `left == right` | 最后一个元素未处理 | 循环条件必须包含等号 |
| 结果数组顺序错误 | 忘记倒序填充 | 从后往前填 k-- |

## 📝 总结

### 三层理解

| 层次 | 内容 | 目标 |
|------|------|------|
| **L1 实现层** | 暴力、双指针两种写法 | 能正确写出代码 |
| **L2 思维层** | 极值在两端、反向填充 | 理解核心思想 |
| **L3 应用层** | 接口抽象 + 场景识别 | 判断何时适用 |

### 核心要点

1. **适用前提**：有序数组 + 平方后极值在两端
2. **核心矛盾**：能从大到小获取，需要从小到大输出 → 反向填充
3. **与同向快慢指针区别**：一个是收集（通用），一个是特化（仅适用有序+极值在两端）
4. **思维门槛**：需要连续推理多个环节，链条较长

> 💡 **关键心得**：这道题的价值不在于记住双指针的写法，而在于体会「如何利用题目给出的条件优化暴力解法」的思维过程。
