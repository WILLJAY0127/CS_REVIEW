# Java 并发：权威官方来源 + 学习边界 + 实操清单（适配资深后端面试，和前面 JVM 的体系对齐）

> 核心区分：
>
> 1. **Java 语言规范 JLS（The Java Language Specification）**：并发、JMM、`volatile`、`synchronized`、`final`、happens‑before 的**唯一官方标准**。
> 2. **JDK 源码 + JDK 官方 API 文档（java.util.concurrent）**：`AQS、ThreadPoolExecutor、Lock、CountDownLatch` 等并发工具的官方实现说明。
> 3. **JVMS（Java 虚拟机规范）**：只规定底层 monitor（监视器锁）的语义，**不包含 JMM**，这点很多资料会混淆。

> 一句话类比：
>
> &#x20;JLS 定义「Java 并发语法、内存可见性规则，语言层面必须遵守什么」；
>
> &#x20;JDK 源码 / API 文档 定义 `java.util.concurrent` 工具类「具体是怎么实现的」；
>
> &#x20;HotSpot 实现（OpenJDK）是操作系统层面：monitor、CAS、park/unpark 的底层实现。

## 一、官方文档清单（标准出处）

### 1. JLS《Java Language Specification》（最核心，权威标准）

官网：[https://docs.oracle.com/javase/specs/jls/](https://link.wtturl.cn/?target=https%3A%2F%2Fdocs.oracle.com%2Fjavase%2Fspecs%2Fjls%2F\&scene=im\&aid=582478\&lang=zh "autolink")

- JDK8 / JDK17 任选，优先你业务使用版本
- **第 17 章：Threads and Locks**【重中之重，并发的根】

  &#x20;内容：线程、锁、`synchronized`、`volatile`、final 的可见性，**happens‑before 规则**，内存可见性、指令重排。

> ⚠️ 面试 90% 争议点（volatile 能不能防止重排、happens-before 到底几条）全部来自这一章。网上很多面试总结会简化甚至写错，有歧义直接翻 JLS 原文校准。

> JLS17 核心要点：
>
> - `synchronized` monitor enter/exit 建立 happens-before
> - `volatile` 变量写 happens-before 后续读
> - final 字段安全发布（构造器不要 this 逃逸）
> - 指令重排的约束：不是禁止 CPU 乱序，是**遵守 happens-before 约束**

### 2. JDK 官方 API 文档（java.util.concurrent）

[https://docs.oracle.com/en/java/javase/](https://link.wtturl.cn/?target=https%3A%2F%2Fdocs.oracle.com%2Fen%2Fjava%2Fjavase%2F\&scene=im\&aid=582478\&lang=zh "autolink")

&#x20;找到 `java.util.concurrent`、`java.util.concurrent.locks`

> 这是 `ThreadPoolExecutor，ReentrantLock，AQS，Semaphore` 的官方 API 说明。
>
> &#x20;API 文档只描述**对外行为、约束、异常**，**不详细讲底层实现**（AQS 内部 CLH 队列、state 变量在 API 文档不会细讲）。
>
> &#x20;底层实现要看 OpenJDK 源码：[https://github.com/openjdk/jdk](https://link.wtturl.cn/?target=https%3A%2F%2Fgithub.com%2Fopenjdk%2Fjdk\&scene=im\&aid=582478\&lang=zh "autolink")

### 3. OpenJDK 文档（HotSpot 底层实现，属于实现细节，不是语言规范）

[https://openjdk.org/](https://link.wtturl.cn/?target=https%3A%2F%2Fopenjdk.org%2F\&scene=im\&aid=582478\&lang=zh "autolink")

- monitor 锁的实现（偏向锁、轻量级锁、重量级锁，**JLS 完全没有提到偏向锁！！**）
- Unsafe CAS、`LockSupport.park/unpark` 底层调用操作系统 pthread

> 重点：**偏向锁、锁升级流程，是 HotSpot 的实现优化，不属于 JLS 语言规范。**
>
> &#x20;👉 面试坑：面试官问锁升级，属于 HotSpot 实现；问 volatile、happens-before，属于 JLS 语言规范。很多网上资料混在一起。

### 4. 经典书籍（不是官方，但是严格对齐官方规范，用来做骨架）

《Java 并发编程实战》（JCIP，Brian Goetz）

> 这本书是业界公认标杆，内容完全遵从 JLS，是官方团队写的，适合建立并发整体认知，**用来入门，有疑问回 JLS 核对原文**。

## 二、学习分层：规范层 → JUC 工具层 → HotSpot 底层层（对标 P6/P7 面试，学到什么程度）

### 第一层：JLS 语言规范（必须吃透，面试区分度来源）

✅ 需要掌握：

1. 线程生命周期（JLS 定义的线程状态，注意：**JLS 线程状态 ≠ java.lang.Thread.State 枚举，更不等于操作系统内核线程状态**，高频坑）
2. `synchronized`：monitor enter/exit，锁的语义、内存屏障、可见性、原子性
3. `volatile`：语义，禁止重排、可见性；**不保证复合操作原子性（i++）**
4. final 安全发布，this 逃逸问题
5. happens‑before 全部规则（JLS 原文的几条，不要背网上删减版）
6. 指令重排：CPU 乱序 + JVM 编译重排；happens-before 不是物理屏障，是**内存可见性模型**

❌ 规范层不用学：偏向锁、轻量级锁、锁升级（属于 HotSpot 实现）

### 第二层：JUC 并发工具（API + 源码，资深面试必考）

模块清单：

1. AQS：抽象队列同步器，CLH 双向队列、state 状态、独占 / 共享模式
   - ReentrantLock（可重入、公平 / 非公平）、ReadWriteLock 读写锁、StampedLock
2. 线程池 `ThreadPoolExecutor`
   - 核心参数、工作原理、任务提交流程、拒绝策略、核心线程保活、坑
3. 原子类：`AtomicInteger`，CAS 原理、ABA 问题、AtomicStampedReference
4. 工具类：CountDownLatch、CyclicBarrier、Semaphore 选型对比
5. ThreadLocal：原理、ThreadLocalMap、内存泄漏根源（key 弱引用）

> 学习方式：看 JDK API 文档看对外行为；读 OpenJDK 源码看内部实现。

### 第三层：HotSpot 底层实现（锦上添花，面试深挖才需要）

- monitor 锁：对象头 mark word、偏向锁→轻量级锁→重量级锁升级流程
- Unsafe、CAS 底层：CPU cmpxchg 指令，总线锁 / 缓存锁 MESI
- LockSupport park/unpark，内核阻塞原理

> 提醒：**如果时间有限，优先前两层。很多人上来死磕锁升级，但是 JLS 的 happens-before、volatile 理解模糊，面试直接翻车。**

## 三、实操清单（资深面试必须动手，不能只背理论）

> 面试官最爱场景题，动手复现过，口述排查逻辑才不是背书

1. volatile 指令重排验证（DCL 双重检查锁，标准 demo）
   - 手写 DCL，理解为什么必须加 volatile，对照 JLS 的 final/volatile 规则
2. 复现 i++ 并发问题：多线程自增，不加锁出现数据丢失；理解原子性
3. 手写死锁代码，jstack 抓取线程栈，识别死锁（和 JVM 实操打通）
4. 线程池实操：
   - 模拟任务队列堆积，观察拒绝策略；
   - 测试核心线程超时，allowCoreThreadTimeOut 参数效果
5. ThreadLocal 内存泄漏 demo：模拟长连接线程复用，不 remove 造成内存泄漏
6. AQS 简单 demo：自己基于 AQS 写一个简易独占锁，理解 state

> 实操目标：
>
> &#x20;能够回答场景：
>
> - 多线程下数据不一致，怎么定位是原子性 / 可见性 / 重排问题？
> - 线程池线上大量任务堆积，如何排查、参数怎么调整？

## 四、整套学习顺序（和前面 JVM 学习模式保持一致）

1. 先用《Java 并发编程实战》搭建并发整体骨架
2. 读到有歧义概念（happens-before、volatile、DCL），**打开 JLS 第 17 章原文核对**
3. 阅读 JUC API 文档，看接口定义，再看 OpenJDK 源码理解内部实现
4. 动手做上面的实操 Demo
5. 学习 HotSpot 锁实现细节（偏向锁 / 锁升级）
6. 场景题复盘，连环追问训练

## 五、高频避坑（网上面试题常见错误）

1. ❌ 错误：volatile 保证原子性

   &#x20;✅ JLS 原文：volatile 只保证可见性、禁止重排，不保证复合操作原子性
2. ❌ 错误：happens-before 就是内存屏障

   &#x20;✅ happens-before 是**逻辑模型**，内存屏障是 JVM 底层实现手段，二者不等同
3. ❌ 错误：synchronized 锁升级属于 Java 语言规范

   &#x20;✅ JLS 只定义 monitor 语义；偏向锁、锁升级是 HotSpot 虚拟机优化，不是规范强制要求，其他 JVM 可以不实现偏向锁
4. ❌ 混淆：Thread.State 枚举 = OS 内核线程状态
