，Oracle 提供的工具，API 文档是契约。

&#x20;基于 JLS 的并发语义封装出来的工具：

&#x20;AQS、ReentrantLock、线程池、Atomic、CountDownLatch。

> AQS 内部用 Unsafe CAS；CAS 只是**JDK 提供的 native 方法**，是 JVM 提供的能力，用来实现锁。
>
> &#x20;这一层：学习工具的**对外行为契约**，再看内部实现。
>
> &#x20;契约优先：线程池拒绝策略是什么？核心线程什么时候保留？
>
> &#x20;实现细节：AQS CLH 队列，属于实现。

### 第三层：HotSpot 虚拟机实现层（JVM 怎么实现 JLS）

JLS 只规定语义，HotSpot 选择的实现方案：

- monitor 锁：对象头 Mark Word、偏向锁 / 轻量级锁 / 重量级锁升级
- Unsafe.CAS 底层封装
- 内存屏障（LoadStore/LoadLoad 等）

> ⚠️ 重点：**偏向锁、锁升级，不属于 JLS 规范！**
>
> &#x20;JLS 只说`synchronized`是 monitor 锁，没有规定锁要分偏向、轻量、重量。换一个 JVM 实现，完全可以不做偏向锁。
>
> &#x20;这一层属于**实现细节**，不是代码契约。面试官深挖才需要讲，写业务代码不用关心。

### 第四层：CPU 硬件层（最底层）

CPU 乱序执行、寄存器、高速缓存、MESI 缓存一致性协议。

> JVM 的内存屏障，最终转化成 CPU 指令，去限制硬件乱序。
>
> &#x20;这一层，**解释 JVM 内存屏障为什么生效**，但是写 Java 代码你不能直接操作。

## 为什么你会感觉 “破坏层级、混乱”？

市面上面试材料典型的跨层举例：

> 讲 volatile：
>
> &#x20;直接：volatile 底层是内存屏障 → 内存屏障依靠 CPU 指令 → CPU 依靠 MESI 协议。
>
> &#x20;一句话连续跳三层：语言规范 → JVM → CPU 硬件。
>
> &#x20;问题：**很多时候，你根本不需要下钻到硬件层，就能解决 Java 代码问题。**
>
> &#x20;代码层面的问题，本来只用 JLS 的 happens-before 就能解释。但是面试材料直接跳到硬件，抽象直接击穿，层级乱掉。

✅ 学习原则（解决层级混乱）：

> **回答问题，优先在最高抽象层解释；只有当上层解释不够，才向下一层钻。不要一上来直接跳到底层。**

举例子：DCL 为什么加 volatile

1. 【JLS 语言层（优先）】：防止构造对象的指令重排，保证对象初始化完成之后，才把引用赋值给 static 变量，满足安全发布。依据 JLS volatile 的有序性、happens-before。
2. （面试官追问怎么实现？才下钻 JVM 层）HotSpot 通过插入内存屏障，禁止指令重排。
3. （继续死磕内存屏障怎么生效？再下钻硬件）内存屏障翻译成 CPU 指令，阻止 CPU 乱序。

> 不要反过来，一上来就讲 CPU MESI，这就是典型跨层，抽象崩塌。

## 并发学习目标拆分（分清哪些是刚需，哪些是补充）

### ✅ 必须掌握（上层，写代码、排查 bug，立足点是 JLS）

1. 线程基础，线程状态（JLS 定义的 Thread.State）
2. 三个核心问题：**原子性、可见性、有序性**
3. synchronized、volatile、final 的 JLS 语义
4. happens-before 全套规则，安全发布
5. JUC 工具契约：线程池参数、拒绝策略、AQS 对外行为、Atomic 的 CAS 特性
6. 多线程业务坑：i++ 线程不安全、线程池 OOM、ThreadLocal 内存泄漏

### ⚠️ 补充（JVM 实现层，面试深挖才讲，不属于语言规范）

monitor 锁、Mark Word、锁升级、Unsafe CAS、内存屏障

### 🟢 了解即可（硬件层，只做理解，不要作为 Java 问题的主解释）

CPU 缓存、MESI、乱序。**不要拿 MESI 解释 Java 代码问题**。

## 和前面 JVM / Spring 的体系对齐

- JVM：JVMS（规范）→ HotSpot 实现 → CPU 硬件
- Spring：Spring 文档契约 → Spring 源码实现
- Java 并发：JLS（语言规范）→ HotSpot 实现 → CPU 硬件

统一规则：

1. 业务代码问题，优先用**最高层规范**解释（JVMS/JLS/Spring reference）
2. 规范解释清楚，就不要下钻底层
3. 面试官继续追问 “底层怎么做到”，再逐层往下看实现细节
4. 记住：**下层是上层的实现手段，上层是契约，不能反过来用底层硬件去推导上层语言规则**

## 一个典型反例（网上面试题错误跨层）

> 错误说法：volatile 保证可见性，是依靠 MESI 缓存一致性。
>
> &#x20;分层纠正：
>
> &#x20;上层（JLS）：volatile 写 happens-before 后续读，保证可见性（这是 Java 语言契约）。
>
> &#x20;中层（HotSpot）：JVM 插入内存屏障来实现这个契约。
>
> &#x20;底层（硬件）：内存屏障最终依赖 CPU 硬件机制（MESI）。
>
> &#x20;✅ 回答顺序：先说 JLS 的 happens-before；追问实现，再说内存屏障；继续追问才提 CPU 缓存。

## 一句话总结

学习并发，**核心是学习 JLS 定义的多线程代码契约，知道多线程下代码执行的可见性、有序性规则，写出不会出现数据竞争的 Java 代码**。

&#x20;锁升级、MESI、内存屏障，都是不同层级的实现手段，**不是 Java 代码的规则本身**。

&#x20;网上面试资料经常不分层级直接从代码跳到 CPU，所以你会觉得混乱。
