# 技能 9:工程化与团队管理

> 对应手册:第 17 章(技术管理面)、第 15 章(香港 App/PM 角色)、第 18 章(HR 面)
> 硬技术决定能不能进门,这一项决定能不能拿 TL offer 和薪资上限。

## 一、简历原句

> 熟练 Docker / K8s、Prometheus + Grafana、SkyWalking、ELK、XXL-Job、ClickHouse;主导全链路压测、限流降级预案;带 5~8 人后端小组,负责技术规划、架构评审、Code Review、招聘与新人培养,有跨团队(业务、核心系统、供应商、客服)协作推进经验。

## 二、能力信号拆解

这一条其实是 4 个独立能力包,面试官按岗位选着问:

1. **云原生与可观测**:部署、监控、链路、日志——证明系统上线后你能掌控它;
2. **稳定性工程**:压测、限流、降级、预案——证明你扛过大促/开门红;
3. **团队管理**:规划、评审、CR、招聘、培养、低绩效——TL 必考;
4. **项目推动**:跨团队 + 香港 App PM 经历——证明离开你的代码也能拿结果。

## 三、知识地图:工程化

| 主题 | 要点 | 项目锚点 |
|---|---|---|
| Docker/K8s | 镜像分层、Pod/Deployment/Service、HPA、ConfigMap;无状态化是上 K8s 前提 | 核验中台 K8s 部署,LLM 突发靠弹性 |
| 监控三支柱 | **Metrics**(Prometheus + Grafana:QPS/RT/错误率/JVM/线程池/队列水位)、**Logging**(ELK,结构化日志 + traceId)、**Tracing**(SkyWalking 跨服务拓扑) | 全链路 traceId 从网关透传到 MQ 消费 |
| 告警 | 黄金四指标(延迟、流量、错误、饱和度);告警分级,避免狼来了;资金差异必须告警到小时级 | 三方对账长短款告警 |
| 压测 | 全链路压测:链路梳理 → 数据准备(影子表/流量回放)→ 压 → 找瓶颈(线程池/连接池/慢 SQL/渠道限额)→ 扩容限流参数定型 | 开门红 20 万笔/日容量基线 |
| 限流降级 | Sentinel 入口 + 渠道侧限额;降级开关分级(只读降级/功能关闭/人工兜底);**预案要演练,不是文档摆设** | 核验开关、AI 转人工、支付渠道切流 |
| 定时任务 | XXL-Job 分片、失败重试、告警、防重复执行 | 批量代扣、对账、断点聚合 |
| CI/CD | 分支模型、流水线卡点(单测/扫描)、灰度发布、可回滚 | AI 工作流 build→check→publish 自动化 |

## 四、知识地图:团队管理(手册第 17 章展开)

| 场景 | 你的标准答法要点 |
|---|---|
| 技术规划 | 从业务目标倒推(稳定性/效率/创新三条线),项目分"还债/当期/前瞻";团队每个人能说出自己做的事和公司目标的关系 |
| 任务分配 | 难活给能成长的人、稳活兜底、新人带小闭环;关键代码我兜底但不抢功 |
| Code Review | 对事不对人;检查清单化(资金幂等/异常路径/日志/性能),CR 是知识统一的最大杠杆 |
| 架构评审 | 强制讲"为什么不选另一个"和"怎么降级/回滚";上线 checklist:开关、监控、告警、回滚、值班 |
| 招人 | 基础扎实 + 学习力 + 责任心;AI 时代更看重问题定义能力;现场让其讲一个最有挑战的项目细节,挖三层 |
| 培养 | 新人 30/60/90 计划;每周 1v1;给场景不给答案;好苗子让他做 owner |
| 低绩效 | 对事不对人、事实记录、给改进期和明确目标、谈调岗/淘汰不拖;**没真实处理过就诚实说"参与过、没独立决策过",不编案例** |
| 事故复盘 | 对事不对人、5why 到根因、action 必须有人和时间;我承担管理责任,让团队敢暴露问题 |
| 向上管理 | 定期同步风险选择题(带选项不带问题),承诺留 buffer,坏消息早说 |

## 五、项目推动:跨团队 + PM 角色

- **方法论(手册 Q17.3)**:换位思考对方 KPI → 给对方省事(适配层收敛改造)→ 契约先行 + mock 并行 → 样板数据说话 → 推不动先技术层共识再双方主管对齐;
- **香港 App(第 15 章弹药)**:两地需求差异清单、需求冻结 + 变更评审、里程碑 + 红黄绿风险台账、两地分工 UAT、"写下来比说清楚重要"的教训;
- **"做了 PM 还写不写代码"死亡题**:补位不是转岗;核心攻坚没放手;管理动作让技术决策更懂排期和沟通成本。

## 六、高频追问

- "开门红怎么做保障?" → 容量评估(数据说话)→ 全链路压测 → 扩容/限流参数 → 开关预案 + 演练 → 值班和应急手册 → 复盘。五段式。
- "线上出事故你的处理流程?" → 止血优先(回滚/降级)→ 定位 → 修复 → 复盘;先恢复服务再查根因,复盘不追责个人。
- "团队里最刺头/最弱的人怎么办?" → 用事实和目标,不用情绪;低绩效给路径和期限。
- "5~8 个人怎么分工?" → 按业务域 owner 制(缴费/核验/AI),公共组件评审制,避免单点 bus factor。
- "你时间怎么分配?" → 约 50% 技术(方案/CR/攻坚)、30% 沟通协作、20% 规划与培养(按真实情况微调,别报 90% 写代码)。
