## 三、知识地图(深度标尺)

### 并发部分

| 知识点 | 要掌握到什么程度 | 常问形态 |
|---|---|---|
| JMM | 主内存/工作内存、happens-before 八条、volatile 两屏障语义(不保原子) | volatile 和 synchronized 区别 |
| synchronized | 锁升级:无锁→偏向→轻量(自旋)→重量;锁对象在 Mark Word | 锁升级过程、为什么有偏向锁 |
| AQS | CLH 变体队列、state + CAS 入队、独占/共享模式;ReentrantLock/CountDownLatch/Semaphore 都是它 | AQS 原理、公平/非公平 |
| CAS | Unsafe 比较交换、ABA(版本号解决)、自旋开销、AtomicXxx/LongAdder | i++ 为什么不安全、ABA |
| 线程池 | 7 个参数运转流程、4 种拒绝策略、**为什么不能用 Executors**(无界队列 OOM) | 线程池怎么配、IO 密集型怎么估 |
| ThreadLocal | 每线程一份 Entry、key 弱引用 value 强引用 → 用完必须 remove | 线程池下为什么会脏数据/泄漏 |
| 并发工具 | CompletableFuture 编排、CountDownLatch vs CyclicBarrier | 多个远程调用并行怎么写 |
| 安全单例 | DCL 为什么要 volatile(禁止重排) | 手写单例 |

### JVM 部分

| 知识点 | 深度 |
|---|---|
| 内存区域 | 堆/栈/方法区(元空间)/程序计数器;JDK8 方法区从永久代移到 Metaspace(本地内存) |
| GC 算法 | 复制、标记清除、标记整理;分代思想为什么成立(朝生夕灭 + 少数熬过多次 GC) |
| CMS vs G1 | CMS 四个阶段、并发标记漏标(增量更新)、碎片问题;G1 Region 化、可预测停顿、混合回收;**为什么大堆选 G1** |
| 类加载 | 双亲委派及打破场景(SPI/JDBC、热部署) |
| 调优命令 | `top -Hp`、`jstack`、`jmap -histo`、`jstat -gcutil`、Arthas(dashboard/thread/trace/watch/redefine) |

## 四、你的项目锚点(必须会讲)

1. **批量代扣 OOM(缴费平台)**:XXL-Job 分片 + 游标分页,不一次性 load 全量——这是"懂 JVM/内存边界"的直接证据,追问点:游标为什么比深分页好、分片怎么分、单批多大怎么定的。
2. **线程池隔离(AI 项目)**:取数层多账户并行拉取用自定义线程池,**必须讲清参数怎么来的**(核心数、有界队列、拒绝策略 CallerRuns、线程名前缀便于排查)。
3. **LLM 调用线程池隔离**:慢调用(LLM RT 数秒)和业务快接口隔离,防止慢调用拖垮公共池——挂 Q9 AI 章。
4. **可补的真实故事**:把你工作中真实遇到过的 CPU 高 / OOM / Full GC / 线程池队列堆积挑 1~2 个,按"现象 → 排查命令 → 根因 → 修复 → 事后加固(监控/参数)"五段式背熟,没有真实故事就不要在简历写"排查调优实战"。

## 五、高频追问与死亡点

- "Redis 计数并发安全吗?" → 单命令原子,但**读-改-写多步不原子**,要 Lua 或 INCR;顺着说"安全"=死亡。
- "线程池队列满了会怎样?" → 走拒绝策略;线上实际怎么发现?(拒绝计数、队列水位监控)
- "什么时候用乐观锁而不是分布式锁?" → 资金状态机 + 影响行数判定(见技能 5)。
- "G1 一定比 CMS 好吗?" → 小堆(2G 以下)G1 的 Region 开销不划算;会讲代价。
- "Full GC 频繁怎么排查?" → 先看老年代涨速和 GC 日志,再 jmap 看大对象/泄漏;常见根因:大对象直接进老年代、内存泄漏、Metaspace 泄漏、显式 System.gc()。
