# 技能 4:Redis 与消息队列(RocketMQ)

> 对应手册:第一篇 Q6(Redis)、Q7(MQ)、Q8(分布式)

## 一、简历原句

> 精通 Redis(缓存设计、分布式锁 Redisson、大 key/热 key 治理、Cluster);熟悉 RocketMQ,掌握事务消息、延迟消息、消息不丢不重、积压治理,在金融级最终一致性场景大量落地。

## 二、能力信号

- Redis 考的是**边界意识**:穿透击穿雪崩、锁的争议、缓存不一致——八股谁都会,区别在你能不能结合资金场景讲取舍。
- MQ 考的是**可靠性闭环**:不丢、不重、顺序、积压怎么办,以及"消息 + 对账"的双层兜底思路。

## 三、知识地图:Redis

| 主题 | 要点 | 深度标尺 |
|---|---|---|
| 数据结构 | String/Hash/List/Set/ZSet/Stream;跳表原理 | 能说每种结构在你项目里干什么 |
| 缓存三问题 | **穿透**:空值缓存/布隆过滤器;**击穿**:互斥重建/逻辑过期;**雪崩**:过期时间打散 + 多级缓存 + 限流 | 三兄弟名字别混,方案要能区分 |
| 一致性 | Cache Aside(先更库再删缓存)为什么这样;延迟双删;强一致诉求不缓存 | "先删缓存再更库"的坑能讲 |
| 分布式锁 | SET NX PX + 唯一 value + Lua 释放;Redisson 看门狗续期、可重入、主从异步复制丢锁;RedLock 争议 | **死亡题:业务执行超过锁过期时间怎么办** |
| 原子操作 | Lua 脚本(限流计数、库存扣减);MULTI 事务的局限 | 计数"读-改-写"必须 Lua/INCR |
| 大/热 key | 大 key:拆分/压缩/异步删除(UNLINK);热 key:本地缓存 + 打散;发现手段(memory usage、monitor、redis-cli --bigkeys) | 要有"治理"不是只会用 |
| Cluster | 16384 槽、CRC16、跨槽 mget/hash tag、主从+哨兵演进 | 为什么不用 Twemproxy 之类 |
| 持久化 | RDB/AOF/混合;主从复制全量+增量 | 缓存场景可接受丢,票据类不行 |

## 四、知识地图:RocketMQ

| 主题 | 要点 |
|---|---|
| 不丢 | 生产端重试 + broker 同步刷盘/主从同步 + 消费端手动 ACK(处理完再提交位点) |
| 不重 | 消息至少一次投递 → **消费端必须幂等**:业务唯一键 + 去重表/状态机 |
| 顺序 | 同一业务 key 路由同一队列(MessageQueueSelector),消费端单线程顺序消费;代价:牺牲并行度,只在真需要时用 |
| 事务消息 | Half 消息 → 本地事务 → commit/rollback;回查机制;适用"本地落账 + 通知核心" |
| 延迟消息 | 18 个固定级别(或 5.x 任意延迟);缴费提醒、超时关单,替代定时扫表 |
| 积压 | 先判断是生产突增还是消费故障;扩消费者/扩队列、临时转储 Topic、非核心降级;**堆积期间消息是否过期丢失** |
| 死信 | 消费重试超限进 DLQ,人工/程序介入,要监控 |

## 五、你的项目锚点

1. **支付回调三重幂等(缴费平台)**:渠道流水号唯一索引 + Redisson 锁 + 状态机。被问"锁有什么用",答:锁是优化(减少无效竞争),唯一索引 + 状态机才是正确性保证。
2. **本地消息表驱动核心入账**:本地事务写业务表 + 消息表 → 投递 RocketMQ → 核心回执 → 状态推进;失败重试,**对账是最后兜底**。为什么不用事务消息?——早期核心不支持、本地消息表多一层可见可查,运维友好(选型要讲取舍)。
3. **延迟消息缴费提醒链**:缴费日前/宽限期/中止预警/复效 4 级提醒,替代扫表,讲清延迟级别限制与补偿(XXL-Job 兜底扫描防消息丢失)。
4. **票据机制(核验)**:核身通过签发 20 分钟票据(Redis),下游凭票换照片,敏感数据不落地多次传输。
5. **按日失败计数(核验防刷)**:INCR + EXPIRE 原子计数,超限封禁——挂"Redis 计数并发安全吗"死亡题。
6. **AI 语义缓存**:高频问题答案缓存(Redis),命中率约 30%,成本 -60%;要讲缓存失效与口径(知识库更新后缓存版本号)。

## 六、高频追问

- "Redis 锁主从切换锁丢了怎么办?" → 会讲 RedLock 思路与争议(时钟假设、性能),然后给务实答案:资金正确性不靠锁,靠数据库约束;锁只挡并发重复请求。
- "消息积压 100 万条怎么处理?" → 定位消费端 → 扩容(消费者数不能超队列数,先扩队列)→ 必要时新建 Topic 转发 → 事后排查 DLQ。
- "消费两次为什么没重复扣款?" → 缴费单状态机 + 流水唯一索引,重复消息直接返回成功(必须 ACK,否则毒丸)。
- "缓存和数据库最终一致,对账前客户读到旧数据怎么办?" → 容忍窗口 + 关键金额不缓存/缓存时间极短;金额永远以核心接口为准(与 AI 红线一致)。
- "MQ 挂了缴费链路怎么办?" → 同步支付主链路不依赖 MQ(回调落库即可响应),MQ 只用于异步入账;XXL-Job 兜底扫未入账单据。
