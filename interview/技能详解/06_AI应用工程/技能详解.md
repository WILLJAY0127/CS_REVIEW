# 技能 6:AI 应用工程 — Dify / RAG / 投连满期金问答

> 对应手册:第一篇 Q9.1~Q9.20(AI 工程)、第 12 章(项目二连环问)、第 16.1 节(设计题)
> **2025/26 面试差异化最强的一项:会调 LLM 的人多,在金融场景把准确率从 62% 干到 88% 的人少。**

## 一、简历原句

## 二、能力信号(别被当成"调包侠")

1. **场景理解**:为什么选满期金(高频、跨系统、口径乱、金额有权威来源);
2. **准确性方法论**:概率模型怎么在 100% 要求的金融场景活下来——"规则靠检索、数字靠接口、模型只负责表达";
3. **工程闭环**:评测集、回归、降级、缓存、安全审计一样不少;
4. **业务价值**:准确率、转人工率、AHT、咨询→领取转化,用数字收口。

## 三、知识地图

### 3.1 RAG 全链路

| 环节 | 要点 | 你的实战做法 |
|---|---|---|
| 切分 | 按条款"章节 + 语义"切,不是定长硬切;表格结构化;FAQ 以问答对入库 | 切分质量决定召回上限 |
| Embedding | 向量化;中文模型选择;维度/成本权衡 | 私有化/合规部署 |
| 检索 | 向量检索(语义)+ BM25(关键词,产品名/术语精确)**混合检索** | 单向量检索召回率不够 |
| Rerank | 粗排多路召回 → 交叉编码器精排 top-k | 准确率提升的关键一跳 |
| Query 改写 | 口语"我的钱什么时候能取"→"满期生存金/领取条件";多轮指代消解 | LLM 改写,低温 |
| metadata 过滤 | 产品/渠道/生效日期版本控制,失效条款不召回 | 防新旧规则混淆 |
| 生成约束 | Prompt"仅依据检索与接口数据,无依据拒答转人工"、低温、附引用来源 | 防幻觉红线 |

### 3.2 Chatflow 意图分流(三类问题三个出口)

```
用户提问 → 意图识别(低温模型/规则前置)
  ├─ 知识类(条件/材料/流程/税收) → RAG 知识库 → 带引用回答
  ├─ 数据类(满期日/账户价值/进度) → 工具调用(Webhook 查核心/投连账户)→ 模板化表达
  └─ 办理类(我要领钱)          → 给在线领取入口 + 预填保单 → 办理闭环
低置信度 → 澄清反问;红线问题(概念混淆/查他人保单)→ 拒答/转人工
```

- **金额红线**:满期金 = 投连账户价值(单位数 × 单位价格,日波动),模型禁止生成任何金额数字,一律接口直出、模板填空;
- **工具安全**:白名单只读,不暴露写操作;userId 从会话态取,**不信模型传来的参数**(越权防线);入模前身份证/保单号/手机号脱敏;全量审计。

### 3.3 准确率 62% → 88% 四段治理(核心叙事)

| 阶段 | 手段 | 提升 |
|---|---|---|
| 62→78 | 知识库重切分 + 混合检索 + Rerank | 解决"检索不到/检索错" |
| 78→85 | Prompt 改写 + 拒答策略 + Query 改写 | 解决"找到了但答错/瞎编" |
| 85→88 | 办理闭环 + badcase 周迭代 + 评测回归 | 解决长尾 |
| 评测 | 500+ 真实咨询日志题集,知识库/Prompt/模型变更自动回归(人工 + LLM 双评) | 没有评测集就没有准确率,只有感觉 |

### 3.4 工程化

| 主题 | 要点 |
|---|---|
| Dify 集成 | `@NoAuth` 白名单注解 + 签名 + 内网 IP 放行(Webhook 无登录态),不动全局拦截器;事件按真实类型解析(MessageEvent/NodeFinishedEvent);Spring Boot 3 + JDK17 |
| SSE | 流式网关 WebClient 转发,首 token 延迟体验;断线处理 |
| 缓存 | 高频问题语义缓存(命中率约 30%)+ 大小模型分级路由 → 单问成本 -60%;知识库版本号防旧答案 |
| 降级 | LLM 超时/失败自动转人工;限流 + 线程池隔离防慢调用拖垮主站 |
| 选型 | Dify(快、可视化、私有化)vs LangChain 自研(灵活、维护重)vs 裸 API(最灵活但一切自建):按团队结构和上线速度选,讲清取舍 |

## 四、高频连环问(详见手册第 12 章)

- "为什么不让模型算金额?" → 投连账户日波动 + 幻觉不可控;金额错误是监管/投诉事故;接口直出成本极低,没有理由让模型做。
- "怎么证明 88% 而不是 85%?" → 评测集构成、抽样口径、双评一致性;**数字怎么统计的**是必问题。
- "模型答错了谁负责?" → 拒答兜底 + 来源引用 + 转人工 + 审计日志;高风险问题白名单直出。
- "RAG 检索不到怎么办?" → 澄清/拒答,不允许模型自由发挥;badcase 进知识库迭代。
- "怎么防止用户套取他人保单?" → userId 会话态强制覆盖 + 归属校验,模型参数仅作筛选条件。
- "Dify 被绑定了怎么办?" → 知识/工作流可导出;Java 集成层收敛鉴权、工具、审计,编排层可替换。

## 五、项目锚点一句话串讲

> 满期金是高咨询、跨系统、金额日波动的场景;用 Chatflow 把知识类、数据类、办理类问题分三个出口,金额一律接口直出;准确率靠混合检索 + Rerank + 拒答 + 评测集从 62% 做到 88%,转人工 55%→22%、AHT -25%;再把咨询用户一键导进在线领取,形成获客到办理的闭环,断点平台能看到每一步转化。
