## 一、两条职业梯子:IC 序列与管理序列

```
技术序列(IC,个人贡献者)                         管理序列(M,管人管事)
初级 → 中级 → 高级 → 资深/专家 → 架构师          技术组长 → 技术经理 → 研发总监
                              │ ▲
                              └────── 分叉点:不带人靠技术影响力,或转管理靠团队产出
```

**关键区分**:

- **资深工程师(Staff)**:仍是 IC,不带人。靠**技术影响力**推动事情——说话有人听是因为技术牛、判断准。
- **技术经理**:管人,背团队交付结果。说话有人听很大程度因为他是领导。
- **架构师**:IC 序列的高阶,但考察维度从"系统怎么实现"上移到"系统该怎么演进、选型怎么定"。

**为什么常把"资深/经理"混着说**:它们在"超越自己一亩三分地的影响力"这个区间重叠(技术决策、治理意识、跨团队推动),差异在资深深挖决策链、经理深挖带人管事。

## 四、连环/闭环追问设计原理(读攻防前必读)

面试官的追问不是发散的,是有**环形路线**的。每份攻防里的追问链都按下面的环设计——你只要在环上任意一点被问到,就能顺着环答完整圈,且圈与圈之间有"接口"可以主动跳转。

### 环形追问的五种推进方向

```
        ① 实现层(怎么做的)
        ↗                    ↘
 ⑤ 治理层                    ② 边界层(什么时候会坏)
(谁背锅/怎么兜底)           (并发/量级/失败场景)
        ↖                    ↙
        ④ 决策层(为什么这么做/不那样做)
                  ↑
        ③ 演进层(如果重来/量涨 100 倍)
```

- **①→②**:说完实现,面试官必追"这样有没有问题"——这是亮坑点(主动承认+给改进方案)
- **②→③**:坑确认后必追"那当时为什么不做对/现在怎么办"——这是演进预案的入口
- **③→④**:方案对比必追"为什么不选另一个"——这是选型权衡
- **④→⑤**:决策做完必追"出了事故谁负责/怎么降级"——这是治理意识
- **⑤→①**:兜底说完可以主动引回"这个开关的实现在我们另一个模块里也有"——闭环

### 举例:断点项目的完整追问环

```
Q: 为什么用 ES 不用 MySQL?
├─→ A: 多维聚合(10 层 terms 嵌套)+ 倒排筛选
│    └─ Q: 聚合桶怎么限制的? → 亮坑:size(10000) 硬上限 ──────────── ②
│    └─ Q: 桶爆炸怎么办?     → 下钻式交互替代一次性全拉 ──────── ③
│    └─ Q: 为什么不用预聚合/数仓? → 搜索归 ES 分析归数仓 ──────── ④
│    └─ Q: 那写入侧呢?       → 亮坑:for 循环单条 index ────────── ②
│    └─ Q: 怎么改?           → Bulk + 异步 → MQ 削峰 ────────── ③
│    └─ Q: MQ 丢数据怎么办?  → 埋点可容忍少量丢失,Kafka 即可
│                              不需事务消息 ───────────────────── ⑤
│    └─(回到数据治理/成本话题)
└─→ B: 那脏数据呢? → blockCode 降级存裸 code 的宽容策略 ────────── ④
     └─ Q: 业务方乱传编码怎么办? → 编码体系+枚举治理 ───────────── ①
```

每份攻防的追问链都标注了环上的位置(①实现 ②边界 ③演进 ④决策 ⑤治理),被追问时你能预判下一环是什么——**这就是"闭环"的含义:面试官永远在环上追问,而你全环都备过。**

### 主动跳转接口(连环话术)

环与环之间的接口是提前埋好的"钩子句":

- 人脸项目的 Redis 计数环 → 主动跳到香港防刷环:"这套按日计数的思路,我在香港泰生活设计验证码防刷时做了四层扩展……"
- 断点项目的 ES 环 → 主动跳到架构师选型环:"这里其实是个选型问题——香港项目当时直接外采了神策,两边对比很有意思……"
- AI 项目的准确性环 → 主动跳到治理环:"准确性架构本质是风控思维——和核身风控的'放行还是拦截'是同一个决策模型。"

## 五、投递策略

| 档位 | 定位 | 使用简历 | 命中率评估 |
|---|---|---|---|
| 资深后端工程师 | **主攻** | 04 | 材料完全撑得住:三代演进 + 从 0 建断点规范 + AI 落地 = 技术影响力证据 |
| 高级后端工程师 | 保底 | 02 | 现有材料已超额 |
| 架构师(业务/后端) | 冲刺 | 06 | 单域三代演进 + 选型对比够用;大厂"企业架构师"岗会被"公司级架构决策"打穿,攻防里有应对话术 |
| 技术经理/组长 | 可投(非主攻) | 08 | 有带新人 + 跨部门 + 里程碑真实弹药;绩效/招聘/辞退用诚实过渡口径 |

- **架构师档红线**:简历定位写"业务架构师/后端架构师",不写"企业架构师"。
- **经理档红线**:绩效、招聘、辞退三类必考题没有真实经历,用"管理认知 + 诚实过渡"口径,绝不编案例。
