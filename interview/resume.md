**项目背景**:投连险(投资连结保险)满期生存金是公司高咨询量场景——客户高频问"保单什么时候满期""满期能拿多少钱""怎么领取、要什么材料";而满期金金额随**投资账户单位价格每日波动**,客服无法凭记忆回答,需翻多个系统查询,响应慢、口径不一。目标:AI 同事 7×24 准确回答满期金问题,并引导客户在线完成领取。

**技术栈**:Dify(对话型应用 + Chatflow 工作流)· 大模型 API · 向量数据库 · Embedding/Rerank · Spring Boot 3(Java 集成层)· SSE · Redis · RocketMQ

**核心职责与成果**:

1. **整体架构**:Dify 私有化部署作为 LLM 编排层(知识库、工作流、发布);Java 侧建设集成层:统一鉴权、会话管理、SSE 流式网关、审计日志、业务工具 Webhook;主导选型(对比 Dify / 自研 LangChain / 直接调 API)到上线全流程。
2. **"知识 + 实时数据"双轮驱动**:规则类问题(领取条件、材料、流程、税收)走 RAG 知识库(条款、满期金给付规则、FAQ);数据类问题(满期日、投资账户价值、领取进度)由 Chatflow 调业务工具实时查询——**金额类答案一律取自核心/投连账户系统接口直出,禁止模型生成数字**(防幻觉红线)。
3. **RAG 准确率专项(62% → 88%)**:

   - 混合检索(向量 + BM25)+ Rerank 精排;Query 改写(口语"我的钱什么时候能取" → 满期生存金/领取条件)+ 多轮指代消解;
   - 防幻觉:Prompt 强制"仅依据知识库与接口数据回答,无依据拒答并转人工",回答附引用来源,低温;
   - 评测闭环:真实咨询日志构建【500+】题评测集,知识库/Prompt/模型变更自动回归(人工 + LLM 双评)。
4. **咨询 → 办理闭环**:识别领取意图后,AI 给出在线领取入口并预填保单信息,跳转领取流程(核验中台实名+活体生存核验 → 核心给付);办理结果可回查,形成"问答获客 → 自助办理"转化漏斗。
5. **工程与安全**:工具白名单(只读查询,不暴露写操作)+ 越权校验(userId 取自会话不信模型)+ 全量审计;入模前身份证/保单号/手机号脱敏;大小模型分级路由 + 高频问题语义缓存,单问成本下降约 60%;LLM 超时/失败自动降级转人工。

**项目成果**:问答准确率 62% → 88%;满期金人工咨询量下降【50%】;坐席平均处理时长(AHT)下降 25%;AI 引导的满期金线上领取率显著提升,项目推广至续期、保全咨询场景。

**项目成果**:覆盖【10+】条业务流程、【80+】标准节点;流程问题从"客诉驱动"变为"数据驱动",优化周期从周级缩短到天级;标准化口径沉淀为团队规范。
