后端资深工程师 / 架构师面试指南
定位区分：资深后端偏落地、性能、故障、工程质量；架构师偏业务抽象、系统边界、技术选型、权衡、组织 / 成本、长期演进。很多公司架构面试会混合考察，下面按模块整理，含高频题、考察点、回答思路。
一、基础与计算机底层（资深必问，架构筛人）
1. 操作系统
进程 / 线程 / 协程区别，上下文切换开销在哪？
进程：独立地址空间，切换需要页表、内核态，开销大；线程共享地址空间；协程用户态调度，无内核切换，开销极低。
陷阱：协程不是万能，阻塞 IO 会卡住整个调度器。
内存：虚拟内存、缺页中断、PageCache、OOM。
IO 模型：阻塞 / 非阻塞、IO 多路复用（select/poll/epoll）、异步 IO。epoll 水平触发 vs 边缘触发区别与坑。
缓存：CPU 缓存（L1/L2/L3），伪共享，内存屏障。
2. 网络
TCP 三次握手、四次挥手；TIME_WAIT、CLOSE_WAIT 产生原因与线上问题。
TCP 拥塞控制、滑动窗口；粘包现象怎么解决。
HTTP/1.1、HTTP2、HTTP3；HTTPS TLS 握手流程。
长连接、心跳包；断线重连设计。
3. 数据结构与算法（架构不会考难题，但要懂工程取舍）
重点不是 hard 算法，而是：
哈希表、跳表、红黑树；为什么 Redis 用跳表不用红黑树？
队列、环形队列、最小堆；限流 / 延迟队列场景。
一致性哈希原理，虚拟节点解决什么问题。
二、数据库（重中之重，资深 / 架构高频）
MySQL
InnoDB B + 树索引，为什么不用 B 树、红黑树？聚簇索引和二级索引区别。
ACID、隔离级别、MVCC、undo log /redo log /binlog 各自作用。
锁：行锁、表锁、意向锁、间隙锁、临键锁；行锁依赖索引，索引失效会退化成表锁；死锁 4 条件与排查。
主从复制原理，异步 / 半同步 / 组复制；主从延迟成因、监控、优化。
读写分离，分库分表：垂直拆分、水平拆分；分片键选择、数据倾斜、跨分片查询、分布式事务、平滑扩容（双写 + 校验 + 灰度切换）。
慢 SQL 排查链路：慢日志 → explain → 索引优化 → SQL 改写 → 参数调优。
Redis
底层结构，单线程模型（IO 多路复用，命令执行单线程）；持久化 RDB/AOF 优缺点。
缓存三大问题：缓存穿透、击穿、雪崩，分别怎么解决。
分布式锁：Redlock、超时风险、续约、可重入；为什么很多业务不用 Redlock。
内存淘汰策略；过期删除（惰性 + 定期）。
集群：主从、哨兵、Redis Cluster；槽位、数据迁移、脑裂。
三、消息队列（架构必问，重点是一致性、可靠性）
Kafka/RabbitMQ/RocketMQ 选型对比。
消息丢失：生产端、Broker、消费端三个阶段怎么保障不丢。
重复消费怎么处理（幂等）；消息积压排查与处理。
事务消息、延迟消息；消息顺序性怎么保证。
架构追问：什么时候不该用 MQ？过度解耦带来运维复杂度、一致性成本。
四、分布式理论 & 分布式事务
CAP 理论：不存在同时满足 C/A/P；业务选型取舍。
BASE：基本可用、柔性状态、最终一致性。
分布式事务方案对比：
2PC：强一致，阻塞，协调者单点，不适合高并发。
TCC：侵入业务，性能好，开发成本高。
SAGA：长事务，补偿。
本地消息表 / 事务消息：最终一致，业务最常用。
分布式 ID：雪花算法，时间回拨问题；数据库号段。
一致性哈希：原理、虚拟节点、扩容缩容数据迁移。
五、高可用、高并发、限流熔断降级（资深 / 架构高频场景题）
限流：固定窗口、滑动窗口、漏桶、令牌桶；分布式限流怎么实现。
熔断、降级、隔离（舱壁模式）；区别是什么，什么时候触发。
系统雪崩成因与防御。
负载均衡：四层 LVS，七层 Nginx；一致性哈希、最小连接、轮询。
服务注册发现，健康检查；服务雪崩。
降级策略：读走缓存、关闭非核心功能、返回兜底数据。
六、工程能力 & 代码质量（资深工程师重点）
接口设计：REST、版本控制、参数校验、错误码规范。
接口幂等设计；怎么保证重试安全。
连接池：数据库连接池、HTTP 连接池，参数配置，泄露排查。
日志、监控、埋点、告警；指标：P99/P999，错误率，吞吐量，饱和度。
线上故障排查方法论：
先保可用，再定位根因；止损优先；记录现场；复盘。
例子：接口 P99 突然飙升，CPU 打满，数据库连接耗尽，内存泄漏。
单元测试、集成测试、压测；如何做容量评估。
七、架构设计大题（架构师面试核心，开放式，考察权衡）
这类题不要直接给方案，要先问业务约束：QPS、数据量、读写比例、一致性要求、预算、团队。
设计短链接系统
设计秒杀系统
设计订单系统（分库分表、事务、状态机、补偿）
设计一个 IM 消息系统
设计日志采集平台
设计分布式定时任务调度平台
回答结构模板（架构题通用）
需求分析：功能性、非功能（QPS、存储、延迟、一致性、可用性 SLA）
业务模型与核心实体
整体架构分层（接入层 → 网关 → 业务服务 → 存储层 → 离线层）
核心模块拆解
存储选型、分片策略
高可用、限流熔断降级、缓存策略
一致性 / 事务方案
监控、告警、灾备
瓶颈预判、演进路线、取舍（trade-off）
八、业务架构 & 软能力（区分资深 vs 架构师）
如何做需求抽象，领域建模（DDD：限界上下文、聚合根、实体、值对象）
如何拆分微服务；微服务优缺点，什么时候不适合微服务（单体更优场景）
技术选型的判断标准：业务适配、可维护、团队熟悉度、成本，不是越新越好。
技术债务管理；如何推动重构，风险控制。
跨团队协作，方案评审，技术难点攻坚，技术落地。
九、自我介绍 + 项目准备（最重要）
准备1-2 个高复杂度项目，STAR 结构，重点突出：
你面临的性能 / 可用性 / 一致性瓶颈是什么
你做了哪些方案对比（trade-off，体现架构思维）
技术方案，落地步骤，风险预案
指标收益（QPS 提升、P99 降低、故障减少）
踩过的坑，复盘学到了什么
资深后端：重点讲性能优化、故障排查、代码质量、中间件落地。
架构师：重点讲业务抽象、系统边界、技术选型权衡、多方案取舍、长期演进、成本与风险。
