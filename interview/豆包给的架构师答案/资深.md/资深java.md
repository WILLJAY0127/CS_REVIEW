# Java 资深后端面试 系统化备战路线（面向业务域技术经理 / 高级开发，对标 P6\~P7，你当前目标）

> 核心定位：**资深 Java 面试 ≠ 背诵 API。面试官考察三层：①基础原理功底 ②复杂业务架构设计 & 取舍 ③问题排查、性能优化、落地风险。**
>
> &#x20;前提：你有后端基础，目标不是应届生；面试提问风格偏向深挖、追问链路、场景题，连环套，不会停留在 “什么是 HashMap”。
>
> &#x20;整体策略：**先搭建知识骨架 → 逐个模块深挖原理 + 手写 / 画图 → 准备场景案例（重中之重） → 模拟连环追问 → 复盘查漏**

## 整体阶段划分（一步一步）

### 阶段 1：摸底 + 划定范围（1\~2 天）

1. 先看目标岗位 JD，把关键词全部摘出来：

   &#x20;例：Spring、JVM、并发、MySQL、Redis、MQ、分库分表、分布式事务、高可用、链路追踪、业务架构、性能调优。
   > 资深岗一定会问：**选型对比、缺陷、坑、如何兜底，而不是 “介绍下 xx 组件”**
2. 自测摸底：

   &#x20;拿一套高级 Java 面试题，不看答案口述。标记三类内容：
   - ✅ 熟练：原理 + 缺陷 + 场景张口就来
   - ⚠️ 模糊：知道大概，深入追问就卡壳（重点攻坚）
   - ❌ 空白：完全不懂，评估是否岗位刚需，非刚需可降低优先级

> 资深面试最大的扣分点：**只懂优点，答不出局限性、适用边界**

### 阶段 2：分模块深度攻坚（核心，7\~14 天，按优先级排序）

> 学习方式：每个模块遵循固定套路
>
> &#x20;学习模板（每个知识点都按这个准备，专门应对连环追问）
>
> &#x20;1）核心原理（一句话定性 + 画图）
>
> &#x20;2）核心流程
>
> &#x20;3）**优点、缺点、适用场景**
>
> &#x20;4）常见坑 & 生产故障案例（最重要！资深面试核心）
>
> &#x20;5）选型对比（什么时候 A，什么时候 B）
>
> &#x20;6）场景题准备（面试官最喜欢抛场景让你设计）

#### 模块优先级排序

##### ① JVM（必问，资深高频）

学习范围：

- 内存模型、堆 / 元空间、虚拟机栈；对象布局、逃逸分析
- GC：GC 分代模型、各收集器（G1/ZGC 核心差异、适用场景、STW）
- GC 调优：如何定位 OOM、CPU 高、频繁 FullGC；工具链`jstack/jmap/jstat`
- 类加载机制、双亲委派；JIT
- Java 内存模型 JMM，volatile，happens-before

> 面试官套路：不是背参数。给场景：线上服务 CPU 飙升 / 频繁 FGC，你排查步骤？

##### ② Java 并发（重中之重，P7 必深挖）

- 线程基础：状态转换，操作系统内核线程、用户态
- 锁体系：synchronized（偏向锁 / 轻量级 / 重量级，升级流程）、AQS、ReentrantLock、读写锁
- CAS 原理、ABA、原子类；ThreadLocal 原理与内存泄漏坑
- 线程池：核心参数、拒绝策略、工作原理；**生产线程池踩坑案例**

> 高频场景：线程池参数怎么配置？业务高峰队列堆积如何排查？

##### ③ Spring 体系（Spring Core + SpringBoot）

- Spring IOC：Bean 生命周期，循环依赖三级缓存原理
- AOP 原理，动态代理；事务（传播级别、隔离级别）
- 事务失效场景（非常高频！全部背 + 理解）
- SpringBoot 自动装配原理；starter

> 经典追问：事务嵌套会发生什么？什么情况事务会不生效？

##### ④ MySQL（数据库，面试一半场景题来自这里）

- InnoDB 底层：B + 树索引、聚簇 / 二级索引、页结构
- MVCC、undo/redo log、隔离级别、锁机制（行锁、意向锁、gap 锁，幻读）
- SQL 优化：explain，索引失效场景
- 分库分表：分片策略、扩容、跨分页、分布式 ID、跨库 join 问题
- 事务、大事务风险，慢 SQL 排查流程

> 场景题：大表如何加索引不锁表？分表后排序分页怎么处理？

##### ⑤ 中间件（Redis / MQ）

Redis：

- 底层数据结构、持久化 RDB/AOF；缓存三大问题：缓存穿透、击穿、雪崩
- 分布式锁方案对比；集群（主从、哨兵、cluster）；内存淘汰策略

MQ（RocketMQ/Kafka 任选其一，优先你项目用过的）：

- 消息模型、存储结构；消息丢失、重复消费、消息积压
- 事务消息、死信队列；如何保证顺序消息

> 核心：**不要只背概念，准备你生产遇到的故障案例**

##### ⑥ 分布式基础

CAP、BASE；最终一致性

&#x20;分布式事务方案：2PC、TCC、SAGA、本地消息表，**选型对比、优缺点**

&#x20;分布式 ID；接口幂等；限流、熔断降级（Sentinel/Hystrix）

##### ⑦ 架构 & 业务设计（P7 区分点，权重极高）

这一块很多人忽略，**资深面试拉开差距就在这里**

- 微服务：服务拆分原则，怎么拆，拆分带来的代价（不是微服务万能）
- 服务治理：注册发现、配置中心、链路追踪 Skywalking/Pinpoint
- 接口设计：版本、兼容性、接口规范
- 业务域建模：DDD（领域驱动，业务技术经理非常爱问）

> 面试官会抛业务场景：比如订单系统，你怎么设计？怎么应对峰值？如何保证数据一致性？

##### ⑧ 附加（按需，看 JD）

Docker、K8s、网关、Elasticsearch。你之前问的 Docker 放到这一块，**能讲清楚镜像、Dockerfile、资源限制、容器网络，生产隔离风险即可，不用深挖内核**

### 阶段 3：项目案例打磨（非常关键！3\~5 天）

> 资深面试**一定会深挖你简历项目**，不是复述功能。准备 2\~3 个你最熟悉项目，按 STAR 重构，并且提前预设连环追问。
>
> &#x20;项目讲述模板（固定）

1. S：业务背景，遇到什么痛点（并发？数据量大？一致性问题？）
2. T：你的目标、约束（预算、技术栈、时间）
3. A：你的方案，**为什么选这个方案，排除了哪些备选方案？**

   &#x20;这里一定要讲取舍：这个方案带来什么代价，哪些 trade-off
4. R：落地结果，指标（TP99、QPS、故障减少，量化！）

> 必须提前准备追问清单：
>
> - 这个方案有什么缺陷？
> - 如果流量翻 10 倍，架构瓶颈在哪，怎么改造？
> - 上线出现 XX 故障，你怎么排查？

⚠️ 大忌：项目只讲做了什么功能，不讲权衡、风险、踩坑。

### 阶段 4：场景题 + 模拟面试（2\~3 天）

两种题型高频：

1. 故障排查题：CPU100%、OOM、接口超时、MQ 大量积压，口述完整排查链路
2. 架构设计题：设计秒杀 / 订单 / 积分系统，要求：流量预估、分层、限流、数据一致性、兜底降级

找人模拟面试，或者自问自答口述。**口述，不要写！面试是口头表达**

> 训练习惯：先分析需求和约束 → 拆解模块 → 分析瓶颈 → 方案选型 → 风险和兜底。不要上来直接给技术方案。

### 阶段 5：简历 + 反问面试官准备（1 天）

1. 简历：项目描述**量化指标**，去掉空话；技术栈不要写自己不熟的
2. 准备反问面试官：团队架构、技术难点、业务挑战，不要问薪资加班

## 面试答题方法论（资深面试答题范式，直接套用）

**任何原理 / 场景题固定回答套路**

1. 先一句话总结结论
2. 讲核心原理 / 方案，必要画图（面试白板）
3. 讲优点
4. 重点讲**局限、缺点、适用边界**
5. 对比其他方案，说明为什么不选别的
6. 生产注意事项 / 坑

> 举例：问你分布式锁
>
> &#x20;不要只讲 Redis 分布式锁。要讲：Redis 锁实现、优点；缺陷（主从切换丢锁）；Zookeeper 锁的差异；各自适用场景；生产如何兜底，超时风险。

## 避坑（资深面试最容易踩）

1. 不要背网上标准答案，面试官很容易听出来；要用自己理解的话，结合项目经验。
2. 不要只讲理论，缺少落地；高级开发看重 “落地能力，识别风险”。
3. 不懂就坦诚：这块我没有深入实践，但是我的理解是 xxx；**不要瞎编**，一旦被追问直接崩盘。
4. 不要只堆技术名词，缺少权衡思考。高级面试本质考察：**在约束下做技术取舍的能力**。
