词法作用域。局部定义的函数也可以访问其定义所在作用域中的命名绑定。在本示例中，sqrt_update 引用了变量 a，而 a 是其外部函数 sqrt 的形参。这种在嵌套定义之间共享命名的规则被称为词法作用域。关键在于，内部函数可以访问其定义所在环境中的名称（而非调用它们的环境中的名称）。   新的名词
词法作用域 Lexical Scope（61A 核心名词）
局部定义的函数也可以访问它被写在哪里（定义位置）所在作用域里的名字绑定。
内部函数看的是定义时的环境，不是调用时的环境。
拆解两段关键句子
内部函数可以访问其定义所在环境中的名称（而非调用它们的环境中的名称）。
1）什么叫「定义所在环境」
python
运行
def sqrt(a):          # a 属于 sqrt 的局部作用域
    def update(x):
        return average(x, a/x)   # update在这里被定义
    return improve(update, close)

update源代码写在 sqrt 函数内部。
👉定义所在环境 = sqrt 调用产生的局部帧。
所以update可以抓到这里的a。
不管以后update跑到哪里被调用，它找a永远回跑到当初定义它的那套环境。
2）什么叫「调用它们的环境」（这是你不要看的那个）
不要看：谁在调用我，就去谁的局部变量里找名字。
举个反例帮你分清：
python
运行
def f():
    b = 100
    my_update(5)   # 这里是调用my_update，调用者是f
    # my_update 不会来这里找变量！！

u = make_update(2,3)
my_update = u

my_update是在make_update内部定义的。
哪怕现在是在f()里面调用my_update(5)，它不会去 f 的局部作用域找 a、b。
它依旧回到当初make_update创建时那套老环境拿a=2,b=3。
✅词法作用域：看源代码写在哪（定义位置）
❌不是动态作用域：看谁调用我（调用位置）
Python、Scheme、JS 全部是词法作用域。
有些老语言是动态作用域（bash 脚本），调用的时候才去调用者环境找变量。
结合闭包把概念串起来
词法作用域是一套查找名字的规则：源代码文本位置决定名字属于哪个环境。
闭包是这套规则带来的运行时现象：内层函数对象把自己定义时的外层环境保存下来，哪怕父函数已经退出。
词法作用域是静态源代码层面规则；闭包是运行时产物。
因为有词法作用域这套规则，才会产生闭包。
极简记忆句
词法 = 看代码写在哪里，不看代码在哪里被跑。
找变量：回到函数被定义的那层环境链往上找，不去看调用者现场。
小测试，巩固理解
python
运行
def outer(x):
    def inner():
        print(x)
    return inner

f1 = outer(10)
f2 = outer(20)

def caller(x):
    f1()

caller(999)

输出是 10，不是 999。
f1定义时绑定的是outer(10)那一份环境，记住x=10。
虽然是在caller(x=999)里面调用 f1，调用者的 x=999 完全不参与查找。
这就是词法作用域最直观的演示。
如果你学 JS，一模一样的逻辑，JS 也是词法作用域 + 闭包。

局部定义的函数也可以访问其定义所在作用域中的命名绑定。
关键在于，内部函数可以访问其定义所在环境中的名称（而非调用它们的环境中的名称）。
定义所在环境：写 def 那一瞬间，周围的环境。
调用的环境：将来运行、执行这个函数那一刻的现场环境，忽略。
这就是 61A 1.6 新增最重要概念：词法作用域。

为什么突然冒出来「词法作用域 lexical scope」
根源：前面一直在聊闭包运行现象（父函数 return 了，内层还能读父局部变量），现在教材把这个现象背后的静态规则给起名字，叫词法作用域。
先分清楚两件东西，不要混在一起：
闭包：运行时现象（发生在程序跑起来之后）
父函数执行完毕本该销毁的局部帧，被内层函数带走、保留存活。
是内存、对象、帧生命周期层面的东西。
词法作用域：源代码层面的名字查找规则（看代码文本写在哪）
变量去哪里找，由def 写在源码哪个位置决定，不是看将来在哪调用。
👉正是因为 Python 遵守词法作用域规则，闭包这个现象才会存在。
没有词法作用域，就没有闭包。
为什么读到这里突然出现这个词？
前面我们看代码：
python
运行
def sqrt(a):
    def update(x):
        return average(x, a/x)

你看到：update能拿到a。
你一开始朴素想法：“嵌套函数，当然能拿外层变量”。
教材现在要回答：凭什么能拿？这套规则叫什么？
答案：这套规则名字叫词法作用域。
教材原文：
局部定义的函数也可以访问其定义所在作用域中的命名绑定…… 关键在于，内部函数可以访问其定义所在环境中的名称（而非调用它们的环境中的名称）。
这句话就是词法作用域的文字定义。
拿反面例子感受：如果不是词法作用域（动态作用域），就不会有闭包
假设有一门语言是动态作用域：
找变量，不看在哪定义，看在哪调用。
python
运行
def sqrt(a):
    def update(x):
        return average(x, a/x)
    return improve(update, close)

improve内部去调用update(x)。
如果是动态作用域：update找a，会去improve的局部环境里面找 a。
improve里面根本没有 a，直接报错。
动态作用域语言：就算写嵌套 def，也产生不出我们现在理解的闭包。
Python 不是这套，Python 是词法作用域：
update找 a，永远回到当初写 def update 那一瞬间的外层环境（sqrt 的局部帧），不管后来在哪被调用。
帮你理顺阅读顺序（你读 Composing Programs 1.6 的顺序）
遇到问题：sqrt_update(x,a)双参数，和improve不兼容
解决方案：嵌套 def，造出内层update
观察现象：update居然可以访问父函数sqrt的局部变量a，哪怕 sqrt 已经退出
📌现在抛出名词：这套访问规则叫词法作用域
运行时的产物：遵守词法作用域，于是产生了闭包（函数对象携带 enclosing 环境，帧被续命）
阅读顺序：看到现象 → 给现象背后的静态规则命名「词法作用域」 → 运行时实体叫「闭包」。
很多人混乱：
以为闭包 = 词法作用域。❌错。
词法作用域：规则（静态，看源码文本位置）
闭包：运行时产生的实体（函数对象 + 捕获的环境），是这套规则带来的结果。
一句话极简：
词法作用域是 “为什么能找到变量” 的规则；闭包是这个规则跑起来之后，内存里出现的东西。
小类比
交通法规（词法作用域）：一套书面规则。
路上跑的汽车（闭包）：遵守法规，才会出现的实物。
法规≠汽车；但是有这套法规，才有这个实物。

但学术圈不这么命名，有历史原因：
不只是 “嵌套”。不单单看大括号 /def 的嵌套，它是一套完整规则：每个标识符的所属环境，完全由源码文本位置静态决定，运行行为不会改变查找规则。“文本嵌套” 只是最常见的表现形式，不是完整定义。
这个术语来自早期 Lisp 研究（61A 的血脉就是 Scheme/Lisp），lexical scope 是 50‑60 年代就定型的专业术语，后世语言 Python、JS 全部沿用这套术语，属于行业历史遗留。
你可以大脑内部做翻译：
看到书本写 lexical scope（词法作用域）
脑子里自动翻译成：【源码文本位置决定的作用域】。
对比两个名词的侧重点
词法作用域（lexical scope）：强调静态、不依赖运行时。哪怕函数跑到程序任意别的地方被调用，查找规则永远不变。
“文本嵌套作用域”：只是描述我们肉眼看到的代码缩进嵌套，是现象，不是完整规则。
举个例子说明单单 “嵌套” 描述不够：
python
运行
def outer(x):
    def inner():
        print(x)
    return inner

f = outer(100)

def outer2(x):
    f()

outer2(999)

肉眼看，f（inner）的源代码写在outer里面，不是写在 outer2 里面。
虽然调用发生在outer2内部，文本上并没有嵌套在 outer2 里，所以不会拿 outer2 的 x=999。
这里核心重点不只是 “嵌套”，而是：绑定的是定义处的文本环境，跟调用现场无关。
“文本嵌套” 能解释大多数简单案例，但概括不了完整规则，所以教科书不会用它当正式名词。
动态作用域对照理解
动态作用域，就完全不看文本写在哪；只看运行调用栈，谁调用我，我就拿谁的变量。
