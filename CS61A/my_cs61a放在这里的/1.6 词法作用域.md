词法作用域。局部定义的函数也可以访问其定义所在作用域中的命名绑定。在本示例中，sqrt_update 引用了变量 a，而 a 是其外部函数 sqrt 的形参。这种在嵌套定义之间共享命名的规则被称为词法作用域。关键在于，内部函数可以访问其定义所在环境中的名称（而非调用它们的环境中的名称）。   新的名词
词法作用域 Lexical Scope（61A 核心名词）
局部定义的函数也可以访问它被写在哪里（定义位置）所在作用域里的名字绑定。
内部函数看的是定义时的环境，不是调用时的环境。
拆解两段关键句子
内部函数可以访问其定义所在环境中的名称（而非调用它们的环境中的名称）。
1）什么叫「定义所在环境」
python
运行
def sqrt(a):          # a 属于 sqrt 的局部作用域
    def update(x):
        return average(x, a/x)   # update在这里被定义
    return improve(update, close)

update源代码写在 sqrt 函数内部。
👉定义所在环境 = sqrt 调用产生的局部帧。
所以update可以抓到这里的a。
不管以后update跑到哪里被调用，它找a永远回跑到当初定义它的那套环境。
2）什么叫「调用它们的环境」（这是你不要看的那个）
不要看：谁在调用我，就去谁的局部变量里找名字。
举个反例帮你分清：
python
运行
def f():
    b = 100
    my_update(5)   # 这里是调用my_update，调用者是f
    # my_update 不会来这里找变量！！

u = make_update(2,3)
my_update = u

my_update是在make_update内部定义的。
哪怕现在是在f()里面调用my_update(5)，它不会去 f 的局部作用域找 a、b。
它依旧回到当初make_update创建时那套老环境拿a=2,b=3。
✅词法作用域：看源代码写在哪（定义位置）
❌不是动态作用域：看谁调用我（调用位置）
Python、Scheme、JS 全部是词法作用域。
有些老语言是动态作用域（bash 脚本），调用的时候才去调用者环境找变量。
结合闭包把概念串起来
词法作用域是一套查找名字的规则：源代码文本位置决定名字属于哪个环境。
闭包是这套规则带来的运行时现象：内层函数对象把自己定义时的外层环境保存下来，哪怕父函数已经退出。
词法作用域是静态源代码层面规则；闭包是运行时产物。
因为有词法作用域这套规则，才会产生闭包。

教材原文拆解
Hence, we realize two key advantages of lexical scoping in Python.
因此，我们可以认识到 Python 中词法作用域的两大核心优势。
优势 1
The names of a local function do not interfere with names external to the function in which it is defined, because the local function name will be bound in the current local environment in which it was defined, rather than the global environment.
翻译：
局部函数的名字不会和外部名字发生命名冲突，因为局部函数名绑定在定义它时的局部环境帧，而不是全局帧。
举例：
python
运行
def sqrt(a):
    def sqrt_update(x):   # sqrt_update 这个名字，只存在 sqrt 的局部帧
        return average(x, a/x)
    ...

sqrt_update 不是全局名字。别的地方我照样可以定义另一个叫 sqrt_update 的函数，互不打架。
✅解决课本第一个痛点：不污染全局帧，全局名字不会泛滥。
如果没有词法作用域，嵌套定义出来的函数名字会跑到全局，就会到处重名冲突。
优势 2
A local function can access the environment of the enclosing function, because the body of the local function is evaluated in an environment that extends the evaluation environment in which it was defined.
翻译：
局部函数可以访问外层包裹函数的环境；因为执行局部函数体时，使用的环境，是在它定义时刻的环境之上再扩展出来的新帧。
这句话对应环境模型那两条新增规则：
函数定义时刻：函数对象保存 parent = 定义处的环境（sqrt 的局部帧）
函数调用时刻：新建调用帧，新帧的父环境直接复制函数对象存好的 parent。
新帧 =（自己的局部绑定） + 继承过来的 parent 环境链。
执行函数体找变量，沿着这条链往上搜索。
重点：继承的是【定义那一刻】的环境，不是调用那一刻的环境—— 这就是词法（lexical）。
什么叫词法作用域（lexical scoping）
lexical：词法的、文本的。
变量去哪里找，看代码文本写在哪里，不看运行时在哪里被调用。
看代码文本的嵌套结构，决定名字查找链条，而不是看运行时谁调用了这个函数。
对比反例：动态作用域（dynamic scoping，Python 没有）
动态作用域：去哪里找变量，看当前是谁在调用我，看调用栈。
极简对比小例子，感受两者巨大差别
python
运行
def f(x):
    def g():
        print(x)
    return g

x = 100
g = f(10)
x = 200
g()

词法作用域 (Python 真实行为)：输出 10。x 取自定义 g 的时候 f 的局部环境，无视全局 x 后来改成 200。
如果是动态作用域：g 被调用时看调用现场的 x（全局 x=200），输出 200。
这就是课本第二句话的本质：
g 执行的时候，它的环境是扩展它定义时的环境，不是扩展调用它时的环境。
把课本两个优势再通俗复述一遍
命名隔离
嵌套内部的函数名字，只待在外层函数的局部帧，不会跑到全局。不会搞乱全局命名空间。
可以访问外层函数的绑定
内层函数执行时，环境链带上定义位置的外层环境，所以可以读取外层函数的变量 / 参数。
这就是我们 sqrt 例子干的事：内层拿到外层的 a。
⚠️注意：
词法作用域是一套名字查找规则。
闭包是这套规则运行之后产生的运行时现象。
先有词法作用域这套规则（parent、环境链）
当内层函数对象逃逸出去，就产生闭包。
词法作用域是底层规则；闭包是规则带来的一个结果。
一句话吃透第二句长难句
local function is evaluated in an environment that extends the evaluation environment in which it was defined.
执行内层函数的时候，会新建一个调用帧；这个帧的环境链，是在函数当初定义时的环境基础上做扩展，而不是调用现场的环境。
这就是为什么就算外层函数已经退出，只要函数对象还持有那个旧环境引用，依然可以读到旧变量。
联系你前面的 Java 认知
Java lambda 业务效果可以做到类似，但不是词法作用域这套运行时环境链模型。
Java 编译器在编译期就把捕获的变量复制为对象字段；没有运行时沿着 frame 链查找名字这回事。
Python 的词法作用域是解释器运行时的机制，也就是 61A 环境图画出来的那一套。
所以调用链可以理解成动态作用域么
调用链 ≠ 动态作用域，但动态作用域拿的就是调用链
先把两个概念划清：
调用链（call‑stack / 调用栈）：物理运行时栈，记录谁调用了谁，所有语言都有。Python、Java 都有调用链。它只是记录执行历史，本身不是作用域规则。
动态作用域 (dynamic scoping)：一套名字查找规则：找变量的时候，顺着调用链（调用栈）往上搜，看调用者栈帧里的绑定。
关键点：
词法作用域：查找链 = 定义时的静态文本嵌套链（parent 环境链），和调用栈无关
动态作用域：查找链 = 运行时的调用链（调用栈），看是谁调用我
Python 有调用链，但是Python 名字查找不走调用链，走函数对象预先存好的parent词法链。
举个假想动态作用域例子（Python 本身没有，模拟）
python
运行
def f(x):
    def g():
        print(x)
    return g

def h(x):
    g = f(100)
    g()   # 如果是动态作用域：找x，顺着调用链往上，找到h的x=20
h(20)

动态作用域假想输出：20。g 被 h 调用，沿着调用栈找 x，拿到调用者 h 的 x。
Python 真实（词法作用域）输出：100。g 的 parent 是 f 的帧，无视现在是谁在调用 g。
动态作用域：变量看 “谁叫我”（调用链）
词法作用域：变量看 “我在哪写的”（定义时的 parent 链）
非常容易混淆的点
Python 的调用栈确实存在，异常报错打印的栈回溯就是调用链。
但是：变量查找完全不使用调用链。
就算调用栈上摆着一大堆帧，内层函数不会去翻阅调用者的局部变量。
python
运行
def outer(a):
    def inner():
        print(a)
    return inner

def caller(b):
    fn = outer(100)
    fn()   # 调用fn，caller在调用栈上，有局部变量 b
caller(20)

inner执行的时候，调用栈是 caller → inner。
栈上明明存在 caller 的帧，里面有b=20，但 inner 完全看不见 caller 里面的名字。
inner 的环境链只走 outer帧 → global，不走调用栈。
总结
调用链是运行时的执行历史，是硬件 / 解释器通用机制，不是作用域策略。
动态作用域 = 使用调用链作为变量查找链路。
Python 词法作用域：有调用链，但查找名字完全抛弃调用链，改用函数对象定义时绑定的parent环境链。
记忆口诀
动态作用域：顺着调用栈往上找（谁调用我）
词法作用域：顺着定义时文本嵌套链往上找（我在哪写的）
这就是教材那句话背后最核心的区分，也是为什么要给函数对象增加独立于调用栈的parent指针。
